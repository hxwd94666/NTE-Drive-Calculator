## 中文

> **先说明：** 这份文档是随手整理生成的，可能不够专业；目前的语言补丁机制和示例补丁也比较潦草。
> 有任何问题、不清楚的地方或需求，都欢迎积极到 [Discord](https://discord.gg/P3ZvMN7Hwj) 反馈。

### 1. 现状

- 项目**暂未正式开展 i18n**，发行版只有简体中文；未来会进行多语言工作，现在完成的是前期准备：
  界面文字抽取、语言补丁格式和运行时替换机制。
- Calc 源码中会显示到界面的中文已登记进同一个文本目录（约 1.09 万条），覆盖检查会阻止新增未登记的中文。
- 独立分析组件（战报分析、计算求解）直接返回的中文说明，也已按其源码快照登记进同一目录。
- `docs/examples/locales/qps-ploc.json` 只是**伪语言**测试补丁（用《》或［］包裹的加长文本），用来检查长文案布局和缺项回退，
  **不是**可发布的翻译。目前还没有任何真实外语补丁做过整页核对。

参与前请先阅读[项目用途、反滥用与协作声明](RESPONSIBLE_USE.md)。翻译只涉及界面文字，不需要也不授予私有组件源码。

### 2. 需要翻译的文件

| 文件 | 作用 |
| --- | --- |
| `assets/locales/zh-CN.json` | 发行中文目录，唯一基础；所有 key 与命名参数以它为准，补丁不能新增 key |
| `docs/examples/locales/qps-ploc.json` | 补丁格式的完整示例（伪语言） |
| `docs/features/localization.md` | 补丁格式、安装与生效、校验上限的正式说明（中文） |

补丁文件格式：

```json
{
  "format_version": 1,
  "catalog_id": "nte-ui",
  "locale": "en-US",
  "display_name": "English",
  "messages": {
    "common.cancel": "Cancel",
    "teams.menu.delete": "Delete team"
  }
}
```

- `locale` 使用规范大小写：主语言小写、地区大写（`en-US`、`ja-JP`），脚本码首字母大写（`zh-Hant`）。
- `messages` 可以只包含部分 key；缺少的 key 自动回退中文，可以分批翻译、分批提交。
- 未知 key、重复 key、命名参数与中文目录不一致、格式身份错误，都会让整份补丁被拒绝。

### 3. 翻译规则

- **保留全部 `{name}` 参数**：名称不改、不增不减，位置可按目标语言调整；只支持 `{name}`，不支持格式表达式。
- 字面花括号写作 `{{` 和 `}}`。
- 换行 `\n` 按需保留；按钮、标签尽量简短，长说明可完整翻译，界面会换行或省略并保留完整提示。
- 补丁内容按纯文本显示，不要写 HTML 标记。

### 4. 暂不翻译的内容

- **游戏数据**：角色、装备、套装、技能、属性、敌人、副本等名称与官方描述来自游戏静态数据库。
  目前只抽取了国服数据，所以只有中文；游戏术语直接翻译容易不准确，因此暂不翻译，在任何界面语言下都显示中文。
- 用户输入与账号数据：账号名、配装槽位名、用户自定义名称。
- 日志、诊断详情、协议字段、错误码。
- 截图识别（OCR）用的游戏界面词库：它匹配的是国服中文客户端画面，翻译会破坏识别。
- Windows 系统原生对话框，跟随系统语言。

### 5. 运行时如何套用译文

界面文字有两种接入方式：

1. **按 key 渲染**：代码直接用 key 取文案，例如 `teams.menu.delete`。
2. **显示边界投影**：文字交给 Qt 控件显示时，若整行文字等于目录里的某条中文原文，就替换成该 key 的译文；
   带参数的模板（如“暴击率上限 {v1}% 低于基础暴击率 5%”）按整行匹配，取出变量后填入译文。

这会影响翻译方式：

- **同一句中文只对应一个 key**，出现在多处时共用同一译文；如果某处必须换一种译法，请反馈，由维护者拆成独立 key。
- **只做整行匹配，不替换子串**；拼接出来的非整行文字不会被翻译，请把这类位置反馈出来。
- 模板译文必须包含原模板的全部参数，否则补丁校验不通过。

### 6. key 的类型与上下文

| key 前缀 | 来源 | 说明 |
| --- | --- | --- |
| 语义 key（如 `common.*`、`teams.*`、`ui.<页面>.<函数>.<控件>`） | 人工命名或界面层生成 | 多数按 key 直接渲染 |
| `auto.<模块>.<函数>.t<摘要>` | 批量登记的整句原文 | 多为显示边界投影；`<模块>.<函数>` 指出源码位置 |
| `auto.<模块>.<函数>.f<摘要>` | 拼接句改写的模板 | 按 key 渲染，参数名来自源码变量 |
| `analysis_core.text.*` / `analysis_core.template.*` | 独立分析组件返回的中文 | 只能靠显示边界投影；模板参数统一命名为 `v1`、`v2`… |

查看每条文案的出处：

```bash
python tools/i18n/export_key_context.py
```

生成的 `build/i18n/key_context.csv` 列出每个 key 的中文原文、参数、接入方式（按 key／整句投影／分析组件输出／未定位）和出处文件。
“未定位”多为兼容旧补丁而保留、已不再显示的 key，可以最后再翻。批量登记时宁多勿少，少数 `auto.*` 条目实际很少显示，不确定的可以先跳过。

### 7. 安装与自查

1. 打开 Calc → 设置 → “界面语言（预备）”，点“导入文本补丁”选择 JSON 文件，在下拉框选择该语言后点“确认语言”，下次启动生效。
2. 可以先导入 `docs/examples/locales/qps-ploc.json`，熟悉哪些位置会变化。
3. 有源码环境时可运行以下检查（不需要私有组件）：

```bash
python -m pytest tests/localization -q
```

```bash
python tools/quality/check_ui_text_coverage.py
```

第一条检查目录格式、参数一致、缺项回退和显示投影；第二条检查是否有未登记的中文（应输出 `literals=0`）。

### 8. 已知限制

- 游戏数据只有国服中文，原因见第 4 节。
- 分析组件文案按快照同步：组件更新后，新增或修改的说明在维护者重新同步前会显示中文。
- 程序回填到输入框的文字若恰好等于某条已登记中文，在非中文界面里也会显示为译文。
- 配装与练度分享图会套用译文；其他贴图素材中若含中文，不会被翻译。
- 长译文只用伪语言补丁验证过主要页面，真实语言仍可能出现个别截断。

### 9. 反馈与提交

- 问题、需求和翻译成果请到 [Discord](https://discord.gg/P3ZvMN7Hwj) 反馈，附上截图、所用语言补丁和软件版本。
- 翻译成果以**补丁 JSON 文件**提交即可，可以只覆盖部分 key、分批提交。
- 需要修改源码（例如拆分 key、调整布局）时，请先在 Discord 说明需求，由维护者处理或按[开发契约](AGENTS.md)协作。

## English

> **A note first:** this guide was put together quickly and may not be very professional, and the current language
> patch mechanism and sample patch are rough as well. If anything is unclear, broken, or missing, please let us know on
> [Discord](https://discord.gg/P3ZvMN7Hwj) — feedback is very welcome.

### 1. Current status

- The project **has not formally started i18n yet**; releases ship Simplified Chinese only. Multi-language work is
  planned for the future. What exists today is the groundwork: UI text extraction, a language patch format, and a
  runtime replacement mechanism.
- All Chinese text that Calc shows in its UI has been registered in a single text catalog (about 10,900 entries).
  A coverage check prevents new unregistered Chinese text from being added.
- Chinese explanations returned directly by the separate analysis component (battle analysis, allocation solver) are
  also registered in the same catalog, based on a snapshot of its source.
- `docs/examples/locales/qps-ploc.json` is only a **pseudo-locale** test patch (lengthened text wrapped in 《》 or ［］)
  used to check long-text layout and fallback for missing keys. It is **not** a real translation. No real foreign-language
  patch has been reviewed page by page yet.

Please read the [project purpose, anti-abuse and collaboration statement](RESPONSIBLE_USE.md) (Chinese) before
contributing. Translation only touches UI text; it neither requires nor grants access to private component source.

### 2. Files to translate

| File | Purpose |
| --- | --- |
| `assets/locales/zh-CN.json` | The shipped Chinese catalog and the only base. Keys and named parameters come from here; a patch cannot add keys |
| `docs/examples/locales/qps-ploc.json` | A complete example of the patch format (pseudo-locale) |
| `docs/features/localization.md` | Formal spec for patch format, installation, activation and limits (Chinese) |

Patch format:

```json
{
  "format_version": 1,
  "catalog_id": "nte-ui",
  "locale": "en-US",
  "display_name": "English",
  "messages": {
    "common.cancel": "Cancel",
    "teams.menu.delete": "Delete team"
  }
}
```

- Use canonical casing for `locale`: lowercase language, uppercase region (`en-US`, `ja-JP`), title-case script (`zh-Hant`).
- `messages` may contain any subset of keys. Missing keys fall back to Chinese, so you can translate and submit in batches.
- Unknown keys, duplicate keys, parameter mismatches with the Chinese catalog, or a wrong format identity reject the whole patch.

### 3. Translation rules

- **Keep every `{name}` placeholder** — same names, none added or removed; you may move them to fit the target grammar.
  Only `{name}` is supported, no format expressions.
- Write literal braces as `{{` and `}}`.
- Keep `\n` line breaks where needed. Keep buttons and labels short; long explanations can be translated in full —
  the UI wraps or elides them and keeps the full text in a tooltip.
- Patch text is shown as plain text; do not use HTML markup.

### 4. Not translated for now

- **Game data**: names and official descriptions of characters, equipment, sets, skills, attributes, enemies, dungeons,
  etc. come from the game's static database. Only the China (CN) server data has been extracted so far, so it exists in
  Chinese only. Game terms translated directly are easily inaccurate, so they are intentionally left untranslated and
  stay in Chinese under every UI language.
- User input and account data: account names, loadout slot names, user-defined names.
- Logs, diagnostic details, protocol fields, error codes.
- The game-screen vocabulary used for screenshot recognition (OCR): it matches the Chinese CN client and would break if translated.
- Native Windows dialogs, which follow the system language.

### 5. How translations are applied at runtime

UI text is connected in two ways:

1. **Rendered by key**: code looks up a key directly, e.g. `teams.menu.delete`.
2. **Display-boundary projection**: when text is handed to a Qt widget, a whole line that equals a registered Chinese
   string is replaced by that key's translation. Parameterized templates (e.g. “暴击率上限 {v1}% 低于基础暴击率 5%”)
   are matched against the whole line; captured values are filled into your translation.

This affects how you translate:

- **One Chinese sentence maps to one key.** Where the same sentence appears in several places, they share one
  translation. If one place needs different wording, tell us and the maintainers will split it into its own key.
- **Only whole lines are matched, never substrings.** Text assembled from fragments will not be translated — please
  report such places.
- A template translation must contain all of the template's parameters, or the patch is rejected.

### 6. Key types and context

| Key prefix | Origin | Notes |
| --- | --- | --- |
| Semantic keys (e.g. `common.*`, `teams.*`, `ui.<page>.<function>.<widget>`) | Hand-named or generated in the UI layer | Mostly rendered by key |
| `auto.<module>.<function>.t<hash>` | Bulk-registered whole sentences | Mostly projected at the display boundary; `<module>.<function>` points to the source location |
| `auto.<module>.<function>.f<hash>` | Templates rewritten from concatenated strings | Rendered by key; parameter names come from source variables |
| `analysis_core.text.*` / `analysis_core.template.*` | Chinese returned by the analysis component | Projection only; template parameters are named `v1`, `v2`, … |

To see where each string is used:

```bash
python tools/i18n/export_key_context.py
```

This writes `build/i18n/key_context.csv` with each key's Chinese text, parameters, usage (by key / whole-text
projection / analysis-component output / unlocated) and source files. “Unlocated” keys are mostly kept for old-patch
compatibility and no longer shown — translate them last. Registration erred on the side of including too much, so a
few `auto.*` entries are rarely shown; feel free to skip anything you are unsure about.

### 7. Installing and checking

1. In Calc, open Settings → “界面语言（预备）” (Interface language, preview), click “导入文本补丁” (Import text patch),
   choose your JSON file, select the language in the drop-down, click “确认语言” (Confirm language), and restart.
2. You can import `docs/examples/locales/qps-ploc.json` first to see which places change.
3. With a source checkout you can run these checks (no private components needed):

```bash
python -m pytest tests/localization -q
```

```bash
python tools/quality/check_ui_text_coverage.py
```

The first checks catalog format, parameter consistency, fallback and display projection; the second checks for
unregistered Chinese text (it should print `literals=0`).

### 8. Known limitations

- Game data is CN-server Chinese only; see section 4.
- Analysis-component texts are synced from a snapshot: after a component update, new or changed explanations show in
  Chinese until the maintainers re-sync.
- Text the program writes back into an input field is also shown translated if it exactly equals a registered Chinese string.
- Loadout and practice share images use translations; Chinese baked into other image assets is not translated.
- Long translations have only been checked on the main pages with the pseudo-locale; real languages may still truncate in places.

### 9. Feedback and contributions

- Please send questions, requests and translations to [Discord](https://discord.gg/P3ZvMN7Hwj), with screenshots,
  the patch you used and the app version.
- Submit translations as **patch JSON files**; partial patches and batches are fine.
- If a source change is needed (e.g. splitting a key, adjusting layout), describe it on Discord first; the maintainers
  will handle it or coordinate under the [development contract](AGENTS.md) (Chinese).
