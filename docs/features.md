# 功能原理与数据契约

## 1. 库存同步与视觉扫描

nte-core 事件经过内容稳定化后一次事务提交装备、词条、角色实例和当前指针。视觉扫描只有在完整解析
结束后才提交视觉快照；取消和异常不产生半成品。视觉 UID 不进入极速装配或仓库状态写回。

卡带在进入计算投影时统一换算成对应品质的满级主词条，视觉快照缺失数值时也使用同一规则。

## 2. 计算与角色配置

计算请求冻结账号、generation、快照、静态数据集、profile 和锁快照。优化器在唯一 UID、套装、形状、
词条、评分和暴击约束下分配驱动与卡带，返回不可变 `WeightedAllocationPreview`。

未显式覆盖时，角色默认携带毕业模板专武，所有角色的卡带主词条和副词条优先级均为未选择，暴击率
上限根据默认满级专武暴击率生成。升级保留账号已经保存的显式角色配置，不用新默认覆盖。副词条自选
先使用最深匹配池，组合无解时逐层放宽并最终回到完整候选池；只有卡带主词条和副词条黑名单属于
词条硬过滤。账号基础权重是持久输入；角色页动态边际权重只读。

卡带满级值写入方案 `payload.tape_main_values`，逐件驱动评分写入 `payload.assignment_scores`。
下游优先读取保存值，只有旧方案缺字段时执行兼容回退。

## 3. 配装与游戏导入

活动方案按自己的 `source_snapshot_id` 读取装备。游戏配装是 nte-core 快照的只读投影；显式导入后才
成为来源为 `game-observed-loadout-v1` 的活动计算配装，并支持锁、替换、装配和倒带评分。

计算保留锁只作用于账号方案。锁定方案不能删除、覆盖或替换；其他方案不能借用其真实 UID。缺卡带但
含真实驱动的方案可锁，空方案与虚拟占位方案不可锁。

## 4. 仓库与鉴定

仓库固定快照浏览并通过 Service 生成锁定/弃置计划。nte-core 写回需等待新稳定快照确认；视觉来源
只读。管理弹窗中的评估角色范围只影响状态评分，与计算角色隔离。

仓库未应用条件时展示固定快照中的全部卡带和驱动。右侧抽屉默认进入卡带页，冻结在滚动区上方的
“卡带/驱动块”页签负责切换两套筛选页面，并在切换后回到滚动区顶部。卡带页提供使用金色代表图片的
套装、主属性和副属性筛选，驱动页提供使用金色代表图片的形状和副属性筛选，不展示主属性；副属性
命中数量默认不选择，只有玩家点击 0 至 4 后才成为显式条件。词条和驱动形状按游戏筛选页的固定顺序
展示。条件以正式 `suit_id`、`shape_id` 和 `property_id` 保存；同组为“或”、跨组为“且”，副词条可
限制至少命中 0 至 4 条。状态筛选固定为“已装备、已锁定、已弃置、其他”；“其他”表示不属于前三种
状态的装备，视觉来源因没有可靠状态也归入“其他”。重置只清除筛选条件，确认后恢复展示全部卡带和
驱动，不把当前停留的页签当成种类条件。驱动形状在筛选页明确分为 II、III、IV 三组并采用游戏内顺序；
仓库结果将相同套装卡带和相同形状驱动稳定排列在一起。抓包与视觉快照共用同一词条筛选与排序契约。

鉴定把截图、剪贴板、手工输入和仓库单件入口统一为装备对象，调用公共评分与展示，不写库存、权重或
配装。扫描与鉴定通过 owner 隔离的全局热键管理器共享系统热键能力。

## 5. 倒带推荐

工具页读取当前账号偏好、固定库存和活动计算配装。打开页面不自动求解；显式生成后返回八槽形状
多重集合。

评分阈值：

```text
目标分 = 等级比例 × 驱动面积 × 10
缺口 = max(0, 目标分 - 方案保存的逐件评分)
```

- 全面均衡：全部培养角色短板；余位按“形状总缺口 ÷ 库存”比例分配。
- 少角冲分：仅冲分角色；余位按评分缺口的递减边际逐槽分配。

每槽概率 12.5%。同形状重复 `q` 次时，每槽价格 `10 + 5 × (q - 1)`。难度只决定蓝/紫/金品质，
不进入形状、概率或价格求解。

“进行倒带”弹窗确认后会把品质与驱动定制模式合并写入当前账号的 `rewind_recommendation` 设置副本；
再次打开时从该账号恢复，账号之间不共享。显式执行会冻结当前品质、驱动定制模式和已保存八槽方案，
再由游戏输入 Integration 执行。
执行器按所选品质逐个切换初级/中级/高级难度，等待页面刷新后再从右上角区域 OCR 该难度自己的
胡萝卜币；不复用切换前余额，也不在品质间拆分余额。初级难度没有驱动定制，始终选择随机驱动并按
固定十连 600 计算；紫色、金色品质才使用玩家选择的定制模式。“否”模式也选择随机驱动。
“是且不做更改”进入现有定制但不修改候选。“是且应用方案”进入“选择驱动”，切换到自由搭配并清空
右侧八槽；它不信任候选卡片的既有形状顺序，而是用 OpenCV 提取每张卡片的彩色前景轮廓，再与官方
12 种占格拓扑做全局一一匹配。蓝、紫、金只影响前景颜色，不改变识别规则；重复形状按方案数量重复
点击，最后确认并返回。两种定制模式随后从右侧硬币口下方 OCR 当前十连价格，只按
`余额 // 十连价格` 点击“投币10次”，从不使用左侧单抽价格。
难度、随机/定制模式和方案配置等前置点击后均等待 1 秒；十连按“点击 → 等待 1 秒 → Esc → 等待
1 秒 → Esc → 等待 0.5 秒 → 下一次点击”循环，执行期间可按 F12 停止。

候选方案支持逐槽选择与当前页面一键清空；清空不修改当前账号已保存的八槽方案，重新打开页面时仍会
载入保存方案。候选选择弹窗每次只修改一个槽位，不提供批量“添加数量”。执行前必须由玩家提前打开
游戏内倒带页面；游戏输入执行仍为实验能力，尚未完成真实游戏环境验收。每个候选槽在同一行展示“缺分、
库存、概率”三项解释，逐槽替换弹窗的十二种形状也在驱动下方单行展示固定快照中的对应库存数量。
保存八槽方案时同时保存每槽正式 `shape_id` 和生成时的缺分；重新打开页面无需再次分析即可恢复缺分，
库存仍从当前固定快照刷新，不写入方案。

全部倒带点击点、右侧八槽删除点、左侧十二候选点和 OCR 区域统一从 2560×1440 参考画布映射；公共
行为测试覆盖 1920×1080、2560×1440 和 3840×2160，OpenCV 候选识别也在这三档分辨率验证缩放。

## 6. 自动装配

极速装配只消费 nte-core 正式 UID、角色实例和已保存方案；批量任务冻结来源快照并持久化角色项和事件。
游戏界面自动装配使用视觉识别与虚拟手柄。两条链路都阻止账号切换，并以新稳定快照确认最终状态。

极速装配每个角色最多尝试三次：首次下发后等待稳定快照，未匹配时卸空重装并再次等待，第三次复核仍
不匹配才返回报告。每次请求之间保留插件队列等待；没有取得递增稳定快照时停止重试。报告分别标识
管道缺失、管道可用但此前请求超时、插件队列繁忙、核心请求超时、快照等待失败，以及未装备、错误角色、
错误角色实例、错误位置或装备集合不一致。

## 7. 战报

战报使用 nte-core combat 会话的聚合事件和摘要，历史写当前账号库。背包同步与战报按生命周期共享捕获
进程。逐击、Buff/Debuff 区间、队伍和敌人实例等未开放 capability 不由 UI 推测。

## 8. 设置、更新和日志

主题写 `config/global_ui_preferences.json` 并对全部账号生效，账号切换不重新应用账号主题；旧版账号
主题仅在全局文件首次建立时迁移。其他设置写当前账号或既定应用级路径。环境诊断检查 Npcap、
nte-core、dwmapi、插件和资源。Mirror 负责更新
来源、下载与安装。结构化日志记录 operation ID、阶段、耗时和脱敏上下文，不记录完整业务 payload、
用户路径或鉴权材料。
