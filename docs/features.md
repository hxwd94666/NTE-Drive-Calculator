本文描述当前已实现并由公共行为测试覆盖的功能。分层与数据域见 [系统架构](architecture.md)；仍需真实

## 1. 账号、设置与工作台

### 托盘驻留与游戏快捷轮盘

点击主窗口关闭按钮或按 Alt+F4 时，使用分区选择页解释「保留后台运行」与「退出程序」，取消只保留窗口右上角的关闭入口，不再显示底部取消按钮和重复说明。
后台入口优先展示；初始焦点留在对话框，回车保持打开；关闭对话框或按 Esc 只返回应用，不提前停止任务。键盘可到达各动作，主动聚焦后的回车/空格按所选动作执行。
两个动作按钮不显示鼠标悬浮说明；“最小化”统一使用短标签，具体去向由卡片正文说明。窗口在主题生效后按实际换行高度限位，常规内容不出现内页滚动条；屏幕不足时仍保留必要滚动，不截断内容。
托盘不可用时自动改用任务栏，并说明如何返回，避免隐藏成没有恢复入口的窗口。最小化保留后台战报、同步和已开启 HUD，不进入退出收尾。
「退出 Calc」仍经过已有草稿确认、任务物理收尾及组件清理；取消保存确认后窗口继续可见。关闭选择不保存“以后默认退出”偏好。
托盘菜单的明确退出、更新、系统会话结束、启动失败收尾及内部 close 调用不重复询问关闭方式，仍走真正退出流程。
托盘保留打开入口；隐藏窗口不代表业务 owner 已结束。

插件页的「自定义打桩」开关控制游戏快捷轮盘，保存为本机偏好，首次默认关闭；重启、正常重连和账号切换后，在当前模式允许、未暂停且未进行组件维护时自动恢复菜单。恢复创建新的菜单 owner，不重放旧选择，也不自动录制或召唤。主轮盘提供木桩练习、战报开始/结束保存、
技能冷却、敌人状态、性能监测、打开 Calc 和一个取消；指向木桩入口展开次轮盘，回中心返回主轮盘。
木桩次轮盘包含七种模板与清理，各格显示血量和模板短标签，中心显示模板参数。
这套主次菜单复用游戏原生八槽控件，由组件管理分页；不声称游戏已有同样的双环接口。
菜单复用游戏原生键盘轮盘；启用时在大世界和副本的可操作主 HUD 中响应 Tab，其他顶层菜单中不主动打开。
松开确认当前选择，Esc 或切出游戏取消；启用或恢复焦点时已按住的 Tab 需先松开。关闭恢复原 Tab 功能。
非木桩业务仍调用既有 Calc 服务，不启动第二套采集。
性能入口与设置页的“显示游戏内性能”共用同一偏好与控制器，不改变性能日志或战报录制。
动作按本次会话及编号只处理一次，异步保存或显示设置未确认时保持忙碌；断线、账号切换或未知结果不自动重放。
加载插件不等于启用，退出或连接失效后的原生心跳租约负责有界停止接管，自有木桩仍按精确实例维护所有权。
专项验证不替代当前游戏构建的 Tab、召唤及清理验收；交付状态见本次组件配套说明。

### 队伍管理

侧栏「队伍」独立管理当前账号的四人队伍，支持新建、命名、编辑成员、删除，以及按队伍名或成员拼音搜索。
选人弹窗使用头像卡片，点击选择或移除，已选成员在顶部展示；每队最多四名不同角色，未满员可保存为待补齐配置。
不同备用队伍允许共享角色，不绑定深渊或任何玩法。队伍使用稳定 ID，改名不改变身份；成员使用正式角色 ID，
成员候选按姓名拼音 A–Z 排序（英文不区分大小写），同名以正式角色 ID 稳定排序；搜索或缩放不改变已选队内顺序。目录暂缺时保留原成员并标明暂不可用。队伍和成员在账号库内原子保存，旧修订不能覆盖新修改。
切换账号清空旧页面和未提交草稿，提交前复核账号与代次。删除队伍移除该队配置和轻量增强结果，
不删除角色、配装、战报或另一队的联合结果。
计算页通过独立的「战报增强」选择已保存队伍；当前计算行为见[计算结果后处理](#计算结果后处理)。

#### 按阵容匹配战报

计算页的战报选择与队伍毕业率的选轴共用一套范围列表：以战报 ID、整场／半场或原轴微秒时段定位，
含上下半场的记录分别核验，不拿八人并集匹配四人队伍。列表按保存时间发现、分页读取、后台逐项核验，
可筛选场景与状态；不按伤害或 DPS 推荐，也不默认选择首项。

完全匹配仅来自分析组件确认的完整四人集合，队内顺序不影响结果，零伤害成员仍属于队伍。
出伤摘要只用于「出伤成员相关」提示，不提前排除候选。阵容不同显示差异成员；证据不足、范围冲突、
组件未就绪和查询故障分别显示，不把未知或故障计为已确认零匹配。自建、未满员或缺目录身份的队伍保留浏览及具体缺口。
手工指定战报／原轴时段仍走同一核验；指定时段为半开区间，不推断未保存的换队边界。

找战报不要求当前稳定库存，不启动采集或游戏连接，不修改角色、库存、配装与原始战报。
计算页确认范围只进入增强配置，不开始计算；用户仍需确认队伍、原始／已启用编辑 A 配置，并显式开始计算。毕业率选轴仅更新毕业率草稿，不打开增强配置。
选择时重新核对队伍修订和来源摘要，正式计算继续核对当前完整库存、固定队友及轴输入；匹配不等于增强就绪。
刷新失败保留旧列表并提示可能过期；翻页、离页、关窗和账号切换取消本 owner 的读取，迟到结果不回填新页面。
本轮专项及剩余验收见[验证记录](roadmap/teams.md)。

#### 队伍配装简报

队伍列表以单层条目展示，四个成员保留头像与名称，不使用嵌套摘要图块。头像按内容宽度靠左聚拢，不均摊整行；宽屏右侧共用四列两行，配装、毕业率、增强摘要分别对齐下方入口，单独计算居中对齐更多；窄屏将这两行移到阵容下方。重排保留同一批控件及读取结果；四人成组按四／二／一列换行。
常用入口依次为「队伍配装」「毕业率」「增强记录」；「更多」只放编辑队伍和删除，删除仍须原有确认。队伍页不展示匹配战报、战报增强或手动刷新入口，增强配置仍从计算页打开。配装摘要只显示来源、齐全人数及待核对标记；毕业率显示固定轴百分比与历史／待核对／过期状态，尚未读取与未知分开；增强只显示已保存的计分增幅、未提升、仅基础配装或暂无记录。覆盖、搜索预算、缺口及来源原因保留在纯文本提示和相应详情中，不以简写隐藏未知或冒充全场收益。
队伍编辑、配装来源显式保存和计算方案保存后由原通知刷新相关队伍，返回页面也会重新读取；毕业率任务与历史回调独立更新结果。页面不轮询游戏，不自动重算毕业率。读取失败显示待核对，可重新进入队伍页或打开队伍配装重试。
卡片右上角蓝色「单独计算」只准备一次本队计算，不立即求解。它跳转计算页、等待当前账号目录就绪，再打开「进行配置」共用的队伍／战报选择窗口：只显示并预选来源队伍，旧双队绑定及边际战报请求不带入，不自动选择战报。正式阵容、范围和原始／编辑配置仍须确认。
确认成功后，第一步切为使用已有库存（不启动扫描），第二步只保留本队四名角色（按队内顺序），三个相邻优先级均设为 `=`，第三步启用战报增强；原套装、词条、弧盘、暴击偏好、权重、槽位与配装锁不变，不自动保存永久优先级。确认应用新草稿后才清除旧计算预览及保存资格，用户仍须显式点击开始计算，再按原流程保存结果。
取消、关闭或前往队伍时，原选人、增强开关／绑定及旧预览保持不变。准备失败、离页、停止、账号切换、队伍修订变化或用户修改草稿会撤销旧请求；未满四人、角色缺失／身份歧义及正在计算／扫描／配置时不替换原草稿。一个请求只打开一次配置，不因启用开关再弹一层；准备被放弃后可重试，不写背包、不连接或操作游戏。真实主窗口与混合 DPI 验收仍见[剩余门禁](roadmap/teams.md)。
队伍卡片按配装、毕业率、增强顺序显示摘要及对应入口，单独计算位于更多上方并居中对齐。战报增强的选择队伍窗口以一条简短指引或当前状态呈现，底栏从左到右为前往队伍、确定、取消；管理仍按取消本次配置后导航处理。

选择队伍以紧凑阵容行展示四名成员，选中后再展开战报与养成来源；点击卡片被动区域或头像可勾选，内部选择战报/来源控件不会反向取消队伍。人物互斥、最多两队及未满员限制就近显示原因。已知队伍数量影响首次尺寸；异步读取先用紧凑加载窗口，回填、勾选与核验不反复缩放或重置滚动。

队伍页面标题旁显示独立的红色带框单行开发提示，仅该页面可见；窄窗省略时保留完整提示与可访问名称，不改变现有权限或保存逻辑。队伍卡片的配装摘要只显示简短来源及齐全人数，保持单行，缺项原因在提示和队伍配装中查看。

匹配战报的筛选在宽窗单行、窄窗换行；列表分开显示范围、场景、保存时间和匹配状态，详情解释原因及下一步。未确认、不同、证据不足、冲突和故障均保留可读详情，只有正式匹配可确认；确认仍重新核验，不自动选择首条或立即计算。筛选无结果可查看全部状态，读取失败保留已有内容并可重试；进度回填保留当前范围与滚动位置。手动时段默认收起；展开后战报、范围与起止时间采用紧凑表单，宽窗两行、窄窗换行，普通窗口下无需在小区域里逐项滚动。选择战报后秒值可直接编辑，编辑自动选择自定义时段；程序回填旧范围不触发该切换。起止输入等比例填满本行可用空间，保留微秒精度；确认按钮按文字宽度显示，异常长译文有宽度上限，底部动作始终独立可达。回车只作用于明确获得焦点的按钮，列表、来源与时间输入不隐式确认；取消等待本窗口 worker 物理结束，不写入草稿或账号。

「队伍配装」合并来源选择与成员预览，只保留「当前计算」和「当前游戏」。当前计算为每名成员选择一套已保存槽位，当前游戏只读取已有稳定快照；修改先预览，显式保存才更新该队配置，取消不写入，也不触发同步、装配或分析。
旧自动来源升级时一次冻结原来解析的槽位；原指定槽位与游戏来源保持不变。明确保存的绑定始终按稳定 slot_id 使用，删除或归档后保留缺项，不自动换槽。当前计算模式下，尚未绑定的成员仅在可见槽位恰好一个且已有保存方案时默认使用；多槽或空槽仍需配置。默认解析只读，不创建绑定或推进修订；新增第二个槽位后隐式默认失效，已明确保存的选择不受影响。成员预览、简报及后续计算输入共用该口径，完整性与装备冲突校验不放宽。

| 简报来源 | 读取及缺项语义 |
| --- | --- |
| 当前计算（默认） | 按每成员明确选择的稳定 `slot_id` 读取；未选择、删除或归属不符保留缺口，不自动改用其他槽位 |
| 当前游戏 | 只读同一稳定完整库存的已确认装备关系；视觉归属未知或原生缺项不补齐 |

计算方案各读自己的来源快照，不以最新库存重解释旧方案。缺成员、来源、真实词条或合法配装分别提示；
真实装备跨成员重复时显示冲突。「队伍配装」用紧凑头像行区分暂无配装、多槽待选择、空槽、失效槽位与来源缺项；唯一已保存槽位标明默认使用，空槽在选项内明确标记。同名槽按稳定 ID 区分，槽位／方案／来源快照收进默认收起的诊断详情，不输出完整UID列表。每名角色的装备数量与来源说明合并为一行，计算与游戏来源均不换行；长内容省略并保留完整提示与可访问名称。下拉框保留当前字体与主题所需高度，空间不足时滚动内容，不压缩输入或底栏。
底栏区分未修改来源与尚未保存，只提供保存与取消，不再提供前往配装入口。队伍配装使用紧凑初始尺寸，读取成员后按完整四人内容适配尺寸，常规屏幕无需滚动查看默认成员信息；诊断展开也重新限位，空间不足的小屏或异常长译文保留滚动兜底，不遮挡底栏。
简报读取不依赖角色页个人毕业模板，不把实际装备投影到满强化，也不运行个人毕业计算。

旧队伍平均装备毕业率及成员个人毕业数值已从队伍简报源码移除；角色页独立的个人装备直伤毕业率保留。
卡片「毕业率」未读取时显示「未读取」，不是0%或旧均值。入口打开本账号结果窗口，后台分页读取已保存数学基准/评价；历史不依赖源战报仍存在、不启动分析组件。窗口优先呈现结构化百分比、当前期望轴伤、本次搜索参照及有效性，再提供选轴、设目标、建基准路径。百分比只读正式投影字段，不从标题文字解析；未知、真实 0% 和超过 100% 分别保留。结果说明、毕业目标、提升建议与历史记录按标签页分开，详细计算证据、技术 ID 及高级预算与过期检查默认收在「结果说明」的折叠区内；查看或展开不启动计算。养成建议和装备／词条建议在同一区域独立发起，并明确只读、不修改角色或装配。

毕业目标消费冻结目标的独立结构化展示副本，突出版本、预设、装备数量及每名角色的等级／突破／觉醒、弧盘、好感、技能等级和图纸数量；宽窗分两列，窄窗自然转为单列。头像与名字由窗口显式注入的只读展示资料提供，不用名称关联计算输入。切换预设仅切换显示，完整词条池、装备坐标、正式技能 ID、额外假设和限制保留在默认折叠的「词条与完整参数」及纯文本提示中；缺结构副本的旧展示不从中文说明反解析或补造摘要。
目标与建议只使用窗口外层滚动，内部没有可滚动文本视口；长建议保持完整纯文本，不截断、补零或重算。阅读目标、建议和历史时收起重复的大段总结果说明，仍保留比例、轴范围、有效性状态与原操作入口，回到结果页可读全部数值。历史基准和评价使用相邻两行的标签、选择框及各自翻页按钮，不让换行标签撑开行距。

- 「刷新记录」和基准/评价翻页只读库，不计算、不改变操作上下文或选用指针。
- 「1. 选择战报轴」复用四人阵容匹配与明确范围选择，只更新毕业上下文，不进入战报增强或自动计算。
- 「2. 设置目标」读取冻结资料后编辑合法养成、好感/家具与每人固定的已保存布局，觉醒和弧盘暂时冻结当前值；家具目标默认折叠，保留原值精度；确认仅保留草稿，不开始计算或保存配置。布局证据缺失不猜坐标。
- 「3. 建立基准」在目标和参考轴均明确后显式计算，使用显示的评价次数/时长预算，不自动保存或选用。
- 「选用此记录」显式CAS更新指针并恢复冻结轴、目标和规则；不重放或重新冻结实际配装。历史状态不冒充当前仍有效。
- 「更新毕业率」「养成建议」仅在恢复了明确基准后显式发起；需要对应新分析能力。缺组件时旧历史仍可读。
- 「装备与词条建议」需先显式保存基准或选用历史，再独立评价单件、单人整套及整队联合目标；保留当前养成，不重搜分母。理论词条和强化值可在建议页查看，不代表背包已经拥有，也不会执行装配。
- 「检查结果是否过期」只读当前实际来源、评分规则及组件身份，不启动分析进程或重搜。当前输入变动只使分子过期；轴、目标、静态或组件身份变化要求新基准，旧结果保留。换草稿立即清空旧数值，重开/刷新先按历史待核对。
- 「保存结果」先复核本次来源、账号及组件，再原子保存；过期预览不能因刷新历史重新获得保存资格。
- 关闭、取消、离页及账号切换撤销本次任务发布权；线程由队伍owner持有并物理收尾，不影响匹配/增强等其他功能。

结果支持显示“固定观测轴毕业率”：明确假设动作和时点不变，实战可执行性单独标为未证实；100%是本次有界参照，超过100%不截断。当前零伤害可显示0%，伤害模型未知或超目标比较条件时保留原因，不伪造比例。比例由支持新能力的独立组件产生，保存/历史保留其原始结果；旧历史未携带比例时不在界面补算，可显式更新当前评价。

装备建议沿用「保存结果」显式追加到同一基准的历史，原分母和冻结轴不变；读取/选用历史不启动分析。新分析能力缺失只限制对应计算，现有战报及只读历史继续按自身能力工作。随附分析组件已成套接入这些操作，并完成合成schema50库的正式EXE与保存/UI专项；打包安装、实机和整应用验收仍是独立门禁。缺某项建议能力不撤销其他独立操作的入口；失败结果保留为历史且撤销保存权。范围见[开发方案](roadmap/teams.md)和[验证记录](validation/team-axis-graduation.md)。重读简报、打开队伍配装不发起理论求解。

队伍相关选择、来源、目标、毕业率和历史窗口共用明确动作的回车规则：输入、列表或组合框获得焦点时不隐式提交，按钮获得焦点后才执行其动作；Esc 沿原取消与 owner 退场流程处理。来源及历史窗口底栏独立于滚动区，窄窗将状态移到动作上方，导航与动作的 Tab 顺序对应可见顺序。毕业率与增强记录按当前可见内容估算首次尺寸，首次读取完成可校正一次；用户已调整尺寸则保留。隐藏标签页不预占高度，增强记录及诊断的短说明随内容收缩、长说明局部滚动；目标与建议按前述单层滚动处理；诊断展开后滚动到开头，不反复缩放窗口。必要的结果、轴范围、过期／未知和加载／失败状态仍在主内容中，底部动作按文字宽度靠右。毕业率底栏从左到右为「停止计算」「更新毕业率」「保存结果」，不另设关闭按钮；右上角 × 和 Esc 继续按原 owner 取消及退场契约处理。折叠状态、按钮、摘要与新增说明同步发行中文和示例语言补丁，旧补丁缺项回退，长文案保留完整可访问名称及纯文本提示。

#### 最近已保存增强与历史

卡片按同一 `team_id`、相同成员集合的提交时间及稳定结果 ID 取最近记录，不推荐历史最高收益。
新预览明确显示「尚未保存」；仅完整成员方案与队伍结果在同一事务成功提交后进入持久简报。
失败、取消和插入结果故障整体回滚，重复保存同一作业返回已确认结果，不重复新增记录。
只优化部分成员、未形成整队可保存预览时，不从其他当前槽位补造队伍增强记录。

本队提升始终比较该次作业固定的 B0 与最终计分值，不比较战报原装备、上次结果或当前槽位。
有效优化结果保留本队正／负增幅；合法 B0 显示「基础配装已保存」，缺少已证实提升时不写 0%。
范围、原始／编辑 A、量化／估算覆盖及搜索截断与结果一起解释，图纸枚举未完成也属于未完成搜索；
计分部分提升不称为全场实测提升。双队各读自己的结果，综合归一指数与另一队仅在联合详情展示。

「增强记录」按保存时间分页读取不可变轻量历史，不发起伤害求解。少量记录使用紧凑列表，选中后按「优化前后／使用来源／搜索覆盖／关联变化」四个只读标签页展示；来源页先显示战报范围和保存槽位，静态／引擎版本、方案／快照及结果／作业 ID 收在默认折叠的「详细诊断」内。未知不补零，负增幅不隐藏，联合归一指数不解释为队伍伤害。方案替换／删除、来源配置变化、战报清理或静态／组件变化
只改变当前关联状态，不重算旧值；改成员保留历史阵容，改名不继承别队记录，游戏来源不假定已完成装配。
结果只保留展示与身份摘要，不附逐击、整背包、完整 B0 或搜索树。来源配置和结果随账号库导入导出；
旧包迁移为默认来源及空历史，不从旧角色方案拼接结果。恢复旧版须先保全新版库，再恢复匹配版本的完整一致性备份，
不删表伪造降级。专项证据及整应用／多屏验收边界见[简报验证](roadmap/teams.md)。

### 悬浮提示与补充说明

普通按钮、标签和下拉框不重复弹出已完整显示的文字；文字确实被截断时才补全，空间恢复后清除自动提示。
调用方显式提供的帮助、禁用原因或清空意图不被公共标签/按钮的布局刷新覆盖。
问号帮助、图标按钮含义、快捷键、操作范围、计算口径、未知原因及截断内容保留；毕业率与词条权重的解释不因降噪移除。
重要错误在所属区域显示简短状态，详细原因进入日志或检测详情，不把错误挂在整个页面供子控件继承。
角色目录与详情加载异常仅写诊断日志，不显示区域错误文字或整页悬浮；保留已有内容和草稿，重新进入仍可重试。工作台同步动作按钮不附加悬浮说明，状态与操作限制仍在同步卡片内展示。

### 页面响应性与后台任务

角色索引、详情和基础权重表单后台读取；未变化的页面骨架及有界模型复用，替换候选仅打开对应功能时准备。
正式游戏目录的角色首次打开和草稿编辑，会在后台一次准备面板、边际、毕业率、装备及弧盘收益。界面只消费完整冻结数值，不逐卡片启动进程；快速修改时仅接收最新草稿。更新期间保留旧显示并标记待更新，失败或取消保留编辑，过期结果不当成新配置已完成；重新编辑可重试。计算不写角色档案、背包或历史方案。
加载失败保留已保存数据，未完成读取不解释为空配装或零属性；自动刷新不覆盖未保存草稿。
角色及基础权重保存/重置在后台提交，确认语义不变；成功才清除本次草稿，失败留在原页。
离页保存只在提交终态成功后跳转一次；重复点击不重复写入，账号切换及退出等待已接受的提交。

工作台摘要按正式同步修订去重，隐藏页只标记待刷新；显示后读取最新摘要，活动请求间以 500 ms 窗口合并。
同步状态和故障文案独立即时显示，不受摘要调度影响。计算目录在后台按权重、角色养成/原生观察、自建角色、
家具、已观测角色身份、静态身份、工坊模板和数值规则校验；无关账号写入不重建角色卡。
新计算开始前再次校验，更新完成才启动；运行任务、历史方案及已生成预览保留原冻结输入。
性能数据及未执行的整应用人工验收见[响应性验证记录](validation/ui-responsiveness.md)。

应用以 `AppContext` 管理当前账号和 generation。账号数据库、截图与日志互相隔离；切换账号时先停止或
阻止后台任务，再重建同步、扫描、鉴定和战报依赖。旧 generation 的 worker 结果不更新页面或数据库。
账号管理使用绿色「新建」按钮，紧邻「删除」左侧；名称与顺序调整不改变新建、删除及至少保留一个账号的规则。
账号管理与战报导出共用账号昵称事实，不另存导出别名。导入先在暂存目录验证归档、数据库和实际业务配置，
候选有效才停止被替换账号的任务。替换按正式账号 ID：同 ID 改名仍替换该账号，同名但不同 ID 不覆盖彼此；
其他账号在准备期间已成功的更新保留。导出使用一致性数据库备份及必要配置白名单，不带截图、日志、凭据或本机插件偏好。
数据导入完成与运行时账号切换分别报告：回切或切入失败时保留仍在运行的
临时账号并提示重试，不提前删除其数据。删除当前运行账号先切换到仍存在的账号；切换失败时删除不开始，
切换成功后若目标身份改变则保留当前运行账号并提示刷新。切换提交前失败会尝试恢复旧账号；补偿受阻时保留数据，
暂停新账号访问和外部操作并提示重新启动，仍可关闭与清理。已提交账号但自动服务启动失败则单独报告待恢复，不假报回切。
事务、代次与恢复责任见[账号与模式责任](architecture.md#216-账号设置命名与模式检测)。

主题写入本机全局偏好，对全部账号生效；首次缺少全局主题字段时迁移旧账号显式主题，否则新安装默认黑色。
语言设置已接入一个实际预备切片，主题与语言单字段保存不互相覆盖；生效、补丁格式与边界见[界面语言补丁](features/localization.md)。
计算偏好、基础权重、热键、扫描、倒带和 UI 选择按既定 key 写当前账号。工作台只读取账号摘要、环境状态
和当前稳定快照，不重新实现业务查询。
工作台右上角使用已核验角色目录中的黑羽高清头像，按当前屏幕像素比显示。

工作模式、风险确认、自动连接、自动部署更新、暂停和组件清理记录属于本机应用域。首次安装及旧版迁移默认
离线，旧账号的插件风险勾选不授予新模式权限。设置顶部与主窗口入口显示同一模式；检测按各功能分别报告
可用、等待、缺条件、故障和清理待完成。检测详情优先显示故障；原生连接或整次业务检测异常集中展示原因、下一步和已识别错误码，
受影响的业务项标为本次未完成检测，不将未知握手写成失败。文件核对、管道、握手、能力声明、快照和业务就绪分别展示，
未知明确标为未确认。用户可选择文本或点击“复制检测结果”，取得包含应用版本、模式和检测时间的本次报告；重新检测时停用旧结果复制。
开启同步的预检弹窗仅在有明确待处理条件时显示一个底部处理入口，并隐藏同义页脚按钮；就绪时按原流程开启。普通检测详情的阻断项分组、开启同步强引导和正常等待边界见[工作模式检测契约](reference/work-modes.md)。异常概述只显示状态、原因和下一步，故障线索留在折叠排查信息及复制结果中。首页和重启同步窗口也只展示来源相关的处理步骤与错误码，不将异常原文铺在正文。
手动检测失败同时记录固定诊断摘要，不输出原始异常文本、RPC 内容或子进程 stderr。
手动功能入口区分模式受限与组件/连接条件缺失，并可导航到相应设置区域；
设置完成后须由用户重新点击功能，不自动继续。最终执行前仍核对权限，纯离线能力不受影响。完整语义见
[工作模式契约](reference/work-modes.md#手动功能入口与设置定位)。首页通过自动同步与重新同步入口按模式选择抓包或 DLL；角色状态使用独立手动按钮，职责和缺失字段规则见[同步契约](reference/work-modes.md#背包与角色状态同步)。原生四域只接受提供方真实状态；未经正式业务投影证明的部分观察不会写入
正式完整背包。源码与替身测试不代表配套二进制或实机验收已经完成。

首次安装及从旧配置升级时，自动同步默认关闭；成功切换账号后同样关闭，须在新账号显式开启，旧账号迟到的开启确认失效。切换失败保留旧账号偏好，初次启动仍沿用已保存的本机偏好；开启时先只读核对环境。所需组件已核对且没有待清理项时自动开启，无需再点击确认；已确认模式下仅剩清理留下的暂停时，同次核验后恢复同步，不再要求重选模式。缺组件或待清理时保持关闭，仅对已确认的问题显示对应的部署或清理引导，完成后由用户重新开启同步。未确认状态只提示重新检测，不误引导部署。检测弹窗可跳至环境设置中的具体控件；D3D 需要部署时等待游戏退出，Loader 需要启动时还核对所选安装目录的启动器进程。同步关闭不撤销手动功能或已完成引导后的组件维护授权，详细时序见[工作模式契约](reference/work-modes.md)。

Loader 准备时核对所选游戏安装目录中的各个正式启动器入口；启动器仍运行或状态未确认时不执行部署，并在手动启动或开启同步准备时明确提示关闭启动器和游戏。手动“清理游戏目录”在独立窗口显示进度和清理结果，不再自动打开环境检测详情。

旧用户启动时，只读核对已记录的旧部署、游戏目录旧代理及当前组件文件；有明确升级证据才弹出简洁引导，并在工作台保留“继续处理”。步骤依次指向清理、重新确认模式和按需部署；清理及部署仍由原有显式入口执行，文件匹配不宣称同步成功。
从引导发起清理时，清理结果先在独立窗口说明；成功后只有点击“继续升级引导”才返回下一步，关闭结果窗口则由工作台入口稍后继续。结果核对未完成、游戏仍运行或清理故障时不跳步；中途退出计算器后，工作台继续保留未完成引导并在下次启动恢复提示。引导主操作使用与普通关闭、诊断按钮不同的强调样式。

工作台“如何使用”按当前工作模式给出简短的同步步骤，提供“工作模式设置”和“环境设置”两个定位按钮；关闭说明不更改设置或启动同步。工作台“功能说明”以六个紧凑按钮分别打开无系统提示音的普通说明弹窗，按实际入口展示操作步骤和适用模式；说明弹窗内的导航按钮只切换页面，不自动执行功能。“弃置锁定”“空幕鉴定”“倒带推荐”“边际计算”说明按字体、受限宽度与正文换行收紧窗口，屏幕不足时仅滚动正文，导航与关闭按钮留在外层。
图片使用教程的“遇到问题”按钮复用设置页“加入群聊”窗口，关闭教程后再打开群聊信息；“确定”仍只关闭教程。

## 2. 库存同步与不可变快照

配套原生组件声明全部物品读取能力时，自动同步在装备及角色读取后，将客户端已观测物品集合单独保存到
当前账号的不可变物品快照，保留最近 20 份。归档保存原始条目、来源身份、修订、数量和覆盖诊断；仅在
分页齐全、集合完整且复核修订未变化时提交，失败保留旧归档并允许重试。账号切换或取消会撤销未提交写入。
这一集合不代表服务端全部资产；装备库存指针、计算与现有仓库继续只消费正式装备快照，其他物品暂不展示。

nte-core 库存事件经过收集、完整性检查和 `InventorySnapshotStabilizer` 内容稳定化后，一次事务提交装备、
词条、角色实例和当前指针。稳定判断使用完整内容指纹与安静窗口，不使用历史最大数量。角色列表字段缺失
与明确返回空列表属于不同快照内容；补入角色列表时，即使装备不变，也要生成新快照，不改写历史记录。

原生同步只使用已保存的原生快照作为去重基线。视觉库存切回原生同步时，即使条目内容相同，也必须保存
原生来源的新快照。同步提示按来源区分视觉库存和原生库存；视觉扫描不提供角色实例，不称为旧版 Core
快照。原生快照未附带角色列表或尚未观测到角色实例时，分别说明该快照的状态，不据此判断 Core 版本或
所有角色的极速装配可用性；装配仍按其公开校验流程解析目标角色身份。相同内容再次到达时刷新接收提示，
不重复保存快照。

原生来源同时未观测到装备和角色时保留现有背包，等待登录数据就绪；有角色证据的空背包仍可正常保存。
具备数据域变化通知的来源，在完整背包读取后先交给稳定器处理，角色养成读取移到后续监听轮次，
不让角色读取阻塞已完成的背包保存。游戏退出后的首页和顶栏统一显示等待游戏，再次启动后自动连接。

稳定快照保存失败时，界面区分数据库锁冲突、只读或权限问题、容量不足、损坏、读写或打开失败、结构不匹配、
约束冲突与事务异常；无法分类时明确显示原因未知。技术详情保留 SQLite 异常类型、原始扩展错误码与错误名、
失败阶段、安全消息和回滚结果，回滚异常不覆盖首次保存错误。后台继续按既有间隔重试，不自动修库或新建账号。
日志字段和隐私边界见 [日志事件规范](reference/logging-events.md)。

`inventory.get_latest` 读取最近捕获数据，不触发强制刷新。下游启动时解析一次当前 `snapshot_id`，运行中
不追随最新指针。清理保留当前及仍被引用的来源；来源已失效时重新发起计算，不静默换用新库存。
保留边界见[快照与来源能力](architecture.md#5-快照与来源能力)。

账号 schema v21 支持原生库存的运行时状态增量。残缺装备事件只覆盖当前完整快照中已知正式 UID 的
`locked`、`discarded`、`equipped`、角色实例和位置；旧 sequence 不覆盖新状态，未知 UID 被忽略，库存
成员和当前快照指针不改变。极速装配和一键弃置/锁定的已接受指令也会写入相同的当前快照投影，供仓库立即
显示目标角色/状态；后续 nte-core 事件仍覆盖同一 UID。该投影不新增、删除装备，也不推进当前快照指针。

## 3. 视觉与手柄全量扫描

鼠标和虚拟手柄是同一视觉库存能力：

```text
mouse capture  ─┐
                ├→ 有界截图流 → OCR/解析 → 完整 vision snapshot
gamepad capture ─┘
```

扫描冻结账号、generation、用户库、截图目录、静态 dataset、解析 profile、捕获驱动、窗口和 token。
OCR 初始化在首次游戏输入前完成。取消、窗口变化、截图缺失、解析失败、索引不连续或数量不一致时保留旧
当前快照，不提交半成品。

卡带主词条无法识别不等同于整件装备解析失败：该卡带仍进入完整视觉快照，但不伪造主词条或数值，计算时仅排除
这件无法评分的卡带。扫描完成提示只在实际存在此类卡带时显示失败总数，并最多列出两个扫描编号供排查。

### 3.1 鼠标捕获模型

- 基准画布为 2560×1440、7 列×4 行；坐标映射到客户区顶部对齐的 16:9 物理像素内容区。
- 首屏最多 28 件；后续每页跳过重叠首行并新增 3 行、最多 21 件。
- 鼠标与虚拟手柄全量扫描在各自既有导航前，均执行一次从上向下的长按滑动，使用与全自动增量扫描相反的两点方向重置列表位置。
- 鼠标全量扫描使用用户输入总数生成不可变分页计划；末页按总行数映射到底部对齐后的四行视窗，只点击该计划格位，并用连续占用检测复核数量。虚拟手柄扫描保持原有流程。
- 首次点击前对计划首屏执行格位预检，拦截错误页签、未加载、遮挡和整体偏移。
- 普通滚动 profile 为 `-280 × 7 + -120 × 2`；每第六次翻页使用累计补偿
  `-280 × 6 + -120 × 4`。滚轮 delta 不随分辨率缩放。
- 点击位置与时序在安全范围内随机；测试可注入固定 seed。每件截图仍保存完整客户区，以兼容统一解析器。
- 双线程模式使用单截图生产者、单 OCR 消费者和 21 张有界队列；兼容低负载模式使用更慢输入和串行解析。

当前自动化覆盖 1080p、2K、4K、2560×1600 顶部对齐、末页 1–21 件及底部对齐、2000 件分页、滚动补偿、随机安全
区、背压、取消和失败不提交。真实设备行为按 [Windows 验收](validation/windows.md) 记录。

全量采集、解析和补录确认完成后后台保存背包，再发布本次截图。取消补录、资料失效或提交拒绝时
保留旧背包、旧截图及本次暂存，不提前清空旧失败截图或未知图片。背包已保存但文件整理/恢复失败时
明确提示“背包已保存”，仍可使用该背包计算；不把文件错误当成未保存而自动重试入库。
退出确认后撤销尚未授权的提交并等待收尾；取消退出仍可发起新任务。详细边界见
[识别架构](architecture.md#25-视觉输入与共用识别)。

保留本次完整暂存后，可显式继续解析；使用原账号、资料、图片和捕获驱动，不重新操作游戏。
补录窗口普通关闭保留未提交草稿；停止、重置或退出结束本次任务，过期回调不恢复草稿。
若背包已保存但截图发布失败，可显式重试文件发布；不重复保存背包或自动开始计算。
重试必须仍匹配原保存事实和原暂存，失效或恢复不完整时保留现场并报告具体状态。

### 3.2 扫描报告与扫描后管理

每次鼠标扫描原子更新账号截图目录中的 `mouse_scan_last_report.json`，记录分辨率、profile、预检计数、
分页、滚轮、预计/捕获数量、耗时和终止状态；不记录 UID、OCR 全文、截图内容或绝对路径。

启用扫描后管理时，完整采集与解析结果提供同一次冻结扫描索引，用于生成锁定/弃置计划；
这不是最终背包事务已提交。状态管理沿用同会话流程，执行从最大索引
倒序回退，每件依次验证原始截图身份、操作前图标、动作和操作后图标。锁定切换弃置必须等待确认弹窗。
操作前图标与固定计划不一致时，该件不执行输入、记录后继续其余计划，并在扫描完成提示中汇总；定位、
身份、弹窗或操作后复核失败仍停止后续输入。

结果写 `mouse_state_sync_last_report.json`，保存聚合数量、状态迁移、状态不一致跳过项、耗时和安全错误类型。该会话能力
不把视觉临时 UID 变为仓库可延后写回的正式 UID。

## 4. 计算、角色配置与自建角色

计算请求冻结账号、generation、快照、静态数据集、profile、角色顺序/平级组、目标配装槽位和锁快照，
返回不可变 `WeightedAllocationPreview`。保存只消费原冻结输入，不重新读取最新库存或配置。
同级分配未命中时，在固定成功成员和前序预留的条件下有界补救；找到满足冻结约束的完整方案即接回本轮结果，
恢复原图纸身份并逐人保留装备占用，再统一核对图纸、卡带、暴击边界和全局 UID 唯一性。存在冲突或尚未证实可行的成员仍保留失败证据。
默认恢复各角色主槽的当前方案，而非历史活动标记；明确指定槽位时按 `slot_id` 及各方案自身来源恢复，
选择缺项或无效时只恢复偏好，不改选备用方案。实际提交 ID 经只读回执与页面 current 复核后才推进游标；
连续同槽替换保留原输入和历史评分，以前一次真实提交为下一次基线。确认失败或取消不推进旧游标，
但提交后可能已有数据库事实，需核对且不自动重发。此流程不新增记忆备用槽偏好。
计算页重复进入时复用已加载的角色目录与卡片；来源文件变化后在后台读取完整新目录，结果仍按账号代次和来源身份核对后应用。仅账号库发生与角色目录无关的写入时，保留原卡片、鉴定控件和已显示计算结果；目录语义变化才重建角色卡。刷新期间暂不可开始新的计算，已有计算保持冻结输入。
优先级存档和临时草稿属于当前账号。切换账号时在异步目录刷新前清空旧草稿并撤销保存资格；
新目录与完整配置就绪后才重新绑定，缺少配置使用本账号默认值，坏配置或刷新未完成不覆盖未读文件。
同账号手动读取失败保留现有草稿；旧账号草稿不会通过新账号路径保存。旧格式优先级列表按首个有效角色保序去重。
计算页的数据读取、角色优先级、分配策略保持同一纵向页面。第一步默认显示“直接读取库存”，点击“其他”展开离线解析、增量扫描和全量扫描，点击“收起”隐藏这些选项。展开状态为本机全局偏好，跨角色、账号和重启保留，不写角色配置或账号导出。收起不改变已选读取方式；选中其它方式时保留当前方式摘要及所需参数，原扫描提示与执行门禁不变。
第二步在既有优先级链与未选角色区显示轻量头像，
仍保留角色间 `>`、`>>`、`=` 运算符、拖动排序、逐角色“管理”与优先级存档操作；
已选角色的头像及所在角色卡可点击移回待选区，角色名按钮仍支持拖动调整优先级，“管理”和运算符各自保持原操作。
自定义角色始终显示随白色、黑色主题适配的问号头像，正式角色头像缺失时才显示名称首字。
同一头像也用于词条配装角色优先级、已保存计算配装的顶部角色滑动列表及替换候选的临时归属标记；
实际游戏仓库归属仍仅按正式角色身份读取发行头像，不把计算方案的临时归属当作游戏装备状态。
未选角色按名称首个有效字符的拼音首字母 A–Z 排序，同首字母按完整拼音稳定排序；搜索只筛选未选区，
不隐藏已选链或其运算符。常规窗口的已选链每行最多四个较宽的角色单元，保留头像、名称、管理和运算符；
更窄窗口继续减列，全屏宽度超过断点后按可用空间增列。已选单元保留略高的框和管理操作，
保留“管理”和较宽运算符比例，不因四列布局而拉长角色卡；未选卡片适当收窄并均分当前行宽，
未选区不设固定列数上限。已选和待选角色名称统一使用 13px 微软雅黑 UI，不按字宽逐个缩放，也不套用小按钮字号；
两区正式角色头像都使用发行包中的 256px 裁切图，按当前屏幕像素比下采样，并以适配主题的底色衬托透明边缘，
避免高 DPI 下先缩至逻辑像素再被系统放大或浅色头发融入白色背景。
窗口加宽时增加每行角色数，并减少对应行数和区域高度。
点击全量扫描、增量扫描或离线解析时按当前库存来源给出有声提示：已有工作台同步快照保留“继续/取消”确认；
尚无快照或当前为视觉快照时建议优先使用工作台数据同步，仅提供“前往/取消”。前往只跳转工作台，不开启同步；
选择前往时保留原扫描模式；取消、关闭或 Esc 仅拒绝同步建议，正常进入所选扫描模式，不回退到“直接读取库存”。
选择模式和处理提示均不启动同步、扫描或解析，也不修改账号数据；实际执行仍校验模式权限、数量及增量基线。
中风险点击扫描内的弃置锁定管理时，有声建议使用仓库右上角管理；
前往只跳转仓库，取消、关闭或 Esc 仅拒绝建议，仍打开扫描管理；普通自动装配的同类建议取消后也继续原操作。真正的操作许可、准备及执行取消确认仍保留。
第二步不设内部滚动区，全部角色选中后仍完整展开，只沿计算页统一纵向滚动；第三步继续紧邻第二步。
组合计算复用当前固定候选池中的评分数据，不改变图纸候选、搜索顺序、同分裁决或搜索上限；切换候选池或
进入新的预留冲突分支时重新准备数据，暴击阈值等依赖当前配装状态的判断仍按原规则逐次执行。

角色管理采用按字体收窄的紧凑宽度：自选开关第一行依次是“取消主词条硬过滤”“副词条优先级一致”“黑名单为零权重”，第二行的“选取不设置等级门槛”“最低等级门槛”左对齐，问号紧邻等级选择框右侧。多项自选摘要按内容完整换行，屏幕不足时只有一层内容滚动，确认与取消保持可达；不截断所选值或改变保存顺序。问号说明结合卡带主词条、副词条偏好与驱动黑名单解释默认选择及开关效果；配置字段和已保存偏好不改名、不重置。

候选规则：

1. 锁定真实 UID 在候选构造前联合排除；失效锁阻止计算。
2. 账号级“筛选设置”默认不选择品质和类型。选择卡带或驱动后必须同时选择至少一种品质；对已选类型，仅已选品质进入角色管理筛选，其余品质被过滤；未选类型按默认规则处理。该筛选在角色配置前执行一次，角色优先和锁定更新（原增量更新）共用同一候选结果；策略能力限制见 [计算策略](architecture-map.md)。
3. 副词条黑名单同时约束卡带与驱动，默认在Top-K前硬过滤命中任一黑名单副词条的装备；不限制卡带主词条。启用“黑名单为零权重”后，两类装备均不因命中而淘汰，但对应副词条权重置零，主词条与其他副词条照常计分；候选、结果及本次变动对比使用同一冻结口径。同级分配、暴击换卡、主词条软回退和直伤/轴伤后处理均保留该约束，缺卡不静默放宽。旧保存方案与历史评分不重写，新规则在显式重新计算后生效。副词条自选仍为软偏好，组合无解时按既有规则逐层放宽，不放宽黑名单。
4. 卡带默认执行套装、主词条与副词条黑名单硬过滤，默认四件套；当前计算核心在合法卡带中最终按核心评分排序，不承诺副词条命中者总是优先。“取消主词条硬过滤”先按所选主词条求解，仅在合法驱动方案缺卡时，从最早缺卡优先组开始放宽主词条并整轮重求。保留套装、品质、锁、UID唯一、词条及暴击约束；前序消耗匹配卡带也可触发回退。同一冻结输入最多增加一轮/软回退角色，不采用使已合法驱动方案失效的整轮结果，不拼接跨轮结果；该组失败后继续其他缺卡组，不额外建设无界搜索。最终方案记录实际回退或拒绝事实，原用户偏好不回写。
5. “最低等级门槛”是单件装备评分评级，不是角色等级、装备强化等级或品质。等级按该角色基础分数 ÷（装备面积 × 10）判断，例如 A 为 40%。驱动达到门槛才计入副词条优先选择，未达标仍可普通补图纸；勾选“选取不设置等级门槛”取消这一评分门槛，但套装、主词条、黑名单、UID与暴击约束不变。当前原生核心与 Python 参考实现的卡带选择、同级暴击重配仍有差异，待独立核对，见[计算路线图](roadmap.md#2-计算与配装)。
6. 平级组首轮联合求解；补救可重新候选全部同级成员，先比较合法完成角色数，再比较偏好与评分。补救候选发现共用组级探测池，保留逐角色公平覆盖，按失败、占用稀缺形状和暴击约束倾斜，未用额度继续流转；组级再联合筛选 UID、卡带和驱动，不将完整预算复制给每名角色或一次固定均分。
7. 角色优先中，前序组的固定 UID 不进入后续候选；最终图纸内真正等价的同分驱动则延迟归属。等价候选须保持形状、评分、词条优先级、额外形状收益及暴击约束一致；后续组可使用它们，但每次占用都保留前序全部预留槽位的一对一回填。平级组先完成联合分配，再整体建立预留；计算结束按稳定 UID 回填。普通同级矩阵搜索耗尽预留分支且没有可回填结果时，将前序预留槽位纳入同一次匹配，在原图纸候选范围内恢复完整方案，并继续核对原暴击上限等约束；已有可回填结果和显式暴击最低值路径保持原规则。虚拟占位评分为 0，不进入锁或极速装配。
8. 分配设置的“图纸组合数”默认 2000，按当前优先级组控制联合组合预算：理论组合数为组内各角色图纸数的乘积，预算不小于理论数时全部考察，否则按有界优先顺序选取组合，不把数值平均分给角色。单角色组只限制该角色。计算按钮通过分析组件的 `allocation_v1` 执行评分和分配，保留原图纸生成与渲染；卡带、驱动按组内资格与 UID 唯一性联合决定。末级无词条排序、无暴击上下限的同级组会在原候选前缀保底后，复用形状匹配缓存考察额外组合；缓存命中不重复消耗匹配预算，新增匹配仍受预算限制。有界补救按共享额度发现候选，再在组级束搜索中重组，搜索截断不等于库存无解。全局停止键可终止并回收本次计算进程。

失败结果保留已有补救搜索的具体原因；预算耗尽、候选截断不覆盖暴击候选边界或其他约束证据。同级组未全员完成时，明确设置冲突、资料缺失及无图纸直接沿用原证据；其他失败成员在隔离状态中使用本组求解结束时的剩余库存分别诊断，必要时以组开始库存作对照，始终保留前序占用和预留回填限制。不同失败成员不相互消耗诊断装备；后续优先级角色不进入该诊断范围。诊断共用独立有限额度，复用冻结图纸、评分、资格和暴击公式；诊断预算及候选标记与主分配状态分开，不重新读取账号或写数据库，不修改成功方案，也不把诊断找到的方案提升为本次成功结果。可兼容当前成功成员的诊断方案会如实说明原组级搜索未命中；仅有一个与已选装备冲突的达标候选时，只报告竞争证据，不宣称所有达标组合均被占用。有界暴击上下界只描述已检查候选；保留当前配装后的已证实形状缺口与全库存无解分开。页面与源码日志采用简短的一行说明，只保留主要原因、必要数值及同级组已完成人数；搜索未完成与确定的约束缺口明确区分，完整诊断和组开始库存对照保留在结构化响应中，不堆入用户正文；诊断取消随本次分析进程终止，旧方案保存边界不变。响应字段契约见[分析组件集成](integrations.md#11-nte-analysis-core)。

两队同名次并列，例如 `A=G > B=H > C=E > D=F`；不按两队混合伤害占比排序，不修改保存的角色顺序或属性权重。

排序只统计所选范围内已记录的出伤，不加入尚未确认的生命上限推算；原战报装备不作当前 B0。缺排序能力或证据时整批按同级分配并展示降级原因。
每次伤害优化都以冻结请求取得完整基线 B0，
再在副本上搜索；原角色优先、锁定更新、基础权重、图纸生成和原始战报不因选择它们而改义。

不会用伤害值或动态排序分覆盖基础分，也不重新解释历史方案。

两种伤害策略使用配套 Rust 组件的一次冻结作业：生成图纸、原角色优先 B0、正式落位，再在副本上优化。
基础组合、顺序、评分与软主词条回退规则保持；图纸预算截断时，仍可在剩余总预算内使用本次已生成且验证合法的图纸，明确标注枚举未完成；缺能力仍明确停止。不把部分图纸当作全集。
公共 ScoringEngine 保留原接口，基础分/评级统一调用同一 Rust 核；鉴定与库存评分成批处理，
完整伤害作业直接返回基础分/评级证明，展示不再另开评分进程。普通角色优先及其他工具的 Python 图纸入口不因此改义。结果日志只记录已生成摘要，不再为详细装备列表逐件重新计算评级或启动评分进程；求解及冻结分数保持不变。

计算预览与已保存配装共用一行紧凑摘要：突出目标提升或“未找到提升／暂未优化”，旁边的“查看详情”带下拉箭头，

不把同一个目标逐角色相加；零基线只显示绝对变化，小幅正收益不显示为零提升。

直伤在同一次冻结作业内复用装备单位贡献投影，角色元素与完整面板仍分别计算，不跨账号或作业缓存。

档位在发起计算时冻结，双队共用一次预算；途中更改选择不影响当前计算，也不改变其余角色的普通分配。
两档使用相同公式、装备约束与计分口径，深搜增加搜索时间和评价次数，不保证提升更多或达到全局最优。
实际耗时受战报长度、初始化和设备性能影响，搜索可能提前结束；取消沿用现有停止入口。旧组件不支持深搜时提示更新，仍可选择快搜。

直伤按原优先组目标，轴伤按全队共享的本次计分目标。选择一名、部分或全部队内成员，轴伤都使用同一目标，
不另走较窄的单角色生产入口。每轮在预算内扫描单件、同成员双件、两角色互换与空闲补位、单/双成员换图纸；
各邻域保留访问/评价份额，未用额度有限转借。轴伤按实际单次评价耗时分配剩余时间，不把初始化耗时当作每次候选耗时；各角色、槽位交错访问，优先使用已求值增量和基础评分安排顺序。比较已完整评价且通过合法性校验的候选；任务扫描截断不丢弃已证实的改善，也不把已访问范围的最佳声称为全邻域最佳。
双件包含驱动—驱动、卡带—驱动，完整动作统一核验，不因中间单件违反暴击界限提前淘汰。
换图纸只使用本次生成的冻结集合，保持套装模式、目标和禁用格；正式形状/方向、落位、UID与词条约束不放宽。
直伤跨组动作按原优先组目标词典序比较，各成员仍不低于初始 B0；轴伤允许个人下降，但全队总收益必须提高。
完整动作一起接受，之后重查邻域并失效旧增量缓存；不将两次独立的个人结果拼成联合方案。
轴伤所选成员任一来源或基线约束缺口使整队保留 B0，不删去缺员继续搜索。
旧计算配装仅在槽位方案已锁定时保护装备，包括本次参与角色的其他锁定槽位；
未锁定的旧方案不限制候选，即使该角色未参与、未就绪或预算截断。预览不写旧方案，保存时沿用统一事务借出，
原槽位补入占位并保留历史。游戏内锁定只防误弃置，不排除分配候选，也不改写其原始状态。计算期间配装锁变化须重算；本次新方案之间仍保持唯一 UID，套装、主词条和暴击硬约束不变。
副词条软优先与评分评级不升级为后处理硬门槛：基础分更低的合法装备仍可因完整目标更高而胜出。

图纸节点/组合/输出、搜索访问/评价/轮次和整体时长均有预算；未完整求值的候选不接纳，已完整评价的合法改善在同任务或后续任务截断时仍保留，并标明未覆盖邻域。预算与覆盖声明不因保留结果而放宽。原生坐标、分项预算/用量和整体耗时随预览/保存绑定。
部分轴伤推荐采用 `available_fixed_domain_v1`：B0 一次冻结能计算或能明确估算的事件集合，候选比较同一集合的伤害加权目标，未纳入部分不参与收益排序，也不视为实际伤害为零。黑羽累计窗口和来源逐击比例联动的生命上限结算可作为估算计分；同类伤害猜测和缺少窗口时按自身伤害构成猜测不直接计分。候选无法计算已冻结计分事件时保留具体缺口，不能靠漏算原先的负收益项目胜出。
结果及保存方案显示计分覆盖、已量化（含已证实不变）、估算和未计入的伤害量占比；覆盖率分母为同一冻结战报范围的伤害量，不是击数或预测准确率。推荐的提升只针对参与计分部分，不冒充全场提升；源码验证与配套组件晋升分开。
候选枚举完整与本次计分域内候选可评价性分开报告；只有最终状态的声明邻域两者都完整且无改善，才说明“本次计分口径下该邻域无改善”，不表示全部战报伤害已量化。
动态排序只改变访问先后，新配装仍重新评价冻结计分目标，不作为接受标准、上界或删池依据；不采用经验暴击剪枝。换图纸递归可用向外取整的剩余暴击区间证明某分支无法满足上下限后提前排除，仍对完整方案复核约束。不变队伍仅在本次冻结输入的全部装备字段一致时复用结果；同队联动继续完整计算。候选缺少机制时保留具体缺口，其他可完整求值的改善仍可继续搜索和保留。
所有结果都是固定输入、有限预算及声明邻域内的近似改进，不保证全局最优。

缺少配套能力或正式模型时显示后处理未就绪，协议或执行故障显示失败；保留基础分配，不伪装成优化成功或回退另一套公式。
已返回并核对的完整合法 B0 可直接保存，无需切回角色优先重新计算。它使用独立的本次冻结凭证绑定账号库路径、静态身份、来源快照、配装锁、装备、布局及基础分；失败响应改动过的方案不能冒充 B0。保存结果标注“基础配装”，只记录优化尝试的原因，不携带未证实的伤害提升或其他组的共享收益。没有形成合法 B0、取消或冻结身份失效时仍不保存。
取消结束并回收本次分析进程，不留下半保存方案。保存只消费冻结预览，复核账号代次、库存、静态资料、组件、锁、槽位及
所选报告的实际输入身份；无关 UI 设置写入不使报告身份失效。原始战报与历史评分始终不改。
轴伤共享目标同时保存本次完整预览的固定构筑依赖：正式角色身份、装备 UID 与布局、同一来源快照及冻结 A 输入身份，
由同作业摘要和预览证明绑定。首扫截断或未就绪组的依赖明确标为 B0 假定，其合法基础方案可由用户显式保存，但不冒充已优化方案，
其本次 B0 装备不在组间重复分配，但未锁定旧槽位不因此变成受保护方案；没有交换关联的已接纳完整组仍可独立保存。
发生跨组原子交换时，交换两侧及其同级组须一起保存，连续交换形成的关联同样不能拆开；只提交一侧或篡改依赖会被拒绝。
关联依赖按同一个完整保存批次核对，包含独立验真的基础配装；不因保存服务将基础结果和优化结果分流而误判缺员。
基础成员还须与共享目标中的冻结角色身份、来源快照、构筑和作业身份一致，不能用同名旧方案补齐。
共享值是这些固定队友构筑下的条件估算，
不是只装当前角色后的全队伤害；重开结果不读取最新配装补齐历史假定。
组件职责、能力与来源摘要见[后处理集成](integrations.md#12-分配结果后处理作业)。

来源、缺失值和评分口径说明保留在预览窗口，不占用图片底部。
练度预览复用角色面板的后台取消、账号代次校验、复制图片、原子保存 PNG 与屏幕范围限位；两个弹窗的复制图片及保存 PNG 均使用绿色主按钮。
配装页每次进入仍重新读取当前账号槽位、方案及各自来源快照；同模式且内容未变时保留现有角色列表和详情控件，不闪空或重复构建卡片。角色切换仅构建所选角色，并有界复用最近三个角色的详情；切换属性对比槽位时更新当前详情。属性汇总的别名权重一次批量查询，两种面板模式复用结果，不逐项启动分析进程。评分仍调用统一入口。保存、删除、锁定、导入和替换会使在途读取失效，下一次展示按新数据重建；切换模式或账号则清除旧投影。单角色游戏配装导入后只更新受影响角色、槽位和导入状态，保留其他角色控件、当前选择、搜索与滚动；批量导入、模式或账号变化仍按完整读取刷新。读取故障不改原方案。
游戏配装与计算配装每次加载共用一个正式静态只读单元与请求内角色详情缓存，计算配装对比与游戏投影借用同一份 pin／事务；完整哈希仍验证一次，退出校验失败不发布结果，不建立跨账号或跨请求的角色缓存。游戏配装的评分按有界矩阵批量预热，再复用原单件评分入口；不在主线程为每件装备重复启动评分组件，也不改历史方案的冻结分数。游戏配装与计算配装的角色属性汇总均读取本次当前账号角色档案，并共同计入等级/突破、当前弧盘等级与精炼、
好感度 10 级、家具加成和额外形状；游戏与计算方案对比时，两侧只替换装备，角色养成保持同一当前值。
游戏配装按正式角色 ID 列出该角色全部计算配装槽位，不按卡带套装筛选，也不把游戏导入方案作为候选；
默认选择列表中的第一个槽位，用户可在汇总框右上角的“对比槽位”中切换。对比固定显示“游戏、计算、变化”，
变化为计算属性减去游戏属性；没有计算配装槽位时只显示游戏配装自身属性，不显示选择器或对比列。
装备卡片与空幕属性汇总使用同一角色词条权重和颜色分级；汇总以正式属性 ID 区分百分比与固定值，不能把
`AtkUp` 的“攻击力%”按 `AtkAdd` 的“攻击力”显示或着色。

同一角色的多个槽位是备选配装：它们可引用同一个真实 UID，不视为装备复用冲突。角色优先和
锁定更新（原增量更新）均以角色为 UID 冲突边界；只有不同角色的当前槽位同时引用同一 UID 时处理冲突。当前策略入口限制见 [计算策略](architecture-map.md)。

计算和加权计算保存前为每个角色显式选择目标槽位，可新建槽位或跳过；差异比较使用同一目标槽位，
不把其他备用槽位当成基线。批量保存是事务性的，后续角色验证失败时整批回滚。
计算页“保存配装”在后台共用一次冻结库存与形状目录完成方案转换，全部目标槽位在同一事务中保存。
保存同时检查未参与计算角色的所有当前槽位；借走的真实装备从原方案解除占用，以原位置的零分虚拟占位
保留图纸，并标记原方案不完整，历史方案保持可追溯。主力和备用槽位均处理；同角色备选方案继续允许
共用装备，锁定槽位拒绝借用，不将不同视觉快照中恰好相同的局部 UID 当成同一装备。
进度条显示方案准备、校验和事务写入阶段，保存期间阻止重复提交；失败或提交前取消整批回滚。保存后仅重绘当前计算结果，角色和配装页在下次进入时读取新方案，避免同步重建后台页面。
主计算结果标题与角色标签使用相同的青色描边和文字；同尺寸的“保存配装”和“清空计算”分别使用浅绿色、浅红色底纹及同色描边文字。“清空计算”经确认后只丢弃本次预览，不改已保存方案、角色选择或分配设置。保存成功后播放一次系统提示音，并在紧凑结果弹窗内提供可选的“觉得计算器好用？支持我们吧”链接，指向设置页同一支持地址。链接与确认按钮分开，避免误触。计算完成但未保存、取消或失败时不展示该链接。
计算结果仅提示本次第二步角色选择中“全部槽位已锁定”的角色；未选择的锁定角色不显示该提示。

游戏配装是 nte-core 稳定快照的只读投影。显式导入后保存为 `game-observed-loadout-v1`，冻结来源快照、
目标槽位、逐件评分和卡带满级值。完整驱动但缺卡带的方案可保存为 `incomplete/missing_tape`；视觉来源
不进入游戏配装导入。
游戏配装的“已导入”仅匹配该角色未归档槽位当前关联的游戏导入方案及装备指纹；空槽位、归档槽位、
历史方案及旧 `is_active` 标记不作为已导入或当前方案锁定的依据。任一可见当前槽位匹配即可标记已导入。

锁作用于当前账号的具体槽位方案，不调用游戏锁 RPC。至少一个真实装备即可锁定；空方案和虚拟占位方案
不可锁。锁定槽位不可覆盖、归档或单件替换；其他角色/槽位不得借用其 UID。归档 `primary` 时由 DAO
提升剩余可见槽位；每个角色至少保留一个可见槽位。

配装页、角色空幕详情、替换、倒带和装配都读取选中/默认槽位。批量装配对每个角色显式选择一个 `slot_id`，
并在执行前检查角色唯一、槽位存在、原生来源和跨角色 UID 无冲突。

### 替换优化候选

官方角色从所选保存方案自己的来源快照准备候选，不跟随最新背包：排除当前装备、本方案已选UID及其他锁定计算槽位预留UID；驱动保持同正式形状与套装，卡带保持同套装，虚拟占位只保留其已知形状约束。其他未锁定方案的装备仍可候选，借用时按既有事务为原槽补入占位。
当前方案与全部合格候选统一投影到满级；先由当前完整面板计算一份固定的直伤边际权重，用公共评分入口计算候选分数，再按分数降序、完整替换后理论直伤降序打破同分，稳定保留最后完全同分的原顺序。服务计算全部合格候选，弹窗默认显示前30个（不足则全显示）；候选数量旁的“全部候选”分批展开本次已冻结的完整合格候选池。展开不重读库存、不放宽形状、套装、锁等限制，不改变评分及顺序；关闭、账号代次失效或进入确认提交时停止加载。
30只是初始展示数量，不是全局最高伤害保证，更不是多件组合搜索；候选也不只保留正收益。自建角色使用当前基础权重排序，同形状驱动/同套装卡带筛选后提供同样的30件与全部候选入口，不冒用官方边际模型。实现分别见 `src/services/official_role/equipment/replacement.py`、`src/features/official_role/replacement_controller.py` 与 `src/features/inventory/equipment/optimization/plan_optimizer.py`。

## 6. 仓库与鉴定

仓库管理采用独立窗口、配置和后台处理链，评分、手动及智能规则统一生成待保存预览，右上角保存才写游戏。
套装匹配页不再重复显示账号作用域小字；配置隔离、统一保存与预览门禁不变。
交互、阶段仲裁、两区排序／复制、冲突原因和管理筛选见[仓库管理与智能规则](features/warehouse-recommendation.md)。

仓库读取固定快照并通过 `WarehouseInventoryService` 生成投影。卡带按套装、主属性、副属性筛选；驱动按
形状和副属性筛选。条件使用正式 ID，同组为“或”、跨组为“且”；状态分为已装备、已锁定、已弃置和其他。
“符合副词条的数量（多选）”按所选正式副词条ID的命中数量精确筛选，同件重复ID只计一次：选3仅展示恰好3个命中，选0表示零命中，多选取并集；数量未选时不筛数量。重置清除全部条件，视觉来源因无可靠原生状态归入其他。

原生仓库状态管理固定快照和正式 UID，Service 生成计划，Integration 提交 RPC，随后等待递增完整快照
确认。打开管理设置及生成本地预览不要求开启实时同步；真正保存时，仓库状态保存与极速装配使用同一简短提示，引导前往工作台开启自动同步、进入游戏场景并等待同步就绪；引导不启动同步或自动续接原操作。
一键弃置/锁定和仓库状态保存会在命令接受后立即更新目标 UID 的仓库投影；若这两个动作守卫期内
收到单个、覆盖全部目标 UID 的背包快照，则由动作本身替换库存集合，允许新增或移除库存。只有该动作收到
声明数量减少的背包事件时提示玩家在工作台重启同步并等待完整背包读取；后台监听不会单独执行这种库存替换。视觉仓库本身只读；只有扫描完成后的同会话
鼠标管理使用扫描索引执行即时写回。

弃置和锁定各自保存评估角色范围，旧共享范围分别迁入两份，后续修改互不联动。处理类别决定有效类型范围：范围摘要单行显示驱动与卡带数量；当前不参与处理的类型显示红色0/0，不加说明尾字。两类范围均可继续编辑并保存，单项与全选作用于同一草稿；是否参与本次评估仅由处理类别决定。未保存过的范围默认包含全部驱动形状与卡带套装，界面默认全选与实际生效一致；只有显式保存的列表才收窄范围，套装按去除「」外框后的名称比较。
扫描管理保留首条命中、原排序及扫描后执行时点；两个管理的完整未匹配弃置均为固定启用的模块规则，不显示独立开关；仓库采用独立分阶段决策，不能以仓库仲裁替换扫描旧行为。
两管理分别冻结自己的配置与匹配范围，角色范围只控制各自评分模块，不改计算角色、活动配装或倒带偏好。
评估角色按拼音首字母和全名稳定排序，自建角色使用随主题变化的问号头像。详细规则及 UI 操作以专属功能文档为准。
原生一键弃置、锁定及手工状态保存使用装配的批次读取隔离：批量指令期间保留变化通知，暂缓背包与角色快照读取，
结束或失败后释放，随后核对状态。锁定前先取消弃置，弃置前先解锁，恢复普通状态时分别清除两个标志；
已满足目标的标志不重复发送。组件声明 `native_equipment_state_batch_v1` 时，每批最多 16 条锁定/弃置指令，
同一装备的多步转换不拆批；Core 每批查询一次状态后派发，DLL 在游戏线程顺序执行，每步复核对象域和取消状态。
旧组件沿用单条接口。两条路径都只保留一个在途请求，不等待逐件背包变化。明确未派发的 `source_changed`
或组件忙碌只重试当前请求；重试前复核仍属于同一提供方和对象域。批次部分派发、超时、结果未知、上下文变化
或其他失败均停止后续指令，不自动重发整批；进度表示已提交，最终成功仍由背包状态核对。
不能将部分完成的状态转换标为整体成功。全部派发完成后只通过新的完整背包快照统一核对；“弃置”只设置游戏标记，不删除装备。

鉴定把截图、剪贴板、手工输入和仓库单件入口投影为统一装备对象，调用公共评分与
`EquipmentPresentation`，不写库存、基础权重或配装。扫描与鉴定共享 `GlobalHotkeyManager`，通过 owner
隔离会话和停止权限。

### 角色匹配套装

实现与验收边界统一维护在本节及[开发契约](../AGENTS.md)；旧的单项路线图已删除，未完成的发布、构建和真实游戏门禁仍归总路线图与 Windows 验收。

鉴定页面的蓝底白字「套装匹配」、仓库快捷鉴定结果窗口，以及仓库和计算弃置锁定管理的第三个「套装匹配」栏目，复用编辑控件和公共匹配算法，但持久化身份独立：鉴定与仓库快捷鉴定一域，扫描管理一域，仓库管理一域。管理窗口直接内嵌角色列表，不再从「评分处理」跳出第二个弹窗。首先展示全部角色头像卡片，角色名下显示当前匹配套装；支持搜索角色，点击角色后通过卡带图片多选套装。默认采用官方搭配，可添加其他套装，也可取消官方套装、只选自己的搭配；已知角色至少保留一个套装。图片按正式 ID 从公共素材读取，缺图不猜配其他套装图片，完整名称和检查原因可悬停查看。

「恢复此角色」位于套装搜索框右侧，只清除当前角色的自定义；「恢复全部」确认后清除所有角色自定义。以上都只修改草稿；卡带选择页的「返回」回到角色列表并保留选择，筛选隐藏的已选套装仍生效。鉴定独立弹窗点击「保存设置」才写入账号并关闭，角色列表上的「取消」、关窗及账号切换丢弃草稿。设置随账号导入导出，不影响计算配装、角色权重、养成、历史评分或游戏锁状态。

扫描管理保持原保存时序：内层「保存设置」只提交扫描域匹配；外层「保存」统一提交评分、规则和未保存匹配，取消不撤回已经明确保存的内层内容。同一扫描域窗口保留草稿冲突核对，不刷新其他管理域。
仓库匹配是本窗口草稿，内层「完成选择／返回」不落库，外层仅「取消／生成预览」；生成前在同一事务保存全部有效配置。鉴定仍使用自己的显式保存入口。
三域分别做 CAS、账号代次与缓存失效；同一域的已打开草稿不覆盖新配置，跨域修改不互抄，也不撤销无关任务。匹配图片按正式身份读取，角色／套装列表支持搜索和键盘操作；图纸预览只处理最后一份草稿，返回、提交或关闭时取消本 owner 的待检查任务。

旧版追加配置仍使用默认与额外套装的并集；显式替换配置只使用所选集合，资料缺失或没有合法图纸时不偷偷补回官方套装。有效集合去重后，分别按原鉴定条件求合法图纸。卡带须套装匹配且有合法图纸；驱动须形状出现在图纸套装位或散件位。同一角色只评分一次，使用原评分引擎和有效基础权重，不评估套装技能、团队收益或边际伤害。鉴定、仓库快捷鉴定及鉴定对比的结果默认只显示「匹配详情」入口，点击后显示所有命中套装、来源及适配位置，不再重复显示原套装摘要和占比；右侧评分徽标不随详情拉伸。仓库快捷鉴定和对比窗口的「套装匹配」采用文字自适应宽度，放在底部「关闭」左侧。高分表示词条适合该权重，不表示该套装实战最优。

评分管理与弃置、锁定各自选择的角色范围取交集。完整评估但无适用角色时显示「未匹配」，不伪造零分或 D 级。扫描与仓库均在弃置模块启用且范围有效时默认纳入完整未匹配项，不显示可选开关。旧配置或导入包中的关闭值不再改变该固定规则；模块关闭、范围排除与跳过状态仍生效。资料缺口、失效身份、图纸或评分错误属于「评估未完成」，不走未匹配弃置分支。指定范围缺项只停止该模块的评分，不阻断其他有效模块和用户独立规则；扫描保持旧优先级；仓库只让真正未决定项进入后续阶段。

角色变体仅按正式且唯一的逻辑身份投影，失效角色或套装保留提示与清理入口，不按名称猜测、不静默删除。未改动有效草稿的保存不改旧身份或使结果失效。实际修改后，已打开的鉴定结果提示重新鉴定，旧评分计划在派发前及后续批次复核配置；停止未派发部分，已接受动作继续按原后验流程核对，不反向解释或自动重发。仅保存匹配设置不会自动重新鉴定或操作游戏。

编辑器只在选择角色或调整其套装时后台检查该角色的有效组合；总览只加载目录和图片，不扫描全角色与全套装笛卡尔积。同批装备共用角色、评分器和图纸上下文。源码专项与三主题窗口检查不替代发布前的 core/full、打包和真实游戏验收。

## 7. 倒带推荐与执行

## 8. 极速装配与游戏界面自动装配

配装页顶部的极速装配、自动装配均先显式勾选角色，默认不勾选；支持搜索、全选，每个角色选择一套已保存槽位。取消或没有勾选不创建任务，视觉方案从极速入口转自动装配时保留原选择，不扩大到其他角色或替换为默认槽位。

极速装配只消费 nte-core 正式 UID、角色实例和已保存槽位方案；游戏界面自动装配消费视觉投影与输入动作，
可支持自建角色。两条链路冻结账号、generation、来源快照、槽位列表和任务 token，并持久化角色项与事件。

极速装配的角色选择框不显示操作说明或额外信息框，点击“开始极速装配”就是本次执行确认，不再另弹普通确认。
选择框底部动作靠右；批量选择与倒带角色卡按视口宽度重排，长评分提示保留完整可访问名称与悬浮提示。
选择框的说明控件从创建起归属本页，不先显示成独立顶层窗口；该行为同时用于批量删除、导入和装配选择。
同一窗口转为进度并最终显示结果；极速装配不提供底部停止或关闭按钮，使用窗口右上角关闭键停止后续派发或退出结果页；设置中的全局停止键（默认 F12）仍有效。停止后续派发和补救时，
不回滚已执行部分，也不关闭自动同步。用户关闭进度窗后不被进度刷新或普通结果重新打开。

执行与结果页用紧凑列表展示本次冻结的角色、槽位、计算配装分数及逐角色状态；缺少分数保持未知，不按后来权重重评。
已下发与完整确认分别计数，跳过、未执行、待核对与失败另列统计。极速装配进度条表示已完成操作下发的角色数，等待新观测不阻塞进度；进度达到 100% 不代表已核验成功。自动装配保留图纸校验进度口径。虚拟占位／缺件数量显示在对应角色下，可用子集确认不计作完整方案确认，

同时勾选原生与其他来源方案时整批阻止并列明不兼容角色，不静默执行其中一个子集。

第一次或第二次明确不一致时卸空重装，第三次仍不一致才生成最终错误。报告区分管道缺失、短暂不可用、
队列繁忙、核心请求超时、完整快照等待超时、范围事件未确认，以及角色/实例/位置/装备集合不一致。

游戏界面自动装配使用角色识别、普通鼠标输入和画面状态；角色列表、卸载、筛选、拖拽及返回均使用同一
鼠标动作 contract，并在安全检查点响应全局停止键。

## 9. 战报

独立分析组件以正式错误码拒绝当前静态结构时，界面明确提示更新与资料包匹配的分析组件，原始战报保持不变；
只有组件及响应协议身份匹配的已知错误才归因为结构不兼容。未知或身份不符的响应保留通用故障，不展示原始错误载荷或绕过分析接口。

分析组件与客户端分别绑定版本及文件身份。源码目录成套更新组件后，已经运行的源码实例需重启以重新绑定；
这不更新已安装的发行版，也不重解释原始战报。新资料仍按[数据更新待处理项](roadmap.md)独立核验来源与晋升。

战报的采集、冻结、历史、副本编辑、逐击分析与固定轴边际行为统一见[战报功能](features/battle-report.md)。
原始事实与派生结果的安全边界仍以仓库契约和[系统架构](architecture.md)为准。

## 11. 环境、更新与日志

### 插件

侧边栏「插件」提供两个独立、默认关闭的显示开关：「技能冷却」显示队伍技能剩余冷却、冷却遮罩与 E/Q 就绪光效；
「敌人状态」显示敌方血量和倾陷数值。技能冷却只保留总开关，图标、倒计时与原生就绪光效一起启停；旧版独立就绪提示偏好不再生效。
血量和倾陷选项仍在敌人状态卡片中设置。
「自定义打桩」复用相同的标题、状态标签与滑动开关样式，但由独立控制器维护状态和偏好。卡片正文先显示自有木桩数量，再显示操作说明，不重复运行状态；完整状态由顶部标签及提示呈现。具体行为见[托盘驻留与游戏快捷轮盘](#托盘驻留与游戏快捷轮盘)。
两张卡片分别维护应用状态和运行状态；修改一张卡片的开关或显示选项，不改写另一张卡片的状态标签。
开关变更经独立后台任务提交到既有原生连接，不等待完整环境检测或背包刷新，也不另建采集连接。
关闭请求尚未确认时显示「正在关闭」或「关闭待确认」，收到组件响应后才显示「已关闭」。
开启技能冷却时，技能显示优先使用独立的原生 E/Q 控件与已确认的技能形态；E 在冷却结束后显示就绪状态，
Q 还需能量充足，光效不代表其他施放条件均已满足。原生控件证据不足时保留数值和冷却遮罩，不把未知施放条件显示为已满足。
后备遮罩以本轮观测到的最大剩余 CD 为 100%，随剩余时间从上向下消退；该比例仅为显示估计，
不作为游戏总冷却或战报证据。归零、观测中断或角色/技能身份变化后重新建立基准。
偏好保存在本机全局 `config/plugins.json`，切换账号不重置。仅在已确认的中风险或开发模式启用；
所有模式均可查看「插件」页面；低风险和离线模式禁用开启及显示选项，并在页面内引导前往工作模式设置。
页面的「检测详情」在所有模式下复用设置工作模式的显式检测与处理入口，不仅跳转部署或模式设置；
检测和处理仍遵守当前已确认模式及既有权限，不因入口变化自动开启插件。
降为低风险或离线时自动关闭并保存两个启用开关，保留血量和倾陷显示选项；切回中风险或开发模式后需手动重新开启。

关闭插件停止对应读取和绘制，不启停战报采集；两项都关闭时不再执行 HUD 对象发现、属性读取或绘制。
退出 Calc、暂停连接或撤销原生权限时停止显示；正常重新启动且模式仍允许时按保存偏好恢复，临时暂停不清空偏好。游戏未启动显示「等待游戏」，
缺少配套能力提示更新组件，游戏入口不匹配则提示版本不支持，不把请求接受当成 HUD 已安装。
配套协议与验收边界见[原生显示插件](integrations.md#原生显示插件)。

环境检测核对 Npcap、原生整包、D3D 采集入口、备用原生 Loader、Microsoft Visual C++ 运行库，以及原生连接、握手和各业务能力。后台检测只读取已有业务状态，不周期性启动角色、背包、队伍或环境的完整刷新；显式检测仍可采集手动功能所需证据。自动同步和 HUD 都关闭后，无战报、库存租约或进行中读取时释放共享 Core 连接；后续操作按需重连。手动部署的同步服务收尾、原生会话关闭、文件核对与写入在进度窗口的后台任务中执行；完成后在界面线程保存部署记录并刷新状态。部署直接替换组件，不备份旧 DLL；不再部署或加载旧 Mods 工作区。
两种加载方式互斥，Loader 会话由应用 stop event 和 owner PID 管理。游戏路径检测先读取 Windows 卸载注册表，再检查各盘符下固定的常见游戏库目录，不递归扫描磁盘；确认路径保存到本机工作模式配置。Loader 从该 `HTGame.exe` 的官方目录结构定位同一安装根的启动器。进程存活或管道存在都不代表装备功能可用，须由原生装备接口及完整背包证据确认。

自动组件管理保留游戏目录的旧 `dwmapi.dll` 及其他非当前组件；手动部署原生组件、手动启动 Loader 和旧部署记录的手动清理
保留旧代理清理行为。旧代理存在不使当前组件判为不匹配。处理范围和失败边界见
[原生整套部署](reference/game-component-bundle.md#原生整套部署)。

安装版的 Mirror 支持版本检查、下载、取消与安装器启动。发现更新时显示版本差异和可滚动说明，可选择提醒偏好、Mirror、发布页或网盘；群聊入口复用设置中的说明与复制操作。手动下载旧版本时先展示两端版本及自动启动安装程序的提示，默认取消；同版或新版沿正常下载流程。切换账号或退出撤销旧请求，取消后不再自动派发；安装包校验在后台执行。下载完成不等于安装完成，失败保留旧版本。详细边界见 [Calc 更新与安装器派发](integrations.md#calc-更新与安装器派发)。

常驻日志为账号目录下 `nte_runtime.log`；用户开启详细日志时创建独立时间戳文件。账号切换结束旧账号会话
并在新账号目录创建会话。稳定事件名、公共字段和脱敏边界见 [日志事件规范](reference/logging-events.md)。


### 免安装候选的更新方式

免安装版本与安装版使用同一业务功能。手动便携包保留程序目录内的数据，更新前完整退出，再在原位置替换发行文件；平台包由平台管理程序更新，KoKodayo 候选将数据放在程序目录外的固定位置，以避免平台重建程序目录时丢失数据。两类便携版的更新入口均不启动安装器。免安装不等于免除所有系统依赖，也不自动开启同步或部署游戏组件。

当前候选仍待真实包与平台验收；支持条件和剩余门禁见[免安装方案](roadmap/portable-distribution.md)。已有用户参考[数据迁入与恢复](integrations.md#便携数据迁入与恢复)，维护者制包命令见[免安装构建](integrations.md#免安装-zip-与平台候选构建)。
