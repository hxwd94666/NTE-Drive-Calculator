# 功能原理与数据契约

本文描述当前已实现并由公共行为测试覆盖的功能。分层与数据域见 [系统架构](architecture.md)；仍需真实
环境或上游能力的部分见 [当前路线图](roadmap.md)。

## 1. 账号、设置与工作台

应用以 `AppContext` 管理当前账号和 generation。账号数据库、截图与日志互相隔离；切换账号时先停止或
阻止后台任务，再重建同步、扫描、鉴定和战报依赖。旧 generation 的 worker 结果不更新页面或数据库。

主题写入 `config/global_ui_preferences.json`，对全部账号生效；首次没有全局主题文件的新安装默认黑色主题，只有旧账号已显式保存的主题才会在首次建立时迁移。
计算偏好、基础权重、热键、扫描、倒带和 UI 选择按既定 key 写当前账号。工作台只读取账号摘要、环境状态
和当前稳定快照，不重新实现业务查询。
工作台右上角使用已核验角色目录中的黑羽高清头像，按当前屏幕像素比显示。

工作模式、风险确认、自动连接、自动部署更新、暂停和组件清理记录属于本机应用域。首次安装及旧版迁移默认
离线，旧账号的插件风险勾选不授予新模式权限。设置顶部与主窗口入口显示同一模式；检测按各功能分别报告
可用、等待、缺条件、故障和清理待完成。检测详情优先显示故障；原生连接或整次业务检测异常集中展示原因、下一步和已识别错误码，
受影响的业务项标为本次未完成检测，不将未知握手写成失败。文件核对、管道、握手、能力声明、快照和业务就绪分别展示，
未知明确标为未确认。用户可选择文本或点击“复制检测结果”，取得包含应用版本、模式和检测时间的本次报告；重新检测时停用旧结果复制。
手动检测失败同时记录固定诊断摘要，不输出原始异常文本、RPC 内容或子进程 stderr。
手动功能入口区分模式受限与组件/连接条件缺失，并可导航到相应设置区域；
设置完成后须由用户重新点击功能，不自动继续。最终执行前仍核对权限，纯离线能力不受影响。完整语义见
[工作模式契约](reference/work-modes.md#手动功能入口与设置定位)。首页通过自动同步与重新同步入口按模式选择抓包或 DLL；角色状态使用独立手动按钮，职责和缺失字段规则见[同步契约](reference/work-modes.md#背包与角色状态同步)。原生四域只接受提供方真实状态；未经正式业务投影证明的部分观察不会写入
正式完整背包。源码与替身测试不代表配套二进制或实机验收已经完成。

首次安装及从旧配置升级时，自动同步默认关闭；开启时先显示只读环境核对，明确确认后处理已授权组件，核验完成才保存开启偏好。检测弹窗可跳至环境设置中的具体控件；D3D 需要部署时等待游戏退出，Loader 需要启动时还核对所选安装目录的启动器进程。同步关闭不撤销手动功能或已完成引导后的组件维护授权，详细时序见[工作模式契约](reference/work-modes.md)。

Loader 准备时核对所选游戏安装目录中的各个正式启动器入口；启动器仍运行或状态未确认时不执行部署，并在手动启动或开启同步准备时明确提示关闭启动器和游戏。手动“清理游戏目录”在独立窗口显示进度和清理结果，不再自动打开环境检测详情。

旧用户启动时，只读核对已记录的旧部署、游戏目录旧代理及当前组件文件；有明确升级证据才弹出简洁引导，并在工作台保留“继续处理”。步骤依次指向清理、重新确认模式和按需部署；清理及部署仍由原有显式入口执行，文件匹配不宣称同步成功。
从引导发起清理时，清理结果先在独立窗口说明；成功后只有点击“继续升级引导”才返回下一步，关闭结果窗口则由工作台入口稍后继续。结果核对未完成、游戏仍运行或清理故障时不跳步；中途退出计算器后，工作台继续保留未完成引导并在下次启动恢复提示。引导主操作使用与普通关闭、诊断按钮不同的强调样式。

工作台“如何使用”按当前工作模式给出简短的同步步骤，提供“工作模式设置”和“环境设置”两个定位按钮；关闭说明不更改设置或启动同步。

## 2. 库存同步与不可变快照

配套原生组件声明全部物品读取能力时，自动同步在装备及角色读取后，将客户端已观测物品集合单独保存到
当前账号的不可变物品快照，保留最近 20 份。归档保存原始条目、来源身份、修订、数量和覆盖诊断；仅在
分页齐全、集合完整且复核修订未变化时提交，失败保留旧归档并允许重试。账号切换或取消会撤销未提交写入。
这一集合不代表服务端全部资产；装备库存指针、计算与现有仓库继续只消费正式装备快照，其他物品暂不展示。

nte-core 库存事件经过收集、完整性检查和 `InventorySnapshotStabilizer` 内容稳定化后，一次事务提交装备、
词条、角色实例和当前指针。稳定判断使用完整内容指纹与安静窗口，不使用历史最大数量。角色列表字段缺失
与明确返回空列表属于不同快照内容；补入角色列表时，即使装备不变，也要生成新快照，不改写历史记录。

原生同步只使用已保存的原生快照作为去重基线。视觉库存切回原生同步时，即使条目内容相同，也必须保存
原生来源的新快照。同步提示按来源区分视觉库存和原生库存；视觉扫描不提供角色实例，不称为旧版 Core
快照。原生快照未附带角色列表或尚未观测到角色实例时，分别说明该快照的状态，不据此判断 Core 版本或
所有角色的极速装配可用性；装配仍按其公开校验流程解析目标角色身份。相同内容再次到达时刷新接收提示，
不重复保存快照。

原生来源同时未观测到装备和角色时保留现有背包，等待登录数据就绪；有角色证据的空背包仍可正常保存。
具备数据域变化通知的来源，在完整背包读取后先交给稳定器处理，角色养成读取移到后续监听轮次，
不让角色读取阻塞已完成的背包保存。游戏退出后的首页和顶栏统一显示等待游戏，再次启动后自动连接。

稳定快照保存失败时，界面区分数据库锁冲突、只读或权限问题、容量不足、损坏、读写或打开失败、结构不匹配、
约束冲突与事务异常；无法分类时明确显示原因未知。技术详情保留 SQLite 异常类型、原始扩展错误码与错误名、
失败阶段、安全消息和回滚结果，回滚异常不覆盖首次保存错误。后台继续按既有间隔重试，不自动修库或新建账号。
日志字段和隐私边界见 [日志事件规范](reference/logging-events.md)。

`inventory.get_latest` 读取最近捕获数据，不触发强制刷新。下游启动时解析一次当前 `snapshot_id`，运行中
不追随最新指针。快照清理保护当前快照、活动配装槽位、锁定方案和未完成任务引用。

账号 schema v21 支持原生库存的运行时状态增量。残缺装备事件只覆盖当前完整快照中已知正式 UID 的
`locked`、`discarded`、`equipped`、角色实例和位置；旧 sequence 不覆盖新状态，未知 UID 被忽略，库存
成员和当前快照指针不改变。极速装配和一键弃置/锁定的已接受指令也会写入相同的当前快照投影，供仓库立即
显示目标角色/状态；后续 nte-core 事件仍覆盖同一 UID。该投影不新增、删除装备，也不推进当前快照指针。

## 3. 视觉与手柄全量扫描

鼠标和虚拟手柄是同一视觉库存能力：

```text
mouse capture  ─┐
                ├→ 有界截图流 → OCR/解析 → 完整 vision snapshot
gamepad capture ─┘
```

扫描冻结账号、generation、用户库、截图目录、静态 dataset、解析 profile、捕获驱动、窗口和 token。
OCR 初始化在首次游戏输入前完成。取消、窗口变化、截图缺失、解析失败、索引不连续或数量不一致时保留旧
当前快照，不提交半成品。

卡带主词条无法识别不等同于整件装备解析失败：该卡带仍进入完整视觉快照，但不伪造主词条或数值，计算时仅排除
这件无法评分的卡带。扫描完成提示只在实际存在此类卡带时显示失败总数，并最多列出两个扫描编号供排查。

### 3.1 鼠标捕获模型

- 基准画布为 2560×1440、7 列×4 行；坐标映射到客户区顶部对齐的 16:9 物理像素内容区。
- 首屏最多 28 件；后续每页跳过重叠首行并新增 3 行、最多 21 件。
- 鼠标与虚拟手柄全量扫描在各自既有导航前，均执行一次从上向下的长按滑动，使用与全自动增量扫描相反的两点方向重置列表位置。
- 鼠标全量扫描使用用户输入总数生成不可变分页计划；末页按总行数映射到底部对齐后的四行视窗，只点击该计划格位，并用连续占用检测复核数量。虚拟手柄扫描保持原有流程。
- 首次点击前对计划首屏执行格位预检，拦截错误页签、未加载、遮挡和整体偏移。
- 普通滚动 profile 为 `-280 × 7 + -120 × 2`；每第六次翻页使用累计补偿
  `-280 × 6 + -120 × 4`。滚轮 delta 不随分辨率缩放。
- 点击位置与时序在安全范围内随机；测试可注入固定 seed。每件截图仍保存完整客户区，以兼容统一解析器。
- 双线程模式使用单截图生产者、单 OCR 消费者和 21 张有界队列；兼容低负载模式使用更慢输入和串行解析。

当前自动化覆盖 1080p、2K、4K、2560×1600 顶部对齐、末页 1–21 件及底部对齐、2000 件分页、滚动补偿、随机安全
区、背压、取消和失败不提交。真实设备行为按 [Windows 验收](validation/windows.md) 记录。

### 3.2 扫描报告与扫描后管理

每次鼠标扫描原子更新账号截图目录中的 `mouse_scan_last_report.json`，记录分辨率、profile、预检计数、
分页、滚轮、预计/捕获数量、耗时和终止状态；不记录 UID、OCR 全文、截图内容或绝对路径。

启用扫描后管理时，完整视觉快照先提交，再根据同一次冻结扫描索引生成锁定/弃置计划。执行从最大索引
倒序回退，每件依次验证原始截图身份、操作前图标、动作和操作后图标。锁定切换弃置必须等待确认弹窗。
操作前图标与固定计划不一致时，该件不执行输入、记录后继续其余计划，并在扫描完成提示中汇总；定位、
身份、弹窗或操作后复核失败仍停止后续输入。

结果写 `mouse_state_sync_last_report.json`，保存聚合数量、状态迁移、状态不一致跳过项、耗时和安全错误类型。该会话能力
不把视觉临时 UID 变为仓库可延后写回的正式 UID。

## 4. 计算、角色配置与自建角色

计算请求冻结账号、generation、快照、静态数据集、profile、角色顺序/平级组、目标配装槽位和锁快照，
返回不可变 `WeightedAllocationPreview`。保存只消费原 preview，不重新读取最新库存或配置。
计算页的扫描模式、角色优先级、分配策略保持同一纵向页面。第二步在既有优先级链与未选角色区显示轻量头像，
仍保留角色间 `>`、`>>`、`=` 运算符、拖动排序、逐角色“管理”与优先级存档操作；
已选角色的头像及所在角色卡可点击移回待选区，角色名按钮仍支持拖动调整优先级，“管理”和运算符各自保持原操作。
自定义角色始终显示随白色、黑色主题适配的问号头像，正式角色头像缺失时才显示名称首字。
同一头像也用于词条配装角色优先级、已保存计算配装的顶部角色滑动列表及替换候选的临时归属标记；
实际游戏仓库归属仍仅按正式角色身份读取发行头像，不把计算方案的临时归属当作游戏装备状态。
未选角色按名称首个有效字符的拼音首字母 A–Z 排序，同首字母按完整拼音稳定排序；搜索只筛选未选区，
不隐藏已选链或其运算符。常规窗口的已选链每行最多四个较宽的角色单元，保留头像、名称、管理和运算符；
更窄窗口继续减列，全屏宽度超过断点后按可用空间增列。已选单元保留略高的框和管理操作，
保留“管理”和较宽运算符比例，不因四列布局而拉长角色卡；未选卡片适当收窄并均分当前行宽，
未选区不设固定列数上限。已选和待选角色名称统一使用 13px 微软雅黑 UI，不按字宽逐个缩放，也不套用小按钮字号；
两区正式角色头像都使用发行包中的 256px 裁切图，按当前屏幕像素比下采样，并以适配主题的底色衬托透明边缘，
避免高 DPI 下先缩至逻辑像素再被系统放大或浅色头发融入白色背景。
窗口加宽时增加每行角色数，并减少对应行数和区域高度。
第二步不设内部滚动区，全部角色选中后仍完整展开，只沿计算页统一纵向滚动；第三步继续紧邻第二步。
组合计算复用当前固定候选池中的评分数据，不改变图纸候选、搜索顺序、同分裁决或搜索上限；切换候选池或
进入新的预留冲突分支时重新准备数据，暴击阈值等依赖当前配装状态的判断仍按原规则逐次执行。

候选规则：

1. 锁定真实 UID 在候选构造前联合排除；失效锁阻止计算。
2. 账号级“筛选设置”默认不选择品质和类型。选择卡带或驱动后必须同时选择至少一种品质；对已选类型，仅已选品质进入角色管理筛选，其余品质被过滤；未选类型按默认规则处理。该筛选在角色配置前执行一次，角色优先和增量更新共用同一候选结果。
3. 驱动副词条黑名单默认是硬过滤；启用“黑名单为零权重”后不淘汰命中驱动，而是在 Top-K 评分时将黑名单词条按零权重计分。副词条自选按最深/最多命中候选池优先，组合无解时逐层放宽。
4. 卡带先执行套装与主词条硬过滤，再执行同一副词条回退；默认四件套。
5. “不限制评分等级”只移除副词条自选门槛，不移除套装、主词条，也不改变黑名单当前的硬过滤或零权重语义。
6. 平级组暴击恢复依次为只换卡带、冻结必需套装件后重选额外件、仅失败角色从零重配。
7. 角色优先中，前序组的固定 UID 不进入后续候选；最终图纸内真正等价的同分驱动则延迟归属。等价候选须保持形状、评分、词条优先级、额外形状收益及暴击约束一致；后续组可使用它们，但每次占用都保留前序全部预留槽位的一对一回填。平级组先完成联合分配，再整体建立预留；计算结束按稳定 UID 回填。普通同级矩阵搜索耗尽预留分支且没有可回填结果时，将前序预留槽位纳入同一次匹配，在原图纸候选范围内恢复完整方案，并继续核对原暴击上限等约束；已有可回填结果和显式暴击最低值路径保持原规则。虚拟占位评分为 0，不进入锁或极速装配。
8. 分配设置的“图纸组合数”默认 500，按当前优先级组控制匹配求解预算；单角色组只限制该角色，同级组限制组内联合组合。可填写任意正整数；超过理论组合数时只评估理论总数。计算按钮通过分析组件的 `allocation_v1` 执行评分和分配，保留原图纸生成与渲染。末级无词条排序、无暴击上下限的同级组会在原候选前缀保底后，复用形状匹配缓存考察额外组合；缓存命中不重复消耗匹配预算，新增匹配仍受预算限制。改进方案必须保持原配置约束及优先顺序，且得分不低于原前缀方案，不承诺每次严格提分或全局最优。全局停止键可终止并回收本次计算进程。

计算结果只展示由固定背包快照确定的“空幕属性汇总”，不把角色当前养成拼接成预览面板。结果开始时同时
冻结各角色全部已有方案的可见配装槽位装备基线；存在装备变化时，“变动”菜单先从固定快照补全旧装备，
再按同形状、同族、同面积及稳定顺序把旧、新驱动配成同一次替换，跨形状重排也不拆成两个独立变动。旧、
新驱动与卡带都显示逐件评分和评级：优先使用方案冻结的逐件分，旧方案缺失时按当前角色评分输入统一补算。

## 5. 配装槽位、游戏导入与锁

每个角色最多三个可见槽位。`primary` 是兼容默认槽位，默认显示角色名；用户可新建、重命名、归档和
选择槽位。每个槽位同时只有一个当前方案，覆盖会创建新方案版本并原子更新 `current_plan_id`，历史方案
仍按自己的来源快照解析。槽位管理中的套装名称读取该槽位当前方案的卡带，不从驱动或其他槽位猜测。

计算预览不显示完整角色面板。方案保存到明确槽位后，配装页才提供“角色属性汇总”：装备部分
固定读取该方案及其来源快照，角色部分读取当前等级与突破阶段、弧盘等级/突破/精炼及无条件常驻属性、
好感度 10 级、家具加成和官方额外形状。角色养成变化会更新该汇总但不改写已保存装备、逐件评分或方案总评；
带触发条件的弧盘、武器或套装效果不进入静态面板。汇总面板沿用紧邻图纸的旧版紧凑样式，不使用大字或
内嵌滚动条，前五项之外通过详情按钮查看；计算配装发生装备变动时，空幕与角色属性汇总都以旧、新、变化
三列对比前一固定方案，其中角色两侧使用同一份当前养成，只改变各自方案装备。计算页仍只有空幕属性汇总，
配装页才提供角色属性汇总。
游戏配装与计算配装的角色属性汇总均重新读取当前账号角色档案，并共同计入等级/突破、当前弧盘等级与精炼、
好感度 10 级、家具加成和额外形状；游戏与计算方案对比时，两侧只替换装备，角色养成保持同一当前值。
游戏配装按正式角色 ID 列出该角色全部计算配装槽位，不按卡带套装筛选，也不把游戏导入方案作为候选；
默认选择列表中的第一个槽位，用户可在汇总框右上角的“对比槽位”中切换。对比固定显示“游戏、计算、变化”，
变化为计算属性减去游戏属性；没有计算配装槽位时只显示游戏配装自身属性，不显示选择器或对比列。
装备卡片与空幕属性汇总使用同一角色词条权重和颜色分级；汇总以正式属性 ID 区分百分比与固定值，不能把
`AtkUp` 的“攻击力%”按 `AtkAdd` 的“攻击力”显示或着色。

同一角色的多个槽位是备选配装：它们可引用同一个真实 UID，不视为装备复用冲突。角色优先和
增量更新均以角色为 UID 冲突边界；只有不同角色的当前槽位同时引用同一 UID 时处理冲突。

计算和加权计算保存前为每个角色显式选择目标槽位，可新建槽位或跳过；差异比较使用同一目标槽位，
不把其他备用槽位当成基线。批量保存是事务性的，后续角色验证失败时整批回滚。
计算页“保存装备锁定”在后台共用一次冻结库存与形状目录完成方案转换，全部目标槽位在同一事务中保存。
保存同时检查未参与计算角色的所有当前槽位；借走的真实装备从原方案解除占用，以原位置的零分虚拟占位
保留图纸，并标记原方案不完整，历史方案保持可追溯。主力和备用槽位均处理；同角色备选方案继续允许
共用装备，锁定槽位拒绝借用，不将不同视觉快照中恰好相同的局部 UID 当成同一装备。
进度条显示已校验方案数量、事务写入和页面刷新阶段，保存期间阻止重复提交；失败或提交前取消整批回滚。
计算结果仅提示本次第二步角色选择中“全部槽位已锁定”的角色；未选择的锁定角色不显示该提示。

游戏配装是 nte-core 稳定快照的只读投影。显式导入后保存为 `game-observed-loadout-v1`，冻结来源快照、
目标槽位、逐件评分和卡带满级值。完整驱动但缺卡带的方案可保存为 `incomplete/missing_tape`；视觉来源
不进入游戏配装导入。

锁作用于当前账号的具体槽位方案，不调用游戏锁 RPC。至少一个真实装备即可锁定；空方案和虚拟占位方案
不可锁。锁定槽位不可覆盖、归档或单件替换；其他角色/槽位不得借用其 UID。归档 `primary` 时由 DAO
提升剩余可见槽位；每个角色至少保留一个可见槽位。

配装页、角色空幕详情、替换、倒带和装配都读取选中/默认槽位。批量装配对每个角色显式选择一个 `slot_id`，
并在执行前检查角色唯一、槽位存在、原生来源和跨角色 UID 无冲突。

## 6. 仓库与鉴定

仓库读取固定快照并通过 `WarehouseInventoryService` 生成投影。卡带按套装、主属性、副属性筛选；驱动按
形状和副属性筛选。条件使用正式 ID，同组为“或”、跨组为“且”；状态分为已装备、已锁定、已弃置和其他。
重置清除全部条件，视觉来源因无可靠原生状态归入其他。

原生仓库状态管理固定快照和正式 UID，Service 生成计划，Integration 提交 RPC，随后等待递增完整快照
确认。一键弃置/锁定和仓库状态保存会在命令接受后立即更新目标 UID 的仓库投影；若这两个动作守卫期内
收到单个、覆盖全部目标 UID 的背包快照，则由动作本身替换库存集合，允许新增或移除库存。只有该动作收到
声明数量减少的背包事件时提示玩家在工作台重启同步并等待完整背包读取；后台监听不会单独执行这种库存替换。视觉仓库本身只读；只有扫描完成后的同会话
鼠标管理使用扫描索引执行即时写回。

评估角色范围只影响仓库锁定/弃置评分，与计算角色、活动配装和倒带偏好隔离。计算扫描与仓库管理的角色选项、默认权重及图纸可用性在一次操作内读取完整游戏静态库；已安装的独立目录只提供经校验的头像，不混入战报数据源。评估角色选择按显示名称首个有效字的拼音首字母 A–Z 排列，同首字母按全名拼音稳定排序；自定义角色使用随主题变化的问号头像。
原生一键弃置、锁定及手工状态保存使用装配的批次读取隔离：批量指令期间保留变化通知，暂缓背包与角色快照读取，
结束或失败后释放，随后核对状态。锁定前先取消弃置，弃置前先解锁，恢复普通状态时分别清除两个标志；
已满足目标的标志不重复发送。组件声明 `native_equipment_state_batch_v1` 时，每批最多 16 条锁定/弃置指令，
同一装备的多步转换不拆批；Core 每批查询一次状态后派发，DLL 在游戏线程顺序执行，每步复核对象域和取消状态。
旧组件沿用单条接口。两条路径都只保留一个在途请求，不等待逐件背包变化。明确未派发的 `source_changed`
或组件忙碌只重试当前请求；重试前复核仍属于同一提供方和对象域。批次部分派发、超时、结果未知、上下文变化
或其他失败均停止后续指令，不自动重发整批；进度表示已提交，最终成功仍由背包状态核对。
不能将部分完成的状态转换标为整体成功。全部派发完成后只通过新的完整背包快照统一核对；“弃置”只设置游戏标记，不删除装备。

鉴定把截图、剪贴板、手工输入和仓库单件入口投影为统一装备对象，调用公共评分与
`EquipmentPresentation`，不写库存、基础权重或配装。扫描与鉴定共享 `GlobalHotkeyManager`，通过 owner
隔离会话和停止权限。

## 7. 倒带推荐与执行

工具页读取固定库存、账号偏好和活动配装槽位。打开页面或修改选项不自动求解；显式生成后返回八槽形状
多重集合。偏好字段为 `target_character_ids`、`main_character_ids`、`strategy`、`target_grade`、
`target_threshold_mode` 与 `target_custom_percent`。标准等级保留 D 至 ACE；选择“自选”后必须填写
1.0% 至 100.0% 的目标百分比，按 0.1% 精度保存到当前账号。角色选择卡按显示名称首字拼音 A–Z 排列并统一等高；角色拥有当前计算方案时
显示其全部可见配装槽位中的最高总评分，并按完整配装 D–ACE 评级使用同色强调；已从游戏配装导入并保存为
计算配装的方案使用导入时核对过的冻结评分参与最高分比较。未导入的游戏内展示不参与；无已保存计算方案时
显示“暂无计算方案”，不编造评分。

```text
标准目标分 = 等级比例 × max(1, 驱动面积) × 10
自选目标分 = 自选百分比 × max(1, 驱动面积) × 10
缺口 = max(0, 目标分 - 方案保存的逐件评分)
```

等级比例：D=0、C=.2、B=.3、A=.4、S=.5、SS=.6、SSS=.7、ACE=.8。自选百分比按每件驱动自身的
实际面积分别计算，等于目标不形成缺口；高于目标的分数不抵消其他驱动缺口。该阈值只改变倒带推荐的
缺口统计，不改变单件评分或配装方案总评；自建角色和同角色的每个活动配装槽位均独立参与统计。

- 全面均衡：全部培养角色每种正缺分形状保留一槽，余位按“形状缺口 ÷ 库存”比例分配。
- 少角冲分：只看冲分角色，每种正缺分形状保留一槽，余位只按评分缺口比例分配。

超过八种正缺分形状时返回提示。每槽概率 12.5%；同形状重复 `q` 次时，每槽价格
`10 + 5 × (q - 1)`，总价为 `q × 每槽价格`。难度只决定蓝/紫/金品质，不进入形状、概率和价格。

显式执行冻结品质、定制模式和八槽方案。每个品质先切换对应难度再读取该难度余额；余额不跨难度复用。
初级随机十连固定 600；紫/金定制从右侧硬币口下方识别十连价格。“不做更改”保留现有候选，“应用方案”
通过轮廓与 12 种拓扑全局匹配后配置八槽。十连循环为点击、等待 1 秒、Esc、等待 1 秒、Esc、等待 0.5 秒；
执行期间可按设置中的全局停止键停止。真实执行仍为实验能力。

## 8. 极速装配与游戏界面自动装配

极速装配只消费 nte-core 正式 UID、角色实例和已保存槽位方案；游戏界面自动装配消费视觉投影与输入动作，
可支持自建角色。两条链路冻结账号、generation、来源快照、槽位列表和任务 token，并持久化角色项与事件。

原生同步保留最近三份完整快照；已保存配装、装配任务及导出仍引用的旧快照继续保留。
极速装配在开始时冻结最近已保存的完整快照，新一轮读取或等待稳定不阻塞该快照的使用；
首次尚无完整快照时仍需先同步。装配接口的实际就绪状态独立检查，执行后继续确认结果。

原生极速装配在指令批次期间暂缓背包与角色快照读取，保留 DLL 变化通知及同一 Core 连接；
批次内冻结提供方和对象域，逐次核对后按“卸空、装配”执行。库存通知导致的 epoch 递增不终止批次，
Core 对每条请求独立冻结及核对 epoch。批次成功、失败或取消均释放读取，
后验确认在释放后进行。明确未派发的忙碌拒绝沿用有界重试；超时或执行结果未知不自动重发，也不切换主角
实例重复尝试，需待同步核对实际装备后再操作。原生结果未知只结束本次请求，不因此退出共享 Core。

极速装配每个角色最多三次完整请求。每次下发后先等待 10 秒完整递增快照；无论后续收到完整快照、范围化
装备事件或没有事件，已接受指令中的卡带/驱动都会立即投影为目标角色和格位。完整快照是首选确认来源，
可核对角色、实例和装备全集；不以驱动格位差异触发复装。范围事件仅用于发现遗漏：目标装备出现在事件中但
未装备时，才重试对应角色；没有快照或范围事件时本轮直接结束，不将其当作遗漏，也不改写库存集合。

第一次或第二次明确不一致时卸空重装，第三次仍不一致才生成最终错误。报告区分管道缺失、短暂不可用、
队列繁忙、核心请求超时、完整快照等待超时、范围事件未确认，以及角色/实例/位置/装备集合不一致。

游戏界面自动装配使用角色识别、普通鼠标输入和画面状态；角色列表、卸载、筛选、拖拽及返回均使用同一
鼠标动作 contract，并在安全检查点响应全局停止键。

## 11. 环境、更新与日志

### 插件

侧边栏「插件」提供两个独立、默认关闭的显示开关：「技能冷却」显示队伍技能剩余冷却、冷却遮罩与 E/Q 就绪光效；
「敌人状态」显示敌方血量和倾陷数值。就绪提示、血量和倾陷选项直接在各自卡片中设置，不再打开二级弹窗。
两张卡片分别维护应用状态和运行状态；修改一张卡片的开关或显示选项，不改写另一张卡片的状态标签。
开关变更经独立后台任务提交到既有原生连接，不等待完整环境检测或背包刷新，也不另建采集连接。
关闭请求尚未确认时显示「正在关闭」或「关闭待确认」，收到组件响应后才显示「已关闭」。
开启就绪提示时，技能显示优先使用独立的原生 E/Q 控件与已确认的技能形态；E 在冷却结束后显示就绪状态，
Q 还需能量充足，光效不代表其他施放条件均已满足。原生控件证据不足或关闭就绪提示时保留数值和冷却遮罩。
后备遮罩以本轮观测到的最大剩余 CD 为 100%，随剩余时间从上向下消退；该比例仅为显示估计，
不作为游戏总冷却或战报证据。归零、观测中断或角色/技能身份变化后重新建立基准。
偏好保存在本机全局 `config/plugins.json`，切换账号不重置。仅在已确认的中风险或开发模式启用；
所有模式均可查看「插件」页面；低风险和离线模式禁用开启及显示选项，并在页面内引导前往工作模式设置。
降为低风险或离线时自动关闭并保存两个启用开关，保留就绪光效、血量和倾陷等显示选项；切回中风险或开发模式后需手动重新开启。

关闭插件停止对应读取和绘制，不启停战报采集；两项都关闭时不再执行 HUD 对象发现、属性读取或绘制。
退出 Calc、暂停连接或撤销原生权限时停止显示；正常重新启动且模式仍允许时按保存偏好恢复，临时暂停不清空偏好。游戏未启动显示「等待游戏」，
缺少配套能力提示更新组件，游戏入口不匹配则提示版本不支持，不把请求接受当成 HUD 已安装。
配套协议与验收边界见[原生显示插件](integrations.md#原生显示插件)。

环境检测核对 Npcap、原生整包、D3D 采集入口、备用原生 Loader、Microsoft Visual C++ 运行库，以及原生连接、握手和各业务能力。后台检测只读取已有业务状态，不周期性启动角色、背包、队伍或环境的完整刷新；显式检测仍可采集手动功能所需证据。自动同步和 HUD 都关闭后，无战报、库存租约或进行中读取时释放共享 Core 连接；后续操作按需重连。部署直接替换组件，不备份旧 DLL；不再部署或加载旧 Mods 工作区。
两种加载方式互斥，Loader 会话由应用 stop event 和 owner PID 管理。游戏路径检测先读取 Windows 卸载注册表，再检查各盘符下固定的常见游戏库目录，不递归扫描磁盘；确认路径保存到本机工作模式配置。Loader 从该 `HTGame.exe` 的官方目录结构定位同一安装根的启动器。进程存活或管道存在都不代表装备功能可用，须由原生装备接口及完整背包证据确认。

自动组件管理保留游戏目录的旧 `dwmapi.dll` 及其他非当前组件；手动部署原生组件、手动启动 Loader 和旧部署记录的手动清理
保留旧代理清理行为。旧代理存在不使当前组件判为不匹配。处理范围和失败边界见
[原生整套部署](reference/game-component-bundle.md#原生整套部署)。

Mirror Controller/Integration 负责版本检查、下载、取消和安装器启动。日志不记录 CDK、Token 或鉴权 URL。

常驻日志为账号目录下 `nte_runtime.log`；用户开启详细日志时创建独立时间戳文件。账号切换结束旧账号会话
并在新账号目录创建会话。稳定事件名、公共字段和脱敏边界见 [日志事件规范](reference/logging-events.md)。
