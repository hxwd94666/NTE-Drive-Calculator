## 1. 文档目的

本文记录 NTE Drive Calculator 2.1.0 与 nte-dps-toolkit / `nte-core.exe` 的合作开发需求，
作为双方讨论、开发、交付和后续更新的临时权威清单。

本期业务目标包括：

1. 建立来源清晰的逐击伤害轴；
2. 取得角色、武器、编队及战斗上下文的固定快照；
3. 取得 Buff/Debuff 的生效区间，用于计算时间覆盖率、命中覆盖率和伤害覆盖率；
4. 支持四人队伍以及深渊上半、下半两个队伍；
5. 在 NTE Drive Calculator 内计算角色直伤、DOT、不同环合伤害和 Buff 的队伍贡献；
6. 将武器和空幕技能 Buff 的覆盖率纳入角色边际收益。

本文只定义合作数据边界，不要求合作方实现 NTE Drive Calculator 的边际收益、配装、评分
或队伍贡献算法。

以下能力已经通过 `nte-core serve --stdio` 对 NTE Drive Calculator 开放，不应重复提出为新

### 3.1 当前下游实际调用边界

NTE Drive Calculator 当前只封装了：

- `capture.start(profile="combat")`；
- `event.battle.summary`；
- `battle.get_summary`；
- `battle.reset`；
- `capture.stop`。

`event.battle.summary` 在本地使用合并队列，只保留最新摘要，适合实时 UI；它不保留逐击历史。
当前 stdio 没有 `battle.get_axis`、`battle.get_record` 或 JSON 导出 RPC。合作方桌面端/调试工具
曾产生过一份逐击 JSON，但它不是当前 CLI contract，也不是普通用户可稳定取得的产品输入。

## 6. 希望合作方开发或开放的功能

### 6.1 P0：完整角色养成快照

建议新增 `character.get_roster`，返回当前账号已经观测到的完整角色列表。

最低字段：

```json
{
  "generation": 123,
  "observed_at_unix_ms": 1780000000000,
  "complete": true,
  "characters": [
    {
      "uid": {"slot": 1, "serial": 2},
      "character_id": 1075,
      "level": 80,
      "breakthrough_level": 6,
      "awakening_level": 3
    }
  ]
}
```

期望扩展字段：

- 已解锁觉醒节点；
- 普攻、战技、终结技等技能等级；
- 弧盘或其他会改变技能机制的养成节点；
- 每个字段的已知/未知状态，禁止用 `0` 伪装未取得的数据；
- 数据所属连接、generation、采集时间和完整性。

难度判断：等级、突破和觉醒整数为 D2；技能等级、具体觉醒节点和弧盘状态为 D4。

### 6.2 P0：角色当前武器快照

每个角色希望返回：

```json
{
  "weapon_uid": {"slot": 5, "serial": 10},
  "weapon_id": "official_weapon_id",
  "level": 80,
  "max_level": 80,
  "breakthrough_level": 6,
  "refinement_level": 5
}
```

必要字段：

- 官方武器 ID；
- 当前账号内的武器实例 UID；
- 当前装备角色；
- 武器等级和等级上限；
- 武器突破等级；
- 武器精炼等级；
- 可读取时返回当前基础属性和副属性；
- 武器更换或养成变化时产生新的角色/装备 generation。

难度：D4。主要风险是把运行时武器对象稳定映射为官方 ID 和实例数据，以及兼容游戏版本
变化。

### 6.3 P0：完整逐击伤害轴

建议新增 `battle.get_axis`。战斗结束后批量返回，不要求把每次命中作为独立 stdout 消息
实时推送。

每条记录至少包含：

- `battle_record_id` 和递增序号；
- 相对战斗时间及统一时间基准；
- 深渊上半/下半；
- 来源角色 ID；
- 技能名称、Ability、GameplayEffect；
- 直伤、DOT、追加伤害、环合伤害等稳定分类；
- 伤害属性和数值；
- 目标实例及怪物官方 ID；
- 是否成功归因、归因来源和未知原因；
- 对应队伍快照 ID。

大量命中必须使用分页、游标或有上限的批量 DTO。停止抓包后的最终记录必须可靠获取。

难度：D2。内部逐击模型已存在，主要工作是稳定协议、分页和兼容。

### 6.4 P0：Buff/Debuff 状态区间

这是精确计算武器、空幕技能和队伍 Buff 覆盖率的核心依赖。

期望记录：

- 应用、生效、刷新、层数变化、移除和自然结束；
- 稳定 GameplayEffect/状态 ID；
- 来源角色、武器、空幕或其他机制；
- 作用对象：自己、单个队友、全队、单个敌人或敌方全体；
- 开始时间、结束时间、层数和数值；
- 深渊上半/下半、队伍快照 ID 和战斗记录 ID；
- 未识别状态和事件丢失计数。

建议由 Core 将原始事件合并为稳定区间，通过 `battle.get_status_intervals` 批量返回。原始
Mod 事件可作为诊断信息，但不应成为下游唯一业务协议。

难度：D5。主要风险包括状态系统研究、刷新/覆盖/叠层语义、作用对象识别、事件丢失以及
游戏更新造成的布局变化。

### 6.5 P0：当前编队及深渊双队快照

建议新增 `team.get_current`，返回：

- 普通队伍最多四个角色及队伍位置；
- 当前前台角色；
- 深渊上半四人和下半四人；
- 队伍/半场的稳定 ID；
- 队伍变化 generation；
- 战斗开始时冻结的队伍快照；

难度：D4。需要确认普通队伍、深渊选队和战斗过程中切换角色的权威来源。

### 6.6 P0：战斗上下文绑定

每条战斗记录应冻结并关联：

- `battle_record_id`；
- 捕获 operation ID；
- 账号连接 generation；
- 角色养成快照 ID；
- 武器快照 ID；
- 队伍快照 ID；
- 数据版本、协议版本和质量来源；
- 战斗开始、停止和最终完成时间。

如果角色、武器或队伍在战斗中变化，应明确生成新快照或记录变更事件，不能让下游把战斗

难度：D3。

### 6.7 P1：角色当前面板

希望取得进入战斗时的最终面板：

- 攻击、生命、防御；

- 穿透、减防等伤害公式相关属性；

难度：已有敌人身份、等级和生命值部分为 D2；防御、抗性和 Debuff 区间为 D4～D5。

## 8. 双方职责边界

### 8.1 nte-dps-toolkit / nte-core 负责

- 从游戏数据、抓包或插件取得可观测的原始事实；
- 将运行时对象稳定映射为官方 ID 或明确标记未知；
- 维护角色、武器、队伍、敌人和战斗记录的不可变快照；
- 输出逐击数据、时停区间和 Buff/Debuff 状态区间；
- 维护协议版本、capability、分页、数量上限和兼容性；
- 输出完整性、丢失、未归因和未知字段等质量信息；
- 保证停止抓包后能够可靠取得最终批量结果；
- 不记录或输出不必要的账号隐私、鉴权信息和完整原始网络 payload。

### 8.2 NTE Drive Calculator 负责

- 按当前账号、generation 和固定快照将数据持久化到账号 SQLite；
- 管理四人队伍、深渊双队和用户选择；
- 维护武器、空幕和技能的静态效果规则；
- 计算 Buff 时间覆盖率、命中覆盖率和伤害覆盖率；
- 将覆盖率计入角色边际收益；
- 计算每个角色的直伤、DOT、不同环合伤害和 Buff 队伍贡献；
- 实现反事实收益、边际收益、评分、配装和 UI 展示；
- 对估算值、实测值和缺失值做明确区分；
- 不从显示名称反查官方关系，不把运行时对象指针当作稳定 ID。

### 8.3 不要求合作方实现

- NTE Drive Calculator 的词条权重和边际收益公式；
- 武器/空幕 Buff 的最终评分；
- 队伍伤害贡献和反事实收益算法；
- 配装求解器、角色优先级和装备分配；
- NTE Drive Calculator 的账号数据库、角色页和编队 UI。

## 9. 覆盖率口径

合作方负责提供状态区间和逐击事实；NTE Drive Calculator 负责计算以下指标：

1. 时间覆盖率：Buff 有效区间与有效战斗时间交集，除以有效战斗时间；
2. 命中覆盖率：Buff 期间符合条件的命中数，除以符合条件的总命中数；
3. 伤害覆盖率：Buff 期间符合条件的伤害，除以符合条件的总伤害；
4. 有效收益贡献：基于 Buff 公式和反事实伤害计算，不由覆盖率直接替代。

是否扣除时停、过场和无目标阶段必须作为计算配置保存，不能隐藏在单一“覆盖率”字段中。

## 10. 下游先行开发与依赖门禁

合作方功能交付前，NTE Drive Calculator 2.1.0 可以先开发：

- 账号内不可变聚合战报、半场和收益画像 contract；
- 使用现有 `battle.get_summary` 和 `event.battle.summary` 展示实时/最终摘要；
- 按本地静态库 GE 映射计算角色、技能和渠道聚合伤害占比；
- 生成明确标记 `summary_only` 的聚合伤害配装权重和单角色综合边际；
- 基于人工定义区间的覆盖率计算器；
- 直伤、DOT、不同环合和 Buff 的贡献分类；
- “实测/规则推算/手工输入/未知”数据来源标记；
- 上游 capability 缺失时的降级和用户提示。

以下能力必须等待合作方接口交付后才能声明完成：

- 自动读取人物等级、突破、觉醒和当前武器；
- 自动读取武器等级、突破和精炼；
- 自动读取当前四人队伍及深渊双队；
- 来源清晰的真实逐击伤害轴；
- 通用 Buff/Debuff 精确覆盖率；
- 真实游戏战斗上下文与角色/武器/队伍快照绑定。

临时降级方案必须明确标记：

- 人物及武器养成允许手工输入；
- 已知固定触发和持续时间的 Buff 可显示“规则推算”；
- 个人逐击 JSON 只作本地研究证据，不作为应用降级入口；
- 未取得状态事件时不得把推算覆盖率标记为实测覆盖率。

## 11. 合作交付验收条件

每项上游能力交付时至少确认：

- 接口和 capability 已写入中英文协议文档；
- 字段使用稳定官方 ID，运行时指针不跨进程暴露；
- DTO 有明确版本、数量上限和分页/批量规则；
- 时间戳使用统一基准，并说明与战斗相对时间的换算；
- 同一记录能够关联角色、武器、队伍及捕获 operation；
- 未知、缺失、不完整和丢失有独立质量字段；
- 抓包停止后最终数据不会被普通 latest-value 更新覆盖；
- 新字段不破坏现有 `inventory.get_latest` 和 `battle.get_summary` 消费者；
- 提供一份脱敏示例 JSON；
- NTE Drive Calculator 完成接口适配和真实游戏验证。
