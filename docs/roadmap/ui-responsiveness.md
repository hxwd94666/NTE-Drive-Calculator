# 页面响应性：后续优化与验收

角色、基础权重、工作台和计算目录已有后台路径及隔离证据，但整应用、真实低配、同步运行与窗口体验尚未全部验收。
本页只维护剩余目标；当前复审按[复审开发方案](architecture-post-refactor-review.md)推进，不重新实施已经落地的后台化。

- 分层、冻结输入、任务 owner 与账号生命周期：[系统架构](../architecture.md)及[开发契约](../../AGENTS.md)。
- 基础权重的当前源码、真实消费者和必要检查：[Fork 开发路线](../reference/fork-development.md)。
- 历史优化前后数据、原始失败及当前基础权重 v2 基准：[响应性验证记录](../validation/ui-responsiveness.md)。
  历史路径与命令保留原貌，不作为当前开发导航；单核离屏代理也不代表真实低配绘制。

旧方案中的同步刷新位置已经迁移，不再把旧文件名、旧阻塞调用或早期局部耗时当成当前问题清单。
已有专项与同条件测量仍适用时直接复用；源码接入、业务通过、性能改善和发行验收分别判断。

## 2. 尚待完成的工作

| 工作 | 要回答的问题 | 必要证据 |
| --- | --- | --- |
| 当前保留集合的集中集成 | 各页面与正式组合根连接后是否仍保持计算、保存和账号边界 | 复审末期当前 `core/full`，失败分类与修复；不重复历史矩阵 |
| 真实窗口与低配体验 | 首次打开、热切换、保存、滚动和绘制是否仍卡顿 | 固定输入与环境的真实 Windows 记录；离屏、单核代理单列 |
| 同步与页面交错 | 连续版本变化是否重复查库、覆盖草稿或积压任务 | 有界连续操作，关/开监听两种场景；游戏连接仅按相应授权执行 |
| 冷态与结果应用 | 延迟加载是否把启动停顿移到首次使用，后台完成后是否再次阻塞 | 分别记录读取、投影、布局及首次可操作时间，不只测回调返回 |
| 重复生命周期 | owner、线程、句柄、控件和缓存是否可回收 | 固定轮次后的静止点、峰值和趋势；无增长线索不扩成长时间耐久测试 |
| 三主题、键盘及混合 DPI | 加载、错误和禁用状态可辨，主要操作可达且不遮挡 | 真实窗口专项；不固化像素、边距或私有控件结构 |

缺组件、查询错误或数据库忙碌也须保留旧事实并给出下一步；性能问题不得用空结果、吞错误或放宽保存门禁掩盖。
只修已测得的瓶颈，前端保持现有菜单与视觉体系，不以复审名义重新设计页面。

## 3. 测量与验收目标

沿用[响应性记录](../validation/ui-responsiveness.md)的冻结输入、计时边界和基线，不为文档合并重跑。
发生热路径变化或回归线索后，在相同机器、依赖、构建及匿名数据规模下做受影响场景前后比较：

- 区分冷态首次进入与热态重复操作；热态角色、权重、首页切换原基准为各 30 次。复用相符样本，新增采样有界。
- 记录角色/库存规模与 dataset 身份，以及 UI 回调、事件循环延迟、后台读取、结果应用和业务就绪时间。
- 同时核对完整重建次数、worker 峰值及静止点资源。后台耗时、磁盘 I/O、绘制和游戏帧率是不同指标。
- P95 按统一口径计算；小样本不作稳定 P99 承诺，不用单次最好结果代替分布，不在后测失败后放宽阈值。

原目标保留：普通热态切页/确认回调 **P95 ≤ 50 ms**，页面框架约 **150 ms** 内给出可操作反馈；
受测路径不造成持续 **超过 200 ms** 的事件循环阻塞；已有明确角色加载基线时，主线程工作时间下降至少 **70%**。
这些是验收目标，不是所有设备的现有承诺。冷加载可较长，但等待期间应可导航和取消，完整就绪前禁用依赖完整输入的操作。

未变化热态不重建整页、索引或完整计算目录；无关战报/历史写入不触发整目录重查。
若结果应用仍超标，先复用未变控件并收缩投影；只有测得必要时才分批，8–12 ms 可作初始批次预算而非新硬协议。
分批间复核身份，半成品不作为业务输入；不使用循环 `processEvents()`、嵌套事件循环或主线程等待伪装异步。
CPU 瓶颈先减少重复计算；没有证据不引入新进程池、全角色预加载或平行任务框架。

## 4. 优化不得破坏的行为

| 场景 | 验收结果 |
| --- | --- |
| 相同冻结输入 | 属性、汇总、权重、槽位、候选和业务排序保持等价；不靠省略已有信息提速 |
| 保存或重置后计算 | 新任务等待有效目录并使用新权重；既有任务、预览和历史评分仍用原冻结输入 |
| 未保存编辑与后台刷新交错 | 草稿保留；保存/放弃/取消仍由用户明确决定 |
| 离页保存与重复点击 | 一次提交、成功后一次导航；失败原页保留草稿，不重放已提交写入 |
| 账号、角色、资料或快照变化 | 旧回调与应用批次失效；新操作复核来源、锁和代次，不使用失效缓存 |
| 查询/保存/后续刷新失败 | 三者分别报告；刷新失败不撤销或重复已提交数据，不伪装成零值或空集合 |
| 连续同步、切页、关闭 | 请求合并且并发有界；关闭逻辑失效与物理收尾分开，不销毁运行中线程或跨账号写入 |

具体输入字段和完成门禁以开发契约及对应领域事实源为准，本页不再复制一份实现协议。

## 5. 回退与完成判断

变更采用同一逻辑批次的工件及受保护回退，不复制整账号库；已合法提交的用户配置保持不变。
隔离输入的活库副本走 SQLite 一致性备份，不复制活动 WAL/SHM。已验收的新入口替代旧入口，不长期维持双实现。
必要检查沿当前授权与复审计划安排，构建、部署和真实游戏操作不由一次源码专项代替。

最终要证明的是：切页和确认不再等待整页重查、重建，同时计算结果、冻结身份、保存和外部操作边界保持正确。
性能未达标或必要业务/真机项目尚缺时，保留具体缺口，不标记整应用卡顿已经解决。
