## 1. 要解决的一个问题

固定词条权重适合稳定评分，却未必能选出完整面板伤害最高的组合。攻击、暴击、增伤、套装和条件效果
相互影响；在一套高分装备附近逐件替换不再提升，也不代表两件同时替换没有提升。

未来目标是：**在同一个冻结模型、战斗场景、库存与合法约束下，寻找伤害更高的可行配装**。
基础权重可生成起点和排序，最终接受候选必须计算完整目标；不迭代改写用户权重来冒充伤害求解。

第一项研究应固定一个有完整模型的角色、固定技能或短轴、养成、弧盘、敌方参数及条件假设，
仅联合选择范围内的驱动、卡带和合法图纸。先用小库存证明目标和约束正确，再扩大规模。
任意轴优化、武器切换、队伍 Buff 时序和跨队总收益暂不纳入。

角色优先保持不变。以后扩展同级组时，必须先定义组内可比较的收益单位与聚合目标，再联合处理 UID 竞争；
各角色独立最优后拼起来不等于组内最优。不同轴时长的总伤害不可未经解释直接相加。
严格同分预留、锁和失败隔离沿用正式 contract；新目标的数值误差处理不等于放宽现有严格同分政策。

## 2. 输入与结果先说清楚

在现有冻结请求基础上，额外固定伤害模型/轴版本、敌方与环境、条件效果、量化范围和缺失证据。
账号及 generation、库存 `snapshot_id`、dataset 身份、角色次序/同级组、目标 `slot_id`、锁、配置、
取消 token 和搜索预算继续冻结。随机起点保存种子；可复现实验优先用确定性评估次数预算，
相同时间上限在不同负载下不保证相同结果。

完整目标函数应覆盖本次声明的全部效果、封顶、触发条件和装备组合，不把单词条边际值直接相加。
卡带主词条自选、额外形状和图纸全集是否参与，在搜索前确定。候选逐次复核正式形状、套装、品质、
词条约束、黑名单、暴击约束及 UID 唯一性；虚拟占位不冒充真实可执行配装。

缺模型或关键输入时明确未就绪；只建模部分伤害时，明确命名范围，禁止称为整场收益。
未知参数不默认为零、倍率一或通用敌人。未来伤害指标与 `ScoringEngine` 基础分分别保存和展示，
不覆盖 `assignment_scores` 或重新解释历史方案。

## 3. 推荐实用路线

> 合法图纸枚举 → 合法/保优裁剪 → 多样候选与多起点 → 单件及双件联合改进 → 返回预算内最好可行解。

这是首轮实验路线。分支定界及可证明上界是后续研究，不是首版可用的前置条件。

本轮占位验收只核对三件事：这条算法路线与输入/证明边界已记录；现有占位仍明确表达未就绪；
重构没有顺手加入搜索器、伤害 RPC、数据库字段或默认启用的入口。现有评分、面板和边际分析继续保留，
它们不被误删，也不作为新伤害分配已经交付的证据。后续研发授权后，再执行本文实验与集成步骤。

### 3.1 为什么组合这些方法

| 方法 | 有用之处 | 局限 |
| --- | --- | --- |
| 按权重优先填套装再补散件 | 很快得到可用起点 | 初始取舍可能丢掉非线性收益 |
| 高分面板逐件替换 | 成本低，容易比较 | 容易卡在单件局部最优 |
| 每张图纸先按权重填满再比伤害 | 扩大布局覆盖 | 每张图纸内部仍只探索少量组合 |
| 每图纸多起点加组合替换 | 覆盖更广，能处理双件联动 | 依然是近似搜索，预算和起点影响结果 |
| 完整枚举或有证明的精确剪枝 | 小库存真值、精确性验证 | 大库存成本高，复杂效果的上界难证明 |

它们是互补工具，不是几个等价的“全局最优算法”。先比较最简单组合的收益/耗时，再决定是否增加复杂性。

原 issue 里的困难可拆成三类，不宜把它们全部归为“动态权重不准确”：

- **目标不一致**：静态高分与完整伤害最高不是同一个目标；改进方式是用完整模型接受候选，而非覆盖用户权重。
- **搜索不充分**：固定图纸、固定起点和单件替换可能遗漏组合收益；图纸覆盖、多起点及联合替换分别补这三个缺口。
- **规模和证明成本**：扩大候选会增加计算，有限搜索仍缺最优证明；明确预算、保留最好可行解，并用小库存真值校准。

因此推荐路线是更有机会找到高伤害、可复现且可控制成本的实验方案，**不是已经解决全部全局最优问题**。
基于成熟业务补足任务和结果框架，能为以后研究提供接入基础；框架本身不增加算法的最优性保证。

### 3.2 研究范围与停止条件

首次实验不同时追求全角色、全武器、全队伍和严格最优。按以下三级逐步回答问题：

1. **正确性级**：一个完整模型、小库存、合法图纸全集，穷举得到真值；先证明目标、身份与约束实现正确。
2. **实用搜索级**：相同实例比较权重起点、单件邻域、多起点与双件邻域，再扩大库存，记录收益差距和资源成本。
3. **精确性研究级**：只有实用搜索仍有重要缺口时研究可证明上界和分支定界；始终说明证明覆盖的原始搜索域。

某一级没有通过，先定位该级问题，不用增加搜索技巧跳过验证。穷举是小实例的真值工具，
不是所有规模下唯一可选的实现；是否值得增加精确搜索，由目标结构、有效界和实测成本决定。
这些步骤属于后续研发排期，当前四日只保存设计和占位语义。

### 3.3 候选整理：把保优删除与启发式筛选分开

非法候选和已证明不可行的分支可以删除。属性 Pareto 支配则需更严格的替换证明：
即使 A 在相关属性上优于 B，同形状的两个槽位可能仍需同时使用 A、B，因为同一真实 UID 只有一份。
多人竞争、套装门槛、上下限、属性转化和非单调被动还会破坏逐属性支配关系。

只有在该分支的资源容量、可替换性、全部约束和完整目标上都证明保优，才删除被支配候选。
其余情况将“更强”用于排序，不从全集抹掉 B。

Top-K、分数门槛、属性分桶、边际估计筛选属于启发式。首轮可以使用，但应保留不同属性方向、套装和形状的
多样性，报告候选和布局截断情况。筛选比例不等于最优性保证；未来精确搜索应重新覆盖原始合法域。
这里讨论新目标的候选筛选，现有正式分配中 Top-K 的用途和语义保持原样。

### 3.4 布局与起点

- 枚举声明范围内的合法图纸及卡带配置，按正式 ID 去重；预算截断时记录尚未覆盖的范围。
- 起点包括按基础分生成的解、不同属性方向解及受控扰动，先检查可行性再计算目标。
- 可复用现有合法基线作为下界，但须在本次模型与约束下重新验证和评估，不混用历史伤害数字。
- 评估重复明显时再加有界缓存，键覆盖本次模型、环境、dataset 与装备/面板身份；不跨不等价上下文复用。

“遍历了生成器返回的图纸”不等于证明图纸全集完整。布局完整性本身需要小实例核对。

### 3.5 组合邻域

对可行起点先做单件替换，再在收益停滞时尝试双件联合替换；最终联合状态合法且完整伤害改善才接受。
两次单件中间状态可以各自不提升，甚至暂时不满足套装条件；检查的是最终联合状态，而非分步提交。
同时考虑同形状槽位交换与卡带/驱动联动，不只在固定卡带上微调。

采用明确数值误差策略、确定性同分选择和去重，防止循环。预算、取消或定义邻域内无改进即停止。
三件以上邻域、更多随机重启或更大候选池，仅在小库存误差分析证明有收益时增加。
最好可行解给出的是当前目标的下界，不是全局最优证明。

## 4. 结果诚实，比过早证明最优更重要

结果至少分开表达以下语义；这是设计约束，不提前增加 RPC 字段或枚举：

| 维度 | 应说明什么 |
| --- | --- |
| 目标身份 | 模型、轴、环境、dataset 与量化范围；结果在哪种假设下有效 |
| 可行性 | 已找到并完整校验的方案；尚未找到；或已证明声明域无解 |
| 终止原因 | 邻域无改进、预算耗尽、取消、完整搜索结束或模型/组件未就绪 |
| 覆盖与证明 | 图纸/候选是否截断，近似搜索或在哪个精确子域内完成证明 |
| 数值 | 同目标下基线与候选伤害；仅有有效上界时显示最优差距 |

预算结束但没找到方案，不等于无解；找到合法方案，也不等于最优。取消不自动保存，
失败不覆盖旧方案，保存仍消费用户确认的冻结预览。

首轮上线前应按模型类型与代表性库存定质量/时延预算：相对小库存真值的差距、相对简单基线的收益、
大库存尾延迟与内存成本一起看。具体阈值在实验后、验收前确定，不先许诺普遍伤害提升或固定耗时。

### 4.1 低配运行约束随算法一起设计

未来求解通过应用任务框架执行，冻结请求、取消、结果投影与保存复用同一套成熟机制。
长搜索和结果恢复均避免阻塞 UI；枚举、邻域轮次和组件等待有取消检查与资源上限，进度更新合并限频，
不让高频日志或事件刷新抵消算法收益。先按单个受控作业验证，再考虑并行扩展。

预算分为可复现的评估次数、运行保护用的时间/内存/并发上限；任何截断都进入覆盖与终止说明。
用低配真机或明确标识的资源受限代理测“等待中仍可交互、取消有反馈、进程有界收尾”，而非只比求解吞吐。
后续质量档位若有实际需求再设计，本轮保持现有界面与流程，不提前堆设置项。

## 5. 后续研究：何时值得做分支定界

只有多起点和组合邻域仍留下实际重要的质量缺口，且能为选定模型构造便宜而有效的上界时再推进。
目标不是为了“精确”引入比用户收益更昂贵的维护成本。

设最好可行解为下界 `L`。对每个未完成分支，构造不低于该分支真实最大目标值的上界，
只有上界不超过有效下界时才剪枝。可以研究放宽 UID 冲突或套装耦合后求最大值，
但逐属性取最大值需要对完整伤害模型的单调性和约束放宽分别证明。
暴击封顶、阈值被动、特殊转化和非单调效果不得直接套用线性界。

上界保守向上、下界保守向下处理数值误差；缺少证明就保留分支。
用 `best + epsilon` 剪掉可能改善分支属于近似精度策略，不是严格最优证明。
全局上界 `U` 必须覆盖所有未搜索图纸、候选和分支；同级组还要覆盖联合 UID 竞争。
在筛选子集内搜索完成，只证明该子集，不证明原始全库存。

有有效 `U` 且 `L > 0` 时，可报告绝对差 `U-L` 和相对差 `(U-L)/L`；缺上界或非正下界时不编造相对差。
先在小实例逐分支穷举核对上界，再谈大规模加速。若有效界过松或评估太贵，保留近似方案是合理结果。

## 6. 本轮只保留必要的接入边界

正式计算继续由独立 `nte-analysis-core.exe` 承担，Calc 保留输入冻结、图纸准备、响应校验、投影和保存。
后续真实实现须经正式组件版本、清单、能力与协议接入，不在 Calc 加第二套 Python 生产求解器。

框架本轮可以基于现有加权计算、后台读写和结果展示补足任务/上下文/错误投影等共性，
这是为已经存在的业务建设基础，不以未来伤害求解作为创建空抽象的唯一理由。
相关旧修复代码先归并到完整计算流程，关键身份、取消、缓存及协议边界用中文说明；
这些通用约定只在[架构方案](architecture-renewal.md)维护，未来求解按同一约定接入。

- 已有未来目标占位若展示，明确禁用和未就绪；若没有入口，本轮只留文档，不为占位增加 UI。
- 请求遇到未实现目标明确报告缺口，禁止静默使用权重结果冒充伤害结果。
- 复用现有能力和请求门禁；只有实际组件方案确定后才扩展目标/模型身份及响应语义。
- 数据库 schema、组件清单、协议版本、部署和用户基础权重在本轮保持原样；求解器接口等待真实调用需求再设计。

占位在本轮的最小交付就是这份输入/算法/证明边界备忘，以及对既有入口“未就绪”语义的核对。
不添加返回空结果的搜索类、模拟伤害数字、预留数据库列或未被使用的通用策略注册器。
以后有正式实现时再定义窄协议；现在只让框架承接已存在的加权业务，不让未来功能成为额外复杂度的借口。

## 7. 将来如何验证与继续

| 实验 | 核对点 |
| --- | --- |
| 小库存完整穷举 | 目标数值、最优值、合法性与布局全集；穷举原始合法域而非筛选池 |
| 非线性反例 | 暴击上下限、套装门槛、属性转化、卡带联动及两件分别无益而联合改善 |
| 支配删除反例 | 较弱物品因 UID 容量、同形状多槽或多人竞争而仍必要 |
| 多起点/筛选消融 | 与简单权重起点、单件搜索比较质量及成本，确认复杂度确有收益 |
| 优先级与同级组 | 前序目标保持、同分预留、联合竞争、组内失败隔离；目标单位定义一致 |
| 预算与取消 | 确定性评估预算、时间上限、没找到方案、覆盖截断及取消后无写入 |
| 低配持续响应 | 主线程长尾与最大停顿、进度限频、峰值内存、任务并发、取消反馈与收尾分别计量 |
| 上界研究 | 每个小分支的界不低于其真实最大值，误差策略符合声明 |
| 集成与复现 | 同冻结输入可追溯；协议异常与未知保留；基础分、历史方案及原始战报不变 |

顺序是：完整目标和小库存真值 → 最简单可行基线 → 多起点/组合邻域 → 质量与成本评估 → 正式组件接入；
精确搜索可以长期作为研究项。扩大到同级组前另行确认收益聚合，扩大到更多角色模型前逐个确认完整性。
当前无需决定具体库、类名、协议枚举或“全局最优”发布时间。
