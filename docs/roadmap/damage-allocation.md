# 直伤优先与战报轴伤优先：计算逻辑与调整方案

本文记录维护者确认的目标、有限搜索的决策依据和实施证据。第 1–7 节解释模型与约束，第 8 节是可继续调整的策略要求，
第 9.1 节记录交付核对，第 10 节保留 Rust 覆盖审计，第 11 节明确必要验收及历史证据范围。
已交付行为唯一见[功能说明](../features.md#计算结果后处理)，协议/进程职责见[集成说明](../integrations.md#12-分配结果后处理作业)。
公式引用[伤害计算索引](../reference/damage-calculation.md)和[固定轴反事实](../reference/damage/replay-and-buffs.md)，不在本方案再维护一套公式。

## 1. 两个策略分别解决什么问题

| 项目 | 直伤优先 | 战报轴伤优先 |
| --- | --- | --- |
| 输入 | 固定库存、角色与原优先组 | 相同分配输入，加明确选择的冻结战报 A |
| 目标 | 自身元素、100% 攻击倍率的标准期望直伤 | 同一冻结事件域的全队期望反事实伤害 |
| 装备数值 | 基础计算的满级主词条口径 | 实际品质、等级及真实主/副词条 |
| 适用 | 没有合适战报时比较攻击/暴击/增伤组合 | 围绕自己选定的战斗轴配装 |
| 不承诺 | 真实技能循环、辅助价值或所有机制的实战输出 | 新操作轴模拟、全场采集完整或全局最高伤害 |

两者只在原角色优先 B0 副本上优化，不改变基础权重、原基础评分或原始战报。
基础分低但目标收益高的合法候选仍应可用；评分不是后处理目标，也不是已证明的剪枝界。

## 2. 总流程与三份基线

- **A**：用户选中的原始战报或已启用编辑副本，只供轴伤使用。
- **B0**：本次完整角色优先基线；轴伤先固定 R，再只为 S 生成方案，与 R 合成完整队伍。
- **Bk / Bbest**：当前已接受结果/已确认最好结果，试算不改持久事实。

一次 Rust 作业内完成图纸、基线、落位和搜索；队伍/来源预检先行，保存另行复核冻结边界。
策略提升始终比较 Bbest 与同一 B0；相对原战报 A 的变化是另一种对比，不能混用分母或把反事实反复当实测连乘。
具体调用与保存流程链接上述集成说明，不另维护第二份时序。

## 3. 库存、保护和候选规则

### 3.1 哪些装备能用

候选来自原角色优先允许的完整冻结库存。计算配装锁、固定 R 和本次正式预留有效，
游戏防误弃置锁、未参与/未就绪/预算截断角色的未锁定旧方案不增加排除条件。
本次 Bk 其他成员的 UID 不是空闲候选，只能通过完整合法联合动作交换/补位；不能拿走后留下虚拟缺口。
预览不改旧方案，保存才统一事务借出、补入占位并保留历史。实际边界以功能说明和仓库契约为准。

### 3.2 哪些约束保持原样

套装目标、品质、正式形状/方向、主词条硬过滤、黑名单硬禁用、暴击上下限和 UID 唯一性不放宽。
B0 的合法主词条软回退保留冻结来源，后处理不新增回退；词条排序、评分门槛和零权重不升级为额外硬禁用。
换图纸仅在声明的冻结集合、套装模式和禁用格内进行；任意跨套装及三角色以上循环交换不保证覆盖。

## 4. 直伤优先：目标和搜索

### 4.1 当前目标

由同一 Rust 面板核消费冻结原值，使用攻击力缩放、100% 倍率、自身元素及固定标准环境。
标准环境为比较假设，不是实测敌人；准确参数、单位和模型版本以执行输入/结果为准。
连续期望口径不同于轴伤逐击取整再加权。每次完整投影从共同事实重建，不在前轮面板累加误差。
模型内暴击封顶与请求暴击上下限分属期望计算/合法性两个层次。
生命/防御缩放、条件弧盘、DOT、环合、队伍增益不因选择此指标而自动支持；必要来源缺口保留未就绪。

### 4.2 一轮怎么决定替换

在预算内比较完整扫描任务的单件、双件、交换/补位与图纸动作，以完整目标决定是否接受，
不直接采用基础分或动态排序第一名。严格改善且全部约束成立才原子接受，之后失效旧增量缓存、更新占用再扫描。
相等保留当前方案；未完成任务的临时最好结果不发布，覆盖及截断状态随结果保存。

### 4.3 多角色 / 同级组

同级目标使用各成员相对初始 B0 的收益率，不相加不同角色的绝对指标；具体接受/跨组规则见第 8.1–8.2 节。
缺模型、非有限值或非正分母使整组未就绪，不删缺员重算平均；其他独立组仍可继续。

## 5. 战报轴伤优先：固定什么，重算什么

### 5.1 先选轴，再构造基线

明确报告、半场/时段及 A，正式四人 T 中选择非空 S，固定 R。队伍证据及预留须先于 B0 闭合，规则见第 8.3–8.4 节。
固定的是动作、命中、时间、目标与已观测事件，不生成新攻击、治疗、死亡或操作轴。
装备改变且已建模的面板、Buff、机制和派生结算重新评价，未闭合机制报告缺口而非补造事件。

### 5.2 目标与暴击

完整冻结域的期望反事实与已证实联动只聚合一次；固定成员装备不变，其受影响伤害仍重算。
普通暴击消费逐击有效暴击率，固定暴击使用正式值，不可暴击渠道不消费暴击属性；
普通/暴击金额依正式逐击规则分别取整再加权，不用原实测运气直接评选候选。
暴击触发影响后续状态仍需相应模型，单击期望公式不自动闭合整轴状态变化。
选一人或多人的目标相同，不截取个人伤害，也不重复相加各人的重叠整轴。

### 5.3 不完整数据如何处理

`complete/partial/unavailable/not_applicable` 分开，自动接受须完整量化或证明无关。
采集覆盖、冻结读取完整、变化量化完整是不同状态；已声明观测域可比较，但不伪称真实全场。
显式残缺/未结算、正式身份未知、S 的基线或来源缺口不通过缩小目标范围伪造成功。
取消、账号切换、来源过期和保存复核失败都不写新状态，原始事实保持不变。

## 6. 有限搜索、排序与预算

### 6.1 已做与尚未做必须分开

完整候选评价决定接受。当前轴伤的单件真实增量用于访问顺序，接受后失效；这不是逐属性动态权重或有效上界。
逐属性差分权重、暴击上界剪枝可继续研究，但零边际、暴击已满或基础分低不能单独证明候选无用。
只有证明分支全部合法完成状态的上界不优于已知解，才能称为保优剪枝；Top-K/分桶限制须如实记为启发式截断。

### 6.2 当前服务默认预算

| 路径 | 评价次数 | 轮数 | 事实源 |
| --- | ---: | ---: | --- |
| 直伤作业 | 20,000 | 100 | `execute_damage_job` |
| 轴伤作业（队内任意非空子集） | 1,024 | 100 | `execute_damage_job` |

调用方可传预算，后续数值以代码/本次冻结输入为准，不是完成时限或性能承诺。
图纸节点/组合/输出、搜索访问/评价/轮次与时间分开计量。原进程超时内最多预留 1 秒交付终态结果，不重开搜索。
首扫未完成且无已接受改善只留 B0，不提供优化保存；只要基础方案须切回角色优先重算。

## 7. 结果展示与保存

展示目标、相对 B0 提升、原因、覆盖及停止状态；基础分和目标分开，不按新权重解释旧预览。
保存绑定最终装备、角色投影、基础分、组件/模型、预算、轴来源和原生坐标。冻结边界失效时重新计算，不读取最新状态补齐。
跨角色交换及其同级组关联必须一起保存；固定构筑依赖、未保存组的 B0 假定、借出事务和历史保留按功能说明执行。

## 8. 本轮确认的目标方案

本节要求已按第 9.1 节落地。维护者后续调整从本节修改目标，经过实现/验证后覆盖功能说明，不让旧阶段描述充当当前规则。

### 8.1 直伤：统一 100% 攻击倍率，同级组按提升率

- 所有角色统一使用 `skill_multiplier = 1.0`、攻击力缩放、自身元素和同一标准敌人环境。
  100% 是攻击倍率，不是 100% 暴击率；仍按各自暴击率、暴伤和支持的增伤乘区计算期望。
- 保留第 4 节的标准环境、连续期望及数值口径；不随角色技能等级、生命/防御缩放或实战轴切换模型。
  此指标用于装备选择，不承诺衡量辅助价值或所有角色的真实输出。
- 同级组继续使用 `J_group = mean(F_i(B) / F_i(B0) - 1)`。分母固定为各自初始 B0，
  不随交换或轮次变化；同级组争用驱动比较组目标提升，不按角色绝对伤害大小分配。
- 保留当前各成员不低于初始 B0 的边界，防止牺牲一人的基础方案换取另一人高提升。
  缺模型、非有限值或非正分母按未就绪处理，不剔除该成员后重算平均。
- 跨优先组交换建议沿原角色优先采用词典序比较各组目标：首个发生变化的组必须改善，
  后面的组不得把前面组已获得的收益换走；各成员仍守 B0 下限。这是落地细则建议，需维护者审阅，
  不是把全部角色合并成同级组。组内沿现有并列规则，最终按正式身份稳定打破平局。

### 8.2 共同搜索：预算内允许交换和换图纸

目标是扩大邻域，而不是枚举全库存的所有角色配装笛卡尔积。一次作业内部由 Rust 维护完整 Bk、候选池和 UID 占用。

1. **候选来源**：完整冻结库存，沿原角色优先的品质、套装、自选词条及锁 contract；
   基础分低、游戏内防误弃置锁、未锁定旧计算配装都不得额外淘汰正常候选。
2. **单件和同成员双件**：保留已有邻域，先取得便宜的改善。
3. **跨角色交换**：先支持两个可优化角色的原子交换，以及预算内交换后的必要补位。
   整个动作验证后一起接受；不得先拿走别人的装备再期待后续补齐。三角色以上循环交换暂不保证覆盖。
4. **换图纸**：在角色冻结的套装、套装效果模式、棋盘及形状规则内，枚举不同合法图纸，
   为新图纸重新匹配完整驱动，并联合检查卡带兼容性。不是只修改图纸标签，也不是擅自更换用户指定套装。
   单角色换图纸可以使用空闲装备；涉及另一角色已用装备时必须组成完整联合动作，计入交换预算。
5. **选择与接受**：每轮在实际评估到的合法动作中选目标改善最大的动作；直伤按 8.1，轴伤按 8.3。
   接受后更新全局占用，重算受影响候选的真实收益，继续搜索。旧增量只可用于排序。
6. **停止**：可用邻域一轮完整扫描均无严格改善，或评价/枚举/轮次/时间预算耗尽，或取消、身份失效、量化缺口。
   平分动作不来回交换；保存已确认的最好完整结果。取消或身份失效只丢弃本次任务，不提交半成品。

预算同时约束候选生成节点数、图纸数、联合动作数、目标评价次数、轮数和总时长；不要只限制最终评价，
却让图纸枚举先跑到失控。单件、交换、换图纸各预留访问份额，支持未使用额度转借，并共享总预算。
重复完整状态按装备 UID、布局和模型身份去重；缓存必须绑定冻结输入，接受动作后失效相应增量缓存。

同级组驱动提升率排序和轴伤局部边际均只作访问顺序；未经有效上界证明，不得以局部收益为负剪掉联合改善。
启发式 Top-K 应记为搜索截断，而非“装备不合法”。暴击封顶、套装切换、双件互补必须进入相关反例。

**计算量判断**：任意交换、换图纸和全局穷举组合会迅速膨胀；有界邻域可以控制工作量，但 Rust 本身不会消除组合爆炸。
本方案不预设新的数值预算或秒数承诺，沿第 11 节代表性库存/轴实测调整。总预算包含失败候选与基线开销，
进程启动、传输及取消收尾另记耗时；截断时列明未扫完邻域，不宣称全局最优或完整局部最优。

### 8.3 轴伤：全队总收益，支持只优化部分队员

定义 `T` 为所选冻结轴对应的正式四人队伍，`S` 为本次选择优化的角色，`R = T - S` 为固定成员。
必须满足 `S` 非空且 `S ⊆ T`。选一人、两人、三人或全队使用同一个全队目标：

```text
J_axis(B) = F_T(B | A) - F_T(B0 | A)
接受动作：完整量化且 F_T(Bcandidate | A) > F_T(Bk | A) + 数值比较容差
```

- `F_T` 是同一冻结事件域上的全队期望轴伤，不是个人提升率平均，不按计算页同级组拆开寻优，
  也不重复相加重叠的个人影响域。同级组/角色顺序仅可影响基础方案或确定性访问顺序。
- 可以接受 S 中某人的个人伤害下降，只要全队总伤提高；不沿用直伤的每人 B0 收益下限。
  装备合法性、配装锁和来源完整性仍是硬边界。
- **R 的装备、图纸及槽位保持不动，但伤害仍参与重算**：例如 S 中辅助换装增强队友 Buff，
  R 的装备不变，其受影响伤害应随完整轴模型变化，不能把 R 的伤害总额简单视为常量。
- 固定成员默认沿当前轴语义使用用户选定 A 的冻结装备/图纸/养成，来源在确认界面明确展示；
  不读取实时游戏装备或未指定旧方案替换。若未来支持另选固定基线，须显式选择并整体冻结。
- **在生成 B0 前先固定 R 并预留其真实 UID**，只对 S 调用原角色优先生成合法基线，然后与 R 组成完整队伍 B0。
  不可先让基础分配改掉所有人，再声称后处理未改 R。该限制通过冻结请求传入，不改上游求解规则。
- S 内允许预算内交换和换图纸；不从 R、锁定方案或其他正式保护对象借装备。
  R 的占用属于这次明确的“保持不动”，不能扩大成保护所有未锁定旧方案或游戏内锁。
- R 的真实装备身份若无法与冻结库存可靠关联，应提示缺口并阻止本次优化，不虚构 UID，
  也不按显示名猜装备或默默解除固定。仅保证搜索目标在声明的观测域内，不把固定轴当作新操作轴模拟。

### 8.4 队伍选择与弹窗拦截

校验时点：选定战报/半场/时段及 A 后、启动基础分配前。以正式角色 ID 检查完整 S，不只检查下拉框当前角色。

- 若存在 `S - T`，弹窗列出队外角色并说明“轴伤优先仅优化所选战报队伍，请移除这些角色或更换战报”；
  返回配置，不开始计算、不静默过滤、不退回直伤/角色优先。
- 从正式冻结队伍证据确定 T，不以“有伤害记录的角色”推断全部四人；无出手的队友仍属于队伍，
  召唤物/代执行实体按正式归属处理，不作为第五名队员。
- 跨半场、跨时段队伍不同，先要求选择队伍稳定的范围；不把两半队伍并集当一个四人队伍。
  队伍身份或固定成员来源不足时具体提示缺口，禁止猜补。
- 前端负责可读提示，应用服务和 Rust 请求入口重复校验 `T/S/R`、UID 预留及来源身份，避免绕过 UI。
  用户改选择后重新冻结请求；不在已有预览上补换队伍。

### 8.5 Rust 计算边界

这两种策略的正式计算链目标为 **Rust 一次作业内完成**：评分、属性/装备贡献投影、图纸生成与摆盘、候选生成/合法性、
角色优先基线、标准直伤/轴重算、组目标、交换/换图纸、动态排序、缓存、剪枝和预算计数。
统一倍率是分配策略模型参数，不修改其他页面真实技能公式。既有 ScoringEngine 的公开语义保持，
迁移后作为无公式适配入口消费同一 Rust 评分，不再长期维护两套生产公式。

Python 保留账号与数据读取、冻结请求、正式身份和协议校验、进程生命周期/取消、UI 与原子保存；
展示格式、哈希、SQL、集合一致性检查不属于另建计算算法。边界校验继续保留，但重复基础分重算等数值逻辑
应收敛到 Rust 公共核，不以“校验”名义长期保留 Python 数值实现。最终结果须携带版本化模型与冻结身份。

不要逐候选跨进程 RPC：成批发送冻结事实，Rust 内部复用同一模型与缓存，返回结果和覆盖信息。
缺所需能力时明确提示更新组件，不静默转回 Python 搜索。Rust 源码改动归独立分析工作区，Calc 只消费成套组件。
第 10.2 节中其他功能的 Python 计算属于后续迁移审计项，本轮没有顺手迁移整个项目的授权。

## 9. 实施顺序与交付核对

1. 先用公共行为用例固定第 8 节目标、队内子集、固定成员来源和原子交换语义；跨优先组细则由维护者审阅。
2. 给正式 Rust 请求补齐 T/S/R、冻结棋盘/形状、模型参数和分项预算；版本化协议，不给旧组件伪造新能力。
3. 将当前链上的 Python 图纸枚举/摆盘、数值投影及重复评分收敛到 Rust 公共核；逐项验证与原行为一致，
   再让新后处理消费同一内存模型。基础角色优先规则保持不变，避免迁移与策略调整互相掩盖偏差。
4. 先落实统一直伤口径、轴伤全队目标与子集保护，再接入双角色交换和换图纸；每项有预算、取消及原子接受边界。
5. 经明确测试授权后，只先跑新反例及受影响边界，复用既有入口衡量收益、评价次数、耗时和取消。
   确认正式调用已迁移后删除废弃计算入口，不因存在旧 Python 文件就直接删掉其他功能依赖。
6. 独立分析组件按清单与哈希成套交付；证据闭合后更新 features、架构及必要契约。第 11 节发行门禁另行执行。
