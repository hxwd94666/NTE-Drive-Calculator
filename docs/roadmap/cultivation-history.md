# 养成历史与材料录入：开发契约及剩余验收

## 1. 状态、范围与事实源

源码已接入历史、材料准备和相关专项；本轮已运行部分养成检查，但完整领域验收尚未闭合。
既有执行结果按[架构验证记录](../validation/architecture-renewal-day1.md)和本轮实际专项范围保留，
不再沿用“尚未收到测试授权”或“所有新增测试均未执行”的旧结论，也不据此宣称功能全部交付。

本文保留仍需完整兑现的产品契约；已交付行为归[工具功能](../features/tools-and-catalog.md)，
材料、合成与体力算法归[养成体力规划](../reference/progression-stamina-calculator.md)。
整体开发、测试授权和复审顺序见[当前复审方案](architecture-post-refactor-review.md)。

本任务同时完成三件事：保存完整工作配置与轻量历史合计；同一草稿重算更新同一记录；
提前准备已有材料输入，并提供跨页选择及确切集合删除。只完成其中一项不代表全部完成。
不保存完整结果页面或求解过程，不新增版本管理平台、自动淘汰、回收站或未计算草稿持久化。

## 2. 保存什么

### 2.1 完整编辑配置

| 字段组 | 必须保留的内容 |
| --- | --- |
| 模式与角色 | 单/多角色、正式 `character_id`、稳定 `line_id`、顺序、当时展示名 |
| 人物与技能 | 当前/目标等级、突破、参与开关；技能使用正式 `skill_id` |
| 弧盘 | 正式 `fork_id`、名称、当前/目标等级与突破、参与开关；关闭模块仍保留编辑值 |
| 公共设置 | 猎人等级、生效鉴别等级、全部/仅体力展示偏好 |
| 已有材料 | 正式 `item_id`、原始数量、手工覆盖标记、来源类别及必要观测时间 |

隐藏或暂不相关材料仍保留在草稿里；未填写与显式手填零不同，零也属于手工覆盖。
不保存控件、焦点、滚动坐标、整背包或图片。有效计算请求未必包含关闭模块的编辑值，不能直接代替完整配置。

### 2.2 轻量、可独立查看的结果

- 按正式材料 ID 合并的总需求、有效抵扣、仍需、当时名称及“仅体力”冻结分类。
- 原始持有量从配置读取，不拿不同档位件数直接相减。例如低档 6 件上合抵扣高档 2 件，保存两个不同量。
- 合并体力的完整/部分/不可用状态、已知值、可空的完整值及缺口码；未知不填零。
- 合并副本的正式档位 ID、当时名称、次数、单次与总消耗、来源类别。
- 每角色简短状态、体力解释和缺口摘要；合并体力不是逐角色值相加。
- 可携带的 dataset、schema/importer、算法与正文格式身份，不包含本机绝对路径。

历史只承诺这些合计及摘要，不保存各模块重复材料表、完整来源账本、候选副本或静态库。
详情只读冻结值；完整当前明细需加载配置后重新计算，不能将历史结果静默更新为当前资料下的结果。

配置与结果来自同一计算信封：开始前冻结账号、generation、dataset、草稿 ID、请求修订及完整输入，
接受结果后复核，再单事务保存；回调不重新读取已经改变的控件。

## 3. 草稿、保存和失败

每个单/多角色模式各有运行期 `draft_session_id`，不同于账号代次、角色 ID 和请求号。

| 动作 | 历史行为 |
| --- | --- |
| 草稿首次有效计算 | 新建一条，保存配置与结果 |
| 修改目标、技能、弧盘、档位或已有量后有效重算 | 更新同一条，不为中间编辑堆积历史 |
| 信封与输出完全相同 | 不重复写入、不刷新计算时间 |
| 只编辑，或计算失败、取消、过期、半成品 | 保留上次有效记录，不用新输入配旧结果 |
| 重置、单角色改选角色、多角色清空后重建 | 新工作草稿，原历史保留 |
| 多角色只增删或修改部分目标 | 仍更新本草稿；不按角色集合跨草稿去重 |
| 切模式、返回工具再进入 | 各模式会话草稿继续，不因导航新建记录 |
| 加载历史 | 克隆新草稿；之后计算新建记录，不覆盖源记录 |
| 重启、账号或 dataset 变化导致页面重建 | 结束旧草稿，保留历史 |

浏览、展开或切材料范围不求解、不写历史；展示偏好随下一次有效计算保存。
同草稿从目标 60 级改到 70 级会更新原条；要比较两份方案，应先加载原条为新草稿再编辑。
尚未计算的材料输入退出后不保证恢复。含明确资料缺口但可展示的有效计划可以保存；异常半成品不保存。

结果接受与持久化完成分开：保存排队时显示正在保存，提交后才标为已保存。
保存失败保留计算结果和旧行，首条失败不建空行；窄重试绑定原信封，账号或草稿变化撤销重试。

## 4. 材料提前准备与低配性能

共用 Qt 无关的材料准备入口返回需求及可上合输入目录，沿既有 Controller 防抖、末次请求与单任务 owner：

1. 目标稳定后，按冻结 dataset 准备材料及“仅体力”分类；多角色复用相同材料服务并合并，不运行体力优化、不写历史。
2. 准备中显示具体状态；可展示需求，不将它标为最低体力已计算。玩家先填写或显式同步已有量。
3. 正式计算冻结输入，一次完成抵扣、合成、共享材料分配和体力求解，再接受结果及保存历史。
4. 用户在准备结束前点击计算时，同一个 owner 串行处理最新正式请求；复用匹配结果或调用同一准备入口，不启动平行公式/任务。

只缓存本草稿最近一份不可变准备结果：键含账号/代次、dataset、人物/技能/弧盘的完整有效目标及参与开关。
已有数量不进需求缓存键，但必须进入正式请求；仅改数量时复用成本和目录，重新抵扣并求解体力。
目标变更使需求失效，猎人/鉴别变化复核副本条件，dataset/账号/新草稿使全部缓存与旧任务失效。
准备和正式结果分别绑定修订，旧回调不覆盖新目录；程序性更新控件不冒充用户编辑。

目录刷新仅改变展示，按正式 ID 保留数量、来源、覆盖标记，新增项未填写，隐藏项不清零；
抵扣只消费当前目标及资料相关材料。同步未观测项仍未知，手工覆盖优先级不变。
目标/数量变化立即使旧正式结果和复制入口失效，准备完成不解除过期状态；仅接受新正式结果后恢复。
准备失败保留输入，正式计算可沿同一服务重试；必需静态数据缺失使用既有缺口语义，不伪造总量。
SciPy/HiGHS 继续位于可重启独立进程，不搬入 GUI。单角色换角色清草稿的既有行为不用于历史恢复；恢复走专用原子入口。

## 5. 历史列表、详情与加载

### 5.1 查询和选择

“历史记录”入口位于重置与复制清单之间。顶栏为返回计算、全选、取消全选、删除所选、已选数量；模式及搜索靠右，
不再添加第二行选择工具或重复小标题。列表按最后有效计算时间、ID 稳定倒序，列为选择、完整本地时间（到秒）、体力、角色配置。
选择/时间保留必要宽度，体力紧凑，角色列占剩余空间；行高适应字体，长名单单行省略且悬停/详情可看全量，不截取前三角色。
角色按原顺序显示为“角色甲（弧盘甲）、角色乙”，关闭弧盘参与也显示已选弧盘，等级与技能明细不堆进列表。

按模式及冻结角色/弧盘名称搜索，复用原文、全拼、首字母、忽略大小写的名称规则；不读取当前角色页改写历史。
DAO 内逐条有界投影和连接内有界匹配缓存，查询、计数、分页、全选使用同一条件，不读取结果正文、不建全局 payload 缓存。
无筛选只读取当前页所需摘要和有界配置；旧记录不因新搜索迁移正文、哈希、修订或时间。
畸形配置仅使用有界旧角色检索字段，不猜弧盘；仍可无筛选浏览与按 ID 删除。

### 5.2 只读详情

- 列表/预览初始约 45%/55%，可拖动；后续选记录、切范围、重新进入不覆盖用户比例。
- 预览工具栏左侧为蓝色合并体力，右侧为范围与加载配置；未选、筛选变化或删除后清旧数值。
- 配置卡占整行且与材料/副本同宽，首个角色展开、其余折叠；保留当前/目标、突破和模块开关，未参与明确标识。
  同级技能合并范围与数量，否则按保存顺序显示；没有冻结技能名时不猜当前名称。
- 材料展示图片、名称及纵向总需求/有效抵扣/仍需（加粗）。空间足够每行五项，窄屏/大字体减少列数，数值不遮挡；
  长名悬停提供全文及三数量，键盘能选到末项。模型/委托绘制及有界图片缓存保留，不逐项创建子控件。
- 展开材料按范围显示全部行，无三行限高或内层滚动，外层统一滚动并确保键盘目标可见。
  图片仅从受管目录按材料 ID 读取，缺图占位；历史不携带图片路径或字节，图片不补造旧事实。
- 全部/仅体力使用冻结标记，完整体力只显示一份合并值；未知时标明合并已知值和完整值未知，缺口保持可见，副本建议默认折叠。
- 不重复显示“历史预览”、配置时间、猎人/鉴别等级、只读说明、“原始已有材料”“更多信息”分区或常驻加载解释；
  这些必要输入与身份仍在正文。底部只在进度、失败或结果需说明时出现，正常浏览不占行。

### 5.3 加载到新草稿

查看旧合计不依赖当前目录仍有角色/副本；名称和数字用保存值，缺图占位。
加载原样恢复人物/技能/弧盘的当前值、目标、数量、来源及覆盖标记，不自动同步；提示“已加载历史配置；当前状态与材料数量请确认”。
读取最新当前值是另一个显式动作，入口仍待确认，不在加载中暗改输入。

先校验结构、正式 ID 与等级范围，再整体替换；缺角色/技能/弧盘/材料或范围失配时列出问题并保留原页，
不自动跳过、按名称猜测或夹取等级。dataset 不同但输入合法时可加载，后续只用当前一套完整资料重新计算。
恢复停止旧排队重算、屏蔽控件中间信号、清除当前结果，等待点击计算；旧历史结果只留详情。
多角色保留顺序，为克隆后的各行生成新 `line_id` 并保留对应关系，避免与旧控件/请求冲突。

## 6. 确切集合删除与防复活

选择跨页保留，换筛选清空，翻页不清空。“全选”取得当前账号当前条件全部匹配 ID/修订号，包括跨页而非仅本页；
全选后新增记录不进入集合。只读取身份，不为选择加载全部结果 JSON；有界后台 owner 显示忙碌并拒绝重复提交，资源不足不退化为只删本页。

确认前冻结账号、generation、ID/修订号和数量，提示删除配置与当时结果、保留当前草稿/角色/背包；默认取消并使用统一警告及提示音。
确认窗口不持写锁；确认后 Service 复核身份，DAO 参数化 SQL 在单事务内分块删除确切 ID，不重跑筛选扩大集合、不无条件 DELETE。

- 已被删记录幂等处理；修订已更新则整批保留，刷新并重新确认，不能悄悄换成新版本。
- SQL、校验、取消或账号失效在提交前导致整批回滚；提交后晚到取消不假称恢复。成功提示实际删除数，清空选择、详情及加载入口，页码重新限位。
- 迟到详情不重新展示旧选中项；坏详情仍可按合法 ID 删除。排序、同名和行号变化不改变对象。
- 首次保存明确插入，后续使用 ID/预期修订条件更新；零行更新不 upsert 补插。新 ID 永不复用。
- 删除成功关闭该 ID 的保存绑定，撤销排队写入与重试；旧计算结果可以继续展示，但不重建已删历史。
- 当前草稿及有效结果保留，自动重算抑制历史写入；只有删除完成后新提交的主动计算能建立新绑定/新 ID。
  主动/自动来源在提交时冻结，删除前的旧主动请求不因晚到变成“新主动计算”。
- 同账号窄服务协调写入与删除顺序，DAO 条件更新作为末端保护；删除不改既有导出和升级备份。

删除是逻辑删除，不保证介质擦除；空闲页、WAL、独立备份可能留有字节，不为此运行 VACUUM、删 WAL 或重建账号库。

## 7. 容量、分层与数据安全

同草稿更新和完全重复不写是首要容量控制；保留合计而非重复明细，不另建压缩格式，不按天数/条数自动淘汰。
列表默认每页 20 条，选择后才读完整详情。正文合计保护预算以正式模型为准（当前 4 MiB/记录）；
超限保留计算结果并报告历史失败，不截断角色、材料或缺口，不只保存一半。
必须测量单角色、常用多角色和当前完整正式目录的 JSON、数据库增量及 WAL；合成估算不是实测，删除后文件也未必缩小。

| 责任 | 当前入口与边界 |
| --- | --- |
| 纯模型/格式 | `src/domain/progression/history.py`；显式配置、信封、快照、摘要与版本 |
| SQLite | `src/storage/sqlite/progression/cultivation_history_dao.py`；追加迁移、条件更新、分页、确切集合事务删除 |
| 业务 | `src/services/progression/history_service.py`、`history_adapters.py`；账号、保存绑定、兼容校验、快照与重试 |
| 页面 owner | `src/features/toolbox/cultivation/` 的历史 Controller、绑定与草稿适配；修订、取消和迟到结果 |
| 组合根 | `src/ui/toolbox_composition.py` 注入窄服务；账号切换关闭旧 owner 后重建 |

历史使用账号独立表，记录不可复用 ID、模式、修订、首次/末次 UTC 计算时间、格式、配置/结果、列表摘要与必要索引。
不建立静态角色/库存快照/物品归档的级联删除关系。generation 只作运行期门禁，不持久化为未来加载身份。
不新增平行 SQL、公式、调度器或巨型页面；触及代码按责任收敛并遵守行数门禁。

JSON 按白名单序列化，不对含路径/图片对象直接 asdict，不使用 pickle/动态执行；解析前限字节，解析后限深度、集合，
校验版本、未知字段、重复 ID、整数类型与范围，负数/冲突报错，零和未知分开。名称不转成 SQL、路径或执行内容。
摘要也校验版本、类型和体力状态；一条损坏只显示该条异常，保留选择/删除能力，不阻断整页。
忙碌沿 DAO 有界策略处理，不阻塞 GUI、不换冻结输入、不兜底写共享库。

迁移只追加，覆盖新建、旧库、失败回滚与重试；升级前按 DAO 策略一致性备份，不复制活动 WAL/SHM、批量清理备份或混入默认导出。
代码回退不等于数据库回退：需要恢复时停止账号任务，再用升级前备份。历史随账号库导入导出，不附图片、日志、截图、凭据或整份采集归档。
坏/新版正文明确隔离，不覆盖其他有效业务数据。日志仅记生命周期、数量、错误码与耗时，不输出配置/姓名集合/材料/结果全文。

## 8. 收尾与必要验收

沿已接入实现继续，保留已有检查，不重建整套验证平台。以下要求全部保留，完成后将已验证行为移入功能文档，路线图只留余项。

| 验收组 | 必须确认的后果 |
| --- | --- |
| 保存与格式 | 单/多角色、关闭模块、顺序/ID、显式零/来源完整往返；同草稿更新与原子输入输出；失败/迟到不覆盖；删除后不复活 |
| 材料与计算 | 三合一与经验材料区别、共享材料一次消费、合并体力唯一；部分/未知不伪装完整；准备不求体力不写历史，数量变更复用、目标/资料失效 |
| 加载 | 原样恢复关闭模块/技能/弧盘/材料，恢复期间无完整求解；点击后一个有效任务；缺 ID/范围冲突保留原草稿；旧结果可独立看 |
| 删除与账号 | 跨页全选、修订冻结、新增保留、冲突整批回滚、已删幂等、晚到回调、主动解除抑制；准备/求解/确认/写入期间换账号不串写或刷新 |
| 持久化 | 新建/旧库迁移、失败重试、一致性备份恢复、临时账号导入导出、坏记录与摘要隔离 |
| 容量与体验 | 正式全目录容量实测；大列表、长名单、三主题、键盘/确认、屏幕及混合 DPI、求解期间滚动可操作 |
