### 1. 摘要与推荐决策

目标是回答：在当前四人阵容、同一段轴和环境下，如何选择合法养成与装备词条，使整队伤害最高，以及当前方案距该目标还有多远。

推荐决策：

1. 队伍主指标采用整队轴伤比例，不再平均四个个人装备直伤毕业率。
2. 保留队伍、配装来源、战报选择、冻结身份、异步取消和历史展示等通用能力；替换其上的毕业指标。
3. 第一批实现即删除旧队伍均值聚合、专属适配/缓存和前端数值；新能力就绪前显示未建立基准，不留旧值兜底。角色页个人装备直伤公式独立保留。
4. 只评价用户选定的当前四人构筑，并求解合法理论毕业目标；本功能不搜索当前库存、不推荐背包内的具体装备替换组合。
5. 分子与分母均使用同口径计算重放；历史实测伤害用于对账，不直接充当毕业率分子。
6. 搜索找到的最佳方案与已证明的全局最优分开命名。缺证据时展示覆盖及搜索限制，不宣称已算出真实上限。
7. 理论目标按定义作为100%标尺，展示其轴伤与养成/词条构筑；不是再求一个独立的“理论毕业百分比”。当前毕业率只有一个分子与一个同版本分母。

#### 1.1 范围收缩

本轮方案明确移除：库存候选池生成、全背包装备组合搜索、跨成员真实装备争抢、借出/回填、库存可达伤害输出及其专属协议、缓存与验收。

### 3. 难度与主要风险

收缩后，已有模型支持且目标明确的首个闭环评估为中高，约6–7/10，低于原完整方案约8/10。以上是工程估计，不是实测指标或交付日期承诺。
下降来自真实库存分配链路退出，以及理论装备可压缩为有限的合法词条预算变量；不是因为百分比公式本身变简单。
推广到全部角色机制、穷举所有养成/弧盘/套装，以及证明全局最优的难度仍高。

| 子问题 | 难度 | 原因与交付证据 |
| --- | --- | --- |
| 页面、来源选择、任务进度 | 中 | 已有组件可复用；重点是显式启动、取消、状态和过期结果隔离 |
| 基准身份与版本管理 | 中 | 需冻结轴、目标、覆盖、静态和引擎，防止分母随用户状态暗中变化 |
| 合法理论构筑生成 | 中高 | 省去实物组合；仍需满足每件词条、品质、几何、套装及总预算约束 |
| 整队联合优化 | 中高 | 变量可压缩，但边际收益仍随属性及团队耦合变化 |
| 条件机制与暴击期望 | 高 | 换构筑后增益数值、触发和可执行性可能变化；历史观测状态不等于新构筑状态 |
| 全角色覆盖 | 很高 | 模型和来源缺项需要逐机制审计，界面完成不代表所有阵容可量化 |
| 全局最优证明 | 很高 | 有界局部搜索没有全局证明；有效上界需要覆盖耦合与分支 |

当养成目标、弧盘、套装和图纸已固定或只允许少量明确预设时，理论词条搜索通常比全背包分配更易控制；若仍要求遍历这些离散选择，组合数会重新增长。
主导成本可概括为“合法候选评价次数 × 单次整队轴重放成本”，加上预处理和校验；尚无实测证据支持固定耗时承诺。
主要风险仍是用不完整模型、错误的必选词条假设或非法理论面板给出精确百分比。先审计代表性输入及机制覆盖，再评估性能。

### 4. 数学定义与用户口径

#### 4.1 固定上下文

- `A`：用户选择的冻结轴范围，含事件顺序、时间、正式角色/技能/目标身份及已观测证据。
- `T`：固定四人阵容，包含零伤害成员；换阵容视为新上下文。
- `E`：冻结敌人画像、环境及用户明确确认的假设，未知值保留未知。
- `P`：不可变的毕业目标约束版本。
- `M`：分析模型、算法、覆盖与暴击口径的版本。
- `X`：四人的养成、装备和词条联合构筑。
- `D(A,T,E,X;M)`：同一计分域上的整队计算重放伤害。

当前指标的合法参数域记为 `F(P,A,T,E)`，指明确养成、装备词条预算、套装及图纸约束；固定观测动作/时点，不搜索新轮转。动作资源可执行性独立表达，不作为这条假设下数学比例的额外门禁。理论目标为：

```text
X* = argmax D(A,T,E,X;M)，其中 X 属于 F(P,A,T,E)
D* = D(A,T,E,X*;M)
轴伤毕业率 = D当前 / D* × 100%
```

这是整队目标，不是个人毕业率平均，也不是个人伤害比值加权。
当轴时长固定且一致时，总伤害比例与同口径 DPS 比例相同；首版统一采用轴总伤害，避免混用时长口径。

#### 4.2 两类计算结果、一个毕业率

| 名称 | 含义与限制 |
| --- | --- |
| 历史实测伤害 | 只读原始事实，用于对账与模型解释，不和理论分母直接相除 |
| 当前方案轴伤 | 当前实际等级、技能和装备在共同模型下的计算重放值；不沿用旧指标的强制满练度归一 |
| 理论毕业基准轴伤 | 自选合法词条、在用户冻结的目标约束下生成的理论方案；作为100%标尺，另附搜索与最优性状态 |

历史实测是可选对账信息，不是第三条求解任务。理论目标卡片显示“理论目标：100%”及其基准伤害、养成和词条，而不是再次计算一个独立比例。
当前养成低于目标是正常的毕业差距，分子照常使用实际养成；目标养成固定为更高等级时，不要求当前方案先达到该等级才计算比例。
示例：当前计算重放140万、理论搜索基准200万，则当前毕业率70%，理论目标标尺100%，尚差60万基准轴伤；若换成该目标，同口径计算的相对提升为约42.9%，并非30%。
页面不出现库存可达伤害或“已有装备换装即可达到”的承诺。建议中的目标装备不代表背包已经拥有。

#### 4.3 有界搜索的诚实命名

设已找到的最佳合法伤害为 `L`，真实全局最优为 `D*`。精确评价下有 `L <= D*`。
有界搜索返回的 `D当前/L` 可能高估真实毕业程度；继续搜索提高分母时，该比例可能下降。
首版不以全局最优证明作为交付硬门禁；理论目标的100%表示所选基准的归一化标尺，不代表已拿到全局最优证书。

- 默认展示“当前搜索基准下的轴伤毕业率”，明确预算、停止原因与已完成邻域。
- 局部收敛仅说明声明邻域内未发现改善，不标成全局最优。
- 若另有经证明有效的上界 `U`，可展示毕业率区间 `[D当前/U, D当前/L]`。
- 上界需对全部目标机制及约束成立；没有证明时留空，不以独立属性全满或经验倍数冒充。
- 只有合法域已完整处理，或上下界满足预先声明的证明精度时，才使用已证明最优的表述。

分母为零、非有限或关键输入未知时不生成比例。已确认的零伤害与未知伤害分别处理。
当前构筑确属目标合法域时，将其纳入初始候选，使该域内的 `L` 至少不低于当前值；若目标固定了另一养成状态，可生成满足目标的对应起点，不预设养成变化对所有机制都单调增伤。
当前使用了目标禁止的弧盘、超出目标觉醒/精炼上限等情况，显示“超出基准条件”；单纯尚未达到目标养成不属于此类异常。比例异常时检查约束、搜索或模型，不靠截断到100%掩盖问题。

已实现一项严格正向见证：实际四人养成、世界加成和逐件装备恰好等于某固定目标预设的合法满值构筑时，经统一词条物化及静态布局复核，将其作为受保护起点优先评价；即使该预设排序靠后、总预算只有一次，也保留这一已知合法下界。所有用户起点仍完整校验并保留，总评价/时间预算不增加，结果证据仍按目标预设原顺序返回。未强化、部分数值、未知坐标、不同养成或世界条件不作满值投影，也不据此判成非法；该窄域见证不替代完整合法域/可执行性判断；是否产生数学比例由显式固定轴策略和同域可比条件独立决定。

核心现已将该正向见证扩展为每个固定预设的三态证据：`member`有逐件合法构筑，`not_member`有足以否定“恰好属于该满值子域”的已知原因，`unverified`保留未观测位置等缺口。证据绑定本次实际输入、目标、规则与已静态验证布局；静态准备与连接释放后才生成，并复用为受保护起点。较低养成/强化或部分词条值可属于`not_member`，但仍是正常比较进度，不等于超出原养成比较条件，更不等于装备非法。缺坐标不掩盖另一成员已知的数值差异；输入重排可改变输入摘要，但不改变物理成员身份。全部固定预设按整队合并：任一整队成员证明成立即属于参数域并集，全部已知否定才否定，否则未证实；未检查实际输入不返回结论，不逐人拼接不同预设。

该精确参数域证据当前只在核心内保存/消费，尚未迁入正式响应、当前更新与保存/UI。既有线协议的养成比较证据仍保留原scope与`exact_domain_membership=not_evaluated`；参数域并集不包括冷却、能量及条件传播等轴约束，不冒称最终可执行合法域已经闭合。

### 5. 毕业目标与合法性

当前比例由独立内核在显式`fixed_observed_axis_ratio_v1`策略下产生，界面只展示已校验结果；当前为零时比例是0%，未知不是0%，超过100%不截断。实战可执行性始终单独提示；100%是选定的有界搜索参照，不是全局最优证书。旧技术字段`current_ratio_percent`仍为空以保持旧历史/数据库契约，本次产品只展示新固定轴指标，不同时维护另一条用户毕业率。格式、能力与旧请求兼容边界见[协议第9节](../reference/team-axis-graduation-protocol.md#9-固定观测轴假设下的比例)。

#### 5.1 目标设置

| 项目 | 默认策略或必须明确的条件 |
| --- | --- |
| 角色等级、突破、技能、好感、家具 | 用户明确选择合法目标；首版按目标或少量显式预设评价，不做多资源预算下的全局养成分配 |
| 觉醒与弧盘精炼 | 默认冻结建基准时配置；允许用户显式设目标或上限，不默认要求全满 |
| 弧盘与装备套装 | 明确固定选择或允许的少量预设及数量假设；扩大范围时单独说明搜索成本，不把不存在的模型当可计算候选 |
| 卡带主词条、副词条 | 复用Calc严格属性池及品质满值，逐件条数取正式静态；副词条属性不重复，主副关系沿当前Calc口径 |
| 驱动及图纸 | 保留真实格数、几何布局、套装和额外形状条件，词条预算与合法图纸绑定 |
| 装备强化 | 当前值使用实际已知词条；理论域按正式强化和词条规则生成，不虚构必得的未来强化结果 |
| 养成成本 | 建议可附已证实材料成本；最短养成路线、全局资源预算分配及刷取概率优化不在首版范围 |

用户选择的目标约束必须在结果中可见。固定某套弧盘/套装后，得到的是该约束内的理论基准，不称为遍历所有构筑后的全游戏上限。
角色觉醒、精炼、词条等不是同一资源单位；首版不暗中把抽取投入与可刷取资源换算成一个成本。

#### 5.2 理论与当前构筑隔离

理论构筑使用独立候选身份，不生成真实 UID，不写完整库存指针，不直接进入装配或借出流程。
相同模板是否可重复使用由游戏规则及目标数量约束决定，不把模板 ID 当真实装备唯一身份。
当前构筑继续按其来源执行真实UID唯一性、来源快照和已保存槽位 contract。读取这些证据不引出全背包优化任务，也不依赖背包规模决定理论搜索维度。

明确未装备可作为已知状态；来源未返回、映射冲突和词条未知不是空装备或零属性。
冷却、能量、解锁等实战条件仍需独立审计；未覆盖时明确标为未证实。按当前产品口径，这不单独阻止固定观测轴数学比例，但不能据此承诺新构筑能在实战原样打出。若条件缺口同时使伤害模型本身未知，仍不生成比例。

### 6. 轴重放与模型边界

1. 固定动作及观测时点，不重新搜索轮转，不自动增加施法次数或预测真实击杀后的新战斗长度。
2. 新构筑改变面板、增益数值及已支持触发时，使用新输入重算；不复制旧配装的全部 Buff 数值作为新构筑事实。
3. 普通直伤默认采用暴击期望；必暴按机制处理。历史逐击暴击结果用于复现对账，不固定套用到所有毕业候选。
4. 暴击影响后续触发、资源或动作的机制，需要状态传播模型。采用模拟时记录共同随机数策略、采样量与不确定性，不将统计估计描述为精确期望或最优证明。
5. 分子与分母冻结相同事件计分域，分别标明严格量化、估算和未计入部分。禁止通过丢掉难计算事件提高比例。
6. 覆盖不足时使用“已建模部分”名称并展示覆盖范围；关键缺口导致同口径比较不成立时，主指标保持未就绪。
7. 未支持的新角色/技能/条件机制仍需逐项建模审计。历史原始事实和用户编辑副本各自冻结，不相互覆盖。

当前比例统一明确标注固定观测轴假设；暴击模式、候选评价和条件传播按实际模型覆盖核验，不以能力名相似就宣称支持。纯动作/资源可执行性未知与伤害模型未知分开，后者继续阻止数学比例。

### 7. 求解方法

推荐“属性与预算压缩 + 条件性剪枝 + 少量离散分支 + 整队重放评价”的实现；复杂机制下再扩展多起点和联合邻域。

#### 7.1 自选词条为何能降量，以及必选条件

不从成千上万件实物中组合。按当前Calc既有固定词条数值模型，对每名角色、每件理论装备记录主词条及不同副词条属性的选择；满值由品质、格数及卡带/驱动规则确定，条数由该正式装备的静态上限确定。不虚构可无限叠加的同属性次数或连续词条份额。
效果确实等价的组合可合并为属性向量并缓存，但必须保留可重建的合法逐件构筑；涉及单件触发、套装或形状差异时，不跨这些边界合并。

高收益属性按以下分级处理，而不是写死全局必选名单：

- 对已审计模型确无直接或间接贡献、也不触发资源/辅助机制的属性，可从该上下文排除。
- 只有在当前合法域内有单调性或支配证据时，才固定某属性份额或删除被支配选择；证据与目标、静态和模型版本绑定。
- “通常收益很高”但没有上述证明的属性，只用于优先候选和初值，保留替换空间。
- 暴击到达角色实际有效上限后，额外暴击的收益可能消失；存在超额转化时另算。攻击、增伤等会受稀释和条件覆盖影响，收益排序可能反转。
- 辅助的生命、防御、充能等可能通过全队增益或轴可执行性产生高收益，不按个人出伤低就删除。

自由词条不代表每条都能取最高值。总条数、档位、每件上限、互斥、主副词条关系等约束始终先于收益排序。

#### 7.2 搜索过程

1. 核验阵容与轴范围，冻结目标、当前构筑、环境和模型，生成有效性与覆盖诊断。
2. 采用用户固定的养成、弧盘、套装和图纸，或其明确允许的小集合；枚举必要主词条分支，并进行有证据的合法性剪枝。
3. 在每件固定条数、属性不重复的合法词条选择中生成候选；优先评价高收益初值，再做边际排序与属性替换，避免从全实物组合开始。
4. 每次属性、养成或组合变更都以同一整队重放目标评价，更新边际信息。
5. 同时搜索单角色调整和跨成员交换；允许辅助自身伤害下降而整队提高，不保护角色优先基线而阻止合法团队改善。
6. 多起点、缓存、并行与有界预算共同控制成本；只发布校验通过的最好候选，不发布半完成构筑。
7. 记录邻域、枚举、量化及可执行性覆盖，区分取消、预算截断、局部收敛和最优性证明。

新流程不调用库存分配器。当前方案或其满足目标养成约束的对应方案可作为合法起点，公共静态规则和轴评价能力按职责复用。
先在固定目标的小词条空间建立穷举对照，再验证压缩和剪枝等价性；扩大范围时保持声明的合法域，不为简化计算偷偷缩小目标。

#### 7.3 建议直接来自当前值与理论目标差异

建议分为养成差距与词条差距：前者比较当前等级/技能等与选定目标，后者指出主词条及合法副词条预算如何调整。
每项建议以一个完整合法变化或必要组合重放，给出整队轴伤差值、相对提升和毕业率百分点变化；一次只加词条而不扣除其占用预算的方案不算合法建议。
存在阈值或跨角色依赖时保留联合建议，不把各项收益相加当总收益。目标伤害减当前伤害也不是一条可以立即兑现的单步收益。
本功能不寻找背包里的具体替换件、不保证装备已拥有、不保存或装配理论装备。材料成本仅在有证据时附带，首版不计算最短养成路线或刷取次数。

#### 9.2 独立分析组件

私有实现留在独立分析仓库。建议在其业务模块内新增 `team_axis_graduation`，内部按 `contract`、`legal_build`、`search`、`advice` 分责；实际 crate 路径以实施时仓库结构为准，不在 Calc 复制私有源码。

1. 从现有轴评价中提取可复用的整队候选评价入口，保证当前、理论和建议使用同一 evaluator 与事件计分域；不另写简化攻击公式。
2. `legal_build` 将正式规则编译为离散主词条、逐件不同副词条属性/满值及形状/套装约束。每个输出都可还原逐件合法构筑，而不只输出四人的合计面板。
3. `search` 先生成可行起点，再做主词条分支、单角色预算交换、双角色联合变更及多起点搜索。跨角色“交换”指联合调整各自合法配置，不把一人的词条次数非法转赠给另一人。
4. 对等价候选缓存整队评价；缓存键包括触发、单件效果、形状、套装和机制状态，不只按总攻击/双暴合并。只有有证明的规则能硬剪枝。
5. 每次完整评价前后检查预算与取消；候选生成、合法性检查和事件遍历也需检查，避免单次大循环阻塞取消。只更新完整且合法的 incumbent。
6. `advice` 对当前到目标的整件/整组变化作反事实重放，按整队增益排序；保留具有依赖关系的联合建议，不要求计算每个变量的所有交互排列。
7. 搜索预算至少包括候选评价上限和墙钟超时；确定性比较采用固定 seed、稳定排序及评价次数预算。线程数和 seed 记入结果；不以墙钟截断承诺每次得到相同最优值。

首批验证必须包含小空间穷举、单人双暴饱和、辅助属性提高整队伤害、主词条切换及跨成员耦合，不只用四个独立输出角色证明功能。

#### 9.3 首版求解循环与规则证据

变量细化到 `角色 / 装备位置 / 主词条 / 不同副词条属性`。词条池、满值及品质系数优先复用Calc的 `AllocationScoringRules` / `StatCatalog` / `ScoringEngine`；驱动固定主属性复用 `calculate_drive_main_stats`，逐件数量、形状、套装和强化上限读取完整主静态。首版不另造随机强化次数/数值档位模型，也不把缺少解包随机池成员表当作既有Calc数值不可用的前提。新增或异常规则另审计；确需新增静态字段时再走候选构建/校验/晋升，不直接改发行库。

```text
验证并冻结上下文、规则、当前构筑与目标
current = 统一评价器(实际构筑, 固定计分域)
seeds = 目标域合法起点 + 高收益初值 + 有界多起点
best = 完整评价过的合法起点中的最好者
对每个离散主词条分支和起点，在预算内：
    生成保持条数不变的单件属性替换、主词条分支及双角色联合邻域
    先检查逐件合法性并保留轴可执行性状态，再按完整候选身份去重
    用统一整队评价器评价，不复用旧权重预测值作为最终伤害
    保留改善及必要的其他起点，更新 best 和搜索证据
    无改善则切换起点/分支，全部声明邻域完成或预算耗尽后结束
再次验证 best 的逐件规则、身份与同口径覆盖
返回 best、current、搜索停止原因；只有有效分母才生成比例
```

上述循环是有界搜索，不把“无改善”推断为全局最优。第一版先实现稳定的单进程/受控并行评价；只有正确性和成本样本闭环后再引入更复杂求解器。进度先显示阶段、已用时间及可获得的评价数，不虚构总候选数或完成百分比；若现有一次性传输只在结束时返回计数，运行中仅显示阶段/计时，流式进度另按协议演进。

### 10. 协议与结果 contract

#### 10.1 能力与操作

基准、当前评价、养成建议和装备建议均已通过正式独立分析路由并成套晋升；固定观测轴比例由显式策略和独立能力控制。具体操作名、版本、字段与能力只由[正式协议](../reference/team-axis-graduation-protocol.md)维护，不在本方案复制另一份清单。

沿用正式请求信封和受界传输。理论搜索可取消，不启动采集Core，不依赖游戏运行。缺某项建议能力不禁用已有当前评价；缺组件时保留历史只读和明确待就绪提示，既有战报查看、匹配和增强按各自能力判断。未声明的全局最优性与动作可执行性不因数学操作可用而成立。

#### 10.2 请求字段

| 分组 | 必带字段或规则 |
| --- | --- |
| 关联 | `request_id`、操作、payload版本；Calc 本地冻结账号、generation 和任务序号，原样校验回调，账号敏感标识不进入诊断日志 |
| 轴与环境 | 战报冻结引用、半场/自定义范围、规范化轴输入摘要、四名正式角色、敌人/环境/假设及摘要；包含零伤害成员 |
| 当前构筑 | 四人实际养成、实际装备和字段级来源/未知状态、来源模式及修订、槽位/方案/来源快照和构筑摘要；不携带全背包候选集合 |
| 静态与规则 | dataset用途、版本、schema、内容哈希；合法词条规则和规则编译版本；以完整主库身份核对，不混读图鉴 |
| 模型 | 组件/引擎、伤害模型、算法、暴击策略、条件传播和事件计分域版本；涉及模拟时带 seed/采样策略 |
| 目标 | 目标ID/修订、固定养成、觉醒/精炼、允许弧盘/套装/图纸、主副词条池及逐件条数/品质满值规则、额外假设；显式保存目标摘要 |
| 预算与基准 | 评价次数/时间上限、搜索 seed；当前/建议评价必须引用不可变基准ID及其上下文摘要 |

请求字段缺失时返回结构化原因，不用旧个人毕业模板、默认零、全满养成或最新背包补齐。Calc 与组件双方都验证合法性；组件不信任 UI 已校验这一前提。

#### 10.3 响应字段

| 分组 | 返回内容 |
| --- | --- |
| 身份回显 | request/context/target/current-build/scoring-domain 摘要、实际静态/引擎/模型版本；不匹配则不展示、不保存 |
| 数值 | 当前/参照数学伤害与显式固定轴策略的比例；保留旧比例字段为空，不挪用旧字段。未知带原因，非有限JSON值判协议错误；字段以正式协议为准，理论100%是标尺标记 |
| 理论构筑 | 每人目标养成、每件主/副词条属性与满值、逐件条数、形状与套装、理论候选ID；该ID不冒充真实装备UID |
| 覆盖 | 完整事件域摘要、已量化/估算/未知事件及机制原因、可执行性结论；原始逐击与完整伤害表不进入常驻日志 |
| 搜索证据 | `stop_reason`、已评价数量、耗时、seed、已检查邻域/分支、最佳值与可选已证明上界；枚举完成与局部收敛分开 |
| 建议 | 合法完整变化、前置依赖、整队伤害差值/相对提升/百分点变化、估算或未知原因；同一基准版本下计算 |

建议可在基准求解后单独加载，首个百分比不等待穷尽建议。失败时保留已完成基准，建议区单独显示原因和重试，不伪造“无提升”。

`stop_reason` 至少区分完成声明邻域、全局预算截断、预设份额截断（`preset_budget`）、候选量化受限、取消、输入失效和计算失败。未知候选记录实际数量；计分域漂移直接使比较失效，不静默换域或跳过后宣称完整。预算截断若已有完整合法 incumbent，可标记“搜索受限”并供用户显式保存；取消/失败不自动发布或保存半完成结果。无结果与已确认零伤害是不同状态。

当前真实构筑与目标固定养成可能不同。合法域内的当前起点保证参照值不低于当前；不在同一固定养成子域时并无此保证。出现大于100%时不截断：区分当前超出目标允许条件、搜索不足、以及所选目标养成造成的非单调变化，展示诊断并提示调整目标或深搜，不声称已经找到更高的理论上限。

#### 10.4 必须先审计的评价接口

在写 solver 前，使用冻结样本形成以下审计表：当前组件的暴击模式是否为期望、是否重算团队增益、条件是否被历史值锁死、冷却/能量是否支持候选可执行性、缺项如何上报、单次评价成本与取消粒度。每项写“已支持/需扩展/缺来源”及对应测试。

若关键机制尚无可比模型，则保留诊断，不给整队完整毕业率。覆盖计数不是阈值豁免：大量普通事件已支持，也不应抵消一个决定全队增益的未知机制。非关键缺口允许展示明确命名的“已建模部分毕业率”，但分子分母必须严格共享计分域；换构筑导致域变化时先判比较失效，不自动删事件对齐。

### 11. 状态流、持久化和失效规则

#### 11.1 用户动作到结果

```text
选择队伍/配装来源 → 匹配并明确选轴 → 编辑目标草稿
→ 校验与冻结 → 显式“建立基准” → 当前评价 + 理论求解
→ 完成/搜索受限预览 → 显式保存目标版本、基准与当前评价
→ 查看建议 / 更新当前评价 / 显式重新深搜
```

首次仅打开队伍页、翻页或刷新简报不启动求解。读取已有结果不依赖启动分析进程；展示历史结果时同时标明其版本与当前有效性。更新当前评价不更换分母；更新目标或深搜更高参照创建新基准版本，历史比例不随之重解释。

Controller 状态至少分开：未选择轴、未建基准、输入缺失、组件待更新、计算中、可用、已建模部分、搜索受限、当前评价过期、基准过期、失败、取消。来源简报和增强状态不共用该瞬时状态字段。

任务持有冻结请求、取消token和序号；owner 关闭/账号切换先撤销发布与保存权限，再有界结束 worker/子进程。回调复核账号、generation、序号、目标/基准、静态和源摘要。结果可读不代表还能保存；保存前再次复核并由 DAO 单一事务提交。

#### 11.2 账号事实与已实现事务

| 表 | 关键字段与约束 |
| --- | --- |
| `team_axis_graduation_target` | target_id、team_id、revision、format_version、规范化约束/假设、target_digest、created_at；同队伍修订唯一，保存后不可原地改义 |
| `team_axis_graduation_benchmark` | benchmark_id、target_id、context_digest、轴/环境冻结正文、dataset/规则/组件/模型身份、计分域摘要、最佳合法构筑、reference_damage、搜索证据；同一目标允许多个深搜结果 |
| `team_axis_graduation_evaluation` | evaluation_id、benchmark_id、current_build_digest、来源修订与证据、current_damage、ratio、coverage、建议及算法版本；结果引用不可变基准 |

显式选择由`team_axis_graduation_selection`保存队伍、基准、评价和CAS修订，不靠最大伤害或最后插入行猜测。基准与目标版本使用完整队伍外键，评价绑定基准，选择绑定同队伍同基准评价；首评价复用基准正文，不复制整份轴。正文逐行受界、SHA及typed关联校验，应用边界另做完整协议校验。SQL对JSON关联、正且有限分母、当前比例为空、操作和正文大小有约束；具体schema数字不在文档抄写。

为使历史可解释，保存必要的轴与环境计算输入、目标、当前构筑及来源摘要，不依赖原槽位、最新库存或战报仍存在。重复数据按协议冻结子集约束体积，不应以正文持久化为理由复制整背包或其他账号事实。

目标版本迁移已在既有账号schema后追加；基准/评价/选择表已继续追加，覆盖新建、旧版升级、失败回滚和重试，不修改既有迁移。现有 source/binding 和 enhancement 表继续保留；旧平均值只有会话派生结果，无旧百分比数据需要回填。

`save_completed_result` 在一个事务内写入目标版本（如新增）、基准和首个评价；后续当前评价单独追加并引用既有基准。保存前复核 team/source/target 修订、成员及构筑摘要，不只检查全库时间戳；不相关账号写入不应使冻结轴无故失效。任一步失败保留旧有效结果，不提交半套引用。

同时检查账号导入/导出的表清单、大小限制、成员路径规则及一致性备份；新增表必须随本账号迁移、导出、导入及删队伍策略验证，不因“已建表”就认为备份自动覆盖。删队伍按其所有权级联清理新结果，不扩展到角色页数据、战报或增强的无关记录。

#### 11.3 失效矩阵

| 变化 | 处理 |
| --- | --- |
| 当前实际养成/装备/所选槽位改变，仍满足同一参照条件 | 仅当前评价过期；复用有效分母，显式更新分子和建议；未满目标等级不触发基准重建 |
| 保存了无关角色/槽位方案 | 不失效；按冻结来源核对。来源为游戏配装时，保存计算方案不当作游戏装备已改变 |
| 只更新当前库存但所选历史方案冻结内容未变 | 不重解释旧方案，不触发理论搜索 |
| 阵容、轴/范围、环境、目标、合法规则、模型/覆盖口径或静态身份改变 | 基准过期，保留旧版只读；显式建立新版本，不静默沿用旧分母 |
| 当前弧盘/觉醒/精炼越出目标允许条件 | 显示超出基准条件；保留旧基准，可修订目标，不用旧比例冒充可比结果 |
| 同一目标下增加搜索预算并完成更好基准 | 新基准版本；用户选择后再生成对应当前评价，不覆盖历史比例 |
| 切换账号/generation 或退出 | 取消本次任务并丢弃旧回调；其他账号不读取本账号会话缓存 |

源码已把固定参照上下文与当前构筑摘要分开：详情中的“核对结果有效性”仅在worker读取当前实际来源和评分规则、核对组件清单/哈希，不启动分析进程、不读取原战报或搜索新分母。分别输出当前评价过期、基准需重建、组件待就绪或有效性待确认；只有本次读取匹配才恢复对应预览的保存权，真正保存仍执行原有来源/组件复核。旧战报后续变化或删除不影响已封存轴；同目标的新搜索、未选用目标版本不替换既有参照。

计算方案保存通知按账号/generation/数据库和冻结成员/槽位定向撤权，游戏来源忽略该类通知；来源配置保存同样撤销该队当前评价。换轴或目标草稿立即清空旧百分比和伤害展示，分页不会把旧选择冒充新草稿；重开已有结果先标历史待核对。已知基准过期不被后续配装通知降格为仅当前过期，失败或取消核对不恢复旧预览保存权。

只把generation作为会话隔离，不作为跨会话持久化内容身份；重开历史可保留原数学事实，不能以缓存命中绕过新输入/组件检查。新版组件已成套交付并有专项与隔离窗口证据，真实安装/升级和混合DPI验收仍独立保留；静态缺失等读取失败保持未核实，不把故障等同于已证实变化。
