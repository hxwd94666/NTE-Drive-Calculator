# 轴伤完整估算待解决问题

状态：待解决，已复现并定位当前拦截点，尚未修改伤害模型或放宽量化门禁。

## 现象与影响

选择安魂曲执行战报轴伤优先时，正式四人队伍及固定队友装备预检已通过，结果仍提示“基础配装尚未得到完整伤害估算”。
基础角色优先方案已经生成，但轴伤搜索未启动，未生成可保存的优化结果。
这与无半场归属单击的处理属于不同阶段；事件域处理及已交付行为见[计算结果后处理](../features.md#计算结果后处理)。

## 已确认原因

在账号一致性临时副本中，仅复查基础估算、不保存方案，得到以下诊断：

- 外层原因是 `axis_baseline_not_ready`，基础量化状态是 `unavailable`。
- 具体缺口是 `outer_realm_recipient_evidence_missing`：缺少赛季环合增益的受益角色或生效区间证据。
- 当前独立分析组件先检查每击的赛季受益证据缺口，再进入后续候选收益比较；缺口会使该击返回未知。
- 该次复现的基础估算整体未量化；不是角色在队外，也不是继续被无归属单击阻断。

这些证据确认了当前拦截路径，尚未证明全部相关伤害都实际受到缺失增益影响；也不据此认定是游戏错误、采集丢失或角色伤害模型整体不支持。

## 当前完整估算判定

基础方案 B0 是本次角色优先结果与保持不动的队友组成的完整配装；参照 A 是用户明确选择的冻结战报构筑。
“完整”判断的是同一事件域内从 A 到 B0 的反事实变化是否有依据，不要求公式伤害与实测伤害完全相等。

当前门禁要求同时满足：

1. 全队汇总量化状态为 `complete`，或有依据判定变化不适用的 `not_applicable`。
2. 最终候选伤害是有限数值。
3. 每击伤害与相关联动事件的量化状态同样属于上述两类，没有仍为 `partial` 或 `unavailable` 的项目。

这不是覆盖率达到某个百分比即可放行。只优化部分队员时，仍核对全队目标；有依据证明未变化的部分可以保持不动，而不是一律要求重新计算绝对伤害。
Calc 的汇总提示入口为[结果说明](../../src/features/allocation/damage_result_summary.py)，协议验收入口为[轴伤评价适配](../../src/integrations/battle_axis_evaluation.py)。

## 待处理事项

1. **核查缺口是否真正相关。** 在独立 Rust 分析组件内，区分已确认生效、已确认未生效、受益对象或区间未知，核对当前赛季规则是否被过宽应用到每击。
2. **按实际变化依赖判定。** 只有正式证据能证明本次换装不影响某部分、或缺失维度可严格抵消时，才将其标为不变并继续；缺失增益确实影响收益排序时，保留未知并说明原因。
3. **保留已有冻结边界。** 仅消费所选战报的正式来源、受益对象和区间证据，不把静态赛季定义当作已触发，不用当前角色配置补造历史状态。
4. **展示具体原因。** 将底层机制缺口转成简洁玩家说明，区分队伍预检、基础估算及搜索预算阶段；当前笼统提示应能说明缺哪项以及下一步如何处理。

不以删除出伤记录、跳过受影响机制、把未知收益当零或直接标记完整的方式绕过门禁。
无半场归属事件的既有筛选规则保持独立，不扩大为忽略机制缺口的通用规则。

## 必要验收与完成条件

- 用合成四人队伍覆盖：缺口真实影响收益时继续拦截；证实不受影响时继续计算；受益角色或区间证据完整时正常量化。
- 覆盖仅优化队内部分角色、固定队友联动、原始 A 与启用修改副本 A；两侧比较沿用同一冻结事件域和来源身份。
- 提示显示具体机制原因，部分结果不伪装成全队完整结果，原战报与历史方案保持不变。
- 只运行受影响的 Rust 量化专项和 Calc 原因展示／接纳边界测试；需要组件更新时成套构建、核验并交付，不据此重复运行无关全量测试。

复核实际来源后确认依赖边界、相关回归通过且配套组件已更新，才标记解决。稳定行为整合进功能文档后，从本问题文档移除已解决计划，避免与事实文档长期重复。
