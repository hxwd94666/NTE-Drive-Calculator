# 角色匹配套装：开发验收记录

状态：源码实现与本需求专项验收已完成；未发布、未构建安装包、未执行真实游戏弃置或锁定。
本文件保留原需求的交付范围与验收对应关系，不再维护另一份功能说明。
用户行为及限制以 [角色匹配套装](../features.md#角色匹配套装) 为唯一事实源；跨功能边界见 [开发契约](../../AGENTS.md)。

## 1. 完整交付范围

- 鉴定页面主入口、弃置锁定管理「评分处理」栏目、仓库快捷鉴定结果入口，共用一个编辑器和一份账号配置；不在角色页新增入口，不把 UI 按钮函数作为服务。
- 角色头像总览、当前匹配套装、卡带图片多选与显式替换、单角色／全部恢复、草稿保存与取消。旧追加配置保留；无效角色/套装保留修复入口。新增文本接入现有语言资源，三主题与小屏操作保持可达。
- 有效匹配集合统一求合法图纸，卡带按正式套装匹配、驱动按合法套装位/散件位匹配；同角色只评分一次，可展开每个套装的适配位置。
- 基础评分引擎、主词条权重及原有评分公式不变。额外套装不附加奖励，不评估套装技能，不引入边际权重或新玩法模板；计算、两种伤害策略、养成及历史评分不接入该设置。
- 鉴定和仓库/扫描后评分管理共用匹配上下文，移除旧 `PostActionScoreContext` 及失败后全角色回退路径；弃置、锁定各自的角色范围与独立规则优先级不变。
- 完整未匹配、低分与评估未完成分开处理；默认不对未匹配生成评分动作，新增默认关闭的「未匹配装备也弃置」。配置、资料或评分失败不进入该分支；指定范围缺项只停止该模块评分，不阻断另一有效模块或独立规则。
- 账号设置版本化校验、原子比较保存、无变化不失效、账号隔离及导入导出；角色变体只认正式唯一映射，不靠显示名猜测，不静默改写旧身份或删除失效条目。
- 冻结账号、代次、静态资料、角色权重及匹配设置；实际修改使旧鉴定结果和待派发计划失效。每批/逐件派发前复核，已接受动作按原后验流程收尾，不反向改义、不重发。保存设置本身不操作游戏。
- 仅默认及显式新增组合在后台求图纸，同批复用评分器和上下文；沿用既有任务取消和图纸缓存，不新增常驻服务、线程池或全组合扫描。

## 3. 原验收要求与证据对应

以下覆盖原方案的全部八项必要验收，不以“能打开弹窗”代替服务和数据边界验证。

| 原要求 | 对应代码/检查 |
| --- | --- |
| 1. 默认一致，额外套装跨鉴定入口生效且同引擎同分 | `tests/identification/test_role_suits.py`、`test_batch_service.py`、`tests/inventory/test_warehouse_identification_service.py`；现有静态目录隔离账号实跑：角色 1003 增加 Suit1 前不匹配，增加后鉴定和管理均为 135.0，移除后恢复 |
| 2. 多套装去重，合法形状，无图纸和资料失败分离 | 公共 `matching_context`、`EquipmentMatchContext`；角色套装用例及展开详情的真实 Qt 行为用例 |
| 3. 额外套装高分参与保留/锁定，角色范围独立 | 角色套装评分用例、账号权重及规则约束用例；失效指定范围只影响所属模块 |
| 4. 未匹配默认不动作，显式开关不覆盖故障和独立规则 | 默认、显式未匹配、资料错误、异常分值、独立规则及模块范围用例 |
| 5. 保存/取消/恢复/旧账号/导入导出/切换/旧任务失效 | 账号配置与备份恢复用例、编辑器异步生命周期、最后一件处理期间变更拒绝整批、派发前及接受部分后的失效用例 |
| 6. 不改变计算请求、权重和历史评分 | 设置仅写自己的账号键；计算/后处理没有该设置依赖；非干扰用例比较整个账号逻辑转储（含权重、计算偏好、历史评分），增删匹配设置均不改变其他内容；真实目录前后角色权重相同 |
| 7. 三主题、小屏/DPI、键盘、取消和 worker 收尾 | 编辑器/三个入口用例、屏幕限位与键盘展开/收起；Windows Qt 原色/黑色/白色窗口目视检查，右侧评分展开前后均保持内容高度 |
| 8. 唯一角色变体映射，失效配置可见可清理，范围外不扩大影响 | 正式主角变体映射、歧义映射、未知套装移除、空搜索、无改动保存及指定角色范围用例 |

现有目录端到端检查使用隔离账号与合成卡带，不使用个人库存：默认 → 添加额外套装 → 鉴定与管理同分 → 移除并重新评估。单次四次服务准备及管理评估合计约 1.8 秒，仅代表当次本机测量，不承诺所有账号的固定耗时。

检查沿用 `tools/quality/run_tests.py` 的专项入口，并复用直接受影响模块的 pytest 结果。鉴定目录集中检查 58 项通过；指定范围/规则相关检查 31 项通过，两组有重叠，不累加为独立用例总数。旧手工/剪贴板替身缺少新冻结身份的两项失败已迁移并复跑，未削弱生产守卫；运行记录保留原失败和修复后结果。静态检查覆盖本次 Python 文件的 E9/F63/F7/F821/F401 与 800 行门槛。

## 4. 交付与回退边界

本地交付记录包含任务文件清单、当前哈希、相对任务前基线的补丁、检查命令/结果及带哈希守卫的回退入口。回退仅操作本需求登记文件，遇到后续改动即停止，不覆盖其他开发者工作；不删除账号额外套装设置或其他个人数据。不保留长期新旧双实现，也不以旧弃置评分作为运行时错误回退。

本需求未改造 OCR 识别算法、伤害分配、外部分析组件或游戏驱动；扫描与派发改动仅传递现有取消/冻结复核。手柄驱动未复测。正式发布前仍执行仓库既有 core/full、构建及 Windows 业务门禁；本次专项与合成输入验收不冒充这些发布证据。
