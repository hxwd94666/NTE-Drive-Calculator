# 仓库管理与智能规则

## 独立设置与直接预览

仓库「管理」有独立窗口、任务 owner 和账号配置；扫描管理保留自己的窗口、设置与扫描后执行流程。
两者的套装匹配也分域保存，鉴定及仓库快捷鉴定使用第三个独立域；共享公共评分和编辑控件，不共享业务草稿。
旧账号一次迁移现有设置，扫描保留可执行静态条件和原有顺序，动态智能策略只留仓库；新账号分别建立默认值。
设置、匹配范围及版本随账号导入导出，本机主题和语言不随之迁移。
普通账号偏好保存保全两个管理 owner 的最新字段；旧偏好草稿不会回滚已保存管理配置，扫描独立保存也不覆盖仓库配置。

底部只有「取消」「生成预览」。取消丢弃未保存草稿；生成预览先校验并在同一账号事务保存评分、规则及匹配草稿，
成功后使用相同冻结输入计算。保存失败不计算；计算失败或取消保留已保存设置，不提交半份结果。
设置变化使旧生成目标失效并撤销其保存资格，用户在仓库亲手设置的目标仍保留。
匹配页内「完成选择／返回」只保留本窗口草稿；不提前落库，也不改变扫描管理与鉴定的保存时序。

完成后结果直接投影到仓库卡片，无额外建议采用窗口。卡片变化仅为待保存状态；点击仓库右上角「保存」并确认才派发游戏操作。
仓库右上角「清除」位于「管理」与「保存」之间，确认后撤销全部未保存状态，包括筛选隐藏的装备和人工目标；按本次读取的原始锁定／弃置状态恢复卡片，不删除装备、不修改游戏或规则设置。清除同时撤销预览见证、冲突及旧任务回填资格；保存正在派发时不清除已执行操作。普通逐件改回原状态不会自动撤销整批见证，明确「清除」才会结束本轮草稿。

打开设置、生成智能规则、保存设置和生成预览都不写游戏。保存前复核账号、固定快照、运行态、配置、资料及智能见证；
自身已接受的状态指令不使整批反复失效，其余输入变化则停止未派发部分并核对已接受部分。

## 处理链与决定

```text
冻结仓库已有人工目标 → 手动规则 → 评分处理 → 智能规则 → 仓库待保存草稿
```

智能规则标题右侧的「跳过前置评分处理」只控制中间的评分处理阶段。开启后走「手动规则 → 智能规则」，
不执行评分页的锁定／弃置判断；评分页标记为已跳过，保留原阈值、角色范围和模块开关，关闭跳过后恢复使用。
智能算法内部的公共评分、原锁、配装保护和整批校验仍有效，不将此开关解释为完全不评分。

仓库与扫描共用的评分表单在「遇到锁定」「遇到弃置」选项右侧提供可点击、可悬停的问号。
说明仅强调模块边界：跳过不是全局保护，其他模块或规则仍可处理；正常处理会重新判断并可能解除原标记；评分阶段被跳过时，本页设置不生效。帮助不修改选项或草稿。

每阶段只接收真正未决定的装备。「仅保留」即使没有状态差异仍是决定；「恢复正常」也属于决定，不再进入后续阶段。
冲突、状态未知和受阻分别保留原因，不冒充未决定。原游戏弃置标记本身不是本轮人工决定。
用户直接设置的弃置、锁定或正常先于规则定案，即使目标与原状态相同也跳过后续裁决。顶部冲突只展示待规则裁决装备的手动规则冲突；受保护的人工弃置在状态提示中说明，保存时再次核对。
仓库页汇总游戏状态未知、状态保护／跳过、评分资料不足等原因及全量件数；不随卡片筛选变化，也不把摘要转成新目标。

- 手动规则收集全部命中：同动作合并，不同动作逐件冲突；排序只影响展示，不按排列或隐藏动作优先级裁决。
- 评分仅处理手动未决定项，仍先锁定模块；明确锁定或恢复正常即停止，否则再处理弃置模块。锁定与弃置同时满足时保持锁定优先。
- 仓库的弃置模块启用且范围合法、资料完整但没有适配角色时，列为弃置候选；不再提供未匹配开关。扫描采用同一固定未匹配策略，旧关闭值经规范化后不再生效；两个入口的模块开关和范围、状态跳过仍独立有效。资料失败不按未匹配或低分处理。
- 智能只处理前两阶段均未决定的装备，本区仍按列表优先级、首条实际命中生效。其全角色范围不受评分模块角色选择静默缩小。
- 前序保留或锁定装备可按真实身份、属性作为固定计算上下文与数量占位，但目标不可修改；前序弃置不进入后序可用库存。
  全角色及已保存偏好的基线从前序决定后的库存建立，不以旧基线反过来恢复前序明确弃置。
- 无启用智能规则时走手动／评分快路径，不调用动态分配求解，不要求智能规则版本或全角色蓝图完备。

## 两个规则区与生成

规则页在同一上下滚动页面中分为「手动规则」「智能规则」两个物理区域。
手动名称显示“（手动规则）”后缀，后缀不写入真实名称；拖动、上下按钮和键盘排序只在本区生效。
智能区排序才是优先级，跨区拖放及数据层重排不能改变来源或执行类型。

普通条件规则复制后成为独立手动规则，追加手动区末尾，包括从智能区复制的普通条件；不插在原智能规则旁边。
动态策略副本仍为智能来源，留在智能区并默认关闭，同类型仅允许一条启用。编辑保留稳定规则身份与来源。
「清空智能规则」为生成按钮右侧的红色按钮，清除全部智能来源草稿，包括编辑、禁用和动态副本；不动手动规则。
重新生成整体替换智能区，普通手动副本不被替换。

生成读取正式套装和形状目录，不打开角色选择。已有评级设置时沿用；首次评级建议以可取消后台任务冻结库存，
复用公共批量评分、蓝图数量及规则统计，不执行配装搜索。目标总量与驱动保留评级与对应动态规则双向同步，0 表示不限。
只有同类动态规则恰有一条启用时可编辑；选择不额外保留会关闭评级规则，可在列表重新启用。
成功生成智能规则后自动开启「跳过前置评分处理」；失败或取消不改变开关。规则生成不改评分页阈值、角色范围或模块开关；后续仓库变化也不自动覆盖用户已有评级。
跳过选择随仓库设置在当前账号保存，扫描管理不受影响。旧配置缺少该字段时，已有智能规则默认跳过，否则默认不跳过；
存在智能规则时，已有显式开启或关闭值优先。开关及问号紧跟「智能规则」标题，生成和清空按钮靠右。
尚未生成、清空或删除全部智能规则时，开关关闭并禁用，评分页恢复原设置；问号说明仍可查看。
生成规则及切换开关只改变窗口草稿，取消不保存；「生成预览」仍统一事务保存设置后再计算。
首次建议只是估算，正式智能预览仍需完整见证和损失检查，必要保护可以超过数量目标。

## 管理筛选与冲突原因

筛选「状态」表示冻结游戏事实；其下「管理」表示本轮目标与基线的净差异：待锁定、待弃置、待正常、无变更。
四项互斥、至多单选，均不选表示不限，重置清空选择。没有改动或目标等于基线时属于无变更。
手工和生成目标共用分类；筛选不删除隐藏目标，右上角保存数量覆盖所有待保存项。

存在手动冲突时，仓库页顶栏「仓库」右侧显示「本次处理有 X 处冲突」及独立的「查看详情」按钮，不随普通筛选减少。点击打开只读冲突详情，展示装备缩略图、
主副属性、原状态、命中的规则及相反动作和条件；名称可相同，导航按稳定规则 ID。
详情只有关闭和「修改相关规则」，不提供装备状态标记、采用或逐件裁决。导航先关闭详情，再定位仓库手动规则；修改后显式重新生成。
证据属于本轮冻结账号和输入；账号切换、来源更新或设置失效后不沿用。

打开或刷新仓库时，库存先展示，再通过独立后台任务补齐仓库分；仓库分显示在顶栏「仓库」右侧，与冲突提示处于同一状态区，不触发弃置决策或配装搜索。
质量统计缺有效样本时保持未知，任务失败保留库存；统计不是配装可行或实际伤害保证。

## 默认规则口径

- 空幕评估全部有正式评分和合法套装蓝图的角色，按角色、套装、主属性保留候选。已确认跨套装用途进入同一匹配流程。
- 仓库分评估高分质量样本，不取当前已装备角色均分，也不再为分数求解配装。空幕取全部有已确认评分用途的库存中最高的 25 件，不足时按实际件数平均。
  每个角色的蓝图按形状数量组合去重后等权平均，汇总全角色各形状需求，再按通常四舍五入取整。驱动各形状独立按最高适配得分率取够对应数量，同一 UID 不重复计入。
  空幕与驱动分别按评分 ÷（格数 × 10）求平均；总分为空幕平均得分率 × 150 ＋驱动平均得分率 × 200，沿用 350 制。缺任一类有效样本时总分保持未知，显示实际样本数和形状缺口。
  数量抽样只进行计数、排序、平均，复用本次冻结评分与蓝图；这些高分样本不承诺能同时配给所有角色，弃置安全仍由独立全角色配装检查保证。
- 驱动对全部角色复用现有合法蓝图、公共评分与角色优先分配。蓝图按形状数量组合去重，平均形状需求只辅助储备，不把同一角色各张可选蓝图的需求直接累加。整批校验保留可行配装见证。
- 未来储备偏好与实际角色模型分开：生命、防御、治疗和输出方向按同类主副属性协同。
  双暴是两个实际副词条，不能把暴击主属性计为缺失的暴击副词条；治疗及元素伤害主属性不伪造为副属性。
- 推测的元素主属性用途须与已审查的套装元素一致，或有当前角色的明确套装与主属性适配；
  光套＋咒伤等已确认跨套装用途仍通过同一角色适配输入生效，不推广成任意套装配任意元素。
  未确认角色时，治疗方向只允许相应生命／治疗或防御套装；不凭有效副属性数量为暗套＋灵伤等组合补造用途。
  未编辑的自动四词条保护规则也执行跨元素用途校验，不允许经最终规则仲裁绕过；通用环合、倾陷、生命和防御主属性不按元素冲突处理。
  用户手写或明确编辑的规则，以及单列的已确认光套组合规则，保留各自明确的保护范围。
  未来储备不纳入已标记弃置的装备；只有当前用途、已装备、配装见证或明确保留规则才能建议恢复正常。
- 双暴＋伤害增加＋攻击力%或环合强度的空幕及驱动，默认生成明确保留规则，不受同类数量、候选排名或评级限制。
  当前没有充分证据判断主属性严重错误时仍保留；不会仅因常用角色暂时用不上而推荐弃置。
- 全套装空幕的倾陷主属性＋双暴＋增伤＋倾陷，以及生命／防御主属性＋双暴＋增伤＋对应百分比副属性同样明确保护。
  驱动另保护双暴＋增伤＋倾陷／生命%／防御%，以及双暴＋攻击力%＋环合／倾陷。
  每种四词条组合独立生成可编辑规则，四条都须是实际存在的正数副属性，不用主属性充当副属性。
- 明确要求的强势套装任意主属性＋双暴＋增伤／环合／攻击力%，以及相应输出、生命、防御、治疗组合直接保留，
  不受额外候选数量截断。其余按套装／主属性（驱动按形状）、用途及有效副属性签名分桶。
- 音速蓝刺猬（正式身份 Suit11）另有五条独立辅助保留规则：不限主属性，实际副属性同时具有暴击率、暴击伤害、通用增伤，
  再有攻击力%、防御力%、生命值%、环合或倾陷之一，四条均须为正数。各品质沿用规则范围，不受预算或重复备用压缩。
  辅助用途不套用元素主属性冲突筛选；仍遵守可编辑规则的首条命中顺序。已有账号需重新生成并保存才能加入新规则，不暗改已保存列表。
- 非支配筛选只对同资格、同签名的候选比较。驱动还覆盖已有合法蓝图中的单组最大形状重复数。
  每个候选组默认保留两件，可在动态规则编辑；前沿不足数量时允许较低质量副本补足。
- 未来用途规则默认目标保留总量为 1000 件，0 表示不限；这是保护优先的目标，不是强制弃置配额。
  已锁定、已装备、可行配装、达到所选保留评级、规则选出的锁定首选、明确组合、手写保护和不能确认弃置的物品先占预算；原已弃置且没有恢复理由的待核对项不占保留数量。
  超出目标时，仅未命中上述保护的当前用途备用候选按同套装/主属性或驱动形状、实际适配范围分组，分别覆盖暴击率/暴击伤害/增伤组合
  与攻击、生命、防御、环合、倾陷、急速方向，先保留各取向最高评分代表，再按归一分数从低到高压缩重复备用。
  同一件可覆盖多个取向，不因无关第四词条变化就额外保留；主词条不充当暴击副词条。不同资格不互相替代。
  基础完美词条和明确储备规则不受该压缩影响，未来用途分桶和组内数量规则仍沿用原契约。
  剩余名额按五种未来用途轮流选择，组内按公共评分面积归一值排序，每个储备组按数量及已知形状重复需求整组纳入或跳过。
  必要保护超过目标时允许超额，预览记录目标、必要保护、额外未来储备及预算未覆盖的组数。
- 驱动评级额外保留可关闭或选现有 D～ACE 任一最低评级，默认 SSS。依据全部适配角色中的最高有效评分，
  使用既有面积归一化评级判定，达到门槛的驱动全部受数量硬保护，重复件也不能因数量目标被压缩。该规则只作用于驱动；与其他规则冲突仍遵守首条命中优先，不调整用户规则顺序。
- 当前用途桶冠军达到现有 SSS 线或属于可行配装见证时，启用规则选择锁定动作则建议锁定；这些锁定首选也不能被数量压缩撤销。未来假设本身只产生保留候选。
  现有锁定单独标记，即使模型认为冗余也不自动解锁。
- 增加未来储备不得扩大弃置集合。没有已确认用途／替代关系、模型缺项或求解未完成时保留待判断。

## 分层与复用

`src/domain/equipment/warehouse/warehouse_recommendation.py` 消费冻结纯值并给出建议；
`src/services/inventory/recommendation/warehouse_calculation_inputs.py` 从账号一致读事务冻结专用业务请求；
`src/services/inventory/recommendation/warehouse_recommendation.py` 只消费该请求并编排公共评分、蓝图和分配内核，不重新打开账号；
`tools/warehouse_recommendation_trial.py` 读取离线账号中已保存的同一规则方案，冻结静态输入、检查来源未变并导出结果；
`tools/warehouse_recommendation_report.py` 生成可筛选的本地报告。推荐本身不连接游戏；仓库 UI 直接投影本轮有效目标。
独立窗口和后台所有权位于 `src/features/inventory/warehouse/management/`；前序决定位于
`src/domain/equipment/warehouse/warehouse_decisions.py` 与 `src/services/inventory/recommendation/warehouse_predecessors.py`。
不可变请求归 `src/domain/equipment/warehouse/calculation_input.py`，DAO 独占只读连接、相关域指纹和关联检查。

试算建立全部可计算角色的正向及反向顺序、逐个角色，以及启用的已保存配装偏好最新版本的冻结方案；正向方案复用本次已建立的基线，不重复求解。
智能基线在前序决定之后建立；按最终目标计算移除集合，包含原已弃置且本轮没有恢复目标的物品。逐角色检查有效性、原有空幕是否仍可配齐及基础评分不下降，不用总分提升抵消个别角色损失。
整份已验证方案的装备均仍保留时，复用其可行性证据；只有受移除影响的范围才重新求解。证据记录明确区分原方案保留、复算方案保留及本轮复算。
发现损失时按需撤回相关装备的自动弃置，再验证；分配重排导致仅补本角色不足时，补回受影响范围内原方案所需装备。最多四次补回后仍有损失则禁止采用。
损失修复不覆盖前序决定；智能区内明确条件弃置与见证冲突时保留失败原因，提示调整规则。取消、超时、证据缺失或求解失败不生成成功证明。
校验后的必要保留可超过目标数量。预览后在仓库人工调整状态时，仍须满足整批必要保留；撤销必要恢复后，正式派发入口会阻止相关弃置，要求重新生成。
撤销所有净状态差异不结束本轮预览身份；必要保留见证仍约束随后人工弃置，直至结果被替换、失效或任务完成。
原库存已经缺少某套空幕时明确提示原有缺口，不把它伪装成配齐，也不允许扩大已知缺口。

评分、批量评级、仓库匹配／质量评估／智能预览的组合与合法图纸搜索，以及无通用属性限制的角色优先求解复用正式 Rust 核心；该求解器具有保守上界剪枝。默认套装图纸按实际参与角色批量提交，同一冻结输入的完整结果复用缓存；截断、取消或组件异常不回退 Python 搜索。评分缓存逐次校验目录内容及顺序，但不重复深复制并序列化整份目录。Python 保留账号冻结、规则分阶段裁决、状态保护、补回证据与事务，不另写评分公式。
已保存配装偏好的组合图纸及见证求解同样使用 Rust。当前组件缺少通用属性上下限、旧暴击阈值或档案策略所需能力时，该见证标为未验证，智能环节不产生依赖该见证的弃置。
报告分别记录原始已装备分数、全仓方案、移除后证据、原游戏状态、模型建议和实际新增动作数量。
搜索有界且角色优先，不宣称全局最优、任意顺序或未来角色均有足量装备，也不把基础评分不降解释为所有战斗条件下伤害不降。


## 验证边界

仓库分、首次评级和建议预览通过同一正式入口，在一个 SQLite 只读事务内物化完整选定库存及运行状态、
角色养成与权重、当前方案锁、作用域规则与匹配；智能预览另固定启用偏好的确切最新版本和全部约束。
角色目录及其嵌套详情借用同一账号读取 owner，不在读取期间另开账号连接混入新版养成。
请求以不可变值保存，每个消费者取得独立投影；搜索不持有账号连接，也不重新读取“最新数据”补齐输入。
不创建兼容账号数据库，不搬运无关历史方案、旧背包、停用偏好或战报域；原账号历史及方案来源不删除、不改绑。
当前锁保留原方案 ID、来源和真实装备 UID；仅保护归属不需要复制该来源的整份旧背包。

读取检查当前完整性、数量及实际消费域的外键关联；没有正式当前指针或当前不完整时，不借旧快照补齐。
读取完毕释放账号；自动同步可以继续写入，写入不使本次读取从头开始。取消或失败不发布半份输入或草稿。
指纹覆盖永久养成、权重、世界加成、当前方案锁及启用偏好的最新版本，规则和匹配另做精确比较；
追加无关历史不使建议作废，相关变更、库存／状态变化和账号代次失效仍撤销交付与保存资格。
未明确物化偏好保护的请求不进入智能配装检查；资料不足和约束失败仍阻止弃置，不假装完整。
现有手动／评分／智能顺序、全角色／逆序／单角色／偏好见证、损失补回和派发后验流程保持不变。

现有专项覆盖算法保护、批量移除、来源快照、输入变更、配置保存、取消和预览草稿；真实仓库副本用于离线试算。
合成专项覆盖发行全部套装的明确空幕组合、含两格形状的七类优秀驱动大量重复、空库存、装备不足、少角色和丰富库存；
整批移除使用公共评分与分配内核复算，不用另一套简化公式代替生产评分。合成蓝图用于验证库存分配边界，不等于全角色真实蓝图验收。
尚未以真实游戏派发验收，也未宣称任意未来角色或任意角色优先级下全局最优。实际约束无法由正式见证求解覆盖时，不推荐弃置。
配置隔离、迁移备份恢复与新旧账号包往返使用临时合成数据库验证；三主题和长语言补丁的 Qt 合成专项不等于实际混合 DPI 验收。
更广泛仓库验证与发布门禁统一见[管理拆分与预览](../roadmap.md)。
