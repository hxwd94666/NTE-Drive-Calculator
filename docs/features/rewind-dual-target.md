# 倒带推荐：兼顾模式

## 范围与入口

工具 → 倒带推荐 → 兼顾模式。低分组和高分组分别维护角色、每名角色的一份计算配装槽位、
每件驱动的目标等级或自选百分比。分组由用户明确选择，不按当前评分自动分组，不要求低分组目标低于高分组。
角色不能同时加入两组；在同一头像选择窗口切换分组并编辑槽位，取消不提交本窗草稿。
其他两种模式继续使用原有名单、目标与槽位偏好。

打开、切换分组或更改目标不求解；只有“生成推荐”发起本次计算。目标或选择变化使旧结果失效。
无效输入、取消、账号切换及来源变化不覆盖已保存方案，迟到结果不写入新账号。

本模式找的是两组都需要的驱动**形状**，不是同一装备可以多人共用。套装、主副词条仍可能不同。
不预测掉落概率、词条收益、所需抽数，不搜索库存最优，不执行角色装配，也不改变基础评分公式。

## 冻结输入与缺项处理

UI owner 冻结账号代次、两组目标和所选 `slot_id/plan_id`，Service 一致读取当前完整库存、静态身份、
所选方案及其各自的 `source_snapshot_id`。当前库存只提供拥有数量，不补全保存方案的缺项。

每组至少一名角色、每名角色只选一份方案；所选槽位归属错误、归档、方案变化、驱动布局不完整、
理论占位、真实 UID 重复、来源不完整或逐件缺分时整体报错。未选备用槽位不参与。
逐件分数使用保存的 `assignment_scores` 或保存 assignment 自带分数，零分有效，缺失不补零。
没有可证实的同口径历史输入时要求重新计算保存，不按当前权重重评历史方案。

`DualTargetRequest`、`GroupTarget` 和结果是不可变输入/输出；形状与面积以正式静态资料为准。

## 缺口与共同候选

等级比例和目标换算复用[倒带公共规则](../features.md#7-倒带推荐与执行)：

```text
本组目标分 = 本组比例 × 驱动面积 × 10
缺分 = max(0, 本组目标分 − 保存的逐件分数)
归一化缺口 = 缺分 / (驱动面积 × 10)
```

只将正缺口按正式 `shape_id` 聚合为每组的缺件数、累计归一化缺口及涉及角色。
共同候选是两组**正缺口形状集合的交集**；已达标驱动和卡带不参加。

某形状在每组的需求占比为该形状累计归一化缺口除以该组全部正缺口。
共同权重取两组占比的较小值；次级按两组该形状归一化缺口总量降序，最后按正式形状 ID 稳定排序。
因此面积大或角色多的一组不会仅靠原始分数或人数独占首要权重。

先给每个优先共同形状一槽，超过八种时只取前八种并列出未覆盖形状。
剩余槽位逐次按以下边际值分配：

```text
共同权重 / (已选次数 + 1) / [增加一槽后的同形状总费用 − 当前同形状总费用]
```

每种形状数量不超过两组实际缺件数之和；费用复用公共定价精确重算。
无共同候选、某组全部达标或实际需求不足八槽时不添加无需求形状，不自动退回其他策略。
这是一种确定性的形状覆盖启发式，不宣称概率最优、最高伤害或毕业保证。

## 展示、保存与执行

培养策略旁的问号只用三段短文解释三种模式的推荐方向，不夹带评分公式或操作提示；兼顾模式按钮不重复弹出文字悬浮。低分组/高分组标题加粗并放大；培养策略下方以与自动装配一致的提示卡解释“两组都缺少的驱动形状”，只在兼顾模式显示，不混入其他模式。
窗口在初次构建完成后按屏幕限位，之后切换模式或生成结果均不主动调整窗口大小；结果内容超出可用空间时在内容区滚动，用户手动调整的尺寸不被模式切换撤销。已保存八槽及草稿语义不变。
两个紧凑分区分别显示组名、已选人数、与少角冲分一致的“选择角色”入口和目标控件；培养策略行放在两个分区下方。目标按每件驱动，不是整套评级或轴伤毕业率。
生成后结果区只显示标题与八槽；没有共同缺口时标题说明直接提示。“清空候选”左侧的“共同缺口”按钮只在本模式出现，仅对最近一次未失效的生成结果可用，打开只读弹窗：
顶部四个指标块依次为共同缺口形状种数、两组各自“未达标件数 / 已检查件数”和按当前八槽计算的费用；推荐后手动调整或仍有空槽时在指标下单独提示。
下方以大图形卡片为主体：“两组都缺 · 推荐范围”按共同权重顺序排列，每张卡片显示放大的形状图、“N 型驱动”、两组各自“缺 xx 分”或“已达标”，角标为当前八槽份数，受八槽限制未选入的标为“八槽已满未选入”；
“仅一组缺 · 不纳入推荐”用虚线卡片列在其后，解释未被推荐的原因；两组都达标的形状不列出。每行五张卡片；窗口按内容收紧高度，最多占屏幕可用高度的六成，超出时只滚动卡片区。弹窗不发起计算、不改八槽，不展示逐件明细或槽位/方案/来源快照编号。
手选驱动弹窗中的缺分／多分为两组合计，规则见[倒带公共规则](../features.md#7-倒带推荐与执行)。
八槽卡片仅在本次共同需求存在时显示“缺件”，已保存方案或手动添加的形状只显示库存与池份额。
窗口初始高度在原紧凑八槽基础上略增，普通屏幕正常字号下八槽无需滚动；屏幕不足时仅由外层结果视口滚动，不嵌套第二层滚动区。底栏仍在外层靠右；文案使用冻结目录，变量按纯文本，语言补丁同批维护。

八槽编辑区复用原控件。用户可明确补齐空槽或修改形状；此时显示“手动调整”，总费用按当前编辑重算，
缺口诊断仍属于原推荐，不伪造手动添加形状的共同需求。原推荐及来源对象不被改写。
只有八槽齐全且结果未失效时才能保存。清空全部候选是明确开始新的手动草稿，不再冒充算法推荐。

### 三策略独立保存与旧版升级

三种策略均在当前账号 `application_setting_copy` 中独立保存，不再共享目标、执行选项或八槽：

| 记录 | 所有权 |
| --- | --- |
| `rewind_strategy_ui` | 仅当前显示的策略 |
| `rewind_strategy_balanced` | 全面均衡的角色、槽位、目标、草稿、执行选项与已保存方案 |
| `rewind_strategy_focused` | 少角冲分的同类独立配置 |
| `rewind_strategy_dual_target` | 兼顾模式的两组配置及同类独立数据 |

每份策略有结构版本、并发修订、`draft`、`execution_options` 和 `saved_plan`。改名单、目标、槽位或八槽编辑内容自动保存本策略草稿，只有显式保存方案才替换已保存八槽；清空候选也只清空草稿。切换前保存旧草稿，随后恢复新策略的草稿和方案，不隐式求解。关闭重开仍恢复各自草稿；未保存的生成结果缺少活动预览时要求重新生成，手动草稿保持手动身份。

账号升级到当前 schema 时先做 SQLite 一致性备份，再在单一迁移事务内把旧 `rewind_recommendation` 与 `rewind_dual_target` 合并成一个冻结初值，深拷贝成三份**完全相同、彼此独立**的记录，不新增归属选择、认领或确认步骤。已有共享八槽优先，只有共享八槽缺失才采用旧兼顾八槽；已有两组原样保留，缺两组时按原培养/冲分名单映射，交叠角色只进入高分组，原始完整名单仍保留。旧来源不伪造为本次生成。

三份与迁移版本一起提交，成功后删除旧设置 key，只读写新结构。失败保留旧配置与旧版本，修复后可重试；后续启动不再次复制。更早 JSON 在空新库初始化之后导入时，仅能填充三份均未编辑的空初值，已编辑的新配置优先，旧 key 不长期残留或双写。实际账号在下次打开时升级，本次专项仅使用合成账号库。

单策略保存按修订比较并原子替换，并发旧草稿、取消或账号代次失效不覆盖现有方案，不影响其他策略或其他账号。旧库降级需退出应用后从升级前一致性备份恢复；先保全新版库，不能直接让旧程序读新版库。

生成方案保存时在单一写事务内复核静态身份，并把预览冻结的库存快照、所选槽位/方案/来源、两组目标与八槽一并覆盖保存；
生成后库存或所选配装更新不阻止保存。取消或提交失败整批回滚。再次保存或重新打开后保存，仍原样保留其原冻结来源，不隐式降为手动方案。
已保存推荐同时保留原分组/目标；重新打开后若草稿已不同，仍要求重新生成保存，不把旧方案称作新目标的结果。
已有生成方案应用到倒带前，在入口及创建输入资源前再次复核冻结身份及目标；库存或所选配装更新时逐项说明并经本次确认继续，静态资料变化仍停止。三个模式共用的确认与执行边界见[倒带推荐与执行](../features.md#7-倒带推荐与执行)。
手动八槽使用原显式倒带确认与工作模式门禁；本模式不新增权限或自动操作。
这些动作只保存倒带偏好，不修改库存、计算配装、角色或游戏状态。

## 实现与证据边界

- Domain：`src/domain/rewind/dual_target.py` 负责纯缺口、排序与八槽启发式。
- Service：`src/services/rewind/dual_recommendation.py` 负责一致读取与来源门禁，复用 `RewindLoadoutReader`。
- 独立保存：`src/services/rewind/preferences.py`、`src/storage/sqlite/accounts/rewind_migration.py` 负责修订、单策略事务与一次性迁移。
- UI：`src/features/toolbox/rewind/dual_ui.py`、`dual_role_picker.py`、`dual_results.py` 负责草稿、单窗分组和结果解释。
- 形状余量：`src/domain/rewind/shape_overview.py` 纯聚合与排序，供手选驱动弹窗的缺分／多分（三种策略）与 `dual_overlap_dialog.py` 的“共同缺口”弹窗使用。
- 原两模式公式与求解器不变；本聚合留在 Python，不新增依赖或改变 Rust 组件。

源码专项覆盖范围及剩余真实验收见[兼顾模式验收](../roadmap.md)。专项与模拟输入不替代真实游戏后验确认。
