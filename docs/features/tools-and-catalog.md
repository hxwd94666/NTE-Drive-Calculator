# 工具与游戏资料库


工具页提供只读“游戏资料库”入口和“养成计算器”。资料库页面在每次刷新时冻结发行静态库的 dataset、schema、importer 和构建
时间；查询前重新核对发行身份，更新发生后要求刷新。安装独立 `reference` 图鉴包时，角色、弧盘、空幕与驱动、
怪物与玩法使用该包；战斗机制与战报继续使用完整游戏库。一次请求冻结各领域的明确数据集，不在同一领域内逐行回退。
仅有 `role_page` 包时只切换角色与弧盘图鉴。首页展示角色、弧盘、
空幕与驱动、怪物与玩法、战斗机制五个游戏化档案入口，不提供“全部”、逐表覆盖总览、资源动画或来源追溯
入口。战斗机制图鉴只展示四类中文伤害公式，不把技能、GA、GE、Buff 或反事实覆盖拆成卡墙条目；schema 覆盖
审计、资源关系、反事实矩阵和来源追溯保留为内部能力，不作为玩家界面。

角色页速览展示至 80 级。技能按普通攻击、E、Q、QTE 和正式存在的 G 组成整行列表，允许编辑 1–10 级，
点击本行向下展开当前等级的正式倍率。正式主动技能逐条保留，不因效果标签为空或重复而隐藏、覆盖；其后展示
来源表绑定的培养被动与固有能力，点击展开中文说明，解锁条件未提供时保留未知，不伪造可编辑等级。
图鉴展示不依赖战报可计算被动名单。养成只分等级养成和技能养成。觉醒玩家顺序为一觉至六觉、三觉、六觉，内部
仍保留正式普通效果与共鸣类型。弧盘页展示升级经验、面板、突破成本和混频技能。轨外之境展示全部编号
配置，环线名称和 Buff 说明直接来自赛季配置；没有限时任务也可展示。没有正式开放时间的配置单列为未提供排期，
仍展示层、半场、怪物池、正式中文名和本次出场公式画像，不凭编号推测当前期或日期。图鉴中的 Buff 文字不代表已接入战报计算。
怪物卡片按正式出场成员消费其 `profile_set + pack_id`，不被缺少默认画像的通用模板覆盖。怪物身份不按中文名猜。
对象关系优先在当前详情直接渲染；缺少正式记录时省略入口，不生成失效跳转，也不把
unknown/unavailable 显示成 0 或倍率 1。详细边界见[游戏资料库](../reference/static-catalog.md)。

角色与弧盘养成页只汇总升级、突破、技能和混频所需材料，不提供活力计算。已发布发行静态 schema v36 保存人物
逐级经验、突破阶段及成本、经验书规格与方斯消耗，以及弧盘经验染剂的单件经验和使用方斯；角色页按“先最少经验溢出、再最少本数”汇总经验书，
并可选择是否计入沿途突破。技能页直接汇总正式逐级 cost。安装独立角色目录时，养成计算器的单角色与多角色模式统一读取该目录的角色、弧盘、养成材料、副本和同套图片；整包未安装时统一回退到完整游戏库，不跨数据集混算。工具页的养成计算器是工具模块内的整页功能，
从工具首页进入并在页内返回，不再打开计算器弹窗；页面只有一个纵向滚动面，角色和弧盘仍使用图片卡片选择器。
角色页已保存的人物、弧盘等级/突破及技能等级会自动预填；单角色页的人物与弧盘各用头像、名称及当前/目标状态卡展示，参与开关保持在卡片右侧。技能目标在标准宽度每行两项、宽屏每行四项，窄窗口降为一项。单角色与多角色的已选头像按屏幕像素比从源图一次缩放；源图像素不足时不放大，多角色与单角色选择器同样按屏幕像素比显示角色和弧盘图片。
角色选择器按显示名称去重并保留目录中的首个正式角色，再按首个有效字的拼音首字母 A–Z 排列。技能按 A、E、Q、QTE 等正式输入分类显示，结果分别列出人物升级/突破/技能及弧盘升级经验、突破消耗后合并成总材料清单。单角色和多角色的当前/目标箭头与技能分类标记共用高对比配色，白色主题下用浅蓝底、深蓝字和明确边框。角色养成、弧盘养成和技能目标各有独立的图形开关，关闭后保留当前
输入供再次开启，但不进入本次计算；混频效果不影响本工具的养成材料数量，不作为输入或成本。schema v36
从正式物品目录规范化弧盘经验材料的单件经验与使用方斯，并按“先最少经验溢出、再最少件数”换算；升级、
突破和合计均以正式材料图片卡片展示。计算结果先显示按正式物品 ID 合并的合计；材料卡片按可用宽度在
1–5 列间重排，不产生横向滚动；标准窗口每行显示五个材料。卡片只显示图片、名称和数量，不重复展示品质。
“已有材料”区为本次草稿中的每种合计材料及可用于上合的低档材料提供手工数量；点击材料卡后自动全选原数值，直接输入数字，框内不显示加减按钮；其他卡片显示已填数量，鼠标滚轮只滚动页面、不改变输入值。修改后标记原结果过期、暂时关闭复制清单，只有点击“重新计算”才从“仍需合计”和复制清单中扣除；材料卡使用固定绘制面和单个可复用数字编辑器，结果回调只更新材料数据，不按材料数量批量创建或销毁输入控件；
它不写入账号背包。页头“材料范围”可选“全部 / 仅体力”，单角色与多角色均默认“仅体力”；该模式的合计、明细和复制清单只显示本次冻结的正式副本档位中单次体力大于零且确定掉落数量大于零的非方斯材料及其可按 3:1 上合取得的高档材料，已有数量区额外显示这些需求材料可上合使用的低档材料。“全部”仍显示方斯等完整材料。其他材料仍保留在完整计划中，不因切换而删除已填数量；切回“全部”恢复显示。切换只是结果投影，不自动提交重算；已有数量修改仍须点击“重新计算”。旁边保留禁用的“同步抓包（待接入）”入口，当前抓包装备快照未提供养成材料数量。
体力计算区提供猎人等级及允许下调一级的生效鉴别等级。工具按当前静态 dataset 的正式副本单次体力和确定掉落
计算最低体力及副本次数：“仍需合计”显示合并结果，每个角色升级、突破、技能、弧盘升级与突破模块分别显示自己的
最低/已知体力和副本建议。已有材料按明细顺序最多分配一次；方斯即使出现在副本附带掉落中也不作为体力目标，保留在“全部”材料清单中。
普通怪与世界 Boss 掉落物不属于材料副本体力规划，即使没有确定副本投影也不触发“部分材料不可计算”；只有本应由
材料副本取得却缺少确定掉落的数据异常才保留部分/不可用状态。逐模块体力不相加冒充合并最低值。
静态物品 ID 的同族 `_lv1/_lv2/_lv3` 关系用于内置 3:1 单向合成：只对白名单中的十五组三档材料扣减已有数量和规划确定副本掉落，逐级合成且不得拆借或重复计数。已有数量区同时提供需求材料与可用于上合的低档材料；未直接需求的低档卡标作“可合成材料”。多角色共享库存按目标顺序消费，合计另按合并需求独立求解。人物经验书和弧盘经验染剂依据正式单件经验值选取，不进行 3:1 转换。
数据完整时省略额外状态行，
存在缺口时仍明确提示。角色升级、突破、技能、弧盘升级与突破等来源明细默认收在单一“计算明细”折叠栏中，
明细材料同样每行最多五个；材料网格和明细分组只占实际内容高度，展开后各分组连续排列，不预留空白伸展区。
用户返回工具首页再进入时保留本次草稿、结果和折叠状态；账号 generation 或
静态 dataset 身份变化时丢弃整份旧页面并重新创建账号服务。页头提供可切换的单角色/多角色模式、重置和复制清单，
两种模式各自保留页面会话草稿。多角色模式通过“选择角色”一次勾选多个不重复角色，选择器提供“全选”“清空”；确认后的勾选集合就是生效目标，取消勾选会移除目标，取消弹窗不改草稿。角色数量没有人为上限；目标卡支持内嵌编辑和删除，不提供上移/下移。已保留角色维持原顺序，新角色按目录顺序追加；这一稳定顺序也是
共享已有材料的分配顺序。编辑与删除按钮同尺寸；点击“编辑”只展开当前角色，其他角色保持摘要。展开区按人物、技能、弧盘分区，技能等级使用宽输入框：默认窗口双列，足够宽的全屏窗口四列，窄窗口单列；弧盘展示当前数据集的图标和名称，更换弧盘时同步更新。在默认宽度下，弧盘图片、选择操作和当前/目标状态同排；更窄时才换行。角色目标、弧盘目标与弧盘选择块使用与当前状态相同的普通底色和边框，不另设强调色。公共体力设置、已有材料与计算入口仍位于角色列表下方。它一次冻结账号、generation、dataset、全部角色目标和公共输入，逐角色复用单角色材料公式，
再按正式物品 ID 合并材料与副本求解。跨角色合并体力是权威结果，逐角色及逐模块同时展示已有分配、仍需材料、体力和
副本次数；合并副本可同时覆盖多角色材料，并展示相比分别刷取节省的体力。逐角色材料网格及模块明细仅在展开该角色结果时创建，收起状态只显示摘要；结果导致的页高刷新合并到一次事件循环处理，避免无上限角色列表在结果展示时集中创建隐藏控件和反复重排。首次计算后，目标集合或档位变化以 250ms 防抖提交末次请求；已有材料修改会取消待提交请求并使旧结果失效，在用户点击“重新计算”前不再自动求解；同一时刻只运行一个求解任务，迟到结果及账号/dataset 过期结果不展示。静态 dataset 身份只使用
路径、大小和修改时间，不把可能因只读查询变化的访问时间当成更新。点击计算后，按钮自身改为“正在计算中”并暂时禁用，不在
按钮外增加挤压宽度的状态标签；完成或失败时页面自动定位到结果区。养成页的等级、技能和已有数量均为纯数字输入，不进入
第三方中文输入法组合上下文；角色与弧盘图片选择器的拼音搜索也使用直接拉丁输入、关闭输入法组合上下文，关闭选择器后延迟销毁而不留在工具页下作为隐藏子窗口。多角色求解结束、计算按钮重新启用后才把焦点移至该按钮；替换结果期间暂存即时滚轮输入，待全部旧结果销毁且新布局高度稳定后再自动定位并应用滚动，不使用固定长延时；切换页面或收到更新结果时丢弃过期定位回调。关闭页面时仍在运行的求解线程由独立收尾引用持有至结束，不随页面销毁。重复计算且材料身份未变时复用原有数量编辑器，结果替换使用原父级内的延迟销毁，不把旧结果
临时变成顶层窗口。养成体力的 SciPy/HiGHS 求解在可重启的独立子进程内运行，断连和超时只使本次计算失败，
不发布部分结果；第三方输入法异常另由启动参数 `--ime-compat` 提供显式进程级兼容模式，需在首个窗口创建前启用，
会停用本应用内中文输入。正常启动保留原有输入法。两条原生异常边界分别验收，控件焦点与滚动时序不作为已修复证明。详细 contract 见
[多角色合并与已有材料分配](../reference/progression-stamina-calculator.md#多角色合并与已有材料分配)。
旧 dataset 没有该表时保留升级经验和具体缺口，
不使用常量补齐。
当前游戏 dataset 由已发行 v31 基线执行受控增量迁移：既有来源文件和未授权旧表逐表哈希保持不变，只消费与
基线 `source_row` 行哈希一致的正式物品/角色行，并重新生成受影响的毕业模板；这条迁移不把独立图鉴数据或
异版本战斗资产拼入完整游戏库。
计算器只读取账号角色数据；已有材料属于页面草稿，不读取或写入账号背包。所有入口均不直接读取外部 JSON；
最低体力只通过[养成体力规划](../reference/progression-stamina-calculator.md)的确定产出 contract 计算，缺少规范化记录时
明确保留数据缺口。
