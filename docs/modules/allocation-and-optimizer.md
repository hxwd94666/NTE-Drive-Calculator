# 计算与优化器

## 模块定位

在固定背包快照内，为一组角色生成满足过滤、套装、优先级、锁和真实装备 UID 唯一约束的配装
预览。

## 当前能力

- 角色优先和平级组分配；
- 全局最优分配；
- 驱动副词条黑名单与顺序/一致候选池；
- 卡带套装、主词条、副词条硬过滤；
- 评分等级、暴击限制、账号基础权重和额外形状；
- 暴击率最小值是最终方案硬约束，未达标方案标记无效；暴击率上限包含固定基础 5%；
- 平级组暴击约束恢复按“仅换卡带 → 仅冻结图纸必需套装件并重选全部额外件 → 仅失败角色
  从零重配”执行；已经成功的同级角色不会因最后阶段再次计算；
- 失败角色从零重配会对全部语义不同图纸执行暴击区间包络检查，仅对区间相交的图纸进入
  有界候选搜索。方向候选仍遵守卡带套装/主词条、黑名单、副词条层和评分等级，暴击词条
  本身不会绕过质量门槛；
- `AllocationLockSnapshot` 在候选构造前剔除全部锁定 UID；
- 跨角色借装生成的虚拟占位槽评分固定为 0；再次替换该槽时按全部逐件评分重建方案总分，
  不在陈旧总分上直接叠加新装备评分；
- 计算方案同时保存总分和每个槽位的基础评分；历史方案缺少逐件评分时，替换入口会按当前
  角色全部满级装备重新补齐后再保存；
- 返回不可变 `WeightedAllocationPreview`；
- 保存前复核账号、快照、profile 和锁。

## 输入与输出边界

输入必须冻结账号、generation、`snapshot_id`、静态数据集、profile version 和配装锁。Optimizer 是
纯计算模块，不读取 SQLite、Qt 页面、当前账号或 Integration。

## 当前限制

- 当前评分不是队伍伤害模拟；
- 角色页动态直伤权重不写回基础权重；
- 最佳四人/八人和综合收益画像驱动优化仍属于后续版本计划；
- 保存只能使用原 Preview，不能重新读取移动中的当前状态补齐旧结果。

## 验证

主要覆盖 allocation、weighted-allocation、lock、replacement 和 dependency-boundaries 测试。
