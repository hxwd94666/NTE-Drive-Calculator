## 1. 显式启动批次

正式依赖方向为 `main.py → app.run_gui → prepare_application_runtime → Qt 入口 → MainWindow(runtime)`。
原先导入主窗口时发生的目录探针、共享库准备、账号初始化和路径环境接线移到显式入口，
账号管理器与主题服务随运行期依赖注入。旧模块级账号对象及其窗口消费者已移除。
日志导入不建立文件 sink，显式开启常驻/详细日志仍保留原生命周期；含大括号的目录按字面路径处理。

### 已取得的证据

- 新进程冷导入阻止目录创建与 SQLite 连接，确认 NTE 路径环境未改变；PySide 自身的 PATH/枚举初始化不属于账号路径接线。
- 隔离目录中显式准备默认账号；打包路径解析与不可写安装目录回退、探针清理、权限确认顺序及失败后的环境恢复有用例。
- 常驻与详细日志在含大括号目录中均可写入，关闭详细日志后常驻日志保持。
- 启动、输入法兼容、日志、账号上下文、扫描/鉴定依赖边界和更新专项：45 项测试及 4 项子测试通过。
- Ruff `E9/F63/F7/F821/F401` 对主入口和自有源码、工具、测试通过。
- 原文件、完整补丁、修改后文件及哈希已保留；独立源码镜像的补丁应用、7 项启动行为用例及源码回退通过。
  回退后的冷导入重新触发旧行为保护断言，且旧文件字节完全还原；本机记录保留每条命令与预期退出状态。

## 3. 基础权重业务与事务部分

`BasicWeightDependencies` 移到 Domain，Feature 只保留冻结工厂；Controller 的目录解析及多字段 SQL 编排
迁到 Qt 无关的 `BasicWeightService`。主角基础权重来源映射、默认值可刷新、无改动保存不冻结默认值及历史评分语义保持。
单项权重与页面整批保存使用同一准备/应用规则，DAO 在一条连接上拥有外层事务与内层保存点。
全部字段先校验再写入；后续 SQL 失败回退完整批次。批量重置、自建角色/底盘/种子初始化同样原子提交。

实际证据：

- 修改前四个反例均失败：后续校验失败、后续 SQL 失败、种子初始化失败及第二角色重置失败均留下部分事实。
  修正测试夹具连接关闭后仍为四项失败，无夹具清理错误。
- 修复后的权重、保存/重置、保存点、账号生命周期、异步草稿/离页、主角身份及分配上下文专项：63 项测试与 4 项子测试通过。
- 保存点专项验证外层提交前其他连接看不到写入、外层失败整体回退、内层失败只回退其范围，以及无改动刷新不撤销外层写入。
- 多字段正常保存和异常输入覆盖权重、底盘、默认套装及额外形状；关键形状/权重数值保留有限数值校验。
