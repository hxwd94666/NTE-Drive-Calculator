# Windows 人工验证清单

本清单只用于必须依赖真实 Windows、游戏、驱动或人工观察的场景。自动化测试能够覆盖的
内容不在这里重复执行，也不要求安装 4K 设备。

## 使用方式

- 推荐先从源码仓库运行半自动验证器；它只收集只读证据并引导确认，不会操作游戏：

  ```powershell
  python tools/windows_validation/run_validation.py --profile all `
    --account-db <账号数据库路径> --log-dir <账号日志目录>
  ```

- 只检查环境、静态库哈希和报告输出时：

  ```powershell
  python tools/windows_validation/run_validation.py --non-interactive --profile startup
  ```

- 报告写入 `build/windows-validation/<timestamp>/`，不进入安装包，也不自动上传。
- 普通功能提交：执行“基础检查”与本次改动对应章节。
- 扫描、装配、nte-core、更新或账号生命周期改动：额外执行对应高风险章节。
- 正式 Release：执行全部适用章节；当前机器无法满足的项目标为“不适用”并说明原因。
- 本文件不要求随每次测试提交修改；维护者可以复制到 Release 记录或本地检查记录中填写。
- 涉及装备状态写回或装配的项目不会自动撤销，执行前确认测试方案和目标角色。

## 协作分工

- 开发代理可以执行非交互预检、生成 profile 命令、读取脱敏报告，并根据日志、SQLite 摘要
  和文件哈希分析失败原因；
- 半自动验证器可以收集证据和提示下一步，但不会操作游戏、安装驱动、修改装备状态或确认
  真实 UI 是否正确；
- 维护者负责管理员启动、真实游戏操作、驱动/插件判断以及通过、失败或不适用的最终标记；
- 维护者完成操作后，可以把 `build/windows-validation/<timestamp>/report.md` 的路径或内容
  提供给开发代理继续审查；
- 只有自动证据与维护者人工结论都完成时，才能把对应 Windows 项目标记为通过。

结果标记：

- `[x]` 通过
- `[ ]` 未执行
- `[失败]` 失败并在备注中记录现象和日志文件名
- `[不适用]` 当前设备或改动不涉及

## 10. 配装冻结值与倒带推荐

- [ ] 分别准备一个 nte-core 稳定快照和一个视觉扫描快照，检查同品质卡带主词条。
  - 预期：配装计算、保存方案、配装卡片、空幕属性汇总和角色属性汇总使用满级主词条口径；视觉快照
    缺少原始数值时仍展示并计算出相同的品质折算值。
- [ ] 保存含卡带的计算方案，重启应用并打开该方案。
  - 预期：方案 payload 中冻结的卡带主词条值被恢复；不因快照一级数值或运行时目录变化而漂移。
- [ ] 在一个账号选择培养角色、冲分角色、策略和目标评分等级，关闭后重新打开工具。
  - 预期：只恢复当前账号的倒带偏好；切换到另一个账号不会带入这些选择。
- [ ] 使用含低于目标评分驱动的已保存计算方案生成全面均衡和少角冲分推荐。
  - 预期：缺口只累计低于目标等级的已保存逐件评分，且方案按自身来源快照解析装备；超过八件时提示
    使用随机倒带或降低等级，不产生伪八槽方案。
- [ ] 生成低存优先推荐，并核对八槽重复、命中概率和价格。
  - 预期：低存优先给库存最低的八种不同形状；其他两种策略的重复数量、`12.5% × 重复次数` 和
    价格满足 8 种不同=80、4 种各两次=120、8 槽相同=360。
