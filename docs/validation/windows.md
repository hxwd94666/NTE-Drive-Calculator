# Windows 人工验证清单

本文件统一保存依赖真实 Windows、游戏、驱动、插件或人工画面判断的验收步骤。自动化测试已覆盖的纯规则
不在此重复。维护者按改动范围选择章节；Release 执行全部适用章节。

## 1. 使用方式

只读验证器不会发送游戏输入：

```powershell
python tools/windows_validation/run_validation.py --profile all `
  --account-db <账号数据库路径> --log-dir <账号日志目录>
```

只检查启动环境、静态库和报告输出：

```powershell
python tools/windows_validation/run_validation.py --non-interactive --profile startup
```

报告写入 `build/windows-validation/<timestamp>/`，不进入安装包或自动上传。真实操作产生副作用时，先准备
测试账号、目标角色和方案；报告记录通过、失败或不适用，不把未执行项目计为通过。

## 5. 视觉与手柄全量扫描

### 5.1 报告与数据库交叉检查

```powershell
python tools/windows_validation/run_validation.py --profile vision `
  --mouse-scan-report <账号截图目录\mouse_scan_last_report.json> `
  --account-db <账号目录\user_data.sqlite3> --log-dir <账号日志目录>
```

- [ ] `mouse-visual-runtime`、`mouse-visual-scan-report` 与 `mouse-visual-current-snapshot` 全部为 `passed`。
- [ ] 报告 `inventory.expected == inventory.captured`，分页索引连续，当前账号快照为 `source=vision`、
  `capture_driver=mouse` 且数量一致。
- [ ] 报告只含分辨率、profile、预检、分页、滚轮、数量、耗时和安全终止状态。

### 5.2 鼠标扫描

- [ ] 使用当前设备分辨率执行三次同一库存全量扫描；人工数量、报告数量和账号快照数量一致。
- [ ] 首屏扫描 4 行，后续页新增 3 行；不足七件的末行不点击空槽。
- [ ] 分页使用 A profile，每第六次翻页使用 B 累计补偿；无重复、漏图和错位点击。
- [ ] 首帧处于错误页签、未加载或被遮挡时，预检在首次点击前停止。
- [ ] 串行和双线程解析生成相同装备内容指纹；双线程队列无乱序和丢项。
- [ ] 在点击、滚动和解析积压阶段分别按 F12；鼠标键释放，任务停止且不创建新当前快照。
- [ ] 扫描中改变窗口尺寸、焦点或账号 generation；任务停止，旧当前快照保持。
- [ ] 鼠标和手柄先后完成全量扫描；账号库始终只有一个 current 快照，结果不合并。

项目支持 1920×1080、2560×1440、3840×2160 的坐标映射测试；实际硬件只记录本机可用分辨率，不把
模拟缩放当作实机输入验证。

### 5.3 扫描后锁定/弃置管理

- [ ] 使用本次扫描的管理配置生成计划；执行顺序按索引倒序，未计划装备不被点击。
- [ ] 普通、锁定、弃置之间的直接切换均在动作前后识别正确图标。
- [ ] 锁定 → 弃置时确认弹窗出现、确认后消失，最终图标为弃置。
- [ ] 人为制造操作前状态不一致；当前目标前停止，后续目标不继续。
- [ ] 人为遮挡详情、移动窗口或触发 F12；输入停止且生成 `mouse_state_sync_last_report.json`。
- [ ] 完成后打开视觉仓库；临时 UID 仍保持只读，仓库不提供延后状态写回。

## 6. 计算、自建角色与配装槽位

## 9. 倒带推荐与实验执行

- [ ] 在账号 A 保存培养角色、冲分角色、策略、目标等级和八槽方案；账号 B 不继承这些偏好。
- [ ] 使用活动槽位方案分别生成“全面均衡”和“少角冲分”；逐件评分来自方案 payload，装备按方案来源
  快照解析。
- [ ] 超过八种正缺分形状时返回提示；不生成局部伪方案。
- [ ] 核对八种不同=80、四种各两次=120、八槽相同=360，以及每槽 12.5% 概率。
- [ ] 清空当前候选后重新打开；账号已保存八槽仍可恢复，库存数量从当前固定快照刷新。
- [ ] 执行输入链前人工打开倒带首页并记录分辨率/DPI。
- [ ] 每个品质先切换难度，再读取该难度余额；不同难度余额不复用。
- [ ] 初级按随机十连 600；紫/金定制从右侧十连价格区域读取，不使用单抽价格。
- [ ] 在难度切换、候选配置和十连循环中分别按 F12；后续点击停止。

## 10. 插件、环境、更新与发行

- [ ] 环境诊断分别显示 Npcap、nte-core、dwmapi、Mod Loader、VC++ 运行库、插件 presence、SDK 缓存和 IPC 管道状态。
- [ ] 在测试环境执行插件部署、备份和还原；失败保留原 DLL 和运行时 SDK 缓存。
- [ ] 代理 DLL 可加载的环境保持默认代理方式，启动游戏后 IPC v7 管道出现且 Loader 未启动。
- [ ] 代理 DLL 不会自动加载的环境先安全还原代理，再经 UAC 启动备用 Loader；游戏启动后 IPC v7 管道出现。
- [ ] Loader 运行时尝试切到代理方式；应用拒绝。停止 Loader 后确认本次注入的启动器退出，再允许部署代理。
- [ ] 取消 UAC、Loader 文件缺失、payload 缺失、VC++ 运行库缺失和停止超时分别显示明确错误，不报告加载成功。
- [ ] 游戏更新后按 [外部集成：插件发行基线与升级复核](../integrations.md#插件发行基线与升级复核) 验证 DLL 哈希、工作区、
