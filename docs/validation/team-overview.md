# 队伍简报与单独计算验证

## 证据范围

本轮必要专项覆盖队伍页操作、角色排序、语言回退、单队计算准备及其直接调用方。输入为隔离合成账号和发行公共静态／图片，不读取个人账号；正式分析组件只消费合成战报的只读接口。
源码专项、Qt 离屏、正式分析组件联调与用户实机反馈是不同证据；均不代替完整 core/full、干净安装或游戏计算验收。当前行为见[功能说明](../features.md#队伍配装简报)，剩余门禁见[路线图](../roadmap/team-overview.md)，真实 Windows 反馈统一见[人工验证](windows.md#队伍单独计算源码实机反馈)。

## 事务与副作用结论

- 正式角色 ID 映射必须唯一；缺失、自建或歧义不替换选人。四人同级只改会话选择与连接，保留套装、词条、弧盘、暴击偏好及永久优先级文件。
- 取消、关闭、旧回调、账号／队伍／用户草稿变化保留原草稿；确认后旧预览失去保存资格，不把旧输入结果当作新队伍结果。
- 真实弹窗联调通过随附分析组件核验完整阵容，使用原确认服务建立单队绑定；全过程账号 SQL 内容前后一致。没有优化器任务、游戏同步、游戏输入或装备保存。
- 修改包已重开核对哈希并执行界面／选人探针；补丁在隔离树应用后逐文件核对，回滚在隔离树恢复原始字节；真实工作区保持修改后状态。基线包含本轮开始前已有的未提交改动，不按 HEAD 整体回退。

## 真实账号隔离计时的覆盖边界

经用户指定使用源码当前账号，仅以 SQLite `mode=ro`、`query_only=ON` 打开原库并执行一致性备份；后续 DAO、读取、页面渲染和计时均在本机 build 副本上运行。备份期间及测量后当前账号选择保持一致；副本主文件测量前后 SHA-256 相同。没有读取其他账号库、调用游戏、修改原库或外发数据。

| 当前样本与阶段 | 测量结果 |
| --- | --- |
| 完整样本 | 同一当前账号，用户补齐后的1支四人队伍；4个绑定槽位、4/4齐全，实际物化32件装备；22个可见槽位、532件库存，无增强历史 |
| 一致性备份 | 约647 ms；不计入页面加载耗时 |
| 角色目录读取 | 首次约156 ms，重复约141 ms；每次一次完整静态身份校验 |
| 完整配装简报服务 | 314–335 ms；其中静态SHA-256约99–108 ms，库存物化约154–169 ms；来源冻结约182–198 ms为含库存的上层累计耗时，不与其重复相加 |
| 卡片构造 | 约16 ms |
| 真实异步 owner | 首卡约297 ms、收尾约301 ms；实际回填UI约0.3 ms |
| 取消及清空当前 owner | 刚提交任务时撤权约8.4 ms；另以读取入口事件和QThread运行状态确认已开始真实读取后，撤权至物理收尾约124 ms。两者是不同取消阶段，不作为真实换账号总耗时 |
| 未绑定对照 | 同账号0/4时服务读取128–141 ms、首卡约148 ms；没有物化装备，不能代替完整样本 |

完整与未绑定两份一致性副本独立保留，不覆盖原始测量。重复读取投影一致，各副本测量前后文件哈希相同。单队完整配装未观察到秒级卡顿证据，主要成本是正式静态校验与库存物化，本轮不据此新增生产缓存、跳过来源复核或更改业务逻辑。

页面渲染为离屏隔离宿主；角色目录、卡片构造和后台读取分别计时，首卡约297 ms不是整应用从点击到显示的总耗时。owner撤权也不冒充真实切换另一个账号。真实多队及增强历史分页仍缺样本，继续保留待验收，不以单队外推为多队性能通过。

## 发行输入的只读核对

新增单队计算模块的静态导入链、物理源码及9个语言key已核对；现有构建脚本从 `assets` 成套收集语言资源。以Python审计钩子限制普通导入，未观察到开库、联网或派生进程事件，也没有创建QApplication／窗口。先前源码专项对应的21份Python文件哈希保持一致；本轮没有以导入检查冒充新增专项通过。

根目录spec是忽略的生成物，事实源仍为构建脚本，不拿旧spec证明新包已经包含模块。此次不执行构建／安装；实际二进制依赖收集及干净安装仍待授权验收。用户再次确认只做专项，完整core/full继续保留待验收。

## 未覆盖和保留门禁

本轮没有执行完整 core/full、应用构建、安装、提交或推送。此前完整回归失败的最终收口、真实账号多队性能、Windows 目录发布间歇拒绝访问、混合 DPI／多屏及发行仍按路线图独立处理。原退役前平均毕业率的性能样本与全量统计不再作为当前通过证据。
