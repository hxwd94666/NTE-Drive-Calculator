# 队伍简报验证

证据适用范围：下文自动结果和性能数值来自旧队伍平均毕业率退役前的简报验收批次，不代表当前源码已复验。当前已按[新开发方案](../roadmap/team-axis-graduation.md)移除旧均值计算及显示；本次退役后的专项、硬静态及后续新指标验证均待运行。

## 范围与输入

本轮在 Windows 的本机 Python 3.11 环境运行明确文件模式的专项及静态检查。
质量命令均通过 `tools/quality/run_tests.py core --pattern PATTERN -j 1`；这里的 `core` 是入口参数，
显式 pattern 限定专项，不是完整 core。临时目录每次独立置于可写构建目录，保留全部成功和失败输出。
账号、库存、战报和命名均为合成夹具；正式静态及随附分析执行物只读消费，没有操作个人账号或游戏。

源码基线是本任务开始时的实际工作区字节，包含上一任务尚未提交的匹配成果，不用 HEAD 冒充干净基线。
逐命令 cwd、argv、环境输入、字面输出、退出码、文件哈希及隔离回退证据保留于忽略的
`build/team-overview-review/`，不将临时绝对路径或原始运行输出纳入公共文档。

## 已归因失败与环境观察

- 养成迁移旧夹具先创建当前库、只删除养成表和版本号，却留下后续队伍表，升级时报 `table team already exists`。
  实际任务起点的基线同样 2 failed、1 passed，退出 1。修正为真正创建 v44 的夹具，
  同时验证养成与简报两个升级前备份边界；现为 3 passed，没有放宽生产迁移或删除有效断言。
- 账号目录发布曾在不同用例的 `Path.rename` 出现 WinError 5。初次当前 4 失败，随后 3 失败；
  初次基线亦有此错误（另含未绑定静态的夹具错误），正确绑定静态的基线 15 通过，当前最终 15 通过。
  独立 48 次对照中普通文件、旧 schema、新 schema 各 12 次无失败；裸 SQLite 关闭后 12 次中 1 次初次重命名失败，
  诊断性 GC 后成功。此证据支持间歇目录占用，不证明占用者或最终根因；未修改生产目录发布、添加重试或跳过用例。
- 开发中的夹具路径、未导入名字等错误均保留在本地逐次记录，最终专项使用当前源码重跑。
