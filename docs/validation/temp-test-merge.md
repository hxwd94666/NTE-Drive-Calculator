# Temp 与目标分支合并核对

## 范围与历史

Calc 在 `test` 合入此前脱离分支的 `ed935b4e`，再合入 `temp` 的启动器识别和倒带缺分修复。
Analysis 在 `master` 合入 `temp` 的 `5cd6d99`，保留目标分支 `5744e92` 及其祖先的原生证据、觉醒边界和计时修复。
全部操作仅在本地，不推送、不改写双方历史，不触碰真实账号或游戏部署。

## 功能保留与冲突处理

| 边界 | 合并结果 |
| --- | --- |
| 队伍 | 恢复固定轴毕业率、理论参照、建议、结果历史、匹配与增强；保留对方双队轴伤和仓库推荐 |
| 分配保存 | 使用唯一 `batch_rows` 参数；混合保存同时核对优化与基础成员的完整构筑、作业身份和凭证，不放宽跨作业或单边保存限制 |
| 评分与工具 | 恢复卡带及驱动统一黑名单、卡带换回评分、Boss 估算、退出选择及界面调整；保留目标分支的统一 Rust 评分与局部刷新 |
| 战报模型 | 合并季节召唤标签、明音直伤分类、黑羽觉醒系数、争锋多目标与副本身份；菜单暂停不算技能时停，不从缺证据推完整结论 |
| 目标等级 | 明确的逐成员等级使用自己的正式属性包；无此证据时只匹配已知同级包，缺失成员保留未知，不凭另一档序号补造等级 |
| 迁移 | 历史 SQL 文件保留原义；规范构建保留目标分支 40–42，追加 43–44。只读消费者按真实表/列区分历史谱系，而非用相同版本号猜结构 |
| 组件 | 合并源码构建分析组件与采集 Core；EXE、清单、来源和许可绑定，保留目标分支已保护的 DLL 与签名字节以及 Temp 的 Loader 修复 |
| 公共图片 | 沿用目标分支素材和清单；移除仅大小写不同的重复技能路径，避免 Windows 索引身份冲突 |

固定的双端黄金样本不随组件版本改写；Rust 测试显式构造当前版本输入，生产历史身份检查仍严格执行。
旧主线缺少好感缺项表时，未证实的加成不重建为零；已确认的当前正式服角色加成继续按实际数据读取。

## 留维护者审查

静态候选尚未晋升。当前正式数据的原解包质量报告仅有已登记哈希，本轮未取得可重新核验的完整原报告。
不删除已有 `known_gaps`，不制造“源包未变”的新证明，也不通过省略审查配置绕过门禁。
保留当前主库、图鉴和公共素材的整套身份；缺口与完成条件只在[数据更新待处理项](../roadmap/game-data-update-gaps.md)维护。

没有为解决冲突而删除任一方的重要功能。完整 core/full、应用打包安装、混合 DPI 和真实游戏验收未在本轮执行；
显式受控文件样本的跳过项仍待对应验收，不将编译、清单通过或有限专项解释为完整实战覆盖。

- Analysis 的毕业理论、目标识别、召唤/觉醒、面板、队伍核验及两个新增谱系/未知边界专项通过；受控文件样本仍按原门禁跳过。
- 采集 Core 的两项正式角色同步、十一项原生时钟专项通过；仅重建组件，不构建桌面应用或部署游戏。

- Python 硬静态、源码空白检查、组件与公共素材绑定分别核对；未运行完整 core/full、应用打包、干净安装或真实游戏验收。

过程中的失败与修复复验保留在本机构建验证记录，不进入账号导出或发行包。典型问题包括：黄金样本版本绑定、同号静态结构碰撞、保存参数改名、缺少真实生产字段的测试夹具；均保留生产门禁后修正，不以删测或跳过掩盖失败。
