# 配装副词条黑名单：卡带与驱动统一规则

## 范围与行为

自选配置的副词条黑名单同时约束卡带和驱动，按角色冻结配置，不改变其他角色的候选。未启用零权重时，命中任一黑名单副词条即排除；只检查副词条，不排除同名卡带主词条。全部卡带被排除时保留缺卡，不静默放宽。

启用“黑名单为零权重”时，两类装备均可参与，但只有对应副词条权重为零，主词条和其余副词条仍按原公共公式计分。候选预热、单件公共评分、原生分配、最终评分复核及新旧装备对比采用同一冻结口径；新对比标识升级，旧保存方案与历史评分不重新解释。无需数据库迁移或重置偏好，已有黑名单在下一次显式计算按新规则生效。

## 修改边界

- Python：Top-K前候选过滤、顺序/最优卡带预分配、同级联合匹配、暴击换卡及修复合法边。
- 独立分析组件：卡带候选筛选、统一合法性谓词及恢复/后处理调用方；轴伤真实属性复核不再跳过卡带，防止评分标签漏项绕过黑名单。
- 公共评分核：零权重覆盖两类装备的副词条，不修改主词条权重。Calc的单件接口、批量适配、后处理及对比分数传递同一零权重集合，不复制公式。
- 缓存：卡带和驱动的评分键都包含零权重集合，同值最大分母的整数/浮点输入统一身份；批量预热、单件读取及切换屏蔽集合不会串分或取值失败。
- UI/文档：帮助与架构动作表明确两类装备范围；控件和配置字段不更名，不影响已有配置保存。
- 身份：分析组件按新版本、能力及执行物/清单双哈希区分，成套交付；旧预览需重新计算，不在运行中混用组件。
