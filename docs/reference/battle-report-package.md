# 战报包格式

战报导出文件使用扩展名 `.ntebr`。它是应用专用的二进制压缩容器，不是可直接打开的 JSON 或通用压缩包；
容器内部仍使用 UTF-8、自描述、版本化 JSON，便于应用做字段校验和后续格式迁移。该格式不提供密码学加密，
“应用专用”表示普通文本编辑器或压缩软件不能直接读取，不表示能够抵抗逆向分析。

## 容器 v1

所有整数使用网络字节序。固定头之后紧跟 zlib level 9 数据，不允许尾随成员或附加字节。

| 字段 | 大小 | 语义 |
| --- | ---: | --- |
| magic | 8 | `NTEBR` 加应用专用控制字节 |
| container version | 1 | 当前为 `1` |
| compression | 1 | 当前 `1` 表示 zlib |
| flags | 2 | 当前必须为 `0` |
| UTF-8 JSON length | 8 | 解压后的精确字节数 |
| compressed length | 8 | 紧随其后的精确字节数 |
| SHA-256 | 32 | 解压后 UTF-8 JSON 的二进制摘要 |

读取顺序固定为：检查文件大小与头部 → 检查容器版本、算法和长度 → 限额解压 → 校验 SHA-256 → 按 UTF-8
解析 JSON → 校验内部格式名、版本和账号库 schema → 校验每场记录的白名单表、外键图及原始摘要哈希。

## 内部 contract v2

顶层 `format.name` 为 `nte-drive-calculator.battle-report-package`，`format.version` 为 `2`。读取器只接受内部
contract v2；未经过产品验收的 v1 包不提供导入或转换入口。`bundle` 保存包 ID、导出时间、应用版本、账号库
schema、当前静态 dataset/schema/hash 和本次导出账号昵称。`manifest` 列明实际包含、
无法提供及导入时舍弃的内容；任何未持久化派生结果必须列入 `unavailable_sections`，不得静默省略。

`reports[]` 每项包含：

- 原战报 ID、采集/结束时间、玩法、上下半场范围、完整性与保留状态，以及最初来源账号昵称；再次导出导入
  战报时保留最初来源昵称，并另记本次导出账号昵称，不用当前账号覆盖来源；
- nte-core 原始聚合摘要、record、axis 元数据、逐击原始顺序/来源字段/原始行和时停区间；
- `frozen_build` 保存冻结角色养成、觉醒选择、技能、好感度、弧盘、空幕/驱动及词条；
- `saved_build_edit` 保存唯一战报角色修改副本及独立的 `is_active` 指针；配装覆盖是已复制的战报装备，不是
  账号活动槽位指针。只要副本存在配装覆盖，即使 `is_active=false`，导出装备仍优先采用该已保存校准；
- `locked_equipment_at_export` 保存每角色最终导出装备、来源种类和规范化 SHA-256。导入后该摘要写入装备锁，
  作为 Service 和 DAO 拒绝装备变化的依据；
- 用户确认目标、环境、生命/防御/抗性、争锋选项和魔女赐福；可用时还保存导出时自动反向匹配与生命投影，
  并标注它们是基于不可变证据重新计算、不是已持久化事实；
- 当前战报存在时保存详情范围、时间范围和角色筛选页面状态；
- `database_rows` 保存白名单战报表的精确可移植行图，作为读取功能的唯一数据库导入输入。

当前 v2 读取器明确接受账号库 schema 36 和 37，不按当前账号库版本做机械的严格相等判断。schema 36
战报缺少 `fork_breakthrough_stage` 时，导入到 schema 37 的 nullable 列保持 `NULL`，继续使用旧战报的
等级派生语义且不改写原始快照；低于 36 或高于 37 的包必须拒绝，新增 schema 兼容性需逐版审计后显式加入。

## 写出和导入

写出先在用户选择目录创建临时文件，刷新并同步后再次校验账号 ID、generation、用户库路径和静态 dataset，
最后使用原子替换发布；失败删除临时文件，不留下半成品。

读取把整个包作为一个事务导入当前账号。`battle_record_id`、`capture_id` 重映射为本地 ID；来源账号的
`source_inventory_snapshot_id` 清空，因为它不能指向当前账号库存；账号活动配装指针从不导出或导入。
`capture_operation_id + raw_summary_sha256` 相同的记录幂等跳过，同 operation ID 但摘要不同会拒绝整包。
导入不会为了满足保留上限静默删除本地记录；容量不足时整包回滚并提示先清理历史。

导入记录写入来源表和逐角色装备锁。其养成、技能、觉醒、弧盘、精炼及手工边际属性可以修改，也可以执行
“从角色页同步（不含空幕驱动）”；空幕/驱动在外层和边际页均只读。切换装备来源、读取游戏当前配装、读取
已保存方案、含装备的角色页同步、临时替换装备和创建新装备覆盖均被拒绝。写入层每次保存角色副本时重新
计算规范化装备摘要并与锁比较，防止绕过 UI。

日志只能记录导入/导出阶段、战报数量、跳过数量、安全错误和战报 ID；不得记录账号昵称、装备 UID、完整
payload 或文件绝对路径。
