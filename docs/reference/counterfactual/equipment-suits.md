# 空幕套装反事实文本盘点

空幕主词条和驱动词条属于冻结面板来源；本表只盘点 12 套空幕的二件套与四件套效果，共 24 条。套装是否
激活由已装备核心的正式 `suit_id` 和该核心要求的不同驱动形状共同判定：重复形状只计一件，四件套必须补齐
空幕 `required_shape_ids` 中的四个图纸形状；不能读取驱动行上不存在的套装 ID。

二件套统一从发行静态库 `equipment_modify_pack` 读取，不复制一套 UI 常量。四件套由
`BattleEquipmentSuitService` 提供稳定审计目录和专用触发规则，替代仅凭 Blueprint 可达关系生成的通用
猜测。所有有限持续时间都使用扣除时停的有效战斗时钟。

## 证据与估计边界

- 数值、持续时间和上限来自正式套装说明、`CT_Equipmentbuff` 曲线和规范化 Buff 定义；它们是高置信数值
  证据。触发时点由正式逐击和推算动作对齐，仍属于可删除重算的推断，不冒充 nte-core 实测 Buff。
- 黯星按结算逐击向前回填 5 个有效战斗秒；延滞结算按基础 5 秒向前回填。浸染从已识别反应事件向后投影
  12 秒。缺少正式反应开始事件时，这些区间属于结构化估计。
- 当前 `BattleInferredBuffInterval` 尚未携带敌方实例键。单目标时，Suit3 的目标状态覆盖可以直接消费；
  多目标时只把它作为低置信估计，未来用原始封包或 DLL 提供的目标 Buff 状态按对象覆盖。
- Suit2、Suit4 当前按正式伤害事件计层；当同一封包聚合多个受击目标而没有逐目标展开时，层数只按当前
  可见事件计算，不根据伤害量反猜目标数量。
- Suit10 的 Q 十层已有明确动作证据。普通扣血触发需要“受击者就是装备者”的可靠对象关系；该证据缺失时
  保留 Q 路径，不把敌方受击或队友受击误当成装备者扣血。
