# 战斗机制图鉴

“工具 → 游戏资料库 → 战斗机制图鉴”是效果、公式与反事实覆盖的统一玩家入口。它不再把“技能招式”、
“效果与 Buff”、“伤害公式”和“反事实模型”拆成四个平级入口，也不提供数据库浏览器、执行器选择或模型
开关。

生产伤害和战报反事实仍由现有 Service 负责。图鉴只读取发行静态数据和版本化审计投影，解释一个机制是什么、
如何生效、进入哪个伤害环节，以及当前战报反事实能否重放。

## 1. 内容归属

内容先按玩家认知中的所有者归档，再决定从哪个页面展示：

- **角色页**：只展示该角色的招式、被动、觉醒和角色专属效果；
- **弧盘页**：只展示该弧盘的面板、混频技能、触发效果和适配角色；
- **空幕页**：只展示该空幕或套装的属性、二/四件套效果和触发规则；
- **怪物页**：只展示该怪物或玩法对象的防御、抗性、倾陷、生命和专属机制；
- **战斗机制图鉴**：展示跨多个对象、没有唯一所有者或属于全局规则的内容。

公共图鉴包含：

- 跨角色或跨装备共享的 Buff / Gameplay Effect；
- 环合、DOT、倾陷、附着物、召唤、治疗、护盾、时停和生命结算等公共机制；
- 面板、倍率、通伤、属性伤、防御、抗性、暴击及特殊结算公式；
- 当前战报反事实覆盖状态和未量化缺口。

同一对象只保留一个权威详情。公共图鉴搜索到有唯一归属的角色、弧盘、空幕或怪物机制时，显示简短关系卡并
跳转其所属页面，不在公共页复制一份完整说明。

## 2. 页面信息架构

图鉴使用一个入口、一条搜索路径和一个详情历史栈：

```text
战斗机制图鉴首页
  → 机制家族
      → 机制卡墙
          → 机制详情
              → 相关对象 / 效果 / 公式 / 反事实状态
```

首页不是四个旧入口的换皮。首屏展示六个机制家族：

- 属性与增益；
- 异能环合与状态；
- DOT 与持续结算；
- 倾陷与目标机制；
- 召唤、附着物与事件；
- 伤害公式与反事实覆盖。

窄窗口把六个家族收为一个可操作的下拉选择，不能只裁掉横向 chip；搜索框仍保持完整可见。桌面宽度继续使用
横向家族 chip，卡墙按 1–4 列响应式重排。

顶部统一搜索支持玩家可理解的正式名称、属性名、技能名，以及确需定位的 GA、GE 和 Gameplay Tag 专业身份。
资源路径、来源表、文件哈希、代码符号和测试名称不作为产品搜索入口，也不直接铺在玩家详情中。

首页底部可显示四态覆盖摘要，但它只帮助理解图鉴覆盖，不做完成率仪表盘，也不能控制计算：

- 完整；
- 部分；
- 不可用；
- 不适用。

## 3. 机制卡

机制卡是三个原领域的统一展示单元。卡片正面只保留玩家决策需要的信息：

- 公共术语 Service 返回的正式名称；没有正式名称时显示“名称暂未提供”；
- 归属对象徽记，没有唯一归属时显示“公共机制”；
- 类型徽记，例如 Buff、DOT、环合、公式、被动或套装；
- 一句话生效摘要；
- 层数、持续时间、目标范围和触发条件标签；
- 当前反事实状态。

stable key、canonical ID、text table/key、locale、GA、GE 和 Gameplay Tag 等专业身份与名称分离，只进入默认
折叠的“更多信息”。View 不复制中文术语映射，也不把 raw ID 当标题或通用替代名。具体本地化规则见
[`static-catalog-terminology.md`](static-catalog-terminology.md)。

没有正式名称且只有类型、持续策略或 unavailable 周期/叠层元数据的占位 effect 不进入默认卡墙；精确搜索
专业身份时仍可进入其折叠审计详情。某家族没有合格公共机制时显示空态，不能用缺名卡凑覆盖。

多属性 Buff 必须在同一卡内显示全部属性徽记，例如 `攻击 +120`、`暗伤 +12%` 和 `无视防御 +5%`，不能按
modifier 拆成多张同名卡。层数和持续时间未知时显示“层数未知”“持续时间未知”，不显示 0。

存在 Calculation 但尚未形成结构化 property / operation / value 时，卡片显示“数值规则尚未结构化”。页面
保留它与来源技能或效果的关系，但不展示资源路径，不从名称或说明文字猜倍率，也不生成 `+0` 或 `×1`。

## 4. 机制详情

详情使用由浅入深的折叠结构，默认只展开玩家层：

### 4.1 效果说明

- 做什么；
- 谁触发；
- 作用于谁；
- 何时开始和结束；
- 是否叠层、刷新或消费；
- 影响哪些伤害。

### 4.2 伤害环节

用乘区流程展示机制的消费者：

```text
面板 → 技能倍率 → 通伤 / 属性伤 → 暴击 → 防御 → 抗性 → 特殊最终乘区 → 结算
```

未消费的环节保持灰色；实际消费者高亮。DOT、倾陷、覆纹和生命结算可以切换到自己的专用流程，不强塞进
直伤流程。

### 4.3 反事实覆盖

显示当前 scoped 状态、“怎么做的”、覆盖对象、缺口和限制。玩家文案使用：

- “已接入战报反事实”；
- “已接入部分规则”；
- “当前无法量化”；
- “不影响本项伤害反事实”。

不在玩家 UI 展示 Service 类名、函数名、源码路径或测试路径。

### 4.4 为什么是这个状态

证据链默认折叠为一条简洁进度：

```text
正式定义 → 触发证据 → 状态轴 → 逐击投影 → 公式消费 → 生产反事实
```

展开后，每段只显示玩家可读结论，例如“正式标签已确认”“缺少逐目标层数事件”“已进入 DOT 公式”。完整的
文件、符号、测试和 dataset 证据仍保留在 Qt 无关审计 DTO 与验收包中，不直接出现在产品页面。

## 5. 伤害公式

公式作为机制家族和详情关系存在，不再是顶层入口。公式卡按以下章节组织：

- 面板；
- 倍率；
- 通伤；
- 属性伤；
- 防御；
- 抗性；
- 暴击；
- DOT；
- 倾陷；
- 特殊机制。

卡片使用公式表达式、变量徽记、适用伤害类型和简短限制，不做公式表。点击变量可跳到提供该变量的公共效果
或所属对象；点击消费者可跳回使用该公式的机制卡。

公式来源在审计层区分正式静态、项目规则与派生展示值；玩家层只显示易懂的“正式数值”“项目公式”“当前
推算”，不展示数据库字段或代码位置。

DOT 只以正式 Gameplay Tag `State.Damage.Dot` 分类。`FinalDamageUp` 单列为特殊最终乘区：通用独立最终增伤
和 Source/Target 都要求 DOT Tag 的 DOT 专属最终乘区必须分开，不能并入通伤、属性伤或易伤。公式权威定义见
[`damage-calculation.md`](damage-calculation.md)。

## 6. 反事实状态

### 6.1 状态规则

每张机制卡只对自己声明的 scope 给出一个状态：

- `complete`：输入、状态、逐击、公式、生产消费者和未知传播全部贯通；
- `partial`：已有可量化子集，并明确列出覆盖对象和缺口；
- `unavailable`：缺少必要历史状态、正式映射或生产消费者，不能生成数值；
- `not_applicable`：已证明该机制在当前伤害 scope 中没有消费者。

上述英文枚举只属于审计 contract；卡片正面使用“完整”“部分覆盖”“不可用”“不适用”，不能把 raw 枚举放入
标题、摘要或徽记。

卡片状态由必需证据链的最弱环节决定，不按已完成环节数量计算百分比。unknown 可以出现在单个字段；只要它
影响本卡必需链路，就不能显示 0、`×1`、空字符串或“未触发”。

### 6.2 当前覆盖分类

当前宽粒度审计投影共有 17 个 scope：4 个 `complete`、9 个 `partial`、3 个 `unavailable`、1 个
`not_applicable`。页面拆成具体机制卡后按新 scope 重新统计，不维持固定比例。

已完整的窄 scope：

- 固定轴重放 contract；
- 未知状态传播 contract；
- `State.Damage.Dot` 正式分类；
- 完整同半场阵容与目标画像下的基础倾陷五乘区。

已有部分生产覆盖：

- 角色被动与觉醒专用规则；
- 弧盘动态状态和空幕二/四件套；
- 结构化 Buff / GE 属性；
- 敌方画像与目标条件；
- 噩梦、蚀心、鸩火、浊燃状态和 DOT 专属最终乘区；
- 倾陷特殊状态、附着物、治疗驱动 Buff、最大生命下降和有效战斗时钟。

当前不可量化：

- 召唤物完整创建、存续、空间、资源和派生命中轴；
- 通用玩家护盾获得、消耗和逐击前状态轴；
- 缺必要运行时状态的具体被动、觉醒、弧盘、Buff 或敌方机制。

对伤害反事实不适用：

- 没有伤害消费者的纯治疗量；
- 只有护盾效率且没有已审计伤害消费者的具体分支。

C++ sidecar 单列为“验证组件”，固定显示 `partial` 和“未接入生产”。它不计入生产反事实完成数量，也不提供
启用、选择或回退操作。

更细的对象审计继续由以下资料拥有：

- [`counterfactual/character-passives.md`](counterfactual/character-passives.md)；
- [`counterfactual/awakenings.md`](counterfactual/awakenings.md)；
- [`counterfactual/forks.md`](counterfactual/forks.md)；
- [`counterfactual/equipment-suits.md`](counterfactual/equipment-suits.md)。

## 7. 互跳与折叠

内部关系使用稳定 typed link：

```text
CatalogLink(domain_key, record_id, relation_kind, anchor)
```

typed link 只存在于 Controller / View contract，不作为玩家文案显示。链接分三类：

- **所属对象**：跳到角色、弧盘、空幕或怪物的权威详情；
- **公共机制**：在战斗机制图鉴内部切换效果、公式或反事实详情；
- **证据关系**：从技能到效果、效果到公式、公式到消费者，仍在同一详情历史栈中前进和返回。

角色、弧盘、空幕和怪物页通过注入的公开导航回调打开战斗机制图鉴，不访问 MainWindow，不扫描其他页面，
也不依赖堆叠页索引。公共图鉴收到有唯一所有者的链接时调用同一导航 contract 返回对象页。

详情折叠只影响展示状态，不改变模型状态。搜索、筛选、展开和历史栈都属于可丢弃 UI 状态，不写账号库或
发行静态库。

## 8. 实现边界

战斗机制图鉴由一个公开页面和三个内部展示组件组成：

- `combat_mechanics_page.py`：唯一入口、搜索、机制家族、详情历史和 typed link 路由；
- `mechanics_effect_panel.py`：效果卡和效果说明；
- `mechanics_formula_panel.py`：公式卡和乘区流程；
- `mechanics_counterfactual_panel.py`：四态卡和证据链折叠。

只公开一个 factory：

```python
build_combat_mechanics_catalog_page(
    *, database_path, game_ui_asset_root, open_catalog_link,
    terminology_service=None, parent=None
)
```

Service 返回 Qt 无关、不可变 DTO，并分别保留：

- 玩家投影：中文说明、标签、消费者摘要和状态；
- 审计投影：正式关系、实现消费者、公共行为测试、dataset 和缺口代码。

正式名称通过 Qt 无关 `StaticCatalogTerminologyService` 解析；组合根可以注入全局静态术语 source，独立页面测试
则使用只读杂项目录适配器。两者都保留 canonical key、text table/key 与 locale 选择，不做大小写归并或页面
级中文回退。

View 只消费玩家投影。截图与审计包可以读取审计投影，但不得把源码路径、测试路径、来源文件哈希或完整资源
路径注入玩家卡片。

页面不修改、不依赖 `menu.py`、公共 `page.py` 或 `src/ui/app.py`。组合根接线、对象页互跳和旧入口收敛由
资料库入口任务统一完成。
