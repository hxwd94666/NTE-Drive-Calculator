# 战斗机制图鉴

“工具 → 游戏资料库 → 战斗机制图鉴”面向玩家解释伤害怎样计算。页面不是数据库浏览器，也不展示反事实覆盖、
源码证据或内部执行状态。

## 玩家分类

默认卡墙只包含具有完整中文投影的伤害公式，分为四类：

- **伤害基础**：角色面板、技能倍率、直伤计算；
- **增益与减益**：增伤、易伤、暴击、防御、抗性；
- **持续与倾陷**：持续伤害、倾陷伤害、覆纹追加伤害；
- **特殊结算**：独立最终增伤、最终伤害取整、生命上限下降结算。

GA、GE、Buff、Gameplay Tag、技能伤害叶子和结构化战斗效果不作为卡墙条目。它们仍是静态库中的正式关系
事实，但只能由所属角色、弧盘、装备或玩法页面投影玩家需要的说明。缺少中文名的记录不进入默认卡墙，搜索
也不会用内部 ID 补标题。

## 中文公式

公式以稳定 key 读取项目规则，由 Qt 无关投影逐条提供中文标题、中文表达式和中文名词说明。原始变量名、
源码符号、公式来源类型和证据路径只留在审计领域，不传给玩家界面。典型展示为：

```text
技能倍率 = 等级倍率 ×（1 + 倍率修正合计）
直伤 = 技能倍率 × 对应面板 × 增伤 × 暴击 × 防御 × 抗性 × 易伤 × 独立增伤
```

持续伤害仍以正式 `State.Damage.Dot` 关系作为领域判定，通用独立最终增伤与持续伤害专属结算保持分离；
这些稳定身份不作为玩家卡片标题。

## 关系与导航

对象归属和相关机制优先在当前详情内显示可读摘要，不生成“查看 GE”“查看 Buff”一类跳转按钮。只有用户从
真正的角色、弧盘、装备或玩法对象详情显式进入图鉴记录时，组合根才负责页面历史与返回；失效或已被过滤的
关系返回不可用，不改变当前页面，也不把异常抛入 Qt 事件循环。

公式详情自身只在图鉴内部切换，返回动作统一由资料库外壳的单一返回按钮承担。页面不会从公式变量自动跳转
到技能或效果叶子。

## 展示密度

卡墙使用紧凑响应式布局：常用宽度一行最多四张，窄屏改用完整四项下拉筛选并在 430 像素宽度回落为单列。
详情采用平面分段和可换行的伤害流程，不使用表格、大型看板、层层嵌套事实框、“更多信息”或“正式静态”
技术按钮。

## 审计边界

反事实模型、支持四态、C++ 差分组件、来源哈希和生产消费者仍可由独立测试及审计 Service 维护，但不属于
战斗机制图鉴产品。删除玩家展示不会改变战报计算、逐击重放或反事实 Service 的生产语义。
