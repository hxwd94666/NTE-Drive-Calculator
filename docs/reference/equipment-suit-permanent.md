# 套装无条件常驻：分类与录入边界

本表区分“满足套装件数即生效”和“还需战斗触发”。常驻不代表已激活，也不代表普通伤害收益。数值由正式修改包、Buff Modifier及其曲线读取，说明文本只辅助人工分类，不作为取值来源。

## 证据与机器录入

人工审查事实源为`tools/game_data/equipment_suit_permanent_reviews.json`，绑定本次主静态dataset/schema、数据库SHA和逐效果证据摘要；其中只登记分类、属性选择器和审查理由，不复制一套数值常量。

- 二件套及守卫/酒馆四件套：从`equipment_suit_effect → equipment_modify_pack → equipment_modify_value`读取，要求修改包条件为空、加法操作。
- 迪亚波罗斯：从装备根Buff的无条件BEGIN关联到Infinite子Buff，再读取暗抗穿透Modifier和`CT_Equipmentbuff`曲线；不选择HasDuration强化子Buff。
- 诅咒/街头：选择根Infinite Buff的无条件Modifier，不选择带应用条件的目标额外增伤或有限时增益。
- 保留正式effect ID、源行哈希、Modifier序号、曲线、条件与持续时间证据。来源变化、缺曲线、多值曲线、条件/标签要求或未知操作先拒绝，不用描述填数、不自动重签审查。

候选入口为`tools/game_data/build_equipment_suit_permanent_candidate.py`，仅在`build/`新建独立审查SQLite，包含24条`equipment_suit_effect_review`、17条`equipment_suit_permanent_property`及来源元数据。数值采用正式property_id，百分比保存为ratio（例如14%=0.14）。此库是审查数据，不是主静态game包，明确标记`release_ready=false`、`runtime_integration=pending`；无正式发行manifest，不替换data、不供运行时旁路读取。

同一投影已纳入追加迁移、importer、主静态构建和正式晋升入口，不保留独立运行时套装侧库。消费者和剩余发布门禁见[实施审查](../roadmap.md)。条件效果的固定轴行为另见[战报套装目录](counterfactual/equipment-suits.md)，本表不将其升级为全场常驻。
