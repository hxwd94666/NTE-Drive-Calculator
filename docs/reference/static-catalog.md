# 游戏资料库

“工具 → 游戏资料库”只读打开发行静态库，以一次冻结的 dataset、schema、importer 和构建时间为请求边界。
页面不读取账号库，不允许输入 SQL、表名或字段名，不启动战报 worker，也不改变任何配置。玩家搜索只消费
中文投影，不以 Gameplay Tag、GA、GE、Buff key 或资源路径补标题。

当前首页不提供“全部”、逐表覆盖总览、资源动画或来源追溯入口，而是按对象所有权组织五个玩家入口：角色、
弧盘、空幕与驱动、怪物与玩法、战斗机制图鉴。

- **角色数据**：角色身份、1–80 级面板、临界等级突破前后、技能等级和正式材料名称、觉醒、好感度、培养
  路线、推荐弧盘与毕业模板。当前 schema 没有角色升级/突破材料关系时明确显示不可用。
- **弧盘数据**：1–80 级经验与面板、突破材料/方斯、混频 1–5 级说明与参数、Buff、GE、触发和角色关系。
- **怪物与玩法**：图鉴、模板画像、争锋、轨外、副本、异象追猎和具有正式怪物池的高危委托。身份只能来自
  正式绑定、ID 或类路径，不从中文名猜测。
- **空幕与驱动**：展示空幕、驱动、套装、形状、属性和归属于该对象的二/四件套效果，关系优先在当前详情
  直接投影，不用连续跨页跳转拼信息。
- **战斗机制图鉴**：只以四个玩家分类展示 14 条中文伤害公式。GA、GE、Buff、技能伤害叶子和反事实覆盖
  不作为卡墙条目；对象归属在详情内显示可读摘要。持续伤害仍以正式 `State.Damage.Dot` 作为领域判定，
  独立最终增伤单独计算，但内部身份不进入玩家标题。

schema v30 的 124 表登记、资源关系及来源追溯仍作为内部完整性能力；空表和发行时省略的
`source_row.payload_json` 继续接受自动审计，但不进入玩家资料库菜单。

反事实矩阵和 C++ 差分组件仍属于内部审计及生产验证能力，不进入玩家资料库页面。
