# 工作模式与本机生命周期

工作模式属于本机应用配置 `config/work_mode.json`，不随账号切换、导入或导出。首次安装、缺失或不兼容配置、无有效确认的配置均使用离线模式；旧装备插件风险勾选不授予新模式权限。用户在模式下拉框选择后立即打开确认弹窗，不再提供“选择并检测”按钮。确认弹窗按“风险提示、可以使用、不可使用、切换后、持久化说明”分区展示，不堆叠长段落；非离线模式以红色“确认风险并切换”明确同意，离线模式使用“确认切换”。确认结果保存在本机配置，后续更新继续沿用该模式；用户仍可随时更改。默认按钮为取消，关闭、Esc 或取消均不改变生效模式，并将下拉框回退到当前生效模式；确认后自动打开检测详情显示进度。下拉框中尚未确认的选择不受后台检测或无关配置刷新覆盖；取消后可重新选择并确认。开发模式固定双路对照，仅供开发和排错，不建议日常开启。组件部署更新随已确认模式管理；背包自动同步使用首页独立开关，偏好保存在本机，默认开启但不授予工作模式权限。旧配置中的开发来源及旧自动开关不再控制行为；缺少新自动同步字段时，旧暂停状态迁移为同步关闭，并保留内部安全暂停。清理或旧配置留下的安全暂停须重新确认工作模式后解除，首页开关不能绕过。

| 模式 | 授权的执行能力（仍须逐项检测） |
| --- | --- |
| 离线 | 本地数据、历史战报分析与诊断信息保存 |
| 低风险 | 本地、诊断、抓包、鼠标或手柄界面操作 |
| 中风险 | 本地、诊断、界面操作、DLL 加载、人物装备/完整库存/队伍环境同步、DLL 战报、原生装配 |
| 开发 | 本地、界面操作、诊断、DLL 与抓包；战报固定双路对照 |

自动部署更新只管理当前发行包中已核对的配套组件，不提高模式授权，并遵守本机选择的 D3D 代理或 Loader 入口；选择 Loader 时，D3D 自动部署不得改变该选择。游戏运行、路径未确认、包校验失败或文件归属不明时等待处理，不强制关闭游戏或覆盖未知文件。Calc 只管理普通部署、启动、停止和连接，不监视插件文件或编排热重载。手工部署的兼容组件可以正常使用。自动同步只启动同步，不启动战报、装配、弃置或游戏输入。首页关闭自动同步只停止背包监听与等待游戏任务，不停止手动战报、不关闭按模式授权的组件部署更新。自动同步偏好变化不使手动任务的权限代次失效；模式、风险确认、安全暂停或游戏路径改变仍使旧任务失效。手动清理先保存暂停再登记清理待办，避免清理后自动重新部署。切换到离线或低风险立即撤销所有 DLL 新操作权限，并保存独立的清理待办；必要清理不受暂停影响。文件归属、游戏退出等待和重启重试规则见[组件整包与清理契约](game-component-bundle.md)。

已核实旧版本即使由手工放置、缺少本机部署记录，也可按组件清单中的确切哈希接管升级；游戏运行时等待退出。
升级接管仍核对组件来源；清理按固定文件名执行：已登记的 `d3d12.dll`、`NTE_Capture.dll` 以及游戏目录旧代理 `dwmapi.dll` 不要求版本或历史哈希匹配。Loader 运行目录内已登记的采集 DLL 使用同一清理规则。仅处理指定目录和正式组件文件名，目录或链接不作为普通 DLL 删除。

设置页环境卡片显示配套组件状态与游戏目录部署状态；自动检测保存游戏路径后复用同一状态刷新，不以“找到路径”代替组件已部署。确认模式切换、检测详情及手动清理立即打开同一个详情窗口，在后台收尾、检测、清理或部署期间显示不定进度；完成后原位展示逐项结果，失败则原位显示错误和重试入口。手动部署、部署转入待清理或 Loader 启动后立即刷新检测报告和设置页摘要，不保留操作前的“清理待完成”快照。等待游戏退出或缺少路径时显示实际等待原因，不伪装为部署完成。关闭窗口只隐藏展示，不取消已确认的模式变更和必要清理，后台结果也不再次弹窗。旧代理加载偏好按当前组件包展示对应入口，不改写已有组件所有权记录。清理待办只表示需要后台核对，不等于已确认文件残留。首次启动、旧配置缺字段或尚未核对时不弹退出提示；已登记组件正在等待游戏退出、原部署路径失效或实际清理失败时，设置页和退出提示使用同一份观测原因。权限不足、文件占用等系统错误保留错误码与对应处理方式，不降为笼统的检测失败。观测绑定游戏路径及部署记录，二者变化后不复用旧原因；清理完成才清除待办，关闭提示不清空记录。

设置以原子替换持久化。保存失败不生效新的高权限；降级失败仍先在当前进程撤销能力并报告故障。历史部署记录和游戏路径仅迁移为管理事实，不迁移风险授权。

游戏路径须为实际存在的 `HTGame.exe` 绝对路径。路径缺失或失效时，后台先从正在运行的游戏、注册安装位置与有限常见目录及原部署记录自动查找；候选经校验和去重后，只有唯一有效路径才自动保存。未找到时每隔至少 15 秒重试，显式重新检测可立即重查；存在多个候选时等待用户选择，不擅自挑选。路径确认前暂停后台游戏进程检测、组件目录检查、自动部署及原生连接，检测详情显示路径等待并提供选择入口；本地计算与离线历史分析继续可用。未确认路径仍保留后台核对待办；只有已登记组件的清理受此阻塞时才在退出提示中说明路径原因，不将单纯未核对表述为组件残留。清理始终使用原部署记录中的绝对目录：即使原 `HTGame.exe` 已被卸载或移动，也按固定文件名核对并清理该旧目录及本程序拥有的加载登记，不把旧组件记录套用到新发现的游戏目录；只有记录本身不是合法的 `HTGame.exe` 绝对路径时才保留待办。已登记的独立 Loader 运行目录可单独按所有权和游戏退出门禁收尾，不依赖游戏主程序文件仍然存在，也不操作其他游戏目录。

检测使用逐功能事实：文件已核对、进程、登录、管道、握手、能力支持、业务就绪、快照到达、完整性与来源覆盖。人物与配装、完整背包、队伍与环境三个逻辑采集能力复用同一原生组件接口，本期组件采用无界面 `NTE_Capture.dll` 与配套 Core，对外声明 `character`、`inventory`、`team`、`environment` 四个独立业务域。文件存在不代表管道可连接，管道存在不代表握手兼容，握手成功与能力声明均不代表业务可用。DLL 战报必须单独确认业务就绪。原始观测与正式业务投影分别核对：原始四域能力不代表可保存背包或角色状态；正式背包还须具备库存 DTO 能力和本次集合及字段映射完整证明。持续变化覆盖未知不能单独否定已经证实的本次完整集合；尚未取得正式证明的部分观察不得覆盖已保存背包。角色状态只使用正式稀疏投影中的已知字段，不将“部分字段可同步”表述为完整人物面板已验证。队伍与环境检测对应“已支持字段的观测”：组件、管道、握手、能力、当前快照与就绪状态通过时显示可用，并说明未覆盖范围，不以原始整域 `complete/sourceCoverage` 要求它们全部完整。快照缺失或来源刷新中继续显示等待，连接、协议和读取故障继续显示具体原因。此展示不改写完整性标记、不补造字段，也不改变战报和正式业务逐字段使用证据的条件。

开发模式可连接手动加载的兼容原生提供方：管道与实际握手通过后，战报、同步和装配按各自业务能力及就绪状态检测，不要求游戏目录中的提供方文件与 Calc 管理的发行组件相同。文件管理状态仍如实独立显示，连接成功不授予覆盖外部 DLL 的权限，也不免除完整库存等业务条件；未完成握手时不能仅凭管道存在认定可用。

各功能分别报告可用、正常等待、缺少条件、故障；清理待完成单独计数。设置页工作模式卡片将短模式选择框与“检测详情”同排，下方分别列出四种模式可使用的功能；开发模式说明为“抓包与原生双线对比，仅供开发人员使用”。模式说明只强调已经确认生效的模式，选择下拉框中的草稿不改变强调项；用户确认或取消弹窗后再按实际生效模式刷新。完整逐功能状态与处理操作仅在检测弹窗展示。文件未核对、Npcap 缺失等给出手工处理或重新检测动作；后台刷新不弹出检测结果，用户选择并确认模式或点击“检测详情”时才显示结果弹窗。后台检测与显式检测均遵守当前模式、暂停、组件归属和游戏退出门禁。低风险和开发模式独立展示 Npcap 安装检测，游戏路径缺失、组件清理失败或 Core 缺失不会掩盖该项；确认缺少时提供官方下载按钮和安装后重新检测的说明。未完成检测不等同未安装，后台检测不自动弹窗或打开下载。

## 背包与角色状态同步

原生背包或角色的只读投影请求收到提供方 `-32001 / control_timeout` 时，保持共享会话并进入正常等待，
由既有监听循环重试；未完成结果不提交，已保存背包与养成保持可用。该处理不适用于装配等写入命令，
不自动重发操作；协议、传输及正式库存映射错误继续按既有故障规则处理。

首页在中风险、开发模式显示“游戏数据同步”，低风险显示“背包同步”。卡片提供“自动同步”开关、“重新同步”和“检测详情”，分别展示本次背包监听状态、上次保存背包，以及原生角色等级/突破的已保存数量或同步错误。“角色目录”统计复用正式逻辑角色列表，合并主角变体并排除额外战斗变身；下方账号同步数量只统计当前稳定快照的角色，手动映射和历史快照不计入。角色养成数量来自当前账号已持久化的等级与突破观测，不把原始快照到达当作保存完成。设置页保留工作模式、组件检测和“采集排错”（原始数据保存、特殊网卡与原始数据目录），不再提供背包获取方式、稳定等待秒数、历史保留份数或手动清理按钮。编辑网卡内容或切换原始数据保存后立即持久化；新设置在下次连接或同步启动时生效，不重启正在运行的同步。低风险使用抓包，中风险使用 DLL；开发模式的正式库存唯一写入来源为 DLL，抓包用于战报对照，不双路写入。离线尝试开启同步进入模式受限引导。缺组件或接口能力时说明实际原因，不切换模式或回退来源。

低风险开启自动同步后，Calc 内的 Python watcher 每秒查找游戏进程；发现唯一目标后停止枚举，绑定进程创建身份与只读句柄等待退出，并启动库存 Core 抓包。抓包就绪后等待登录背包，接收稳定快照后保持同一库存会话监听变化。游戏退出时收尾 Core，再等待下次游戏启动。关闭同步、切换账号或模式、退出 Calc 都取消当前观察与同步，迟到回调不能写入新账号。旧会话未完全停止前不创建替代库存会话，硬错误不会无限快速重试。

“重新同步”保留已保存背包与方案，仅丢弃旧会话未提交的候选。低风险引导用户先返回登录页、暂不进入游戏，点击“开始重启同步”后异步收尾并重建会话；只有 Core 真正报告抓包运行，才提示重新登录。准备期间仅点击“取消重启”才取消该请求；右上角关闭或 Esc 始终只关闭弹窗，不停止等待游戏、组件连接或背包同步。停止自动同步使用首页开关。中风险与开发模式重新连接组件读取，无需返回登录页；部署或更新组件必须先完全退出游戏，部署完成后再启动。首页、重试弹窗、使用帮助、错误详情和手动失败引导按同步来源提供操作步骤：原生等待完整数据时保留实际等待原因，并明确提示“请登录并进入游戏场景，等待同步完成”，不追加停留登录页要求，也不将大世界作为唯一可同步场景；仅抓包来源提示在监听就绪后重新登录。来源未知时引导检测，不套用抓包步骤。仓库和装配的原生恢复引导同样遵循退出部署、完成后启动并进入游戏场景的顺序。离线帮助明确不连接游戏。

首页与重试弹窗使用同一准备状态：进程及组件尚未核实时显示检测中；已检测到部署文件缺失或不匹配时，游戏运行则要求完全退出，游戏已退出则提示暂勿启动、查看检测详情并完成部署。部署检查未报告缺失或不匹配且游戏未启动时显示“等待启动游戏”，不创建库存采集任务；发现进程但连接未就绪时显示“等待同步组件就绪”，长时间等待引导查看检测详情。组件部署条件未满足时不因旧连接握手成功而启动新的同步任务。这些状态由进程和组件检测推进，不依赖尚未创建的库存任务回调；仅实际收尾旧任务时显示收尾中。战报期间禁止重新同步，并提示先结束战报；关闭同步时按钮提供开启入口。新数据接收、稳定保存或与已保存内容一致的确认分别处理，不把旧快照或候选到达显示为本次保存完成。

低风险手动战报使用独立 Core 和抓包句柄，不停止或重建库存 Core，开始、结束、失败和重录都不接管库存生命周期。并行期间增加一份抓包及解析开销，实际游戏并发仍须实机验收。原生战报仍遵守下文共享管道的串行读写边界；账号同步是否继续由首页开关决定。

背包同步更新完整库存，以及角色页面从该快照投影的“游戏当前”装备，不修改用户保存的配装方案。两种来源复用完整快照稳定器和既有保存事务；原生完整候选的稳定等待为 200ms，保存前只复核该候选的提供方、数据域身份和修订，不再次读取全量或等待角色刷新。变化合并阶段缩短状态检查间隔，空闲仍每秒检查状态；真实修订变化会丢弃未提交候选并重试。抓包继续使用账号原有稳定等待和历史保留设置。原生同步保存后仅保留当前版本、方案与装配任务引用的旧版本，以及本次进程已导出为计算输入的版本；计算输入的临时保护随进程退出释放，下次清理重新按持久引用判断。不原地覆盖快照，不清理已冻结的战报副本。DLL 同步复用应用原生 Core 所有者和同步线程，不启动 Npcap 或另一个原生 Core。配套组件声明 `snapshot.changes.v1` 时，同步线程查询各域修订与失效状态，合并连续通知后才刷新对应背包或角色域，无变化时只复核状态，不定时重读完整快照。通知覆盖仍按实际来源标记，不能因此宣称所有变化均已覆盖。登录前没有首份原生快照时，未就绪数据域的空身份属于正常等待；登录后自动读取完整快照。数据域再次消失时撤销本次已就绪状态，保留已保存背包，重新就绪后重新读取，不能复用上次会话的就绪证明；已就绪数据域仍必须具备有效身份。角色经验、技能、好感度和弧盘养成通知只更新角色域，不作废完整装备背包；等级、突破和槽位解锁仍保守复核装备关系。装备增删、装卸、强化、锁定与弃置继续使背包失效并刷新。饱食度计时等无关通知不触发养成或背包刷新。停止自动同步同时停止这条后台角色同步，手动角色同步和原生战报仍由各自操作收尾。

原生背包与角色快照刷新最多等待 65 秒，等待中持续检查停止、账号代次及权限；F12 或停止操作可中断等待。自动同步与战报共享同一当前基线和快照读锁，不并发交错分页。已有战报时由战报 owner 维护变化后的基线，自动同步可消费已完成版本，不能另行刷新；第一击只冻结其对应版本。手动开始战报优先取消在途刷新，等待原 owner 收尾后取得战报租约。交接在采集 worker 内有界且可取消，不修改持久暂停状态；战报结束后允许自动同步恢复。取消进行中的刷新会终止本次独占刷新使用的 Core，下次操作重新连接；不会终止已占用共享会话的战报。

原生装配要求配套 DLL 声明装备执行能力、Core 握手声明对应能力，并由共享会话的装备状态接口确认就绪；原生布局不探测旧装备管道。装备接口检测只在手动检测或实际装配前执行，后台同步观察不定时触发游戏线程的装备接口查找，也不把未检测状态伪装为已就绪。本次同步租约还须已校验完整库存，历史背包不能代替本次就绪证明。未登录或装备上下文变化属于等待，不拆除共享会话。装配命令的派发回执不表示游戏操作成功，成功仍由后续完整背包或正式状态事件确认。

正式原生分页固定提供方、快照、对象代次、观测时间及完整性元数据；具备变化能力时同时冻结数据域修订，跨帧读取、分页和提交前复核期间发生变化的结果不得提交。页数、数量、角色关联和终止游标均须一致。所有条目字段有可靠映射且组件明确声明本次业务投影完整，才生成可保存的完整库存事件。原始完整性与变化覆盖声明仍原样保留，不以旧快照、固定件数阈值或抓包结果补齐原生缺项。取消、账号切换、权限撤销、分页错误和未完成读取均不推进当前快照。

中风险自动同步在首次取得原生连接、角色域变化稳定和定期复核时同步已确认的永久角色养成，角色页仍提供“同步状态”手动入口。该入口只复用正在运行的游戏数据同步；同步未开启、游戏未登录或连接尚未就绪时，弹窗简要说明原因，并引导用户到工作台开启自动同步、进入游戏场景并等待“同步中”，不会启动另一条连接。仅将本次返回角色的已支持观测字段写入该账号；未返回角色和未知字段保留原值。试用、临时及副本专用角色原始观测只属于场景和战报，不写入永久角色配置。正式字段包括角色等级与突破阶段、经游戏基础/觉醒/生效等级查询交叉核对的技能基础等级、好感度十级加成状态，以及同次完整弧盘集合和双向装备 UID 核对后的弧盘身份、等级、突破与混频。弧盘 ID 优先精确匹配冻结目录；仅大小写不同时允许唯一匹配，并保存目录中的标准写法。匹配有歧义、缺前缀或目录确实不存在时保留旧弧盘组并报告具体原因，不改写原始采集记录或历史战报。明确未装备弧盘会清除旧弧盘；缺失或冲突的关联不覆盖旧配置。技能使用正式 SkillID，觉醒加级不重复写入基础等级；觉醒等级与实际选择独立同步：仅在完整槽位观测下，将 Unlocked=true 且 EffectID 非空的已保存槽位投影为具体效果；解锁空槽合法，不能单凭 Unlocked 或觉醒等级推定选择。完整空选择清除旧观测，缺失或不完整选择保留旧值。觉醒观测复用账号 cultivation_json 保存，不改写手工配置；旧库升级后缺字段仍为未知，无需补造或回填。角色页面模型按字段标明原生观测、账号配置或模板来源；手工保存及单角色、全部重置清除对应观测覆盖。字段格式、官方目录或养成组合校验错误只跳过对应字段组，其余已确认字段在单一事务中保存；等级与突破组合冲突时保留旧成长，弧盘身份或养成无效时保留旧弧盘整组配置，技能按正式 SkillID 独立校验。未知角色或重复角色身份不写入对应角色，仍可保存其他角色。同步结果按实际写入角色计数，文本列出未同步角色、字段及弧盘等正式 ID；手动同步在角色页显示可复制的结果文本，不为这些字段错误弹出阻断提示，后台同步在工作台同步详情中显示相同说明。手动同步成功沿用丢弃未保存编辑并刷新规则；后台自动同步不丢弃页面草稿。角色保存失败不停止背包监听，保留原养成并显示待重试状态。读取未完成、数据库写入失败、取消或冻结账号代次失效时不提交本次更新，不修改历史战报和编辑副本。

## 手动功能入口与设置定位

手动战报、同步、组件加载/部署、游戏输入和诊断入口先检查模式。模式不允许时显示“功能受限”，说明当前模式与所需能力，提供“前往设置”和“取消”。例如离线点击战报采集，说明低风险使用抓包战报、中风险使用 DLL 战报，且须明确确认风险。只有模式受限不会使按钮失去解释入口；运行中、没有可操作对象或不满足正式来源等业务禁用条件仍单独保留。

当前模式已经允许，但组件缺失、连接未就绪或业务条件不足时，显示真实原因并引导检测信息或组件部署区域，不能笼统要求更换模式。正常等待游戏、加载和网络状态继续作为等待显示，不反复弹窗；过期结果与自动后台流程不发起手动引导。

导航使用正式的 settings key，设置页显式登记工作模式卡片、“检测详情”按钮与组件部署控件。进入后滚动到相应区域并短暂高亮；模式受限时聚焦模式选择框，检测引导聚焦详情按钮，不覆盖尚未确认的模式草稿。由功能弹窗发起的引导，只有明确点击“前往设置”才关闭原功能弹窗，以便操作设置。

引导本身不切换模式、不确认风险、不触发检测/部署，也不自动重试原操作；用户完成设置后须重新点击原功能按钮。取消、Esc 和关闭只结束引导，不改变模式、账号数据或原功能弹窗。原始抓包等诊断选项在尝试开启时执行同样的模式提示，真正采集前仍复核诊断授权。

界面引导不替代 Service/Integration 的最终执行门禁；权限撤销、取消和账号代次失效后仍须停止操作并正确收尾。纯本地计算、历史分析、已保存数据浏览、离线图片处理与本地推荐不因游戏工作模式受限。

抓包等待按 Core 握手能力协商：仅声明 `capture_wait_v1` 时请求 `wait_for_game`。等待游戏与等待网络是可取消的正常等待；正在初始化仍有 15 秒超时，硬错误保留错误码。这是进程和网络条件等待，不是登录前监听保证；进程启动不能证明已捕获登录数据，晚启动仍可能缺少完整快照。旧 Core 保留原有初始化边界，不承诺自动补齐登录包。诊断信息保存不限制工作模式，也不授予额外采集来源；中风险沿用 DLL，低风险沿用抓包，离线不会因勾选诊断而启动采集。同步回调和持久化前再次核对当前上下文与本次明确选择的同步来源授权。

本文定义产品契约；纯策略与检测投影可用测试替身验证。DLL 真实握手、完整库存、各业务域的独立能力、真实 Windows 部署与游戏退出清理仍需组件和实机验收，不以本地单元测试替代。
