# 伤害计算规则（项目金标准）

本文件记录项目当前确认的伤害计算规则。游戏官方静态数据负责提供技能倍率、等级曲线、伤害
属性、固定暴击率、敌方属性和环合常量；本规则定义这些输入如何进入各乘区。公式以用户确认的
项目金标准为准，官方文件用于补齐可追溯的数值，不以未确认的运行逻辑反向改写项目规则。

Python API 的百分比使用小数，例如 `20%` 写为 `0.20`。

## 数据可信度与 SQLite 边界

数据分为三类，使用时不得混淆：

1. **官方文件确认**：可以从游戏官方静态文件直接读取，并在 SQLite 中保留来源文件、行键和
   SHA-256。
2. **项目金标准**：本文记录的伤害公式、乘区归类和默认值，由项目按已确认规则实现。
3. **待确认映射**：官方文件有原始数组，但没有足够证据把数组档位直接解释为具体角色或技能
   等级。此类数据只保存 `source_tier`，不猜测等级。

发行数据库为 `data/game_static.sqlite3`，当前整体 schema 为 v26。战斗基础表最初由静态迁移 v3 引入，
当前计算读取下列表：

- `combat_level_curve`、`combat_level_curve_point`：倾陷确切等级曲线与环合官方档位。
- `reaction_definition`、`combat_effect_constant`：环合元素组合、默认伤害效果和固定常量。
- `skill_damage`、`skill_damage_rate`：技能伤害属性、固定暴击率、倾陷值以及攻击/生命/防御倍率。
- `enemy_combat_profile`、`enemy_element_resistance`：敌方防御、倾陷上限与分元素抗性。

计算 service 保持纯函数，不直接查询 SQLite；上层数据装配服务或 DAO 负责将静态数据转换成计算
输入。

## 直伤总公式

```text
最终直伤 = 技能伤害倍率
         × 倍率对应属性
         × 增伤区
         × 暴击区
         × 防御区
         × 抗性区
         × 易伤区
         × 所有独立乘区之积
```

战报逐击重放在所有乘区以完整精度相乘后，对一次实际结算的最终伤害统一向上取整到整数；未暴击与暴击
候选分别从各自的完整精度结果取整，不把未暴击的取整结果继续乘入暴击公式。暴击期望是两个整数候选按
暴击率加权后的统计值，并非一次实际结算，因此允许保留小数。DOT 单跳、特殊伤害、覆纹和倾陷同样只在
各自最终伤害出口执行一次向上取整，中间属性与乘区不取整。

技能伤害倍率来自已记录的技能伤害数据。倍率对应属性由技能记录指定，默认攻击力，也可以是
生命值或防御力；本次攻击的伤害属性由技能记录指定，例如暗属性或光属性。

### 技能倍率系数修正

技能等级先从伤害数据中选择对应档位，随后应用作用于该技能标签的 `CoefModify`：

```text
修正后技能倍率 = 当前技能等级的原始倍率 × (1 + Σ CoefModify)
```

残虹三觉共鸣绑定的 `Buff_Zankou_LevelExtraLv3` 对
`Ability.Player.Zankou.UltraSkill` 提供 `CoefModify +0.20`，因此残虹两种极轨终结的所有受该标签
约束的原始倍率统一乘 `1.20`。例如原始分段合计为 `250.1% + 589.5%` 时：

```text
三觉修正后倍率 = (250.1% + 589.5%) × 1.20 = 1007.52%
```

这里的“技能倍率提升 20%”不是给某一段倍率增加 20 个百分点，也不进入通用增伤区。角色养成
界面在觉醒说明右侧展示的粉色提升百分比属于游戏自身的整套养成收益评估，不是觉醒静态参数，
不得用于替代 `CoefModify` 公式。

## 基础属性区

```text
攻击力 = AtkBase × (1 + AtkUp) + AtkAdd
生命值 = HPBase × (1 + HPUp) + HPAdd
防御力 = DefBase × (1 + DefUp) + DefAdd
```

账号世界加成在所有角色构筑中作为固定来源参与合计：妖刀按当前账号设置进入 `AtkAdd`（默认 `+20`），
拳套进入 `CritDamageBase`（默认 `+0.04`，即 4% 暴击伤害）。角色页、配装收益、战报冻结、逐击重放与
边际分析必须消费同一份账号值；世界妖刀的固定攻击力与下文弧盘妖刀的逐击动态暴击伤害是两个不同来源。

角色技能生成的固定攻击力按正式来源口径进入 `AtkAdd`，不折算为受益角色的 `AtkUp`。早雾 Q 的基础团队
Buff 与四觉 Buff 分别取 `(早雾人物 AtkBase + 早雾弧盘 AtkBase) × 30%`，均排除早雾本人、持续 20 个
有效战斗秒，并从 Q 实际结束后的下一微秒生效。哈尼娅 E/Q 分别按自身对应技能有效等级曲线，取
`(哈尼娅人物 AtkBase + 哈尼娅弧盘 AtkBase) × 技能比例`；E Buff 在动作约 0.719 秒生成，所以本次 E 的
两击不读取，Q Buff 在约 2.867 秒生成、早于正式 Q 伤害，所以本次 Q 读取。装备固定攻击、百分比攻击和
其他 Buff 均不反向计入施法者基础攻击口径。

伊洛伊的治疗先生成独立治疗事件，再由伤害 Buff 消费，不能把技能动作本身等同于治疗。点按 E 在正式
`E.1` 动画事件治疗全队，并同时给予
`min((伊洛伊人物 AtkBase + 弧盘 AtkBase) × 20%, 500)` 的 `AtkAdd`，持续 20 个有效战斗秒；长按 E
不进入该治疗分支。QTE 在 `QTE.2` 生成一次治疗；Q 在 `UltraSkill.1` 生成即时治疗，并从其后第 1 个有效
战斗秒开始每秒生成一次持续治疗，共 14 次。时停期间治疗周期、交感性神经系统、五觉清晰和错误的门的
持续时间均暂停。突破 4 的交感性神经系统由每个治疗事件刷新全队 `DefIgnore=5%`、持续 20 秒；五觉清晰
由同一事件刷新
`min((伊洛伊人物 AtkBase + 弧盘 AtkBase) × 15%, 500)` 的全队 `AtkAdd`。满血导致有效回复为 0 时仍是
治疗事件，只有缺少正式技能/动画证据时才保持未知，不从 E/Q 动作兜底猜测。

## 增伤区

```text
增伤区 = 1 + Σ(伤害提升)
```

伤害提升在此区相加，包括通用伤害增强、特定属性增强、特定技能增强、特定状态增强以及各类
Buff 提供的增伤。

## 易伤区

易伤是敌人身上的 Debuff，技能描述通常写为“受到的伤害提升”。它不计入我方的增伤区，而是
独立相加为一个乘区：

```text
易伤区 = 1 + Σ(敌人受到伤害提升)
```

早雾被动「可以吃吗？」不进入易伤区；它使用下文独立定义的 DOT 专属最终乘区。

## 暴击区

```text
暴击区 = 1 + 暴击率 × 暴击伤害
```

DOT 与部分环合伤害的固定 50% 暴击率规则按各自伤害类别处理。

### 妖刀动态暴击伤害

妖刀当前精炼提供的每层暴击伤害、持续时间和七层上限来自冻结弧盘与静态参数。战报按逐击正向重放，
不通过实际伤害误差反推层数：装备者归属的咒属性直伤、DOT 和浊燃均为有效触发；一次命中先使用结算前
层数，结算后才增加一层。每 0.3 秒最多触发一次，重复有效触发刷新 15 秒持续时间。

冷却与持续时间均使用扣除时停后的有效战斗时钟：时停区间内既不推进 0.3 秒冷却，也不消耗 15 秒持续
时间。逐击仍使用包含时停的原始时间定位，服务在判断冷却与过期时才投影到有效时钟。该结果属于静态规则
加正式逐击推算；未来 nte-core 提供实测 Buff 层数时由实测状态覆盖。时停区间优先消费 nte-core 正式起止点；
整场没有任何完整正式区间时，才使用已由逐击及可用静态动画事件推算出的 Q 动作起止窗口作为低置信回退。
回退区间只进入派生分析，不改写战报证据；有任一完整正式区间时不得混用回退区间。

### 预备备的双虎符与司令虎符

弧盘的常驻攻击力直接进入面板；每次 E 或 Q begin 各增加一层普攻/极限反击增伤，每层独立持续十五个
有效战斗秒，逐击最多采用两层。普通增伤的 E begin 与左虎符不是同一时点：左虎符在 E 实际结束时获得，
右虎符在 Q begin 获得。在十五个有效战斗秒内取得另一种虎符，只表示司令虎符已经可用，不等同于已经
主动释放。

战报没有主动调弧事件，因此司令虎符只做低置信阶跃推断：双符解锁以后，以同一目标、相同 GE（无 GE 时
采用技能与伤害项身份）的历史伤害为基线；至少两种可比伤害项，或同一伤害项至少三击，在两秒观察窗内
从某一击开始出现一致的 2.5%～35% 上升，且各比值差不超过 4 个百分点，才把该第一击作为十秒区间起点。
普攻和极限反击不作为阶跃证据，避免把第二层普通虎符增伤误判为主动效果；孤立高伤、暴击式大跳变、目标
变化或证据不足也不命中。区间只绑定提供阶跃证据的同一目标；正式弧盘效果还要求目标满足
`Con_IsBoss`。当前战报与目标条件没有正式 Boss 标签字段，因此阶跃区间只保留为低置信触发证据，不把
Boss 通用增伤数值投进逐击。未来取得正式主动事件和 Boss 分类后再消费该数值。

## 防御区

存在绑定敌方属性包时优先使用实际防御数据：

```text
L = 我方角色等级 + 100
敌人防御 = [DefBase × (1 + DefUp) + DefAdd] / 6
           × (1 - 防御穿透) × (1 - 防御降低)
防御区 = L / (敌人防御 + L)
```

缺少属性包时才使用场景近似：轨外之境为 `敌人等级 + 90`，大世界为 `敌人等级 + 100`。争锋赏宴必须
读取每个难度绑定的 `DefBase`，不能用显示等级或积分倍率替代。第 1～6 关数据恰好可化为显示等级 `+100`；
第 7～8 关“方斯如雨/愿望成真”四档 `DefBase=870/930/990/1050`，归一化后为
`145/155/165/175`，等价于显示等级 `+85`。例如 80 级角色打极难墨菲斯托且无穿透/减防时，防御区为
`180 / (1050/6 + 180) = 0.507042`。

## 抗性区

默认 Boss 基础抗性为 20%：

```text
X = Boss 基础抗性 - Boss 身上的减抗 Buff - 我方角色的抗性穿透 Buff

X >= 0：抗性区 = 1 - X
X < 0 ：抗性区 = 1 - X / 1.10
```

逐击详情必须先分别显示目标抗性和属性穿透合计，再明确计算有效抗性及其分段。例如目标暗抗 `20%`、
迪亚波罗斯暗穿 `24%` 时，展示为 `有效抗性 = 20% - 24% = -4%`，随后代入负抗分支
`抗性区 = 1 - (-4% / 1.10) = 1.036364`；不得把异号来源平铺成误导性的 `20% + 24%`。

负抗性进入增伤区间；减抗来源包括技能，抗性穿透来源包括武器和技能。轨外之境关卡展示的“怪物弱点”
来自 `FirstRecommendElementTypeArray` / `SecondRecommendElementTypeArray`，它表示该半场怪物属性包中较低的基础抗性，
不是一个额外的弱点增伤或减抗 Buff。例如 `Abyss_8` 第 12 站上半光/相基础抗性为 10%、
其他常规属性为 30%；下半暗/咒为 10%、其他常规属性为 30%。官方通用克制表在这些属性/倾陷条组合上
均为 `1.0`，因此不额外推导伤害或倾陷倍率。

战报逐击缺少可靠目标实例/属性包绑定时，不按目标中文名猜基础抗性。用户从静态目录选择对象、环境、难度
与争锋加成，并可人工补正七种“战前最终抗性”；这里的抗性已经包含玩法追加，且弱点属性已直接表达为较低基础抗性，但不包含战斗中
临时减抗，作为公式中的 `Boss 基础抗性` 输入。动态、目标对象明确且数值可解析的 `DamageResist*` 加法修正再作用于对应属性，
角色的 `DamagePenetrate*` 随后作为抗性穿透扣除。未保存敌方条件时，防御忽略和抗性穿透边际保持不可计算，
页面显示的 20% 初值不参与公式。

## 独立乘区

独立增伤不与增伤区相加，而是逐项相乘：

```text
独立乘区 = Π(1 + 每项独立增伤)
```

已确认的该类来源包括浸染增伤等明确的独立效果。早雾「浊燃」强化也不进入这个全伤害公共乘区，
避免普通直伤或其他非 DOT 消费者误用。

## DOT 专属最终乘区

早雾突破 2 被动「可以吃吗？」由反应扩展
`Buff_Reaction_ZhouAn8_1003` 实现。官方 GameplayEffect 修改的底层属性为 `FinalDamageUp`，但其
SourceTags 与 TargetTags 都要求 `State.Damage.Dot`；项目因此把它建模为语义更窄的
`dot_final_multiplier`，不作为易伤，也不并入可供全伤害消费的独立最终乘区：

```text
N = 本击结算前目标上仍有效的持续伤害状态种类数
DOT 专属最终乘区 = 1 + min(N × 25%, 100%)
```

同一种持续伤害无论叠多少层都只计一种；当前已审计并进入状态重放的种类为噩梦、蚀心、鸩火和浊燃，
对应 `×1.25 / ×1.50 / ×1.75 / ×2.00`。只有目标在本击结算前已经存在可供公式消费的已结算浊燃状态，
且本击属于正式 `State.Damage.Dot` 消费者时才采用。残虹由环合先存入、尚未被其他 DOT 跳伤激活的浊燃层
不满足条件；首次可见浊燃跳伤也固定 `×1.00`。直伤、附着物、倾陷及其他非 DOT 伤害固定为 `×1.00`。

该乘区位于 DOT 公式末端，与该击已有的倍率、层数、面板、增伤、防御、抗性、易伤、独立最终和暴击区
相乘，并且每击只消费一次。所有已识别 DOT 的逐击展开式都显式保留该槽位：被动未启用或条件未满足时
显示 `×1.000000`，满足时显示实际乘数。正式环合逐击的「环合·浊燃」只累计未激活浊燃层；首个实际
非浊燃 DOT 跳伤在自身结算后使浊燃补 1 层并激活伤害，所以该触发击仍取 `×1.00`。首次可见浊燃跳伤
使用已经累计的层数但自身也取 `×1.00`，结算后才确认可供早雾消费的浊燃状态；后续 DOT 按结算前仍有效
的种类数消费早雾乘区。

若正式施加事件缺失或其静态持续时间已经到期，但同一半场、同一目标在本击前 1.5 秒内刚出现该种类的正式
DOT 跳伤，则这条跳伤只作为“本击附近仍存在该 DOT 种类”的短窗证据参与早雾种类计数。它不会刷新该状态
的完整持续时间，也不会反推出层数或补造缺失跳伤；公式说明必须标明该种类来自近期正式跳伤。

## 战报逐击 Buff 边际

### 角色培养被动

角色培养被动按本场冻结角色的 `breakthrough_stage` 解锁：第一被动要求突破 2，第二被动要求突破 4；
`1046/1051` 共用主角逻辑规则但保留原始角色 ID。角色基础面板重建不含这些战斗内被动，所以已确认的
被动属性只在逐击 Buff 投影中加入一次。当前可直接量化的规则为：

- 白藏常驻 `AtkUp=20%`，阿德勒常驻 `DefUp=20%`，残虹常驻 `MagBase=100`；
- 法帝娅为全队提供 `HPMaxUp=10%`，其黯星生命汲取只在第一被动已解锁时进入最大生命适配器；
- 零的 Q 获得限定通伤 `25%`，达芙蒂尔「幻影移行」获得限定通伤 `80%`；
- 翳释放 Q 后 15 个有效战斗秒内，兽牙影刺获得限定通伤 `10%`；
- 薄荷驻场期间获得 `DefUp=20%`，切到后台立即移除；
- 哈尼娅黯星结束加攻必须等待逐目标状态真正结束证据；普通黯星伤害 hit 不代替结束事件，当前固定轴不
  数值投影该层；
- 海月每次水母弹命中后获得 `AtkUp=1%`，默认最多十层；六觉把同一状态上限提高到二十层并在 E 结算后
  加十层，所有来源按总层数共同封顶，整组持续 5 个有效战斗秒；
- 真红每次正式盈蓄范围击后获得 `AtkUp=5%`，最多十层，整组持续 30 个有效战斗秒；
- 浔 Q 的正式终结段把原始技能倍率乘 `2`，不进入通伤区，也不影响 Q 的其他段。

以上有限持续时间使用扣除时停的有效战斗时钟。本击触发的叠层从该击结算后开始，不能反向强化触发击。
目标状态、资源循环、召唤生命周期或新增逐击类被动由各自适配器重放；缺少事件证据时保留真实原击并把
机制增量估为 0，不把它们伪装成全局常驻属性。

### 空幕套装

空幕激活条件不是“同套装驱动数量”，而是核心的正式套装 ID 加上属于该核心 `required_shape_ids` 的驱动
形状数量。二件套常驻属性从 `equipment_modify_pack` 读取，并像其他战斗内常驻来源一样加入原始配置和候选
配置各自的逐击公式。四件套使用独立事件规则：

- 失落光芒与音速蓝刺猬在 Q 开始生效，触发 Q 可以消费本次 Buff；影之信条在 E 完整结束后生效；
- 静谧山庄由正式 `BUFF_EVENT_SKILL_AFTER_HIT` 触发，并由普通攻击条件限制；每个普通攻击有效 Hit 后叠一层；
- 森林萤火之心与真红：双生蝶由全队匹配属性的正式伤害事件叠层，每层分别按扣时停时钟到期；
- 迪亚波罗斯、恶魔之血和街头拳王把基础值与条件增量拆成两个加法来源，“提升至”不重复加入完整高档值；
  迪亚波罗斯装备者的 QTE 即使本体按直伤归类，只要正式攻击类型明确为 `环合·黯星` 或 `环合·浊燃`，
  仍在该次 QTE 结算后开启额外 12% 对应属性穿透，和常驻 12% 合计为 24%，持续 20 个有效战斗秒；
- 小小大冒险的 Q 直接生成十层；普通扣血路径在不能确认受击者就是装备者时不从敌方或队友受击反猜；
- 守卫王国四件套和缇娅的夜间酒馆四件套只改变护盾/治疗，固定伤害轴不凭空生成后续联动。

黯星状态可由结算击向前回填 5 个有效战斗秒，延滞结算按基础 5 秒向前回填，浸染按 12 秒状态向后投影。
当前区间没有敌方实例键，因此恶魔之血的条件增量在单目标战报中可直接使用，多目标中属于低置信结构化
估计；以后由逐目标封包或运行时 Buff 状态覆盖。

真实战报伤害已经包含当时 Buff，不再把 Buff 完整乘一次。对属性改动做反事实时，同一击的安全动态
Buff 同时加入冻结面板和改动后面板：

```text
逐击反事实伤害
= 真实逐击伤害
× 乘区(改动后面板 + 该击动态 Buff)
/ 乘区(冻结面板 + 该击动态 Buff)
```

这会保留同一加法区间的边际递减，也不会虚增战报基准伤害。冻结配装常驻属性已在面板中，必须排除；自定义
Calculation、层数不明、敌方 Debuff、非加法操作或未映射乘区不进入第一版数值投影。

选定时段的单 Buff 收益使用相反方向的移除反事实。同一稳定 Buff 来源的全部刷新和叠加区间一起移除，
其他配装、Buff、目标、动作、逐击与时段保持不变：

```text
无 Buff 逐击 = 原始实测逐击 × 无 Buff 公式期望 / 当前公式期望
无 Buff 时段伤害 = Σ(无 Buff 逐击) + 联动生命上限结算 + 其他固定派生结算
Buff 伤害增量 = 当前时段有效伤害 - 无 Buff 时段伤害
Buff 时段收益率 = Buff 伤害增量 / 无 Buff 时段伤害
```

这里展示的是该 Buff 对全队当前时段的独立贡献，不是 Buff 面板数值本身。例如只覆盖部分逐击的 15% 通伤
不会自动显示为 15% 的团队收益。安魂曲五觉生命上限结算继续跟随已归因噩梦逐击的移除比值；其他无法安全
随 Buff 移除重放的逐击和派生结算保持实际值。每条已量化逐击按其正式 `character_id` 归到实际造成伤害的
受益角色，而不是默认归到 Buff 来源角色：

```text
受益角色获得伤害 = Σ(该角色当前逐击 - 该角色无 Buff 逐击) + 已归因联动结算差
受益角色自身提升 = 受益角色获得伤害 / 该角色无 Buff 伤害
受益角色折合全队贡献 = 受益角色获得伤害 / 全队无 Buff 时段伤害
```

所有受益角色获得伤害加上无法归因部分，必须严格等于该 Buff 的全队伤害增量。来源不明的派生伤害单列，
不反猜给 Buff 来源角色。各 Buff 都是在完整当前配置上逐项独立移除，存在覆盖重叠、同区稀释、暴击上限或
条件交互时不可直接相加。

所有带持续时间的静态 Buff 都使用扣除时停的有效战斗时钟计算终点，不只妖刀叠层与噩梦特例。残虹、
安魂曲等角色在 Q 时停前后触发的 Buff 会在原始时间轴上相应顺延；显式移除事件仍以其真实发生时刻立即结束
区间。蚀心和鸩火的 30 秒目标状态同样使用扣除时停的有效战斗时钟；时停期间状态时间不流逝。

残虹零觉使用独立的形态状态适配器。现实形态的「狩」向自身通用增伤区加 `25%`；幻境形态的「惑」向
全队持续伤害暴击伤害加 `25%`，但只投影到带 `State.Damage.Dot` 语义的噩梦、蚀心、鸩火和浊燃，不能进入
普通直伤。幻境持续时间、现实切幻境后的旧状态保留时间、幻境切现实后的旧状态保留时间均从
`DT_ZankouEffectFigure` 的 `ZankouMagicDur`、`ZankouRtoMRetainBuffDur` 和
`ZankouMtoRRetainBuffDur` 读取。形态边界由绯影闪、离魂错、Q、换人以及现实/幻境专属 GE 共同推算；技能
动作存在动画尾段或与下一角色动作重叠时，切形态时点优先取该动作 `evidence_event_ids` 中最后一击，而不是
动作展示窗终点。时长统一扣除时停；一觉不复用这套 25% 区间，而由整场常驻的狩 40%/惑 50% 接管，切形态
与离场均不移除。三觉生效时，正式惑 Buff 的 `Period=1s` 和 `MaxHPRecoverHPExecution` 每个有效战斗秒生成
一次残虹自身 `MaxHP×4%` 治疗；时停期间周期暂停，缺少玩家阵亡事实时投影到战斗结束。

本场选择的魔女赐福属于用户确认的外部条件，从战斗开始覆盖到结束。攻击、暴击、暴击伤害、通伤和原质
驱力使用同一安全加法属性投影进入逐击；历史战报不读取当前日期状态。蓄质速率和其他未被伤害公式消费的
属性仍保存选择，但不会产生虚构伤害增益。

## 固定轴配装反事实

角色养成、弧盘、空幕、驱动、技能等级或手工面板属性改变时，第一阶段固定原战报的动作、逐击、目标、
Buff 时段和分析范围，不凭空生成新的动作或命中。原轴每一条对敌逐击必须得到候选值，不能因缺少专用
适配器而从队伍总量中消失。

动作识别把正式 `GA_*_Appear` 作为进场/G 动作，即使它复用了普攻或下落攻击的伤害 GE；该归类只修正
动作身份和 G 专用触发，不改变原始逐击的倍率父级、时间或伤害事实。

结构化逐击同时存在原始配置与候选配置的预计值时：

```text
逐击比值 = 候选配置预计值 / 原始配置预计值
候选逐击 = 原始实测逐击 × 逐击比值
```

原始逐击已高/中置信识别为暴击或非暴击时，原始与候选预计值必须使用同一个已识别分支；候选重放不能因为
更接近同一条原始实伤而重新选择分支。原击分支仍不唯一、但伤害渠道的暴击策略已确认时，双方统一使用期望
公式；暴击策略未知时不强行选最近分支，降级到后续估计梯级。`corrected_expected_damage` 只供误差展示，
不得作为原始/候选公式比值的分母或分子。

这样以实测伤害为锚，系统性目标误差和尚未解释的共同乘区不会被重复带入候选绝对值。结构化逐击不可用时，
按以下顺序选择第一个可用比值：

1. 同一角色、同一稳定技能、同一伤害属性和分类中已结构化逐击的中位比值；
2. 同一角色、同一伤害属性和分类中已结构化逐击的中位比值；
3. 原始与候选角色面板的攻击、暴击期望、通用/属性增伤和已确认目标乘区比值；
4. 该角色其他已结构化逐击的中位比值；
5. 完全无法量化时取 `1`，即保留原击并把未知特殊机制增量暂估为 `0`。

已归因生命上限结算优先按已知来源机制联动，证据不足的其他派生结算按原值纳入。于是：

```text
候选总伤害 = Σ(所有原始逐击 × 所选比值)
             + Σ(可联动生命上限结算 × 来源机制比值)
             + 其余固定派生结算
候选 DPS = 候选总伤害 / 原分析时段有效时长
总收益 = 候选总伤害 / 原始有效伤害 - 1
结构化重放占比 = 采用原始/候选逐击公式比值的原始伤害 / 原始有效伤害
估计占比 = 1 - 结构化重放占比
```

结构化占比描述证据强度，不代表公式误差为零；估计占比也不是“未计算”。同技能、同类型、面板和同比保持
都产生明确候选值，并在内部保留方法、置信度和说明。主页面只展示总收益、角色贡献、伤害构成及结构化/估计
占比；逐击误差位置留在审计结果中，不要求用户逐项处理。

生命上限派生事件若已有 `source_character_id`，继续计入该角色的候选贡献和伤害构成；没有归因时仍进入公共
未归因项。安魂曲五觉按其 `evidence_event_ids` 中对应噩梦逐击的候选/原始伤害比联动，候选未激活五觉时归零；
法帝娅被动按候选/原始 `inherent_hp` 比联动。只有来源公式或配置证据不足的事件才固定原值。调整后逐击轴
保留原时间与动作，把每个正式逐击和生命上限结算替换为候选值，并同步重算技能条、动作汇总和角色贡献。
候选逐击详情中的“预计提升/下降”定义为：

```text
预计变化 = 调整后候选逐击 - 原始实测逐击
预计变化率 = 预计变化 / 原始实测逐击
```

这是固定轴反事实变化，不是候选公式相对原始实测值的模型误差。原始/候选结构化公式值和实际采用的估计
梯度分别展示，避免把系统性公式偏差误认成配装收益。

## 噩梦、蚀心与鸩火

噩梦、蚀心和鸩火是独立的伤害渠道与状态名称。它们的单层、单跳伤害继续使用技能倍率、面板、增伤、
防御、抗性、易伤、独立最终、DOT 专属最终和暴击乘区；同一结算时刻的总伤害还取决于命中前仍有效的层数：

```text
单次结算伤害
= 技能基础倍率 × 命中前当前层数系数 × 面板乘区
× 增伤区 × 防御区 × 抗性区 × 易伤区 × 独立最终乘区
× DOT 专属最终乘区 × 暴击区

同一状态总伤害 = Σ(命中前仍有效的每一层单跳伤害)
```

`DT_SkillDamageData` 将三类状态的暴击率固定为 50%；是否暴击仍按非暴击与暴击候选和正式逐击值判定，
不能把 50% 期望直接当成本击实伤。常规逐击状态机只使用更早发生的施加击更新状态；施加伤害发生后才加层，
本击不会提前吃到自己新增的层数。噩梦另允许一条只影响本击展示和边际缩放基准的低侵入补正：若本击前
0.7 秒内存在有效施加 hit，且本击实伤按“正向层数减 1”能与同目标最近 10 秒内的噩梦实测单层值唯一吻合，
则标记服务器少接收 1 层并显示反算层数；该结果不反写状态机，也不影响后续击层数。

- 噩梦：普通攻击、极限反击、E 和极轨终结的每个有效正式直伤 hit 都在该 hit 结算后施加 1 层，最多
  10 层；多段技能按实际 hit 数逐层增加。`Lacrimosa_Skilldotnum_1` 与
  `Lacrimosa_UltraSkilldotnum_1` 不作为战报状态机的单次施加层数输入。默认每层持续 3 秒，选中 `Effect4`
  后每层持续 6 秒。战报正向重放按每个 hit 的施加时点分别保存和到期；时停期间不推进到期时钟。
- 蚀心：幻境形态普通/分支的每个正式命中加 1 层，强化变轨命中加 5 层，最多 10 层，持续 30 秒；
  现实形态普通攻击不施加蚀心。持续时间按扣除时停的有效战斗时钟到期。
- 鸩火：「血宴入梦时」最终施加点加 5 层，最多 10 层，持续 30 秒；普通攻击和 DOT 跳伤都不增加层数。
  零觉时只有幻境形态「魇舞」本体具有 DOT 扩散，一觉额外让现实形态指定攻击与强化变轨具有扩散；本场
  固定轴显示「魇舞」扩散会刷新原目标已有鸩火的持续时间，但保持原层数，持续时间仍按扣除时停的有效
  战斗时钟推进。扩散到其他目标的复制仍保留原状态的层数、剩余时间和周期，不凭单目标逐击推造额外伤害。

蚀心另把“正式活跃层数”和“本跳有效结算系数”分开。历史纯自跳轴已经排除“每一跳始终使用唯一聚合总层数”
这一项目假设，因此每条蚀心只枚举 `{单份, 本击前正式层数}` 与 `{非暴击, 暴击}` 的组合，并按实伤选择；
暴击对整跳只判定一次。该选择只修改本击公式、误差和边际缩放基准，不反写正式状态机。禁止把有效系数开放
成任意 `1..10` 层逐击拟合，以免固定暴击倍率被误识别为层数。施加事件缺失而轴中仍出现 DOT 时，系数 `1`
仅表示“至少存在一份”的计算下限，必须保持低置信，不显示为确认一层。

噩梦 GE 的导出属性还直接确认 `Period=1`、`StackLimitCount=10`、
`StackPeriodResetPolicy=NeverReset` 和 `StackExpirationPolicy=RemoveSingleStackAndRefreshDuration`。
`Buff_Lacrimosa_MeleeTotal` 与一觉替换 Buff 都通过自定义 `CoefModify` Calculation 计算总倍率；导出文件能
看到 `StackCount`、`MaxCoef`、`StackMult`、减法、乘法和钳制节点名称，但没有保存蓝图字节码和这些局部值的
运行时默认值。因此文档不再把 `MaxCoef/StackMult` 猜成另一个层数上限，也不把“层数 × 1”冒充完整的原生
Calculation 函数体。当前 Service 的逐层求和是可删除的项目侧重放模型，静态事实和项目模型必须分开。

安魂曲三觉“冰淇淋在烈阳中融化”是独立的提前结算规则：指定普通攻击终段命中后，一次性结算目标当前
已累积的全部噩梦效果；`GE_Lacrimosa004_SettleRemainingDam_Lv3` 的
`SettleRemainingDamageGEComp` 以 `State.Damage.Dot.Blood` 查询这些效果。该次结算应逐层计算各层剩余
伤害并在完成后清除已结算噩梦，不得套用“常规一跳 = 当前层数 × 单层倍率”后继续保留原层数：

```text
三觉提前结算总伤害 = Σ(第 i 层剩余结算次数 × 该层单次直伤公式结果)
结算完成后：已结算噩梦层数 = 0
```

当前逐击状态适配器只完成常规噩梦、蚀心与鸩火的层数重放；三觉提前结算需要先把终段施加事件和随后
生成的噩梦伤害事件做稳定关联，再进入精确重放。未建立关联前必须明确列为未覆盖，不能按普通噩梦跳伤
给出伪精确结果。本期用于验算的战报修改副本选中了 `Effect1/Effect5/Effect6`，没有选中 `Effect3/Effect4`，
因此该场不触发三觉提前结算，噩梦持续时间为 3 秒。

持续时间和层数推进使用扣除时停的有效战斗时间；时停期间状态时间不流逝。`0.3` 秒触发冷却属于妖刀
弧盘叠层，不属于噩梦、蚀心或鸩火的公共规则。当前单目标
阶段在逐击缺少正式目标实例 ID 时采用显式的单目标假设。未来 nte-core 提供目标 Buff 全量与增量状态后，
运行时实测层数按对象和时间区间覆盖静态重放结果。

## 环合基础规则

环合由角色打满环合条后，切换到相邻属性角色时触发切出角色的 QTE 与相应效果。环合归属角色
取参与者中 `环合强度 × 角色等级乘区` 较高者；该角色决定创生、浊燃等环合伤害的等级、环合
强度、防御与抗性相关乘区。

```text
环合强度乘区 = 1 + 环合强度 / 600
```

这里的 `/ 600` 表示“环合强度 / 6”是百分比增伤。覆纹与浸染共用同一个专用环合强度区：

```text
覆纹/浸染环合强度区 K = 1 + 20% × 环合强度 / (环合强度 + 180)

基础额外伤害率 B = (1 + 20%) × K - 1

浸染期间的总伤害倍率 = 1 + B = (1 + 20%) × K

覆纹追加伤害
  = 原直伤实际伤害
  × B
  × Π(其他特殊乘区)
```

因此基础覆纹和浸染提供的最终伤害增量相同，只是表现形式不同：浸染把 `B` 作为持续期间的增伤，覆纹把
每次已记录直伤的 `B` 部分延后结算为追加攻击。旧式
`24 × 环合强度 / (环合强度 + 180)` 没有表达完整的共享环合强度区，不再使用。

队伍中存在灵可且已解锁「弱点感应」时，仅覆纹公式中的基础 `20%` 替换为 `30%`：

```text
灵可覆纹额外伤害率 = (1 + 30%) × K - 1
```

此外，该覆纹追加攻击获得技能限定通伤 `+10%`，与本击其他通用增伤相加；它不是目标侧独立易伤
`×1.10`。静态扩展字段 `ExtraDamageRatio=0.13` 只保留为底层实现证据，不直接代替官方已确认的
“提升至 30%”进入公式。

覆纹追加伤害继承触发它的直伤属性；灵伤触发就是灵属性，咒伤触发就是咒属性，不改成心灵属性或
环合归属角色的固有属性。`其他特殊乘区` 传入已归一化后的乘数，例如 `1.20`，没有时取 `1`。

所有心灵伤害使用 100% 防御穿透，即防御区为 `1`；但仍计算心灵属性对应的抗性区，不能穿透
心灵防御抗性。

## 倾陷伤害

```text
角色 i 倾陷贡献
= 角色 i 等级乘区 × 角色 i 倾陷强度区 × 敌方倾陷上限区
  × 角色 i 防御区 × 角色 i 属性抗性区

团队倾陷伤害 = Σ(本击所在半场队伍中每个角色的倾陷贡献)
```

```text
角色 i 倾陷强度 = 倾陷强度基础值 × (1 + 倾陷强度提升) + 额外倾陷强度
角色 i 倾陷强度区 = 1 + 角色 i 倾陷强度 / 300 + Σ(该角色倾陷伤害提高)
普通敌方倾陷上限区 = max(1, 敌方 UnbalMax ÷ 3)
争锋高阶 Boss（UnbalMax ≥ 70）倾陷上限区 = 25
```

`UnbaldamagePara` 官方曲线明确记录了 1–80 级数据，其中 80 级角色等级乘区为 `3603`。轨外
之境 Boss 的敌方倾陷上限值默认 `50`；指定敌人时应优先读取其属性包中的 `UnbalMax`，只有
没有可用属性包时才使用默认值。对应常见档位为普通怪 `2 → 100%`、精英 `4 → 133.333%`、队长
`18 → 600%`、标准 Boss `25 → 833.333%`。争锋赏宴“愿望成真”极难墨菲斯托的属性包明确为
`UnbalMax=70`；当前真实战报逐角色求和后验证其进入 `2500%` 高阶 Boss 档，而不是把图文攻略中的
“轨外 Boss 一般为 50”套用到争锋目标。该实测档位不反写或修正用户确认的 `UnbalMax`。

每个格子的倾陷伤害属性与该角色固有属性相同，因此分别读取对应的目标抗性和角色属性穿透；防御区也分别
读取该角色等级与防御穿透。倾陷伤害不使用攻击、
生命、防御倍率属性，也不使用增伤、易伤、暴击或独立增伤；防御区和抗性区沿用当前目标的对应
计算规则。事件虽然由 nte-core 挂在某个触发角色名下，仍是团队合计，不得只按触发角色计算。对于轨外
上下半场，逐击重放只汇总与本击 `scope_half` 相同的正式出伤角色；角色快照没有半场归属，不能把整场
八名角色一起求和。若正式逐击不能唯一确认该半场四名角色，则本击标记为不可完整重放，不从另一半补齐。

失谐只影响敌人进入倾陷的时间和加速退出倾陷的状态时序，不影响倾陷伤害，也不影响敌方倾陷
上限值的计算。敌人处于倾陷状态本身不提供“受到伤害提升”或其他额外易伤；只有明确写入技能、觉醒、弧盘
或环境效果的倾陷伤害提高才进入对应角色的格子，不能由目标倾陷状态自动添加。

目标出现正式 `Buff_Tenacity_damage` 逐击后视为进入倾陷；恢复区间按
`倾陷持续秒数 = UnbalMax ÷ UnbalReduceReset` 计算，并使用扣除时停的有效战斗时钟。当前
`Abyss_8` 第 12 层上下半属性包均为 `UnbalMax=50`、`UnbalReduceReset=5`，对应 10 秒。该状态区间本身
不改变普通逐击；只有「炽火灼痕」等明确要求“对倾陷状态下敌人”的效果才消费它。

达芙蒂尔的专用固定轴适配器按 QTE 动作维护最多两层 E 强化并由下一次 E 整组消费；三觉前，Q 对正式目标
只建立或刷新一层洞察，并在首次倾陷后移除；三觉启用后才允许重复 Q 叠至两层且不因倾陷移除。四觉的
`UnbalDamageUp=15% × 洞察层数` 只进入达芙蒂尔自己的倾陷格子和同一已观测
倾陷结算簇。`GE_Player_Daffodill_ExtraUnbalance_Damage` 在零觉战报中也可出现，只作为达芙蒂尔个人额外
倾陷公式锚点，不能证明五觉。零觉洞察已有一次额外结算；边际候选明确勾选五觉时，每层洞察在原轴基础
倾陷时点再增加一次派生结算，因此总次数为 `1 + 洞察层数`：一层共两次，三觉叠至二层时共三次；
派生行的基线为零、候选值取当时可重放的个人倾陷公式，不写回原始逐击。六觉共鸣只有在六个普通觉醒全部
启用、且玩法同时提供可靠 `UnbalMax` 与 `UnbalReduceReset` 时才建立目标暗抗 `-15%` 区间；缺恢复速度时
不猜持续时间。

## nte-core 超杀扣减与 v4 最大生命字段

v3 每行的 `overkill_damage` 是 primary `damage` 中超过有效 `target_hp_before` 的权威部分，不包含
`follow_up_damage`。应用保留原值并使用：

```text
有效主伤害 = max(0, damage - overkill_damage)
逐击有效伤害 = 有效主伤害 + follow_up_damage
逐击原始伤害 = damage + follow_up_damage
超杀扣减 = 逐击原始伤害 - 逐击有效伤害
```

字段存在且为零仍表示 Core 已提供权威结论，不能再用 HP 区间重叠规则二次扣减或覆盖其证据。字段缺失表示旧
contract，正式伤害保持原值。Core 生成的 `Server settlement residual` 以零超杀进入有效伤害，用于补足
服务器结算中已确认但无法归到角色的部分；它保留在未归因构成，不得按相邻角色或技能猜测所有者。

v4 还为逐击提供 `max_hp_reduction`，同一行 `target_max_hp` 表示结算后的最大生命。应用只在停止采集后完整
重读同一最终 generation，且轴为 `finalized=true`、`complete=true` 时把该字段作为 Core 的结构化生命上限
结算；分析层直接采用，并把随后观测到的最大生命变化只作为一致性校验，不能再按 HP 样本推导第二份结算。
字段缺失、旧 contract 或最终轴不完整时仍使用下节的比例回退算法。Core 不输出逐击来源或校准状态的推断标签。

## 战报最大生命下降结算

旧战报没有结构化 `max_hp_reduction` 时，正式逐击若连续提供同一目标的最大生命样本，只把低于此前已确认值的样本视为一次最大生命下降；高于已确认
值的回跳样本按陈旧采样忽略，不重置基线。当前生命与最大生命同时按比例下降时，额外有效伤害为：

```text
结算前当前生命 = 变化前同半场、同目标实例、同旧最大生命的附近连续逐击中最小可靠 HPAfter
下降前生命比例 = clamp(结算前当前生命 / 下降前最大生命, 0, 1)
生命上限结算伤害 = (下降前最大生命 - 下降后最大生命) × 下降前生命比例
有效伤害 = 正式逐击伤害 + 生命上限结算伤害
```

若下降后的首行满足 `damage = HPBefore - HPAfter`，该行 `HPBefore` 已是生命上限结算后的样本；正式逐击
直接保留该差值，不能再减一次生命上限结算伤害。跨越旧、新最大生命样本的总血条变化用未解释差额闭合，
不把采样空档或并发逐击硬塞给下降后的首行。

同一目标的并发伤害可能形成多条相交的 `HPBefore → HPAfter` 区间，后到事件的 `HPBefore`
不一定等于此前最低 `HPAfter`。相交区间只能证明血量样本并发或陈旧，不能单独证明同一伤害被重复记录；
旧 contract 分析层才为每个“半场 + 可靠正式 `target_id`”独立维护最低已覆盖生命前沿并记录疑似重叠量，
但不据此改写正式逐击伤害、角色/技能构成、队伍总伤害或 DPS。v3 已由 Core 提供权威超杀，项目侧不再对
这些行运行重叠诊断，避免重复扣减。不同 `target_id`，以及上下半复用的同一 wire ID，生命前沿、最大生命
基线和目标账本绝不合并；缺失或为 `unknown` 的目标 ID 在没有用户确认唯一目标时不生成旧式诊断。
另有一个不改伤害的逐击归属诊断：同一目标 700ms 内两个不同伤害项上报完全相同的伤害，且两条 HP 区间
相交或结算端点一致时，两条重放都标记为“伤害归属污染”，不再用来反推暴击或 DOT 层数。时间距离本身不足以
触发诊断，必须同时满足目标、伤害项、伤害值与 HP 证据。原始逐击、角色/技能构成、总伤害和公式候选仍全部
保留；该规则不把其中任何一条擅自判为重复伤害。

每个目标账本同时保存分析范围内的首个当前生命、最低终止生命、观测耗血、分析有效伤害和有符号未解释差额：

```text
观测耗血 = max(0, 首个当前生命 - 最低终止生命)
未解释差额 = 观测耗血 - 分析有效伤害
观测耗血 = 分析有效伤害 + 未解释差额
```

正差额表示观测耗血仍多于已解释伤害，常见于缺失服务端事件、脚本扣血或当前模型缺口；负差额表示分析伤害
高于净观测耗血，常见于溢出伤害、回血抵消、并发陈旧样本或尚未拆出的复合记录。差额只用于对账，不分摊给
角色或技能；原始伤害、生命上限事件和 `HPBefore/HPAfter` 始终保留。

当前正式样本中，安魂曲噩梦逐击同样满足 `damage = HPBefore - HPAfter`，而最大生命按比例结算发生在旧上限
末端样本与新上限首行之间。因此 200% 技能描述只用于机制归因和缺少实测下降时的描述预计，不能反过来把
正式噩梦逐击替换为“最大生命下降 ÷ 2”。聚合主摘要保留 nte-core 原始总伤害；长页保存每击原始值，并在
v3 行上扣除权威超杀得到有效逐击。生命上限结算只作为独立派生伤害增加一次；旧 contract 的疑似生命区间
重叠只作为诊断展示。

正式逐击、目标最大生命差值和派生结算分别保留，不把结算值伪造成 nte-core 逐击。当前机制归因只有两个
窄适配器：法帝娅 `Buff_Reaction_4_new` 在下降前 5 秒内出现时优先归属于法帝娅被动；有效养成已激活
安魂曲 `Effect5`，且下降前 4 秒内存在 `GE_Player_Lacrimosa_Blood_Damage` 或其 `LV6` 版本时，归属于
安魂曲五觉。窗口只用于归因，不用于预测下降数值；实际结算始终采用目标样本。未命中适配器的下降仍进入
有效伤害，但归属为未知。反事实边际把该结算作为固定、不可由当前普通面板公式重放的贡献。

精确捕获角色 1004 的 `GE_Player_Lacrimosa_Blood_Damage_LV6` 本身还是一条高置信运行时证据。分析在用户
时段筛选之前扫描完整原始轴，生成 `BattleInferredCharacterFact(kind="awaken_effect_active", value="Effect5")`，
并记录精确 GE、证据事件 ID、算法版本和置信度。该事实不改写冻结快照、不默认勾选五觉，也不写回角色页；
默认启用时，它通过统一有效养成覆盖供 Buff、技能、逐击和目标生命重放共同消费。只有该事实会实际补充当前
生效基线时，边际页才显示开关并允许把事实 ID 加入 `disabled_inferred_fact_ids`，以检验“关闭该实测事实”
的反事实；基线已经明确选中相同觉醒时不显示冗余开关，离开边际页后该选择随内存候选丢弃。

缺少对应实测下降时可以生成不计入正式结果的描述预计：

```text
安魂曲五觉预计最大生命削减 = 本次噩梦本体伤害 × 200%
法帝娅被动预计最大生命削减 = 法帝娅固有生命上限 × 200%
预计有效生命损失 = 预计最大生命削减 × 当前生命 / 当前最大生命
```

法帝娅说明还写明全队各获得其固有生命上限的 10%，累计汲取不超过 50%。逐击重放只在正式
`Buff_Reaction_4_new` 黯星结算之后增加一层，最多 5 层，并持续到离开战斗；触发黯星本身不提前享受该层。
每层获取量不是受益角色自身生命百分比，而是固定的 `法帝娅固有生命上限 × 10%`，因此逐击属性投影使用
`HPMaxAdd`。固有生命只取冻结的“人物基础生命 + 弧盘基础生命”；已选择三觉时对该和整体乘 1.30，装备
生命、普通生命百分比、固定生命和最终面板不进入该基数。五次上限只限制我方生命获取，不限制敌方第六次
及后续最大生命损失；上下半场分别累计。描述预计必须具有明确目标实例 ID，或先由用户确认单目标完成绑定。
若本场已经观测到归因明确的目标最大生命下降，则优先用
`目标最大生命下降 ÷ 200%` 反推法帝娅固有生命；这项正式战报证据可以覆盖陈旧的战报配置副本，并用于每层
固定生命获取量。描述预计不推进目标实测最大生命基线；相同技能触发已被实测下降事件引用时，不再生成预计
事件，防止同一次机制重复进入页面。

## 已确认映射与默认状态时序

### 技能倍率的 15 档

每个伤害 GE 在 `DT_SkillDamageData` 中保存攻击、生命、防御倍率数组。15 档数组按
`有效技能等级 - 1` 取值，超过数组末档时钳制到末档。角色页的有效技能等级不是直接相加觉醒数量，而是
基础技能等级加上当前具体觉醒选择所激活的 `character_awaken_skill_level_bonus`。三/六觉共鸣只在普通
觉醒勾选数达到门槛时激活。基础技能范围为 1–10 级；当前正式数据只有三觉共鸣提供 `+1`，所以最高生效
等级为 11，六觉不增加技能等级。`character_skill_level` 的 1–9 行是升到 2–10 级的九次升级要求，不是
角色页最大等级 9。派生 Ability、闪避反击、变轨分支与终结技子段不以自身 ID 回退到 1 级，而是通过
`gameplay_ability_level_hint.damage_effect_ids_json` 反查角色实际升级的父技能；同一伤害项存在多个正式
父技能候选时优先采用逐击观测 Ability，其次采用导入绑定，不猜测。未结构化为技能等级修改的说明文本不
参与倍率档位，避免从文案猜数值。

上游导出中的源数据路径（导出目录不属于仓库）：

`SOURCE_EXPORT_ROOT/Content/DataTable/skill/DT_SkillDamageData.json`

SDK 结构为 `FSkillDamageExecutionData`，位于：

`SOURCE_EXPORT_ROOT/CppSDK/SDK/HTGame_structs.hpp`。

### 环合 16 档

确定采用每 5 级一档：

```text
档位 = floor((角色等级 - 1) / 5)
```

1–5 级为第 1 档，76–80 级为第 16 档，适用于创生、浊燃与黯星。

### 环合状态默认规则

- 除黯星外，重复施加暂按刷新持续时间、不创建新实例处理，标记为未实测。
- 黯星按触发者独立计时、独立爆炸；同一触发者再次施加时刷新自己的实例。
- 覆纹逐次记录实际直伤和该次直伤属性，到期按
  `实际伤害 × [(1 + 20%) × 覆纹环合强度区 - 1] × 其他特殊乘区` 追加同属性伤害；队伍中灵可已解锁
  「弱点感应」时基础追加比例改为 30%，并按
  `(原增伤区 + 10%) / 原增伤区` 补入只属于该追加攻击的通伤，避免误写成独立 `×1.10`。
- 状态被提前移除时不立刻结算，除非技能专属效果明确要求结算。
- 不额外设定“同一帧”规则，事件按服务端接收先后处理。
- 失谐目前按 `敌方倾陷上限 × 15%` 扣除；固定值、等级系数、联机修正均记录为待定且暂不参与计算。

### 怪物实例与属性包

静态迁移 v4 引入 `monster_instance_profile` 与 `monster_instance_profile_variant`，保留怪物实例到属性包
以及世界/副本/深渊等级变体的原始绑定；静态迁移 v5 引入 `abyss_level`、
`abyss_level_monster_spawn` 与 `abyss_monster_pool_entry`，导入 Abyss 关卡、波次、怪物池和属性包关系。
这些表继续保留在当前静态 schema v27 中；v27 还保存轨外怪物池条目的官方本地化名称。v20 起保存属性包的 `HPMaxBase`、`HPMaxUp`、`HPMaxAdd`，
以及 RogueLike 怪物实例和属性修正；战报可据此计算单目标最大生命上限变化，但仍需以运行时敌方实例绑定
确认实际使用的属性包和修正组合。
该链路仅以 `HT/Content/DataAssets/DataAssetSet/Abyss` 的专用配置为准：`AbyssCloneLevelDataTable`
→ `MonsterPoolID` → `DT_AbyssMonsterPool` → `AttributeID` → `DT_MonsterPackData`。当前 648 条怪物池成员
使用 630 个属性包，全部能闭合到普通敌方属性表。v23 另保存官方怪物图鉴、材料/养成副本类目、难度与
刷怪模板绑定，但刷怪模板未必都能闭合到唯一属性包；
未闭合时只能作为目标身份证据，不能代替用户确认的防御和抗性。唯一 `AttributeID` 均命中普通属性包。
`FT_` 是 999 夜子玩法前缀，不表示轨外之境或 Abyss 场景，
不作为场景判定依据。
v24 保存限时战斗奖励任务提供的 `AbyssID` 大陆服生效区间，并标记构建日对应的当前与下一配置。
`AbyssID=Abyss_8` 表示一套包含多个 `LevelID` 的关卡配置；同一任务中的 `AbyssLevel=8` 才表示第 8 层。
v26 进一步保存当前/下一配置的赛季 Buff；赛季说明与曲线属于正式静态事实，逐击触发和倾陷窗口仍由本场
正式命中重建，不把今天的环境覆盖到其他配置。

战报环境反向识别把当前分析范围内每个正式目标实例出现过的最高 `target_max_hp` 作为其初始最大生命，
以实例数及最大生命多重集与静态完整遭遇配置做精确相等匹配；轨外目标句柄按上下半分域。Core 玩法、层数、
半场和怪物 ID 作为额外过滤证据。通常只有一个环境配置完整符合时才投影目标身份和共享敌方参数；黑之书
与无首铁驭在相同世界等级具有相同生命且缺少怪物 ID 时，按产品约定默认黑之书，同时降为中置信并在当前
范围标红“歧义”，供用户打开条件选择器确认。自动候选仅包含当前/下一轨外配置、争锋
全部八个挑战对象、四类材料养成副本和异象追猎单 Boss，不包含异象巡礼或普通大世界怪群。
