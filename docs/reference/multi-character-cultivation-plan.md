# 多角色养成计算

## 1. 目标与边界

多角色模式在现有工具页内与“单角色计算”并列，不新开弹窗。用户建立有顺序的角色目标列表，统一填写猎人等级、
生效鉴别等级和账号级已有材料，得到：逐角色材料、逐角色明细、跨角色合并材料、共享已有材料扣减、正式副本次数和
最低体力。第一版只保留当前页面会话草稿，不写角色档案、背包或游戏状态；账号 generation 或静态 dataset 改变时
整份草稿失效。抓包材料同步继续使用当前占位，直到组件提供完整材料库存 DTO。

“跨角色最低体力”是权威总结果。逐角色体力用于解释角色自己的需求，不能相加后冒充总量：同一副本的一次确定掉落
可能同时覆盖多个角色、多个材料，合并求解可能低于逐角色结果之和。

## 2. 冻结请求与结果

新增 Qt 无关 DTO：

```text
CultivationBatchRequest
  account_id / generation / dataset_identity
  hunter_level / effective_identification_level
  ordered_targets: CultivationTargetDraft[]
  owned_quantities: item_id -> quantity

CultivationTargetDraft
  line_id                 # 页面内稳定身份，不使用角色名称
  character_id
  CultivationRequest      # 人物、技能、弧盘及各参与开关

CultivationBatchPlan
  target_plans: (line_id, CultivationPlan, per_target_stamina)[]
  merged_totals
  owned_allocation
  remaining_totals
  combined_stamina
  gaps
```

请求创建时一次冻结账号、generation、静态 dataset、目标顺序、全部等级、开关、弧盘和已有材料。worker 回调前再次核对
三项身份；过期结果静默丢弃。`line_id` 维持多选变更、删除和重算后的 UI 身份；正式关联仍使用 `character_id`、
`fork_id`、`skill_id` 和 `item_id`。

## 3. 计算规则

1. 对每个目标调用唯一的 `CultivationPlannerService.calculate`，不在批量 Service 复制人物、技能或弧盘公式。
2. 按正式 `item_id` 合并全部 `CultivationPlan.totals`，保留 `line_id → section → item_id` 的来源账本。
3. 已有材料只消费一次。采用页面顺序优先：从第一名目标开始按明细顺序分配，同一模块内先满足低档再以 3:1 合成高档，并在结果中显示每个目标分到的有效数量；
   多选时保留原有目标的顺序，新目标按目录顺序追加。合并“仍需”对合并需求独立执行一次三合一抵扣，不以不同档位的原始件数直接相减。人物和弧盘经验材料不转换。
4. 逐角色体力基于该角色获分配后的缺口计算，用于解释；合并体力对全部合并缺口只调用一次
   `ProgressionStaminaService`，作为总计。
5. 确定掉落使用整数规划，目标依次为最低体力、同体力下最少副本次数。概率、范围、分支冲突或缺失掉落继续产生
   `partial/unavailable`，已知部分与完整总量分开显示。
6. 同一个角色最多出现一次，避免两份目标争用相同角色当前状态。后续如支持同角色多阶段计划，必须以不同
   `line_id` 显式串联前一目标的终态，不能把两行都从账号当前值起算。

## 4. 页面结构

页头把当前只读标签改为可切换的“单角色 / 多角色”。两种模式各自保留草稿，不因切换而丢失：

- **目标列表**：每个角色一张摘要卡，显示头像、人物目标、技能目标、弧盘目标、启用状态，以及同尺寸、键盘可达的编辑和删除操作。点击“编辑”在该卡下方展开人物、技能、弧盘三块编辑区，并收起其他角色；已填目标和计算顺序不因收起改变。技能等级控件比摘要模式更宽，默认窗口一行两项、足够宽的全屏窗口一行四项，窄窗口退到一列；按角色列表实际可用宽度重排，不靠横向滚动。弧盘展示冻结数据集内的正式图标，未选或图片缺失时显示文字占位；更换后名称和图标同步刷新。默认窗口中图标、选择操作、当前状态和目标状态同排，空间不足时纵向排列。角色与弧盘的目标状态、弧盘选择块沿用当前状态的普通底色及边框。
- **选择角色**：图片选择器支持多选、“全选”“清空”；已选目标进入时预勾选，确认后以整个勾选集合更新实际目标，取消不变。保留角色的编辑值和顺序，新选角色按目录顺序追加；取消勾选删除对应目标。编辑在同页展开，复用单角色目标控件。
- **公共输入**：猎人等级、生效鉴别等级、已有材料和抓包同步占位只显示一份。页头共用“全部 / 仅体力”材料范围，单角色和多角色默认“仅体力”；后者仅把冻结副本档位中正体力、正确定产出的非方斯材料投影到已有数量卡片、总计、逐角色/模块明细和复制清单。已有数量编辑器不显示加减按钮，点击后全选原数值。完整合并计划及已有数值不丢失，切换范围不启动后台求解；编辑已有数量后仍需手动重新计算。
- **总结果**：最上方显示跨角色仍需材料、最低体力和副本组合，材料标准宽度五列。
- **角色明细**：每个角色一个折叠栏；内部继续显示人物升级、突破、各技能、弧盘升级和突破，每个模块同时显示材料、
  已有材料分配、仍需数量、最低/已知体力及副本次数。
- **差异提示**：总计旁提示“合并副本掉落已去重”；逐角色体力之和与合并结果不同时给出节省体力，但不把节省值
  写入材料事实。

不设置人为角色数量上限；可选择的正式角色各自最多出现一次。全部角色已选时仍可打开选择器并清空或取消勾选。

## 5. 分层与异步

- `CultivationBatchPlannerService`：冻结多角色请求、逐角色调用现有计划 Service、合并来源账本、分配已有材料，再调用公共
  体力 Service；不访问 Qt。
- `CultivationBatchController`：拥有单一 worker、取消 token、账号/dataset 复核和“最后一次请求胜出”策略。
- `CultivationBatchPage`：只拥有目标卡、编辑状态、折叠状态和结果投影；不打开数据库、不实现合并或体力公式。
- 静态 DAO 在 worker 开始时一次读取正式副本档位；同次计算的总计和全部明细共享该不可变元组。
- 首次计算后，目标或体力档位编辑以 250ms 防抖生成新请求；已有材料编辑使结果过期、取消待提交请求，必须点击“重新计算”才提交新请求。已有 worker 只允许完成后丢弃过期结果，不并发启动多个整数规划。

## 6. 交付状态

### 已交付：批量领域与 Service

- 新增 DTO、合并来源账本、顺序分配和组合体力计算。
- 覆盖重复角色、零目标、材料别名规范化、已有材料跨角色只消费一次、部分掉落和同副本多材料去重。
- 以多于八个角色和当前正式档位做性能基线；超过求解时限保留明确 gap，不返回近似值冒充精确结果。

### 已交付：页面与生命周期

- 启用多角色标签，完成多选、全选、清空、编辑、删除和单/多人草稿切换。
- 接入后台 worker、取消、账号切换和 dataset 更新失效处理。
- 完成总计、角色折叠明细、复制清单和五列响应式卡片；运行期间计算按钮自身显示“正在计算中”并禁用，不增加外部状态标签；
  计算结束后自动定位到结果区，避免较长目标列表使有效结果留在当前视口之外。
- 账号、generation 和静态 dataset 身份在请求前后复核；dataset 文件身份仅含路径、大小和修改时间，读取导致的访问时间变化
  不会把有效结果误判为过期。
- 等级、技能、猎人等级和已有材料数量是纯数字字段，关闭平台文字输入法组合上下文；已有材料使用固定绘制面和单个可复用数字编辑器，点击材料卡时将编辑器定位于该卡，结果回调只更新材料模型、图像和需要数量，不按材料数量批量创建或销毁可聚焦控件。单角色与多角色的已有材料数量不响应鼠标滚轮，滚轮仍可滚动页面。旧结果从布局移除后仍保留原父级直至 `deleteLater` 执行，不临时创建顶层 QWidget。这些 UI 约束降低编辑器生命周期风险，但不能阻止输入法组件自身线程崩溃。图片选择器的搜索框仅接收直接拉丁/拼音输入，不建立中文输入法组合上下文；选择器结束后从页面子树延迟销毁。结果回调先把焦点交给稳定的计算按钮，再更新结果；离开多角色页后不执行该页的延迟自动滚动。
- 后台 worker 的结果、错误和结束信号直接连接控制器的 `@Slot`，显式使用排队连接交还 GUI 线程；旧 worker 的结束回调完成前，下一请求只排队，不新建第二个 worker。多角色请求使用页面内递增的诊断序号，worker、结果回调、材料区更新、结果控件替换、自动定位和用户滚轮/滚动变化共用该序号写入现有有界运行日志。记录阶段、线程数字 ID、耗时和数量，不写角色、材料、账号、数据路径或输入内容；崩溃转储时间可与最后一个阶段标记对齐。阶段日志只定位触发区间，不将第三方原生线程中的访问冲突误判为 Python 异常。

### 后续协议能力：材料同步与可选持久化

- Core 协议增加独立材料库存能力、完整性与 generation；Calc 只在本次完整快照成立时填入已有材料。
- 手工值与同步值并列保留来源；用户编辑后标记为手工覆盖，不被迟到同步改写。
- 如后续需要保存计划，再为账号库追加 migration；第一版不得借用角色档案或装备背包表保存草稿。

## 7. 验收门禁

- 总材料等于各角色正式材料按 `item_id` 合并；账号已有材料在全部角色间最多消费一次。
- 合并体力不大于相同输入下逐角色体力之和；多材料同副本只计一次运行。
- 每个角色及其每个模块均可追溯需求、分配、缺口、体力状态与副本组合。
- 账号切换、静态更新、多选删除目标和快速连续编辑不展示或保存过期结果。
- 1、5、超过 8 个角色以及完整/部分/不可用掉落均有行为测试；标准宽度五列、窄窗口无横向滚动，键盘可完成多选、
  全选、清空、编辑、展开和删除。
