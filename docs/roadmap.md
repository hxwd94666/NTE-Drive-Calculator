# 当前路线图

本文件只保留尚未完成且会影响数据结构、外部能力或产品边界的工作。完成并通过公共行为测试后，将稳定
事实整合进 `features.md` 或 `architecture.md`，随后从本文删除。

## 1. 战报与实战收益

### 1.1 当前边界与研究目标

当前战报输入是 nte-core 聚合摘要，只能确认整场或上下半场的角色、技能、伤害、命中、DPS、承伤和
数据质量统计。页面不得从聚合结果反推逐击、动作、环合触发、目标实例或血量变化。

下一阶段研究目标是一张纵向连续的战报长页：页面顶部只有一个“分析时段”，角色动作轴、环合/倾陷轴、
逐击伤害轴以及后续全部统计区块共同消费这个时间范围，不使用页签切断上下文。拟研究区块按顺序为：

1. 战斗时间轴；
2. 选定时段统计；
3. 角色伤害贡献；
4. 技能伤害明细；
5. 逐击事件日志；
6. 受击目标与血量变化；
7. 未知最大血量削减；
8. 边际收益分析。

这只是研究基线，不代表当前能力。每个区块进入实现前，必须分别完成实现细节、数据结构、算法、UI 交互
事件和公共行为测试设计。

### 1.2 统一时间语义

- 一场战报冻结唯一 `battle_record_id`、账号、`AppContext.generation`、账号库路径、采集 operation、
  nte-core capability/协议版本、静态数据集与名称映射版本。
- 原始时间以战斗会话的单调时钟为准，不使用本机墙钟排序；所有事件保存相对会话起点的整数时间。
- 是否扣除时停属于战报级时间投影，不能让不同区块各自解释。原始时间与展示时间的换算需要可复现。
- “分析时段”候选语义为左闭右开区间 `[start_ms, end_ms)`；应用、重置和加载历史战报时必须归一化到
  有效战斗范围。最终边界规则在逐击协议研究后确认。
- 顶部整场摘要仍表达整场；“选定时段统计”及其后各区块只消费同一个不可变区间快照。每次范围变化生成
  新 request token，旧计算结果静默丢弃。
- 历史战报只有在保存了足以重算区间结果的正式事件时才开放区间分析；只有聚合摘要的旧记录保持现有展示。

### 1.3 事件分层

三类事件不得共用一个含糊 payload，也不得由 UI 改写事实：

| 事件层 | 候选对象 | 含义与所有权 |
| --- | --- | --- |
| 战斗证据 | `DamageHitEvent`、`TargetVitalEvent`、`TimeStopInterval` | nte-core/Integration 提供的原始或正式投影；逐击统计的唯一事实源 |
| 派生推断 | `CharacterActionEvent`、`ReactionActivationEvent`、`CollapseEvent`、`MaxHpReductionEvent` | Domain 根据正式证据和静态映射生成；必须保留算法版本、证据引用和内部置信信息，可删除重算 |
| UI 交互 | `AnalysisRangeChanged`、`TimelineEventSelected`、`DenseGroupExpanded`、`ReportFilterChanged`、`DetailRequested` | Controller 持有的页面意图和可丢弃状态；不冒充战斗事件，不默认写入战报历史 |

角色动作轴只展示“角色在何时做了什么”的推断；逐击伤害轴只展示“何时由何种渠道对哪个目标造成多少
伤害”的证据。环合泳道只展示黯星、覆纹、创生、浊燃等激活推断，环合伤害仍进入逐击轴。近同时事件可
在展示层分组，但分组不合并或删除底层事件。

### 1.4 模块研究矩阵

| 模块 | 实现与数据结构重点 | 算法重点 | UI 交互事件重点 |
| --- | --- | --- | --- |
| 全局分析时段 | `BattleAnalysisRange`、时停映射、区间快照与 token | 边界裁剪、原始/展示时间互转、增量或重算 | 拖拽预览、输入应用、重置全部、历史恢复、旧结果丢弃 |
| 角色动作轴 | 每角色泳道、证据引用、动作类型、段数、推断版本 | 逐击与技能窗口关联，QTE/Q/E/R/普攻段数推断，近同时动作分组 | 悬停摘要、点击选中、密集组展开、定位关联逐击 |
| 环合与倾陷轴 | 激活事件、参与角色/元素、来源证据、独立泳道 | 激活条件、去重、持续区间与伤害事件分离 | 重叠自动增行、选中后高亮关联伤害、名称只显示事件名 |
| 逐击伤害轴/日志 | 稳定事件 ID、时间、攻击者、技能、目标、伤害类型、数值 | 排序、分页、同刻堆叠、技能中文名映射、未知来源保留 | 缩放、悬停、筛选、选中、组展开、跳转日志行 |
| 角色与技能统计 | 区间聚合结果、分类版本、未映射桶 | 按同一区间重算命中/伤害/DPS/占比，避免双重归因 | 行筛选、排序、点击联动时间轴与逐击日志 |
| 目标与血量 | 目标实例 ID、血量样本、最大血量样本、生命段 | 命中与目标绑定，恢复/护盾区分，最大血量下降检测 | 目标筛选、选中命中、血量条悬停、未知变化展开 |
| 边际收益 | 区间伤害构成、角色/技能适用标签、边际输入快照 | 按伤害种类重放可计算维度，给出不可计算占比和假设 | 临时调整边际、恢复默认、查看适用伤害、显示不可计算原因 |

### 1.5 数据所有权与分层候选

- 发行静态库只读，提供正式角色/技能/敌人 ID、中文名、伤害标签、公式和版本化映射；运行时不得写回。
- 逐击和目标事件属于当前账号的一场不可变战报。是否进入账号库、采用事件表还是压缩 payload，必须在
  评估单场规模、分页需求、迁移和保留策略后决定。
- 推断结果默认不作为第二套事实源；优先保存算法版本与必要证据后按需重算。若为性能保存缓存，缓存必须
  可失效、可删除，并且不改变原始逐击。
- 分析时段、筛选、展开组和当前选中事件是页面交互状态。只有明确需要恢复的最小字段才能进入
  `battle_report_page_state`，不得把滚动、悬停或临时边际值写成战报事实。
- Page/View 只投影长页和发出交互意图；Controller 拥有选区、筛选、选中项、worker 与 token；Service
  冻结请求并编排区间分析；Domain 执行纯推断和聚合；DAO/Integration 独占持久化与 nte-core 协议。

### 1.6 UI 交互事件候选

交互事件是 Controller 内部的显式意图，不是日志埋点名称，也不要求逐项持久化。第一轮 contract 研究至少
覆盖：

1. `AnalysisRangePreviewed`：拖动时只更新轻量预览，不启动全部重算；
2. `AnalysisRangeApplied`：提交合法区间，产生新 token，并统一刷新下游区块；
3. `AnalysisRangeReset`：恢复整场区间；
4. `TimelineEventSelected`：建立动作、环合、逐击、目标血量和日志行之间的交叉高亮；
5. `DenseGroupExpanded`：只改变展示，不改变底层事件或统计；
6. `ReportFilterChanged`：角色、技能、目标和暴击等筛选只影响对应明细，不偷偷改变全局分析时段；
7. `DetailRequested`：从统计行定位时间轴或逐击日志，不通过页面互调私有控件实现；
8. `HistoryRecordLoaded`：先冻结新记录及能力级别，再恢复允许的时段和筛选；旧 generation 回调丢弃；
9. `MarginalInputChanged`：页面内临时计算，明确“未保存”；恢复默认不修改账号基础权重。

### 1.7 已确认的 nte-core 逐击 contract

本项目随附的 nte-core 0.4.0 与上游 0.4.1 在本节相关代码和协议上没有差异。`core.hello` 已正式声明
`battle_record_v1`、`battle_axis_v1` 和 `battle_timeline_v1`，因此逐击第一阶段不需要等待新上游版本：

- `battle.get_record` 返回进程内稳定记录 ID、generation、完成状态、起止时间、时停区间、摘要、质量和
  逐击完整性；
- `battle.get_axis` 以 1～500 行分页，使用正十进制 cursor/sequence，提供角色归因、方向、主伤害、追击、
  目标血量、技能/效果标识、伤害分类与深渊半场；
- `battle.get_timeline` 按 0.2～10 秒桶宽返回角色 DPS、伤害、命中、累计伤害、时停和场景标记；
- 逐击可用 `(source_battle_record_id, sequence)` 作为上游会话内稳定身份。追击仍与主击保存在同一轴记录，
  展示层需要以 `sequence:primary` 和 `sequence:follow_up` 拆成两个时间点，但持久层不得改写原记录；
- 每击直接携带 `target_hp_before`、`target_hp_after`、`target_max_hp` 和百分比，因此匿名目标的血量变化可做；
- `ability_name`、`gameplay_effect_name`、`damage_name`、`damage_component`、`attack_type` 和
  `damage_attribute` 可作为中文名映射、技能分类和动作推断证据。

协议边界同时要求应用主动处理：

- Core 只保留最多 50,000 击，超过后一次裁剪到 46,000；`complete:false` 或 cursor expired 代表前缀已经
  不可恢复。应用必须在采集期间分页拉取并自行保留，不能只在结束时读取；
- 逐击没有推送事件，只有最多 4 Hz 的聚合摘要通知；应用应使用有界轮询读取 record generation 和 axis，
  停止后再排空尾页；
- sidecar 只保留当前进程内战报，`battle.reset` 后旧 ID 不可读；toolkit 桌面端自己的历史 JSON 不是
  sidecar 历史接口；
- `timestamp_unix`、`relative_time_seconds` 和追击时间是有限浮点秒，sequence 才是确定顺序。应用持久化
  时可投影为整数微秒，但必须保留 sequence 并定义同刻排序；
- `team_snapshot_id` 当前固定为 null，不能把当前 UI 队伍补成战斗时队伍；
- 没有逐击暴击标记、Buff/Debuff 区间、护盾/治疗事件或角色施法事件。`FixedCritRate` 等静态字段不能证明
  某一击是否暴击；
- 目标 ID/名称/怪物 ID 是可选字段。正式发行尚未包含研究中的 `enemy-telemetry` 脚本；无插件证据时只能
  展示“未识别目标”，不能仅凭相邻血量猜测具体怪物实例。

因此当前真正阻塞项是应用侧 Integration、区间持久化和推断 contract，而不是逐击读取能力本身。仍需上游
或实机证据确认的内容包括：

- 多目标、召唤物、阶段切换时目标 ID 与血量连续性的覆盖率；
- Buff/Debuff 状态区间、环合/倾陷的正式激活证据；
- 角色、武器、队伍和场景的不可变快照；
- 暴击事实、护盾、治疗和最大血量削减的来源标识。

后续研究顺序调整为：应用侧逐击拉取/完整性 → 统一时间语义 → 逐击日志 → 角色动作推断 → 环合/倾陷
推断 → 目标与血量 → 区间聚合 → 边际收益 → 长页交互和持久化。上游没有正式字段时，只记录“不可得”
和候选算法，不以 UI 占位或调试字段固化 schema。

### 1.8 第一阶段应用侧切片

第一阶段只接入“正式逐击证据”，不同时实现动作推断、环合推断、目标命名和边际收益。候选公开 contract：

- Integration 暴露不可变的 `BattleRecordSnapshot`、`BattleAxisPage`、`BattleHitEvidence` 和
  `BattleAxisCompleteness`，并保留上游 record ID、generation、sequence、cursor 与 contract version；
- `BattleCaptureRequest` 冻结账号、`AppContext.generation`、账号库绝对路径、静态数据集、名称映射版本、
  operation token 和 nte-core capability；采集回调与最终写入前逐项复核；
- Controller 在采集活跃期间按有界节奏读取 record，并从已确认 cursor 开始以 500 行分页排空 axis；收到
  新摘要序列可提前触发读取，但摘要通知本身不作为逐击到达证明；
- 停止采集后先等待 record final，再排空到 `next_cursor = null`。record/generation 改变、cursor expired、
  Core 退出或 `complete:false` 都保存为明确的不完整状态，不用聚合摘要补造逐击；
- 账号库候选采用战报主记录加规范化逐击表，逐击唯一键为 `(battle_record_id, source_sequence)`。原始轴行
  只写一次；主伤害和追击拆分、中文名、动作、环合与最大血量削减均为可重算投影；
- 逐击量上限可能达到单场 50,000 行。迁移前需用真实样本测量 SQLite 体积、分页查询和保留策略，再决定
  自动记录是否全部保留逐击以及旧记录何时只保留摘要；
- 页面先交付逐击日志与基础伤害轴。只有当逐击完整、时间范围确定且旧 token 未失效时，才生成区间统计；
  `incomplete` 战报持续显示质量警告，并禁止把区间结果描述为完整战斗结果。

时间持久化候选为整数微秒 `[start_us, end_us)`，同一微秒内以 source sequence 排序。追击在展示模型中
生成 `sequence:follow_up` 子事件并使用自己的时间，但仍引用同一条 `BattleHitEvidence`，避免产生第二套事实。

### 1.9 实现前公共行为清单

- 同一逐击集合在整场与任意合法区间内聚合结果可复算，区间拼接不重复也不漏记边界事件；
- 时停投影前后均可追溯到同一个原始事件，所有区块使用相同时间模式；
- 未映射技能、未知角色、未知目标和未知最大血量削减均保留并进入质量统计；
- 动作或环合推断失败不删除逐击，算法升级不会改变原始事实；
- 快速拖动、连续应用时段、切换历史记录和切换账号时，旧 token/generation 结果不更新页面或账号库；
- 密集组展开、行排序和局部筛选不改变选定时段统计；
- 边际收益逐项列出适用伤害、不可计算伤害与假设，不把推断结果表述为精确实战增益。

## 2. 队伍收益与全局配装

长期目标是把直伤边际、环合、倾陷、DOT、队伍增益和装备竞争统一到可解释目标函数，再扩展四人队与
八人双队搜索。新求解仍使用不可变快照、官方 ID、唯一 UID、配装槽位和冻结方案 contract，不建立第二套
评分事实源。

## 3. 云游戏输入链

自动装配中的云模式保留了角色列表与装配页的手柄映射和输入诊断，Controller 当前固定
`cloud_nte_mode=False`，设置页只显示开发状态。阻塞点是云端鼠标按下/释放、手柄切换后的首个鼠标动作、
滚轮和拖拽在同一会话中表现不一致。

恢复入口前必须完成：

1. 为角色页、角色列表、空幕页和装配页定义“前置画面 → 输入 → 后置画面 → 超时停止”；
2. 单角色完整装配和至少两角色重入各连续通过三轮；
3. 在列表、装配页和拖拽前触发 F12 后，虚拟手柄与鼠标均正确释放；
4. 普通鼠标路径回归通过，账号 generation 与任务记录可复核；
5. 真实 Windows 结果记录分辨率、DPI、窗口模式、输入设备、版本和日期。

入口恢复时默认关闭并标记实验状态，不用局部成功动作推断整条输入链可用。

## 4. 倒带实机执行

倒带分析、八槽保存和输入链已接通，游戏执行仍处于实验状态：

- 启动前尚未识别并确认当前位于倒带首页；
- 坐标映射、余额/价格 OCR 和候选轮廓需要覆盖不同分辨率、DPI、语言与画面设置；
- 花费前尚未回显余额、十连价格和计划次数供最终确认；
- 页面内停止、阶段恢复和中断后的任务记录尚未形成；
- 账号 generation、执行快照与窗口身份尚未持久化为可复核任务。

当前公开策略只有“全面均衡”和“少角冲分”。领域层遗留的成本方案入口不进入 UI；增加策略前先确定
业务规则与公共行为测试。

## 5. 测试服资源收尾

静态 schema v16 已包含角色 1036、1072 的目录、成长、技能、觉醒、推荐权重和毕业模板。新增武器
`fork_DemonBlade`、`fork_GoldRecord` 的图标仍在 `assets/game_ui/manifest.json` 中显式标为
`unresolved_assets`。取得正式导出后重新运行资源构建与 `tests.test_game_ui_assets`，不使用相似图替代。

## 6. 新能力验收原则

新能力先确定 payload、sequence/generation、完整性、错误码、隐私字段、失败状态和回滚方式，再进入
Integration 与账号库。路线图条目只有在实现、迁移、调用方收口和公共行为测试全部完成后才转为当前能力。
