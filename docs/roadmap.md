## 1. 组件交付与实机验收

- **原生完整性**：`character`、`inventory`、`team`、`environment` 四个业务域仍待在登录、换队、换装、场景切换和
  游戏重启后实测能力、快照身份与完整性。完整原生库存须覆盖正式背包全集及未装备物品；`unknown`、`partial`、
  `complete=false` 不写入正式库存、不推进快照、不伪造 UID。场中变更后的多版本快照与分段重放尚未实现。
- **原生背包增量**：候选已能在完整基线上按事件 UID 重读物品与技能字段组并派生新快照；初始化、重连、事件缺失、
  溢出或校验失败重建基线。新增、部分消耗、删除、锁/弃置、强化、装卸、重连与帧时间仍待实机验收。
- **抓包启动时序**：只能宣称等待游戏进程和网络条件；早于启动、早于登录、晚于登录三种时序的网卡选择与首个完整包
  仍需实测。错过完整包时保留旧快照，不以增量补造完整集合。
- **整包与 Windows 验收**：按 [Windows 验收](validation/windows.md) 核对默认离线、模式门禁、两种加载方式、暂停和账号代次、
  DLL 共享会话、分场保存、降级收尾、退出清理、待办恢复、DLL/Loader 共存与性能；没有实测完整库存时结论须保留该缺口。
  极速装配来源变化的有界补救与扫描后单件跳过/汇总已接入源码，实机验收待完成。
- **DLL 分离**：五 DLL（d3d12、User、Combat、HUD、Performance）已接入随附包，职责见[本方插件宿主](reference/native-plugin-host.md)。
  仍需实机验证 User→Combat→HUD→Performance 启动与逆序停止、HUD 独立卸载、队友 E/Q 按钮逐帧耗时、受保护 D3D 与防护软件兼容；
  某个增强插件缺失只标受影响项目。第三方插件手动信任（按确切文件与哈希绑定版本、变化重新确认、无卸载契约只允许冷启动）
  尚未实现，不自动加载用户目录中的任意 DLL。
- **性能指标**：四项悬浮窗控制与统计已随组件晋升，待真实 Windows 验收；独立 User 插件/宿主的全部入口尚未接入统一计时，
  完成前保留 `cost_complete=false`。规则见[性能指标契约](reference/performance-metrics.md)。
- **管理员权限**：系统关闭 UAC 时，被安装器或安全软件以受限令牌启动的进程无法经 `runas` 提升，当前只提示从快捷方式启动；
  已安装版本的真实环境验收待完成。

## 2. 计算与配装

- **计算按钮遗留问题**：同级组部分结果、前序回填、暴击边界、卡带与驱动联合选择、二件套图纸及有界候选一致性待修复；
  “最低等级门槛”的卡带最终选择和同级暴击重配，原生核心与 Python 参考实现存在既有差异，须在计算专项中统一目标契约。
- **轴伤部分计分**：开发态允许已量化部分和明确估算参与推荐，覆盖率不足不再整体阻止搜索；发行组件尚未晋升。
  赛季受益缺证的逐击可不计分（不能声称收益为零）；黑羽窗口与安魂曲生命上限只作标明的估算；覆盖率不是推荐准确率。
  仍需用真实长轴战报验证推荐、覆盖率桶守恒、跨半场隔离和保存读回。
- **配装变动对比**：新旧装备统一按本次冻结权重比较并持久化槽位差异；专项与实机验证待完成。
- **套装无条件常驻**：已接入角色面板、分配、毕业模板、队伍与战报（规则见[常驻参考](reference/equipment-suit-permanent.md)）。
  新游戏版本须逐效果重新绑定证据，不自动沿用旧分类；三主题、混合 DPI、安装升级与真实游戏验收待完成。
- **剩余 Python 计算**：角色有效面板与装备属性合计、养成材料/体力规划（含 SciPy MILP）、倒带形状缺口与定价仍在 Python；
  非桌面主路径的旧程序化分配（`legacy_adapter` → `allocation_kernel`）和离线拼图（`src/solver/`）待盘点消费者后决定迁移或删除。
  不把 Python 编排或纯值参考宣称为已迁移 Rust。
- **长期目标**：把直伤边际、环合、倾陷、DOT、队伍增益和装备竞争统一到可解释目标函数，再扩展四人队与八人双队搜索；
  仍使用不可变快照、正式 ID、唯一 UID、槽位和冻结方案 contract，不建立第二套评分事实源。

## 3. 倒带推荐

- 槽位输入、评分来源与失败隔离已接入；三策略独立草稿与八槽保存已通过专项。兼顾模式行为见[兼顾模式](features/rewind-dual-target.md)。
- 待真实验收：实际账号两组不同角色与槽位的生成/调整/保存/重开不串组；已达标、无共同形状、不足八槽的状态说明；
  混合 DPI 与长译文；真实游戏倒带另行授权。保存或来源门禁通过不表示已实际抽取装备。

## 5. 新版资源与资料来源

- **数据更新缺口**：主静态、图鉴与公共技能图片已按当前正式服来源重建并晋升。仍需：成套正式组件重新验收原生角色与背包同步；
  低风险抓包的新版背包样本与 Core 内嵌属性目录交付；按角色适配矩阵核对条件技能、召唤归属和固定轴机制，未覆盖项标未知。
- **战斗资产升级**：完整战报数据集仍为原版本；同版本 Blueprint、Buff、Montage 需补齐引用闭包。`Abyss_11` 的环合参与者、
  施加时刻与刷新区间须进入规范化协议与分析组件，不得作为全场常驻加成绕过赛季审计。缺正式名称或身份冲突的角色待关系闭合后再开放编辑。
- **轨外 Commander**：`DT_AbyssCommanderConfig`／`DT_AbyssModifyPackData` 尚无现行玩法引用证据，不导入为当前轨外 Buff。
- **图鉴目录**：独立角色图鉴可能仍由旧 importer 生成；取得同版本完整 `Rows` 来源后按正式晋升流程更新，不混用不同版本导出。
- **养成材料来源**：抓包能否稳定提供材料 `ItemID/Amount` 与覆盖范围须独立验证；通过前只用原生归档中的已观测项，缺席不当作零。

## 6. 界面文本与日志

- 界面文案已全部登记进语言目录，覆盖门禁基线为空；实际译文效果仍待用真实外语补丁做整页人工核对，
  重点是显示边界模板投影在长句、复用短语和多模板同时命中时的取舍。分析组件返回的中文按源码快照登记，
  组件发版时需运行 `tools/i18n/sync_analysis_core_texts.py --check` 核对缺口；外部译者协作见 [I18N.md](../I18N.md)。
- 遗留直接日志仍可能输出未分类业务值；按功能收口到受控诊断字段，完整 RPC、UID 列表、原始数据和鉴权信息不得写入。

## 7. 新能力验收原则

新能力先确定 payload、sequence/generation、完整性、错误码、隐私字段、失败状态和回滚方式，再进入 Integration 与账号库；
实现、迁移、调用方收口和公共行为测试全部完成后才转为当前能力。
