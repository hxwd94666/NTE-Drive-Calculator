# 当前路线图

本文件只保留尚未完成且会影响数据结构、外部能力或产品边界的工作。完成并通过公共行为测试后，将稳定
事实整合进 `features.md` 或 `architecture.md`，随后从本文删除。

## 1. 战报与实战收益

### 1.1 当前边界与研究目标

当前采集层已经保存 nte-core 聚合摘要、正式逐击轴、时停区间、实际出场角色的战后游戏当前配装与公式输入
属性快照。精简主页面已经交付统一分析时段，以及把低置信输入投影、角色动作、分渠道技能条和正式逐击点合在
同一时间坐标内的多轨轴；该轴可切换包含/扣除时停，按固定时间密度在 10% 至 800% 间缩放并完整展开纵向
泳道。技能、Buff、逐击和目标证据已收进审计弹窗；固定轴边际使用独立子页面，复用角色页养成与配装编辑器。
现有实现仍通过结构化公式、同技能/同类型比值、角色面板和同比保持的旧证据梯度为原轴 100% 伤害生成数值
候选；1.7 要把其中跨目标 peer、整场单一目标条件和未知 `ratio=1` 回退迁移到逐击冻结画像与四态量化 contract。
目标派生已能从正式最大生命样本计算比例结算，并对安魂曲五觉和法帝娅被动做带置信度的特殊归因。
缺少实测下降时还会展示不计入正式有效伤害的技能描述预计；法帝娅“固有生命上限”的正式字段口径仍待
上游 Buff/属性证据确认。
页面仍不得从摘要或不完整逐击反推动作、环合
触发、暴击、Buff/Debuff、护盾、治疗或完整队伍。

下一阶段只扩展尚无正式证据或可靠算法的派生层，不另建第二张战报页。统一轴顶部只有一个分析时段，后续
新增的环合/倾陷激活轴也必须消费相同范围。剩余研究区块为：

1. 在当前静态动画事件窗口上补充实测输入、无法唯一判定的技能分支和更多角色特殊段数；
2. 环合/倾陷激活事件和持续区间；
3. 护盾、治疗、其他最大生命削减机制与多目标归属；
4. 扩大尚未审计的技能 Buff 触发覆盖，解释自定义 Calculation，并接入未来 nte-core 实测 Buff 状态融合；
5. 继续补齐尚未量化的 DOT、具体环合与特殊队伍 Buff 适配器；倾陷绝对逐击公式、同半场逐角色求和、
   动态倾陷 Buff、防御/抗性、敌方 `UnbalMax` 乘区及现有边际收益归属继续复用当前实现；灵可后续需将
   “E 选择触发”和“处于同频领域”拆成正交事实，再补觉醒一/三的动作调度、觉醒四/五新增命中与反应、
   觉醒六资源回复，不能由当前互斥触发分类或固定轴凭空生成；
6. 用目标最大生命与数量生成遭遇候选，再以逐击鲁棒拟合选择默认目标条件；继续补齐多目标逐击的正式实例
   归属、分目标参数重放和挑战计时/生命/攻击选项对非伤害指标的分析；
7. 用当前稳定库存对完整候选配装执行非线性队伍 DPS 重放。
8. `native/counterfactual-core/` 已建立独立 C++20 sidecar、版本化 JSON contract 与普通加法属性 Buff/
   无状态直伤纵向切片；现阶段只由公开 fixture 做 Python oracle 逐击差分，不进入生产入口。后续须继续迁移
   DOT、倾陷、反应与特殊状态机制，扩大固定战报差分和打包/进程生命周期验证，再单独迁移正式入口。

这只是研究基线，不代表当前能力。每个区块进入实现前，必须分别完成实现细节、数据结构、算法、UI 交互
事件和公共行为测试设计。

### 1.2 统一时间语义

- 当前长页把 nte-core `relative_time_seconds` 作为包含时停的原始轴，并使用 record 中的
  `start_offset_seconds/end_offset_seconds` 投影扣除时停的有效战斗轴。真实长战斗已确认两者与上游
  `subtract_time_stop` 汇总口径一致；后续协议若改为绝对时间区间，仍须保留同一原始事件的可逆映射。
- 当前区间重算是同步只读查询；在 50,000 行真实长战斗上测得 UI 阻塞前，不把它包装成伪异步。若需要
  worker，必须冻结账号、generation、记录、范围和 request token，旧回调静默丢弃。
- 后续动作、环合激活和最大血量派生事件必须继续使用当前左闭右开 `[start_us, end_us)` 语义。

### 1.3 事件分层

四类状态不得共用一个含糊 payload，也不得由 UI 改写事实：

| 事件层 | 候选对象 | 含义与所有权 |
| --- | --- | --- |
| 战斗证据 | `DamageHitEvent`、`TargetVitalEvent`、`TimeStopInterval`，未来的 `ObservedBuffSnapshot`、`ObservedBuffDelta` | nte-core/Integration 提供的原始或正式投影；逐击和实测状态的唯一事实源 |
| 派生推断 | `CharacterActionEvent`、`ReactionActivationEvent`、`InferredBuffInterval`、`CollapseEvent`、`MaxHpReductionEvent`、`BattleInferredCharacterFact` | Domain 根据正式证据和静态映射生成；必须保留算法版本、证据引用和内部置信信息，可删除重算 |
| 用户声明 | `BattleTargetCondition`、未来的 `UserEvidenceCorrection` | 当前账号对目标集合、主要展示对象、环境/难度/争锋加成、人工补正和本场魔女赐福的单一可覆盖输入；改变分析投影但不改写逐击或 nte-core 事实 |
| UI 交互 | `AnalysisRangeChanged`、`TimelineEventSelected`、`DenseGroupExpanded`、`ReportFilterChanged`、`DetailRequested` | Controller 持有的页面意图和可丢弃状态；不冒充战斗事件，不默认写入战报历史 |

角色动作条只展示“角色在何时做了什么”的推断；同一角色固定一行，直伤证据位于动作条上方，后动作在
展示层截断前动作，不制造并行动画。噩梦、蚀心、鸩火等特殊伤害和黯星、覆纹、创生、浊燃等环合伤害使用
全队公共行，角色归属由颜色表达。近同时事件可在展示层分组，但分组不合并或删除底层事件。

当前已可从静态目录选择大世界官方图鉴多对象、材料/养成副本类目与难度、轨外之境最新两期的层/半区，
或争锋赏宴对象/难度/加成，并指定一个主要展示对象。保存环境后已冻结候选/槽位档案，并用
`(half, target_id)` 与初始最大生命建立基础映射；旧记录已保存单目标环境但冻结画像为空时，首次分析使用
已保存敌方条件和实测初始生命生成内存画像，只按需加载正式名称且不自动回写。没有保存条件时，完整遭遇按
逐目标初始最大生命、正式身份和上下文建立静态槽位注入匹配；观测数量是下界，严格池非空即保留 alternatives
并选择稳定默认，再从默认候选的冻结槽位进入统一实例映射。完全重复且缺少 target context 的单次生命转换
只在派生观察层折叠为正式实例别名，不改写原始逐击。缺失 target ID 的逐击不会使用主要展示对象参数；生命
证据仍可显示显式的单目标用户假设，但该假设不进入新逐击敌方属性回退。后续工作是补齐 Core 精确身份、
逐击鲁棒拟合和用户逐实例确认，不允许用目标列表顺序猜测。

### 1.4 Buff 双轨证据与覆盖规则

第一阶段静态 Buff 推算已经从冻结弧盘、按核心指定驱动形状满足 2/4 件条件的装备套装和明确觉醒选择解析
效果来源；24 条空幕套装已经由独立目录接管，二件套属性包按常驻证据读取，四件套按 Q/E、普通攻击逐击、
队伍分属性逐击、环合状态与独立层数投影。其他来源再把可识别的战斗开始/结束、技能、逐击、格挡/闪避和换人触发投影为
`BattleInferredBuffInterval`。结果已保存模型版本、来源
对象、作用对象、起止时间、层数、逐击/动作证据，以及独立的状态/数值置信级别；自定义未知 Calculation
当前只展示、不进入边际；已人工审计弧盘改由专用 refinement Service 接管。空幕的森林萤火之心、真红：
双生蝶与静谧山庄已按各自层数规则重放；普通扣血与多目标状态仍保留证据边界。可确定的动态加法属性已按
逐击投影到直伤/覆纹边际，同一 Buff 的重叠区间按刷新去重。用户确认目标条件已接入敌方防御与分属性抗性；
所选魔女赐福作为整场用户确认外部 Buff 使用同一投影。可解析的
`DamageResist*` 敌方减抗和角色防御忽略/抗性穿透进入匹配逐击边际。
剩余工作是缺少公开施加事件的技能 Buff、冷却/层数精确状态、环合/击杀/暴击等条件、Calculation 语义解释，
以及易伤等其他敌方乘区和其他伤害类别的边际适配器。技能 GA 已纳入正式事件直接绑定的属性 Buff，以及常驻
`passive_buff`；剩余“技能主动 Buff”特指施加逻辑藏在 Blueprint 图中、只有引用而没有公开事件绑定的对象，
不能把引用可达性当成已激活。持续时间和直接数值只在静态曲线或当前精炼参数可解析时采用，不能
把 `ScalableFloat.Value` 系数当最终值。伤害反推仍只能作为弱证据，不能把“最能解释结果”写成实测事实。

未来 nte-core 预计由 DLL 在战斗开始时读取完整 Buff 状态，随后约每 0.1 秒向 Core 增量提交变化。接入前先
冻结公开 contract，至少包含：战斗记录 ID、generation、单调 sequence、游戏内部时间戳、完整快照或增量
标记、稳定 Buff ID、来源角色、作用对象、作用范围、激活/移除、层数、当前参数值，以及丢帧/重同步状态。
开始全量与后续增量重建为不可变实测区间；sequence 断裂后到下一次完整重同步之间不得伪装为连续高置信
状态。

融合按“同一 Buff、对象、字段和时间区间”逐项进行，不整场覆盖：

```text
nte-core 实测状态
> 战斗事件直接证据
> 静态规则的确定性推算
> 伤害公式反推
```

例如 nte-core 只确认 Buff 已激活但未给出数值时，激活区间采用实测证据，数值仍可采用带版本的静态规则，
二者分别保存来源和置信度。若增量只有采样到达时间而没有游戏内部精确生效时间，边界保留最多约 100ms 的
不确定窗口；命中位于窗口内时不得伪造毫秒级先后关系。原始实测事件不可被推算或人工补正改写，派生区间
必须可按算法版本删除重算。未来人工补正作为独立的用户声明层保存，只改变分析投影，不冒充 nte-core 原始
事实。

### 1.6 遭遇候选与逐击鲁棒拟合

目标是：当战报没有保存用户确认条件时，系统优先从正式目标生命证据选出默认环境，并为每个已观测目标
实例生成可供公式重放的敌方属性画像。环境默认、目标属性画像和精确 `monster_id` 是三个独立结论：场景
或公式画像可以确定时，不得因此伪称每个目标身份已经唯一识别；具体身份不可区分但所有可行槽位画像相同
时，逐击可以使用共同画像，同时保留 `possible_monster_ids`。如果生命、数量或上下文证据互相冲突，导致
严格候选为空，则回到“未识别环境 / 未知目标”，不从错误候选中硬选怪物。用户保存的环境条件和目标实例
映射始终覆盖自动结果。

#### 1.6.1 冻结输入与候选生成

一次推断冻结账号、`AppContext.generation`、战报记录、完整遭遇/半场证据范围、静态 dataset、本场原始冻结的
角色/装备公式输入、玩法配置版本和战斗发生时间。环境识别和逐击拟合使用完整遭遇或完整半场证据；用户选择
的时间段只限制展示与普通公式分析，不能截断目标初始生命基线，也不能让自动默认随时间轴缩放而改变。用户
后来保存的战报角色修改副本、边际候选和当前角色页状态不得反向改变本场环境识别。候选只来自当前产品允许
自动识别的目录：当前/下一期轨外、争锋全部八个挑战对象、四类材料/养成副本和异象追猎单 Boss；不把异象巡礼
或普通大世界怪群扩入自动候选，也不能把“未进入候选目录”当作实际玩法不可能出现的反证。

1. 按 `(scope_half, target_id)` 隔离目标实例；`scope_half` 是可空作用域，轨外使用 `upper/lower`，没有
   半场的非轨外使用 `null`（兼容实现可以在边界归一化为空串），不得把 `non_abyss` 混入半场字段。
   `target_id` 只证明逐击属于同一运行时实例，不携带怪物种类语义。当前一场战报只包含一个遭遇时可由战报
   隐含 `encounter_scope_id`；未来若一次采集允许跨多个遭遇且 wire ID 可能复用，实例键必须扩展为
    `(encounter_scope_id, scope_half, target_id)`。初始最大生命从完整遭遇证据重建：Core v4 使用同实例完整轴
    中正数 `target_max_hp` 的单调最大前沿；`max_hp_reduction` 表示该行之后结算的生命上限变化，不与本行
    结算前的 `target_max_hp` 相加。旧记录沿用同一最大前沿。目标首次出现前可能已经发生未捕获削减时，初始
    生命保持未知，不以伤害总量、削减量累计或中文名补造。
2. 每个场景把难度、生命选项和怪物数量展开为有稳定 `static_slot_id` 的静态目标槽位，分别保存
   `monster_manual_id`、`monster_class_path`、模板 ID、`profile_set/pack_id` 和完整公式画像，禁止混写为一个
   泛化 `monster_id`。逐个观测目标按 Core 正式怪物 ID（若存在）、最大生命和玩法/层/半场上下文查找兼容
   槽位。最大生命比较使用基于协议数值精度的明确小容差，只吸收表示误差，不吸收真实难度或生命档差异。
3. 场景兼容性使用“观测目标实例到静态目标槽位”的二分图注入匹配，而不是普通集合求交。这样相同生命值
   出现两次时必须消耗两个槽位，不会把 `{100, 100}` 错当成 `{100}`；所有可行映射都保留到下一阶段，禁止
   按 wire ID、轴展示顺序或首次出现顺序任意绑定怪物。
4. 只有捕获质量能证明当前范围目标完整时，观测数量才与场景数量做严格相等比较；当前没有
   `target_roster_complete` 正式证据，因此观测数量一律只是下界，场景可以含尚未被命中的目标；当前稳定
   默认排序优先较少未观测槽位。不得从聚合摘要推测完整敌人数量。
5. 正式怪物 ID、Core 玩法、轨外层/半场和战斗发生时间是硬证据或强约束；中文名、轴展示顺序和目标首次
   出现顺序不能用来猜静态身份。非轨外缺少正向玩法或正式身份时仍可用 `non_abyss + HP` 缩池和产生稳定
   默认，但置信度只反映严格池和硬证据，不能把稳定默认名称冒充 Core 实测身份。相同生命但抗性不同的争锋
   Boss 必须分别成为候选，不能在 HP 阶段合并。

候选生成只保留满足既定生命、数量、正式 ID 和上下文规则的严格池，不建立逐层放宽后从错误场景中硬选的
回退池。严格池为空时输出 `unknown_environment_fallback`：环境类型、目标身份与具体属性包均为未知，
保留原始目标生命和证据冲突供审计，不套用任一目录怪物的防御、抗性、生命档或玩法修正。页面可以显示
“未识别环境 / 未知目标”；后续公式若缺少目标属性，继续遵守现有未知输入边界，而不是用回退场景制造
完整参数。只有独立证据确认大世界时才使用 `open_world` 场景口径。

候选进入逐击拟合前，按实际影响公式的目标属性包建立带算法版本的“有效战斗画像”，至少包含角色等级口径、
`DefBase/DefUp/DefAdd`、分属性抗性、倾陷/特殊防御参数、玩法修正和观测目标到静态槽位的映射。多个场景若
画像完全相同，可以合并计算，但仍保留各自环境身份作为等价替代项；此时伤害只能确认公共公式条件，不能
证明具体环境名称。画像等价以版本化 `effective_profile_fingerprint` 判断；将来新增怪物专属减伤、阶段机制、
标签或其他公式输入时必须同步扩展该指纹，不能沿用旧算法下的等价结论。

环境条件与目标实例画像分开建模：`BattleEncounterCondition` 只拥有场景、难度、选项和整场外部 Buff；
`BattleTargetInstanceResolution` 按 `(scope_half, target_id)` 保存可空的 `resolved_monster_id`、全部
`possible_monster_ids`、可空的 `default_monster_id`、兼容静态槽位、可空的共同公式画像、身份/画像来源和
各自置信度。`resolved_monster_id` 只表示实测或唯一推断身份；多个 ID 的有效画像等价时，从正式目录顺序和
ID 稳定顺序中选择一个 `default_monster_id` 供默认展示，但计算直接消费冻结的共同画像，不通过该代表 ID
重新查询静态属性。当前 v35 冻结档案尚无可靠正式目录排序字段，已知环境路径先采用大小写归一后的稳定 ID、
再用原 ID 兜底，保证结果不依赖候选输入顺序；未来静态槽位提供正式排序后再把它置于稳定 ID 之前。主要目标
只作为 UI 默认焦点和旧数据迁移标记，不再作为所有逐击的隐式敌方画像。若用户
显式确认某个运行时实例的怪物，以独立 `user_mapped` 映射覆盖该实例，不改写原始逐击或 Core 身份字段。

#### 1.6.2 固定轴公式重放

每个候选及其可行实例映射只允许替换各目标的敌方防御、分属性抗性、倾陷参数、场景修正和目标槽位。角色面板、家具加成、冻结装备、
技能倍率、已投影 Buff、DOT 正向状态、易伤和独立乘区等候选无关输入必须对所有候选完全相同。选择阶段
禁止以下会形成循环论证的补正：

- 用实际伤害反算噩梦、浊燃或其他状态层数；
- 用本击实际/预计比例缩放边际值或公式结果；
- 为每个候选单独重新猜暴击、Buff 激活或自由全局倍率；
- 用最终选中的场景回写原始逐击、目标生命或 nte-core 事实。

每条逐击必须先按 `(hit.scope_half, hit.target_id)` 读取目标实例画像；存在共同画像时可以在身份仍歧义的
情况下重放，画像也不唯一时该击不得回退到主要目标。候选评分联合比较“环境 + 实例到槽位映射”，不能先
按顺序固定映射再计算损失；画像等价的多种映射可以合并，仍保留所有可能身份。

未知环境的技术路线固定为“HP 缩池、候选内联合映射、逐击排序”，而不是先选择环境后按展示顺序绑定目标：

1. 当前 `BattleEncounterCandidateSelectionService` 从完整遭遇证据生成观测实例，目录加载阶段已冻结每个
   候选的目标画像；HP、Core 正式身份和上下文不兼容时不连边，未观测静态槽位在当前缺少
   `target_roster_complete` 时不是硬冲突。
2. 当前 `BattleTargetCandidateGraphService` 为每个环境建立“观测实例 → 静态槽位”的二分图。重复数量展开为
   独立内存槽位并验证一对一可行性；同一相容图同时供自动候选与 `BattleTargetInstanceMappingService` 使用，
   HP 容差固定为 1 点绝对值，不随千万级生命放大。
3. 后续对每个实例和兼容画像只计算一次逐击组损失，形成边代价矩阵；同一批合格逐击必须用于全部候选，不能让
   某个候选通过少解释困难逐击获得更低损失。
4. 后续 `BattleEncounterFitService` 对每个环境求最小费用二分图匹配或最小费用流，不枚举 target/槽位全排列：

   ```text
   edge_cost(target_i, slot_j) = sum(group_weight × robust_group_loss)
   environment_score(E) = min_mapping sum(edge_cost) + environment_penalties
   ```

   场景级修正保持为该环境所有映射共享输入；若未来出现不可拆分的多目标联动机制，只在环境外层联合重放，
   不把自由缩放系数放入每条边。
5. `BattleInferredTargetConditionService` 只负责编排候选、匹配、拟合和稳定选择；已保存环境继续直接调用现有
   `BattleTargetInstanceMappingService` 生成最终解析。选中自动候选后也落为相同的内存解析 contract，现有
   `BattleHitReplayService` 继续按实例消费画像，不新增第二条逐击公式路径。

每个可用逐击同时计算未暴击预测 `P_nc` 和暴击预测 `P_c`。正的实际伤害 `A` 使用对数残差，避免大伤害
仅因绝对数值大而支配拟合：

```text
r_nc = ln((A + 0.5) / (P_nc + 0.5))
r_c  = ln((A + 0.5) / (P_c  + 0.5))
```

已知暴击状态只采用对应分支；暴击未知时不先选“更接近的一支”，而以冻结暴击率 `p` 计算 Student-t
混合似然：

```text
loss_i = -ln((1 - p) * T_nu(r_nc; 0, sigma) + p * T_nu(r_c; 0, sigma))
```

初始研究参数取 `nu = 4`、`sigma = 0.03～0.05`，用于得到比均方误差更不受少数离群击影响的排序；它们
是待用真实战报校准的算法参数，不是游戏公式常量。候选总分采用加权鲁棒负对数似然，并增加无法映射、
未观测目标槽位和低覆盖率惩罚；分数越低越优。不得为每个候选拟合独立缩放系数，否则防御/抗性差异会被
自由倍率吃掉；若后续审计证明存在系统性舍入偏差，只能加入所有候选共享且受限的校准项。

以下逐击不直接参与候选排序，但必须保留在审计输出：归属冲突、缺少正数实际伤害、公式尚未结构化、依赖
候选外未知状态、已使用实际伤害反算层数或比例补正的逐击。证据质量映射为显式权重。为防止同一 DOT 的
大量重复跳伤淹没少量高辨识度直伤，先按 `(目标、角色、GE/公式、属性、Buff 指纹、DOT 状态段)` 分组，
组内权重随样本数按 `1/sqrt(n)` 衰减并设总权重上限。Bootstrap 也以这些近似独立组为重采样单位，不能把
同一状态段的几十跳当成几十份独立证据。

#### 1.6.3 默认选择、置信度与输出

严格池非空时，系统始终返回一个 `selected_candidate`，并按以下稳定顺序选择，保证同一冻结输入重复运行
不会漂移：

1. 正式怪物 ID 匹配数量；
2. 玩法、层、半场和生效时间上下文匹配；
3. 完整目标映射和较少未观测槽位；
4. 当前期和静态目录正式顺序；
5. 稳定 `environment_ref` 排序兜底。

画像不等价的多个严格候选在上述硬约束之后插入“鲁棒拟合总损失”。当前实现对每个候选重放同一冻结逐击，
以按伤害来源分组的对数 Student-t 核损失排序；不把“只满足数量下界”直接淘汰，只通过较多未观测槽位降低
硬证据排序。

输出模式固定为：

| `selection_mode` | 含义 |
| --- | --- |
| `unique_hard` | HP 注入匹配、正式 ID 和上下文只留下一个严格候选，无需伤害拟合裁决 |
| `robust_fit` | 至少两个有效战斗画像不同，逐击鲁棒拟合选出明显更优者 |
| `equivalent_profile_default` | 多个环境身份的有效战斗画像相同；默认名称只是稳定选择，公共公式参数可高置信采用 |
| `ambiguous_default` | 候选画像不同但证据不足或拟合接近；仍选默认值，同时明确保留歧义 |
| `unknown_environment_fallback` | 严格候选为空；环境、目标与属性包保持未知，不执行错误场景拟合 |

每个目标实例另有独立解析模式：Core 直接身份为 `core_exact`；环境内唯一映射为 `environment_hp_unique`；
身份不同但画像完全相同为 `profile_equivalent`；逐击拟合选出画像为 `robust_fit`；用户确认实例映射为
`user_mapped`；身份或画像仍不可区分分别为 `ambiguous` 或 `unknown`。`profile_equivalent` 允许公式重放，
但 `resolved_monster_id` 必须留空并保留 `possible_monster_ids`；同时稳定填入 `default_monster_id`，供默认
名称和审计定位使用。`default_monster_id` 不是实测身份，禁止以它重新加载属性或覆盖 Core 字段。

置信度按证据而不是“是否返回默认值”决定。唯一硬匹配为高置信；当前鲁棒拟合至少三个独立证据组且相对
损失差达到 20% 时为中置信，否则为低置信，尚未实现 Bootstrap 前不把拟合结果标为高置信。若战报没有打出
能区分候选抗性的属性，即使总逐击很多也不能提高辨识置信度。争锋同血量 Boss 的生命
相同但抗性不同的场景，只有包含相关属性且公式证据合格的逐击才能依靠残差分开；若所有可用击在两个候选
下预测相同，则必须进入 `ambiguous_default` 或 `equivalent_profile_default`。

派生结果至少包含：

- 可空的 `selected_candidate`、`selection_mode`、`confidence`、`default_reason` 和 `algorithm_version`；
- 所有 `alternatives` 的场景引用、目标映射、硬证据命中、画像指纹、鲁棒损失、覆盖率、独立组数、
  Bootstrap 胜率、未观测槽位和淘汰原因；
- 参与拟合的逐击引用、属性、预测两分支、残差、权重、分组和采用/排除原因；
- “环境身份置信度”和“公共目标属性包置信度”两个字段，避免等价画像默认值污染公式可信度。
- 每个 `(scope_half, target_id)` 的可行静态槽位、`possible_monster_ids`、可空 `resolved_monster_id`、可空
  `default_monster_id`、共同画像及 `effective_profile_fingerprint`、解析模式，以及彼此独立的身份置信度和
  画像置信度；未命中的静态槽位只列为 `unobserved_slots`，不生成运行时目标 ID。

自动结果属于可删除重算的派生投影，账号 v38 按算法版本和静态 dataset 保存完整派生快照，但不写成用户确认
条件，也不修改战报冻结快照。UI 立即使用唯一、共同
画像或残差胜者重放；残差接近也必须采用稳定低置信胜者并以红字保留冲突，不返回“无敌方条件”。用户显式保存环境后
生成整场环境条件，显式确认实例映射后才保存对应 `user_mapped` 覆盖。实现边界优先拆为环境候选生成、
目标实例映射与拟合三个 Qt 无关 Service，再由现有目标条件推断 Service 编排，不能把匹配或统计拟合塞进
Page、Controller 或 DAO。

#### 1.6.4 实施顺序与现有代码边界

当前已完成“完整遭遇重建逐目标初始生命 → 正式目录冻结目标画像 → HP/正式身份二分图注入缩池 → 稳定选择
默认环境并保留 alternatives → 画像冲突时逐候选原始公式重放与鲁棒残差选择 → 复用实例映射派生
`default_monster_id`/共同画像 → 逐击按实例读取画像”。这是
本路线的最终消费基础，不回退、不另建第二条公式链。后续按以下边界演进：

1. 保留现有 `BattleSelectedTargetProfile`、`BattleTargetInstanceMappingService`、账号 v35 冻结档案和
   `BattleHitReplayService` 消费方式；已知或用户保存环境继续沿现有路径立即得到最终实例解析。
2. 后续在领域投影中增加版本化 `effective_profile_fingerprint`。现有 `default_monster_id` 随完整自动推断写入
   可删除重算的 v38 派生快照，不写入 v35 原始冻结格式、用户确认条件或 Core 字段；重复数量可以在候选图中
   展开为稳定的运行时 `static_slot_id`。未来新增派生字段继续追加账号迁移，禁止修改已发布迁移。
3. 候选目录、候选选择和候选图已拆为 Qt 无关 Service；`BattleInferredTargetConditionService` 只编排严格池、
   稳定默认和现有实例映射。候选图与已保存环境映射共用同一 HP/正式身份相容 helper，不复制第二套语义。
4. 当前逐击损失矩阵使用共同合格击、暴击混合概率、分组 Student-t 损失和稳定平分兜底；下一阶段校准权重、
   增加 Bootstrap 和多目标最小费用匹配，但不得改变已保存环境或把 `default_monster_id` 变成静态查询入口。
5. 继续用固定输入公共行为测试锁定匹配损失、派生快照版本失效与回退后，再完善 UI 置信说明；不在 Page 中
   临时排列怪物或重新计算画像。

`profile_equivalent` 已直接使用共同画像，稳定 default 只承担名称与审计定位，不改变伤害公式，也不成为
新的静态查询入口。当前环境层可输出 `unique_hard`、`robust_fit` 或 `ambiguous_default`；分组 Student-t
残差已实现，跨环境画像指纹合并、`equivalent_profile_default`、Bootstrap 和多目标最小费用边代价仍待完成。

#### 1.6.5 懒加载与缓存

正式目标身份 telemetry 属于采集证据，若接入必须在战斗捕获开始前启用和校验，不能在打开历史战报时懒
加载补造。当前静态环境槽位目录只在分析一场具有可靠目标生命且没有用户保存条件的战报时按需加载；用户
保存条件直接跳过自动目录推断。候选加载当次即冻结画像，实例映射在任何逐击重放前完成；逐击只查内存画像，
不按击访问静态库。后台整场分析把基础候选及后续残差裁决覆盖写入同一份版本化派生快照；再次分析时只有
算法版本和静态 dataset 都匹配才复用。历史列表只读该快照，不为全部旧战报同步加载目录；旧记录在单场分析
完成后惰性补齐。

逐击鲁棒拟合只在严格池至少有两个候选且没有用户覆盖时执行；即使共同合格击为空，也按稳定引用返回低置信
默认而不是无结果。当前在单场历史分析 worker 内完成并覆盖保存派生快照；它不阻塞历史列表。若真实长战斗
仍证明单场分析耗时过长，再增加按账号、generation、战报、完整证据指纹和冻结配装复核的可取消预热任务。
完整目标选择器目录仅在首次打开选择器时加载并按 dataset 缓存。

#### 1.6.6 公共行为与审计样本

实现前先建立以下固定输入公共行为测试和脱敏审计样本：

- 两个争锋 Boss 最大生命完全相同、抗性不同：相关属性逐击能稳定选出低鲁棒损失候选；删除辨识属性后仍
  返回稳定的低置信默认值；
- 多个场景生命/数量相同且有效战斗画像相同：公共目标属性包可采用，环境身份不宣称唯一；
- 同生命值目标重复出现、观测目标不完整、只有一个目标受击和半场缺失：验证多重集槽位与数量下界，不按
  列表顺序分配身份；
- 已选环境内不同怪物具有相同最大生命和相同画像：逐击使用共同画像，具体 `monster_id` 保持歧义；画像
  等价时稳定选择一个 `default_monster_id` 供展示但不以它查公式属性；画像不同时不得回退主要目标，用户
  确认实例映射后只覆盖对应 `(half, target_id)`；
- 非轨外没有半场：实例以 `(null, target_id)` 隔离并正常参与 HP 缩池和逐击拟合；同一 wire ID 在未来跨
  遭遇复用时，以新增的 `encounter_scope_id` 继续隔离，不合并成一个实例；
- 一个环境含多个同 HP、不同画像目标：按逐目标逐击损失构造边代价并求最小费用匹配；改变静态槽位顺序或
  target 首次出现顺序不能改变最佳环境、共同画像或稳定默认；
- 手动环境含多个不同画像目标：每条逐击按自身 `(half, target_id)` 消费对应防御和抗性，改变主要目标只
  改变 UI 焦点，不改变已经解析的逐击结果；
- 当前/下一期轨外同时满足生命条件：战斗发生时间和半场优先，缺少强证据时按稳定顺序默认；
- 生命、数量或上下文互相冲突导致严格池为空：直接产生 `unknown_environment_fallback`，显示“未识别环境 /
  未知目标”，不为其套用任何目录怪物属性；
- 未知暴击逐击在未暴击/暴击混合似然中计分，不把最近分支硬写成暴击事实；
- 少数公式错误、过量伤害、异常大击和无法解释的特殊机制不会翻转大量一致证据的选择；
- 同一 DOT 状态段增加十倍重复跳数不会压过独立的高辨识度伤害组；
- 噩梦/浊燃等实际伤害反算层数、边际同比缩放和未结构化公式不会参与场景选择；
- 用户保存目标条件后完全覆盖自动默认；删除用户条件后可从相同冻结输入重算出相同默认值。

### 1.7 数据所有权与分层

- 推断结果默认不作为第二套事实源；优先保存算法版本与必要证据后按需重算。若为性能保存缓存，缓存必须
  可失效、可删除，并且不改变原始逐击。
- 后续如果持久化动作或机制推断缓存，只能保存算法版本和证据引用；属性单位边际结果、配置试算、滚动、
  悬停和密集组展开仍不得写成战报事实。
- `BattleMarginalCandidate` 完整属于 Controller/UI 会话内存；目标语义只覆盖当前候选养成、弧盘及允许的
  临时装备，不再持有手工面板覆盖，不能调用战报修改副本 DAO、不能进入导出，也不能在切换战报后复用。
- `battle_build_edit` 只属于本机战报的外层持久校准；导入记录的装备由来源与摘要锁保护，只有养成字段可以
  另存修改副本。Core v4 最终轴替换属于采集 Service 的单事务动作，页面不能逐页提交最终事实。

### 1.8 UI 交互事件候选

交互事件是 Controller 内部的显式意图，不是日志埋点名称，也不要求逐项持久化。第一轮 contract 研究至少
覆盖：

1. `TimelineEventSelected`：建立未来动作、环合激活、逐击、目标血量和日志行之间的交叉高亮；
2. `DenseGroupExpanded`：只改变同刻密集点展示，不改变底层事件或统计；
3. `DetailRequested`：从统计行定位时间轴或逐击日志，不通过页面互调私有控件实现；
4. `LongRangeAnalysisRequested`：仅在真实长战斗证明同步查询阻塞后引入 worker 和旧 token 丢弃。

### 1.9 下一阶段：派生事件与长战斗验证

后续继续从账号库只读现有证据，不另建逐击来源：

- 用真实长战斗测量 50,000 行的体积、历史加载和分页延迟，再决定逐击历史保留策略；
- 继续用静态技能窗口校准当前推算输入轴；现阶段普通点按独立投影，静态长按程序区分释放后重击与按住期间持续出伤，但未命中、无敌、中断和真实按下/松开时刻仍需后续输入或运行时证据。继续研究动作实测来源、环合激活、倾陷、其他最大生命削减机制和多目标归属；
- 扩展现有静态 Buff 推算和逐击关联，再以未来 nte-core 全量/0.1 秒增量作为字段级高置信覆盖；
- 用更多真实战报继续校准 1.6 已接入的残差容差、分组权重、Student-t 尺度和置信阈值，并补 Bootstrap 与
  多目标最小费用匹配；
- 沿用当前真实逐击同比、暴击策略和受益角色归属，为尚未量化的 DOT、具体环合和队伍 Buff 建立独立
  反事实适配器；倾陷继续复用现有完整队伍公式，不扩大直伤适用范围；
- 把战报目标函数接到当前稳定库存和现有唯一 UID 分配约束，评估完整候选配装而不是固化线性权重。

### 1.10 剩余公共行为清单

- 用真实记录确认时停投影前后均可追溯到同一个原始事件；
- 未映射技能、未知角色、未知目标和未知最大血量削减继续保留并进入质量统计；
- 动作或环合推断失败不删除逐击，算法升级不会改变原始事实；
- 若引入异步长战斗计算，快速拖动、连续应用时段、切换历史记录和账号时，旧 token/generation 结果不
  更新页面或账号库；
- 动作/目标联动、密集组展开和统计行跳转不得改变选定时段统计；
- 遭遇反向匹配在任何非空候选集中都返回稳定默认值；低置信默认、等价画像和唯一识别必须使用不同模式；
  严格候选为空时回到“未识别环境 / 未知目标”，用户保存条件始终覆盖自动结果；
- 相同最大生命候选不能因普通集合去重、目标展示顺序、单个离群击或大量相关 DOT 重复跳伤被错误唯一化；
- Buff sequence 断裂必须降低置信度；下一次全量重同步只恢复其后的高置信区间，不回填断裂区间；
- 同一 Buff 的实测激活状态只能覆盖对应对象和时段，缺少实测数值时仍保留静态数值的独立来源；
- 位于 0.1 秒采样边界不确定窗口内的逐击必须展示不确定性，不强判 Buff 已生效或已失效；
- 新增边际适配器继续在内部列出适用伤害、估计方法与假设，不把估计表述为精确实战因果增益；即使适配器
  缺失，原轴逐击也必须保留实际值并计入总量，属性单位边际计入未量化覆盖，配置试算才可另列估计值。

## 2. 队伍收益与全局配装

长期目标是把直伤边际、环合、倾陷、DOT、队伍增益和装备竞争统一到可解释目标函数，再扩展四人队与
八人双队搜索。新求解仍使用不可变快照、官方 ID、唯一 UID、配装槽位和冻结方案 contract，不建立第二套
评分事实源。

## 3. 倒带实机执行

倒带分析、八槽保存和输入链已接通，游戏执行仍处于实验状态：

- 启动前尚未识别并确认当前位于倒带首页；
- 坐标映射、余额/价格 OCR 和候选轮廓需要覆盖不同分辨率、DPI、语言与画面设置；
- 花费前尚未回显余额、十连价格和计划次数供最终确认；
- 页面内停止、阶段恢复和中断后的任务记录尚未形成；
- 账号 generation、执行快照与窗口身份尚未持久化为可复核任务。

当前公开策略只有“全面均衡”和“少角冲分”。领域层遗留的成本方案入口不进入 UI；增加策略前先确定
业务规则与公共行为测试。

## 5. 新能力验收原则

新能力先确定 payload、sequence/generation、完整性、错误码、隐私字段、失败状态和回滚方式，再进入
Integration 与账号库。路线图条目只有在实现、迁移、调用方收口和公共行为测试全部完成后才转为当前能力。
