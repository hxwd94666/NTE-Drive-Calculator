# 解包恢复与组件映射

仅在核心表为空、资源级错误或原生映射不支持时使用；普通角色更新不必重复执行。

## 区分空表与缺资源

- 比较旧/新导出的核心角色、装备、物品表的 `Rows`、RowStruct、文件大小和哈希。
  能解析 JSON、存在 Content 或解包进程退出成功，都不证明表内容完整。
- 使用同一游戏构建生成的 USMAP；SDK 留作字段/结构核对，不是 Exporter 的输入。
  先确认生成回执及关键文件，不把 `.partial` 或不完整类型图说成完整 SDK。
- 新映射以新文件名放入 Exporter 的 `mappings`，通过本地 `--help` 核对 `--map` 需要文件名还是完整路径。
  使用独立输出目录，避免旧 checkpoint 跳过本次需要重读的资源。配置中的密钥不进入日志、报告或仓库。
- 开发宿主部署与真实游戏操作单独按用户授权；不重复加载已驻留宿主，不把离线 UI 预览当成游戏导出。
  热键无菜单时先看加载身份、扫描、按键和渲染日志，不反复换 Loader 掩盖图形后端问题。

## 资源级错误的影响

按唯一资源路径去重，不按报错行数计缺失。检查目标文件是否存在且可解析：报错后仍可能留下有效文件。
图片核对格式/尺寸和哈希；JSON 核对完整解析、表行及被引用字段，不只看零退出码或文件存在。
将失败项与 importer 登记来源、公共图片清单及实际消费者关联。无关任务蓝图可列待补，不为少量无关项重跑全量。
确实影响本次功能时才有界补导相关路径并降低并发；不借旧版同名内容补齐。
旧发行登记来源缺失还可能是正式/测试渠道差异、删除或改名，不等同于本轮导出错误。

## 两个 Core 按来源分别验证

- 原生背包/角色转换归采集 `nte-core.exe`；战报重放与反事实归 `nte-analysis-core.exe`。
  先核实 Calc 实际解析路径、发行组件角色、二进制哈希和来源清单，不凭仓库目录名或源码资源推断已安装内容。
  镜像位置与正式组件包若有两份同名 EXE，核对两者；组件晋升后必须一致。
- 新角色除名称映射外，还需角色装备图纸、合法格、形状、主词条曲线及属性单位；只补名字可能继续投影失败。
  NPC、试用和变身行不据物理角色表总数直接提升为永久持有角色。
- 采集 Core 的抓包与原生入口分开判断：抓包消费 JSON/内嵌目录，当前原生入口从 Calc 静态库投影。
  同步目录导出、属性覆盖、实际资源选择与最小回放统一见[采集与低风险抓包更新](update-workflow.md#采集与低风险抓包更新)。
  缺新版抓包样本不等于原生不可用，反之也不以原生通过证明抓包完整。
- 新赛季逐项核对正式 GE 的曲线、Source/Target 必要标签和受益对象。召唤/援护限定不进入全局增伤；
  新静态语义涉及 schema 时追加迁移，同时更新分析组件兼容范围、规则及最小专项。
- 最小证据包括新增角色投影、旧角色可用、非法/不完整输入仍拒绝，及实际组件的版本、能力和内嵌目录。
  只读专项与组件构建不替代真实游戏验收；验收前恢复成套正式组件，不使用留在游戏目录的 Dump 开发组合代验。
