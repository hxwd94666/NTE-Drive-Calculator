# 角色与功能适配矩阵

对新增、删除、改动角色和被复用的新机制逐项记录：正式身份、来源证据、当前消费者、变更类型、验证输入/输出、状态/缺口。
至少区分数据已导入、页面可见、面板可信、评分可用、战报支持、原生支持；不合成一个“角色已适配”布尔值。
现有代表入口会随重构迁移，每次按 AGENTS 事实源和 `rg` 查实际调用；下面是职责索引，不是永久路径白名单。

| 范围 | 必查事实与行为 | 当前代表入口/定位线索 |
| --- | --- | --- |
| 角色身份 | NPC、未实装、特殊形态与逻辑角色分类；character_id、正式 Actor/实例映射；变身不重复生成普通档案 | `catalog_characters.py`、`character_overrides.json`、static character importer、角色目录 Service |
| 基础面板 | 等级/突破、额外形状、好感、家具、具体觉醒/共鸣、技能基础等级和弧盘养成；条件效果与无条件常驻分离 | `src/services/official_role/attributes.py` 及公共角色面板投影；成长/觉醒/形状 importer |
| 技能及机制 | 正式 SkillID/GA/GE、倍率数组、正式属性乘区、条件/持续/叠层、额外层数或特殊伤害；说明文字不是机制证明 | 技能/Blueprint/Buff importer；`docs/reference/damage-calculation.md`、counterfactual 目录和角色人工审计 |
| 弧盘与装备 | 精炼各档、永久属性、条件效果、套装与形状；属性来源完整且映射到 property_id | fork 审查、equipment importer、公共评分/属性服务 |
| 权重/毕业/边际 | 推荐权重来源、账号覆盖、毕业模板假定、直伤模型覆盖；缺模型保留基础权重或明确未就绪 | `ScoringEngine`、毕业模板构建、`src/services/official_role/base_equipment_scoring.py`、`src/services/official_role/marginal_scoring.py`、graduation 服务 |
| 图纸/分配/替换 | 新形状/套装可生成合法图纸；UID 唯一、冻结库存/锁/配置、约束、取消及预览保存不变 | optimizer、solver、allocation 服务；复用原统一评分入口 |
| 配装与分享 | 汇总面板、评分/差异、套装状态、正式槽位、角色/弧盘/技能图片；旧方案不按新权重重解释 | `EquipmentPresentation`、equipment 服务、公共 GameUiAssetCatalog、loadout share |
| 仓库/鉴定/扫描 | 新名称/词条/类型别名、新形状模板与场景/布局；解析后关联正式 ID，未知不制造成功 | vision/recognition、StatCatalog、鉴定服务；多语言识别配置独立于界面语言 |
| 养成/图鉴 | 新角色/技能/弧盘成本、材料链、经验和货币；正式永久字段，不回写账号材料或体力推测 | progression importer、`src/services/progression/`、`src/features/toolbox/cultivation/` 与独立静态资料库；子进程边界在 `src/integrations/progression/` |
| 同步/装配 | 新角色是否有正式原生实例/装备映射、字段覆盖与后验确认；数据导入不代表 RPC 可写 | Integration 与组件协议；缺支持保持原值/未知，组件改动在其所属仓库 |
| 战报/反事实 | 首击与结算冻结输入、角色专属被动、技能归属、Buff/环境证据及重放；实测事实不被新派生模型改写 | battle/passive 服务与正式分析 Core；`docs/reference/counterfactual/`、战报包契约 |

## 什么只更新数据，什么要改代码

- 通用格式和已有公式覆盖时，以新数据驱动原有服务，不按中文角色名增加 if 分支。
- 新官方关系或源格式变化：先复现导入缺口，补规范化/DAO 公共投影；同次计算只消费一个校验 dataset。
- 新机制超出现有模型：根据正式数值/GE/曲线和观测边界补领域计算或已有角色适配入口；区分条件效果、固定轴反事实与无条件面板。
  避免复制评分公式、把描述中的百分比直接填常驻属性、把未知暴击/Buff 当零或从角色名称推归属。
- 需要私有 Core/DLL/分析组件：在其正式仓库/协议范围处理并获取匹配组件包；Calc 不复制其源码或绕开正式接口。
- UI 只补新增配置/缺口提示，文案简洁、三主题可读，不借版本更新重做前端。

## 每个变更角色的最小验收

用同一冻结 dataset 和合成/脱敏输入验证：基础与临界突破、关键技能等级/觉醒、弧盘精炼和条件分离，
一套可用图纸/装备评分及 UID/槽位约束、资料/养成/分享显示与技能图片，以及该角色实际支持的战报/同步路径。
确认旧角色和旧存档行为保持；有数值差异指出公式项、来源和预期，不用旧截图或固定行数当通用答案。
缺失输入和未实装角色单独验收降级提示；超出当前模型的功能记录待支持，不阻断与其无关的已证实功能。
真实 OCR/扫描、原生同步/装配、独立分析和低配性能只按实际授权与环境验证，未执行就保留未验收。

## 重构期间如何维护本 skill

每审完一个功能域，核对该域的正式接入口、必须跟随版本更新的资源/配置与新增角色例外，修正本矩阵的责任索引。
只有存在真实重复操作才补脚本；不要在 skill 复制大量公式、schema 数字、阶段流水账或私人解包片段。
目录/命令变更后核对 references 与示例参数，重新验证并同步个人安装副本。
