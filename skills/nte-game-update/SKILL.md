# 异环计算器版本更新

目标是让当前成熟功能正确消费新版本，而不是只导入更多角色行。解包存在某个角色，不等于该角色已实装、可计算或已被分析组件支持。
仓库中的副本用于随重构维护；个人 skills 目录中的副本用于调用。两份修改后保持一致。

## 定位与授权

- 确认用户所指的计算器仓库、工作分支、未提交状态和解包根；先读该仓库 `AGENTS.md`、`RESPONSIBLE_USE.md`。
  下文仓库路径均相对该仓库，不相对 skill 安装目录。已有开发改动保留，不清理未跟踪文件或替用户切换分支。
- 解包只读。不同地区、版本和导出批次分别识别；多个 Content 根时显式选择，不按目录时间猜游戏版本。
- 记录本次允许的数据构建、代码修改、测试、晋升及外部操作范围。使用 skill 不附带提交、推送、打包、发布或真实游戏操作权限。
  若当次契约要求另行授权测试，按该范围执行并如实列出待验收项。
- 输入路径、完整来源内容及个人环境配置留在本机；公开交付只包含实现、脱敏审查结论和正式清单允许的发行资源。

## 从输入开始

读取 [更新工作流](references/update-workflow.md)，先做只读来源差异与能力盘点。
可运行本 skill 的 `scripts/inspect_update_inputs.py --repo <仓库> --source <解包目录> --report <仓库 build 内的新报告文件>`。
它只定位唯一 Content 根、枚举数据表、对照旧发行库已登记来源；不是完整解包审计、角色接入或晋升证明。
角色/图鉴、公式、静态 schema、importer 和组件身份以当前代码与清单为准，不沿用本 skill 中的历史数字。

## 更新时的分流

1. 分别盘点主静态与独立图鉴两组交付。有完整同版战斗来源时，在 `build/` 构建完整 game 候选；
   角色/资料/公共图片仍需单独维护同版 `reference` 或 `role_page` 整包，主库成功不替代它。战斗来源不足时，可只完成证据充分的图鉴。
   降级目录不提升成完整伤害、原生同步或战报能力。同一次运行只消费一个校验目录；候选使用同版多来源时，按显式优先级逐文件记录来源与哈希，不跨版本或静默用旧数据补齐。
2. 对新增/改动角色及机制逐项使用 [角色与功能适配矩阵](references/character-adaptation.md)。通用数据接入优先；确有新机制再扩展原有公共模型，
   不给每个角色复制一套评分、SQL、面板或 UI 流程，也不因本次更新实现路线图中的新伤害分配器。
3. 同版公共图片与技能 ID 映射一起维护；图片专用维护与数据版本更新走不同晋升入口。
4. 完成当前候选的来源、数值、关系、未知状态、消费者与回归证据，再最终化和预检；正式替换及发行遵循当次授权。

## 完成报告

按本次实际范围说明：输入/数据集身份，来源差异，角色逐功能状态，修改文件与关键中文说明，执行命令/输入/字面输出/退出状态，
候选/清单/差异/备份/回退位置，以及未执行的实机或组件验证。源码合入、候选构建、晋升、打包和游戏验收分别记状态。
缺证据保留未知/部分/未就绪，不用默认零、旧图、同名角色或宣称“全支持”消除缺口。
