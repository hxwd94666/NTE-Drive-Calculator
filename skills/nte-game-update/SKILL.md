# 异环计算器版本更新

让现有功能正确消费新版本。角色行已导入、页面可见、面板可信、评分可用、战报支持和原生支持分别判断。

## 定位与授权

- 核实计算器仓库、Git ref、未提交状态及解包根，先读 `RESPONSIBLE_USE.md`、`AGENTS.md` 和当前 `docs/architecture.md`。
  本文代码路径相对仓库，辅助脚本路径相对本 skill；保留既有改动。
- 冻结地区、游戏版本依据、导出批次、dataset、旧发行与组件身份；解包只读，多 Content 根显式选择，不以目录时间推版本。
- 分别确认本次代码修改、检查、候选构建、正式晋升范围；使用 skill 不附带提交、推送、打包、部署或游戏操作权限。
  完整来源、账号数据与本机绝对路径不进公开交付。

## 从输入开始

读取 [更新工作流](references/update-workflow.md) 的来源与候选章节。可用 `scripts/inspect_update_inputs.py`
定位唯一 Content 根并对比已登记来源：默认主库，独立图鉴显式传 `--baseline-dir data/role_catalog`，报告只写仓库 `build/` 新文件。
未登记文件提示不等于本版新增；角色行、结构、机制和素材差异仍沿正式 importer/资源规则核对。

## 更新时的分流

1. 同版战斗来源完整时构建 `game`；另核对独立图鉴及公共图片。来源不足时只交付证据充分的 `role_page` 或 `reference`，
   不提升为战报/原生能力。一次计算冻结一个校验目录，多来源只在同版且显式优先级下逐文件登记，缺项不以旧版补齐。
2. 新增、删除及改动角色/机制按 [角色与功能适配矩阵](references/character-adaptation.md) 定位真正消费者，
   区分只更新数据、需扩展现有公共模型、组件待支持与未知；不复制评分公式或顺带实现新伤害分配器。
3. 数据与同版公共素材成套维护，核对正式 SkillID、别名关联、图标来源和 SHA-256；数据更新与纯技能图片维护分流。
4. 按实际变更做必要校验，再最终化、只读预检、授权晋升。工具的失败自动回滚不是成功后的持久降级备份，先准备旧整包及匹配配置。

## 维护与调用副本

`skills/nte-game-update/` 是编辑事实源；个人 skills 目录是自动调用副本。维护后逐文件比哈希并明确是否同步，勿默认两份一致。
外部目录写入获准后只同步本 skill 的受控文件，保留安装目录其他文件，再核对哈希；未同步时可明确指定仓库 `SKILL.md` 路径调用。
skill 维护完成、本机调用更新、真实版本更新通过是三项不同结果。
